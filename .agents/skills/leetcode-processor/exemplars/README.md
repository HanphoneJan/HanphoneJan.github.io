# 题解范文：一条线，不是四段跳

这三篇是同一个人（灵茶山艾府）写的，共同点不是文风，而是**顺序**：读者只需要顺着一条线走一遍，不用在「抽象—代码—具体—再抽象」之间来回跳。

我们的旧模板是：

```
解题思路（纯抽象） → 完整代码（跳回代码） → 示例推演（跳回具体）
→ 复杂度（跳回抽象） → 易错点（又一次抽象） → 扩展思考（换话题）
```

读者被弹了四次，每次都要重新建立上下文。范文是：

```
题目/示例（具体） → 手法（抽象，一个锚） → 代码（与手法同构） → 推演（同一套编号，再走一遍） → 边界（就地） → 复杂度（一句）
```

## 三篇共同的六件事

1. **头两句给路线。** 200 那篇第一句就是「先说总体思路，然后说 DFS 的细节」。读者知道接下来会看到什么、按什么顺序看。
2. **一个具象的锚，全文不换。** 1456 是「窗口的进/出」，200 是「插旗子 🚩」，3281 是「每个区间选一个数、x 一路往前推」。比喻只用一个，后面所有讨论都挂在它上面。
3. **手法、代码、推演三者同构。** 1456 的「入—更新答案—出」三步，就是代码注释里的 ①入 ②更新 ③出，也就是举例里每一步的「进 X → 答案 → 出 Y」。读者读完手法再看代码，每一行都能指回上文的一句话。
4. **边界和失败方式就地讲，不另起一章。** 3281 把「x 超过右端点 → 收右界」「全都放得下 → 推左界」写在判定函数的推导里；200 把「先判越界还是先判 grid」写成答疑；1456 用 `left < 0` 的 `continue` 解释「第一个窗口还没形成」。没有一节叫「易错点总结」。
5. **推演只走一遍，而且服务于手法。** 不是「先看样例、再总结规律」，而是「先说手法、再用样例验证」。1456 走 9 步，200 走 4 帧，3281 干脆不走（公式本身已经可验证）。
6. **复杂度一句话。** 不堆三行表格（那三篇里都没有「暴力/优化/最优」的表格，因为没有三条解法）。

## 怎么用

- 写之前读一遍 `README.md` 里的六条，再挑**同一类题**的那一篇看（滑窗看 1456，二分看 3281，DFS/网格看 0200）。
- 写的时候对照检查：**把任意一段单独抽出来贴到别的题解里，如果不用改一个字，那段就是套话，删掉。**
- 不要学：多语言代码块（我们只发 Python）、题单推广尾巴、标题里的表情和票数。

## 文件

| 文件 | 题 | 学什么 |
|---|---|---|
| `1456-定长滑窗.md` | 定长子串中元音的最大数目 | 把一个具体做法上升成「三步套路」，并让代码编号与套路对齐 |
| `3281-二分答案最大化最小值.md` | 最大化区间选数的最小差值 | 判定函数与「二分往哪边走」绑在一起讲；开区间写法省掉 ±1 |
| `0200-岛屿数量.md` | 岛屿数量 | 路线声明 + 一个具象锚 + 用答疑代替易错点清单 |

三篇都只存骨架、摘句和出处，不存全文：范文是拿来学结构的，抄全文会变成照抄。
