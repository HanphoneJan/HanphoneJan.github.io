# 图：draw.io

图不是正文的插图，是正文的一种表达方式。**先选图型，再画**；图型错了，画得再整齐也在误导读者。

## 什么时候画

- 架构、部署、数据流、请求时序、状态机、权限判定、删除/失败路径：用 draw.io。
- **每篇讲流程或结构的文档至少一张图。** 一篇长文只有一张“方框+箭头”通常不够：入口与进程边界、状态迁移、异常路径可以拆成不同的图。
- **表格能说清的不要画。** 服务缺失影响、测试分层、耦合面清单这类内容，表格比盒子图清楚，也不会把读者引向“这些盒子之间有调用关系”的误读。
- 三行以内的流程、纯对照、能从表格直接读出的：不画，写成句子。

## 先选图型

| 内容 | 图型 | 必须有的元素 | 常见错误 |
|---|---|---|---|
| 部署、组件、系统边界 | C4 Container（系统边界 + 容器 + 外部系统） | 谁在边界内、跨边界走什么协议 | 把类名、表名、配置项塞进容器框 |
| 请求时序、重连、重试 | UML 2.5 sequence | 生命线、编号消息、`alt`/`opt`/`loop` 片段、返回用虚线 | 返回路径经过不相关的组件；把备选分支画成顺序步骤 |
| 任务/实例生命周期 | UML state machine | 初始状态、终态、`事件 [守卫] / 动作` | 把前置条件（门禁、鉴权）画成状态；画不会出现的状态 |
| 跨角色流程 | UML activity + swimlane | 一条泳道一个进程/角色，判定用菱形 | 一条箭头穿过多个角色；分支没有判据 |
| 表结构、集合、键 | ER | 实体、主键、关系基数 | 画成流程图，箭头表示“调用” |
| 权限、准入 | decision tree | 每个分支写判据，终点写结果 | 箭头没有判据；把“拒绝”画成一个可继续的状态 |

一张图只用一种图型。部署图里混进状态，或时序图里混进数据表，读者无法判断箭头是调用、数据流还是状态迁移。

## 先写 diagram brief

动笔前先用文字写清这七行，再画：

```text
标题：一次入站任务
一句话：HTTP 请求进来后，经过鉴权、协议分发、任务生命周期，最后落到会话和存储。
图型：UML activity + swimlane
泳道：HTTP / 协议 / 任务 / 执行器 / 会话
节点：POST → 读 body → 限流 → Bearer → 版本 → parseRpc → ensureTask → runTask → session → artifact/SSE
边：主路径实线；拒绝、超时、取消用虚线，从判定点出发
图例：只有虚线需要说明时才有
画布/字号：700 × ≤900，正文 14px
```

brief 里写不出“一句话”，说明这张图想讲两件事，拆开。

## 画布、字号与导出

- **画布宽 ≤700px，正文 ≥14px。** 本站正文栏在 1440 宽的窗口里约 673px；700px 画布在页面上接近 1:1，14px 的字最终约 13.5px。按 1100–1200px 设计时 14px 会缩到 8px 左右，读者只能点开看。
- **节点内最多两行，边标签最多 6 个字。** 整句解释属于正文，不属于图。
- **图里只画结构。** 格子、节点、箭头、短标签是图的内容；不要在底部加通栏说明框，读者会把它当图的一部分硬读，而它和正文重复。
- **中文标签默认 PNG 2x。** draw.io 导中文常把文字栅格化成 `<image>`，一个“SVG”可能 200–400 KB。中文图统一导 PNG 2x；只有纯英文/数字标签才考虑 SVG。
- 导出 2x，单张 ≤150KB；超过就拆图或减少装饰，不要靠压缩把字压糊。
- 一张图只表达一件事。表达两件事就拆两张；宁可多一张小图，不要一张信息过载的大图。

## 语义

- **箭头写“动词 + 对象”**：`调用 SendMessage`、`写入 tasks 表`、`返回 Task`。不写“数据”“请求”“处理”这种没有方向的词。
- **状态迁移写 `事件 [守卫] / 动作`**：`SendMessage(taskId) [任务空闲] / 追加输入`。不要把“门禁通过”画成状态迁移的起点。
- **时序图消息编号**，从发送者指向接收者；返回用虚线；备选分支放进 `alt`/`opt`，不要用一条时间线顺序画两个互斥分支。
- **不混用箭头语义。** 同一张图里，实线/虚线的含义只能有一组；不要一会儿表示调用、一会儿表示数据流。
- **边标签是文字，不是节点。** 白底、**无描边**，14px，放在边的起点附近或直线段中段；不许压在拐角、不许同时贴着两条线、不许两个标签挨在一起。drawio 给边自带的标签底板恒有 1px 描边、`labelBorderColor` 也关不掉（29.x 实测），看起来像按钮 —— 用**独立的 label cell**（`fillColor=#ffffff;strokeColor=none`）贴上去。
- **两条边的标签在 700px 里放不下，说明这两条边不该同时出现。** 合并或删掉，不要靠缩字号解决。
- **不画不可达节点。** 代码里不会出现的状态、不会走到的分支，用 note 说明“不产生”，不要画成节点再连一条虚线。
- **一张图一个抽象层。** 组件、数据表、部署节点、外部 peer 不放在同一张图；要放在一起时，用 container 明确分组，并让箭头只表示一种关系。

## 颜色与图例

- 颜色只在编码信息时用，最多三类语义：主路径、异常/降级、可选/异步。
- **每张图自己的图例**，只解释这张图实际用到的颜色和线型。不要把同一条图例复制到所有图；图里没有绿色时，图例里就不该出现“绿=成功”。
- 没有语义就不上色。中性色节点（`#f5f5f5` / `#333333`，描边 `#666666`）在浅色和暗色主题下都能读。
- 不要用颜色表示“重要性”或“层级”。读者会以为那是协议或状态的含义。

## 反例库

这些是真实踩过的坑，写完后逐条对照：

| 反例 | 为什么错 | 正确做法 |
|---|---|---|
| 12 张图共用一条“绿=成功终态 红=失败终态” | 绿色实际标的是“必需服务”“路由启用”，红色标的是“tombstone”“failed”；图例与语义相反 | 每张图只解释自己用到的颜色；没有语义就不上色 |
| 1256px 画布塞进 673px 正文栏 | 12px 字缩成 6px，页面上不可读 | 画布 ≤700px，正文 ≥14px，2x 导出 |
| 把表格画成一格格盒子（服务降级、测试分层、耦合面） | 盒子之间的空白被读成调用关系，信息密度反而更低 | 用表格；只有真的有时序/状态/边界时才画 |
| 时序图把 registry 放在返回路径上 | registry 只注册工具，不转发结果；读者会以为结果经过它 | 返回箭头从真正产生结果的组件指回调用方 |
| SSE 同一帧画成“发给客户端”和“写入事件日志”两条独立路径 | 实际是先写日志再投递；两条路会被读成两次投递 | 用一条主路径，日志作为旁路，标清顺序 |
| 状态机把“门禁”画成状态，把 REJECTED 画成节点 | 门禁发生在建任务之前，REJECTED 不会落库 | 门禁写在入口 note；REJECTED 只在正文说明“不会出现” |
| 图底部 2–4 行通栏说明 | 与正文重复，读者把结论当图的一部分 | 结论回正文；图里只留节点和短标签 |
| 组件、表、部署节点、外部 peer 混在一张图 | 抽象层不同，箭头无法判断是调用、数据流还是部署关系 | 拆成部署图、存储 ER、调用时序三张 |
| 一个状态的五条守卫全挂在它的出边上，扇出成一束线 | 分不出哪条边对应哪条判据，标签必然互相压线、箭头挤在同一个点 | 判定按顺序求值：一列菱形，每条「是」在自己高度上向右出到结论，最后一条「否」落默认 |
| 5 个互不依赖的端点从左到右串成一条链 | 读起来像一次调用的五个步骤，实际可任意顺序、任意次数 | 有会话状态才画状态机；否则画表格（端点 / 请求 / 后端动作） |
| 进程与存储之间画满六条读写边 | 3×2 的二分图在 700px 里必然交叉，标签挤成一排 | 图上只留一种关系（调用），读写关系落表格；存储容器只列不连 |

## 文件约定

| 类型 | 位置 |
|---|---|
| 源文件 | `static/diagrams/src/<slug>.drawio`，或项目自己的 `static/img/<project>/src/<slug>.drawio` |
| 导出 | 与源文件同级的上一级：`static/diagrams/<slug>.png` 或 `static/img/<project>/<slug>.png` |
| 正文引用 | `![图注](/diagrams/<slug>.png)` 或 `![图注](/img/<project>/<slug>.png)` |

- `<slug>` 用 kebab-case，语义化：`inbound-pipeline`、`task-state`、`outbound-sequence`。
- **源文件必须进仓库**；只提交 PNG 视为不合格。
- 没有 `static/` 的项目放 `docs/diagrams/src/` 与 `docs/diagrams/`，在写作方案里写明。
- 项目文档沿用该项目的图片目录，不要为了统一把已有项目搬到 `static/diagrams/`。

## 暗色模式

- 导出透明背景，节点填中性色（`#f5f5f5` / `#333333`），描边用 `#666666`。
- 不要用纯白底、高饱和品牌色；暗色主题下会刺眼。
- 文字放在浅色节点或浅色标签背景上；透明背景上的深色文字在暗色主题下读不出来。
- 需要精细控制时导出两版：`<slug>.png` 和 `<slug>.dark.png`，用 `<picture>` 或 CSS 切换。默认先做透明背景一版。

## 检查

先跑机械检查：

```bash
python3 .agents/skills/doc-writing/scripts/check_diagrams.py static/img/dsh-a2a/src
```

它检查：

- `pageWidth > 700`；
- 有文字的节点/边标签 `fontSize < 14`，或没有显式字号（draw.io 默认 12）；
- 对应的 PNG 缺失、体积 >150KB、宽度不是约 2 倍画布。

再人工看：

1. 在正文宽度（约 673px）下不点开也能读；100% 与 150% 都不裁切。
2. 箭头方向对，连线没有穿过文字；跨泳道的边从边界进出。
3. 图例、编号、虚线含义与正文一致；没有与图无关的图例。
4. 暗色主题下能读。
5. 正文里的“下图”和图对得上，每张图有 alt 文本。
6. 整篇的图加起来不超过约 500 KB。

## 导出脚本

```bash
# 默认 PNG 2x（中文标签的首选），导出后自动转 256 色调色板
bash .agents/skills/doc-writing/scripts/export_drawio.sh static/img/dsh-a2a/src static/img/dsh-a2a

# 只重导一张：第一个参数给 .drawio 文件
bash .agents/skills/doc-writing/scripts/export_drawio.sh static/img/dsh-a2a/src/outbox.drawio static/img/dsh-a2a

# 纯英文/数字标签才考虑 SVG
bash .agents/skills/doc-writing/scripts/export_drawio.sh --format svg static/diagrams/src static/diagrams
```

脚本遍历 `src/` 下的 `.drawio`（或只导点名的那一张），按 `--format` 导出同名文件；导出后跑一遍 `check_diagrams.py`。

三个不容易发现的点：

- **RGBA 的 2x 图会到 200KB 以上**，而 150KB 的上限是按索引色标的。脚本在 drawio 导出后用 `ffmpeg palettegen`（256 色 + 1bit alpha）重编码一次，体积降到 40–110KB。**不要手工再压一遍**（降色、加边距、pngjs），否则重跑脚本得到的是另一份产物，下一个人改图时会同时改坏体积。
- **透明底要求每个文字都落在浅色填充上。** `-t` 之后裸标签是深灰字落在透明底，暗色主题下看不见。画的时候给标签一个浅色底，或者干脆不要裸标签。
- **单元格 id 撞上 JS 全局名会让导出静默失败**：drawio 29.3.6 里 id 叫 `keys` 的那一页报 `Error: Export failed`、退出码仍是 0、不留产物，而脚本对已存在的旧 PNG 会判过 —— 现象是「改了源文件但图没变」。id 用 `apikeys` 这类带前缀的名字。

## 硬规则

- 不用 Mermaid。
- 最终文档不留 ASCII 图；ASCII 只作为中间稿，转换后删除。
- 每个“下图”必须有对应图片；没有图就删掉这句话。
- 每张图必须有 alt 文本，写清这张图在讲什么。
- 图的源文件必须进仓库。
- 图内不写结论段落；图例只在该图用色时出现；表格能说清的不要画成盒子。
- 时序、状态、泳道必须符合对应图型的语义；不画不可达状态，不把前置条件画成状态。
