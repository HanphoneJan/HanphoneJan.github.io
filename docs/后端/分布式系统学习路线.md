分布式系统这个词太大，直接「学分布式」会迷失。按系统类型拆成五类，每类只需要搞清一两个代表系统，剩下的都是同一套概念的不同实现。

## 1. 分布式存储

| 系统 | 架构 | 该学什么 |
|---|---|---|
| HDFS | 中心化（NameNode + DataNode） | 块存储、副本放置、单点瓶颈 |
| Ceph | 完全无中心（CRUSH 算法） | 一致性哈希的替代方案、PG 与 OSD |
| etcd | Raft 复制 | 强一致的小数据存储怎么做 |

核心概念：**复制、分片、一致性哈希、CAP 的实际取舍**。

## 2. 分布式计算

- **Hadoop MapReduce** —— 批处理的鼻祖，理解「map / shuffle / reduce」三段就够了
- **Spark** —— 把中间结果放内存，DAG 调度；重点是 RDD 的血缘与窄宽依赖
- **Flink** —— 真正的流处理，重点是时间语义（事件时间 vs 处理时间）、水位线、状态与 checkpoint

## 3. 分布式消息队列

- **Kafka** —— 分区、副本、ISR、消费位点。它是「分布式提交日志」，不是传统队列，这个认知差决定了怎么用它
- 对比 **RabbitMQ**：前者吞吐高、顺序只在分区内保证；后者路由灵活、有确认机制

## 4. 协调与共识

- **ZooKeeper**（ZAB）与 **etcd**（Raft）：选主、配置管理、分布式锁
- 共识算法先看 Raft（比 Paxos 好懂），理解「任期、日志复制、多数派提交」三件事

## 5. 分布式机器学习

- **Spark ML** / **分布式 TensorFlow** / **Horovod**：参数服务器 vs AllReduce
- 重点不是框架，是「通信开销怎么摊」：数据并行、模型并行、流水线并行的取舍

## 学习顺序建议

1. 先补**单机**的操作系统与网络（进程、fd、TCP），否则分布式的问题会看起来像玄学
2. 读 Raft 论文（比 Paxos 友好），理解「多数派」为什么能保证一致
3. 挑一条线深入：做存储就看 HDFS + Ceph，做数据就看 Spark + Flink，做中间件就看 Kafka
4. 每一类都动手起一个最小集群（Docker Compose 三节点就够），看它挂了会怎样

最后一件事：**分布式系统的大部分设计都在处理失败**。读任何系统时都先问一句「它假设什么不会坏」。
