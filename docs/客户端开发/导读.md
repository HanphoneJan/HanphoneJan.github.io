这四篇都不属于 Web：Qt 是 C++ 桌面，Flutter 用 Dart 自绘 UI，Android 是原生移动端，小程序与 Uniapp 虽然借了 Vue 的语法，但运行时在微信或 App 的容器里，不是浏览器。

## 先看要交付到哪

```text
桌面（Windows / Linux）        → Qt
移动端 + Web + 桌面，一套代码   → Flutter
只上架 Android / 深度用系统能力 → Android 原生
微信生态、H5 改小程序           → 小程序与 Uniapp
```

## 四条路线的共同点

四篇都是「装环境 → 跑最小工程 → 排障」的顺序，因为卡住人的几乎总是环境：下载器慢、组件一勾几十 GB、代理只配了一半。代码层面的问题反而少。

- **先跑官方最小工程，再迁自己的代码**。最小工程跑不起来时，改业务代码没有任何意义。
- **代理要同时配工具和包管理器**。Android 的 AS 与 Gradle、Flutter 的 pub 与 Gradle，是两套独立的网络配置。
- **别一次勾全组件**。Qt 一个版本一个编译器、Android 一个目标 API 就够。

## 和「前端」怎么分工

- 浏览器里的东西（HTML/CSS/JS、请求、渲染、PWA）在 [前端系列导读](../前端/导读.md)。
- 这里只放「跑在浏览器之外」的客户端。Uniapp 之所以在这边，是因为它最终打包成小程序或 App，调试与发布走的是微信和 DCloud 那一套。
