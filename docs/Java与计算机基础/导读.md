# 系列导读：把 Java 接回计算机基础

> Java 的「运行时」比 Python 更显式：JVM 规范、字节码、类加载、GC、JIT 都是可以单独拿出来讲的一层。学 Java 如果只停在 Spring 和 API，很多问题就只能靠背——为什么 `HashMap` 扩容是 2 倍、为什么虚拟线程怕 `synchronized`、为什么 `@Transactional` 自己调自己失效、为什么 Full GC 后 RSS 还不降。

## 这个系列想做什么

和 [Python 与计算机基础](../Python与计算机基础/导读.md) 同一套骨架：

```text
计算机基础概念
      ↓
JVM / JDK 怎么实现
      ↓
Spring / 中间件 / 业务代码里怎么用
      ↓
常见坑与边界
      ↓
动手实验
```

每篇回答三个问题：

1. 这个概念在 Java/JVM 里对应什么？
2. JDK 的实现和教材里的理想模型差在哪？
3. 写业务代码时，这个差异会以什么形式咬你？

## 版本基线

- 语言与 API 以 **Java 17 / 21 LTS** 为基线；虚拟线程（JEP 444）需要 21+，Foreign Function & Memory API 在 22 正式化，文中会单独标注。
- JVM 行为以 **HotSpot** 为准；OpenJ9、GraalVM 的默认 GC/JIT 策略不同。
- GC、JIT、类文件格式都随版本演进；具体参数和日志格式以你使用的 JDK 为准。
- `javap` 的输出会随编译器版本变化，示例只保证语义，不保证每条指令的编号一致。

## 怎么读

- 每篇独立，可以按需跳读；侧边栏顺序是「数据结构 → 操作系统 → 网络 → 数据库 → 内存管理 → 编译原理」。
- 代码默认是普通 Java（无框架）；Spring、MyBatis、Netty 只作为应用场景出现。
- 每篇末尾的「动手实验」建议跑一遍，尤其是 `javap`、`jcmd`、`jstack`、`-Xlog:gc` 这类能直接看到 JVM 行为的命令。
- 和仓库里的 `docs/后端/Java基础.md` 互补：那篇讲语法与 API，这个系列讲语法下面的运行时。

## 和 Python 系列的关系

- Python 版偏「解释器 + 私有堆 + GIL」；Java 版偏「JVM + 字节码 + GC + JIT」。
- 两套系列可以对照读：同样是哈希表，Python 的 `dict` 是紧凑哈希表，Java 的 `HashMap` 是桶数组 + 链表/红黑树；同样是并发，Python 受 GIL 限制，Java 的平台线程是真并行，虚拟线程是用户态调度。
