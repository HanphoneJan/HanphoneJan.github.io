# 系列导读：把 Python 接回计算机基础

> 学 Python 很容易停在「会用」：会写 `list`、会调 `requests`、会开线程。但应用开发里的很多问题——为什么 `pop(0)` 慢、为什么 GIL 让多线程跑不满 CPU、为什么 `async` 里调用 `requests` 会卡住整个服务——答案都不在 Python 语法里，而在它下面的计算机基础。

## 这个系列想做什么

每篇文章都按同一条线索展开：

```text
计算机基础概念
      ↓
CPython / 标准库怎么实现
      ↓
应用开发里怎么用
      ↓
常见坑与边界
      ↓
动手实验
```

不是再抄一遍教材，而是回答三个问题：

1. 这个概念在 Python 里对应什么？
2. Python 的实现和教材里的理想模型差在哪？
3. 写业务代码时，这个差异会以什么形式咬你？

## 版本基线

- 语言语义按 **Python 3**，代码示例以 **3.11+** 为基线；3.12 / 3.13 / 3.14 的差异会单独标注。
- 涉及解释器内部实现时，明确限定为 **CPython**；PyPy、GraalPy 等实现不保证同样的行为。
- 具体的内存布局、分配器参数、默认阈值都可能随版本变化，**不要把某一次实测当成永久常量**。

### 容易写死的版本结论

| 结论 | 生效版本 |
|---|---|
| GC 默认阈值 | 3.11/3.12 常见 `(700, 10, 10)`；3.13 常见 `(2000, 10, 10)` |
| pymalloc arena/pool | 64 位 3.11+ 实测 1 MiB / 16 KiB；更早或 32 位可能不同 |
| 不朽对象 | 3.12+ |
| `multiprocessing` 默认 start method | 3.14 起 POSIX 默认 `forkserver`（macOS 仍 `spawn`） |
| free-threaded 构建 | 3.13 实验性；3.14 起官方支持 |
| `os.process_cpu_count()` | 3.13+，尊重 CPU 亲和性 |

## 怎么读

- 每篇独立，可以按需跳读；侧边栏顺序是「数据结构 → 操作系统 → 计算机网络 → 数据库 → 内存管理 → 编译原理」。
- 代码块分两类：完整示例可以直接运行；带 `...` 或未定义名字的是片段，会明确标注「片段」或「伪代码」。
- 每篇末尾的「动手实验」建议真的跑一遍，尤其是 `timeit`、`sys.getsizeof`、`ss`、`curl -v` 这类能直接看到差异的命令。
