# 导读

本栏目是一套 Knowledge Hub 的架构与设计文档，已经做过脱敏，主要用于个人复习。

Knowledge Hub 是一个单机自部署的多租户知识库和 RAG 检索服务。它把办公文档、聊天记录和照片收进不同的知识库，再用四种方式召回内容：向量检索、BM25、子串匹配和视觉检索。找到原文之后，它给出带页码和坐标的引用，并通过 MCP 与 A2A 协议把这套能力提供给 AI 客户端和别的 Agent。

文档面向要读代码、改代码的工程师。重点讲设计意图和取舍：为什么这样做、代价是什么、什么情况下会降级。功能介绍和使用手册不在本栏目的范围内。

- 只想快速了解这个项目：先读[项目深度拆解](./项目深度拆解.md)，再读[架构总览](./架构总览.md)的「进程与存储」一节。

- 准备改代码：先读[架构总览](./架构总览.md)和[工程约定与踩坑](./工程约定与踩坑.md)，了解不能破坏的约束。
- 只想知道怎么把系统跑起来：直接读[部署与运维](./部署与运维.md)。

## 全局速览

```
                     ┌──────────────────────────────┐
    浏览器 / 客户端 → │ api（FastAPI）:8010          │ → Qdrant   :6333   （派生索引）
                     │  检索编排 · 托管前端          │ → PostgreSQL :5432（真相源）
                     │  MCP /mcp · A2A /a2a         │
                     └───────┬──────────────────────┘
                             │ 入队 / 查进度
                             ▼
                     ┌──────────────────────────────┐      ┌───────────────────────┐
                     │ worker（无监听端口）          │      │ visual_service :8020  │
                     │  轮询任务 · 摄取 · 清理       │      │  只做“文本/图片 → 向量”│
                     └──────────────────────────────┘      └───────────────────────┘
```

| 维度 | 现状 |
|---|---|
| 检索 | 四条通道 RRF 融合：dense（`bge-small-zh-v1.5`，512 维）、BM25（自实现，jieba 分词）、trigram（PostgreSQL）、视觉（`colSmol-500M` 多向量 MaxSim，128 维） |
| 存储 | PostgreSQL 是唯一真相源；Qdrant 的三个集合是可重建的派生索引；原件按内容寻址存放在本地磁盘 |
| 租户 | 三档可见性（`private` / `workspace` / `global`），过滤条件只在 `auth.py` 一处构造，请求体不接受租户字段 |
| 生成 | 默认抽取式，答案句子全部摘自原文，不外传；接外部 LLM 需要显式配置，并按知识库和用途分别开关 |
| 任务 | PostgreSQL 任务表加轮询 worker；`jobs.progress` 是进度的唯一来源；文档终态要同时看任务状态和索引点数 |
| 规模 | 契约声明 82 个端点，实现 81 个，1 个明确不做；pytest 1335 项；前端 vitest 316 项；三套验收脚本分别 138、218、199 项 |

文中所有性能数字都注明了测量条件，例如用的是哪条通道、多少条候选、什么机器。单个数字脱离测量条件没有意义：比如把四类语料混在一起算出的 overall R@10，就不能用来判断某条通道的好坏。

文档里的人物、文件名和查询内容都是合成示例，域名、密钥和路径使用占位符；代码路径、表名、环境变量和实测数字保留原名。
