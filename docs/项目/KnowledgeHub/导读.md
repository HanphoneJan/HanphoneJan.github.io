# 导读

---

## 1. 定位与边界

KnowledgeHub 是一套单机自部署的多租户知识库服务。它把办公文档、聊天记录、照片收进同一个库，切成块，建四路索引，然后用带引用溯源的检索与问答把原文找回来。

三件事决定了它的形状：

| 目标 | 落到哪个实现 |
|---|---|
| 每条结论都能点回原文 | L3 坐标：`chunks.locations` 存归一化 bbox，前端乘回页图像素画框 |
| 默认不把原文送出本机 | 生成层默认抽取式；接外部 LLM 需显式配置 |
| 单机也能运维 | Postgres 任务表、一条巡检命令、备份只备事实、索引靠重建 |

不做的事：OCR（扫描件只走视觉召回）、对象存储、Redis 或消息队列、k8s、细粒度 RBAC、多实例横向扩展。

---

## 2. 三条主链路

**写入**：上传 → 校验 → 内容寻址存储 → `documents` 行 → `ingest` 任务 → 解析 → 切分 → 嵌入 → 写两条文本腿 → 视觉任务与预览任务 → `ready`。

**读取**：检索 → 四条腿并发 → RRF 融合 → 软删二次过滤 → 路由偏好 → 精排 → 证据组装 → 生成 → 引用校验 → 落库。问答走 SSE，帧序 `sources` → `delta`* → `done`。

**对外**：HTTP、MCP、A2A 三个入口调同一套 `engine.search` 与 `ask.prepare + stream_answer`。权限都读 `UserContext.readable_kb_ids`，没有第二套检索实现。

## 3. 进程与端口

| 进程 | 端口 | 常驻 | 职责 |
|---|---|---|---|
| API | 8010 | bge-small，约 100MB | REST / SSE、MCP、A2A、托管 `web/dist` |
| worker | 无 | colSmol，约 2.65GB（可关） | 轮询任务、摄取、清理、定期对账 |
| visual_service | 8020 | colSmol，约 2.65GB | 只做编码，不查 Qdrant、不做租户过滤 |

Postgres 5432、Qdrant 6333/6334，全部只绑 `127.0.0.1`。

```bash
bash deploy/dev.sh start      # API + worker + 视觉服务
bash deploy/dev.sh restart    # 改了后端代码用这个
bash deploy/dev.sh stop
bash deploy/visual.sh status  # 视觉服务单独管理
```

`dev.sh` 只有 `start` / `restart` / `stop` 三个子命令。看状态用 `curl -s --noproxy '*' http://127.0.0.1:8010/health`，看日志用 `/tmp/pkh_api.log`、`/tmp/pkh_worker.log`、`/tmp/pkh_visual.log`。

视觉服务首次启动要 13 秒加载 colSmol。这段时间视觉腿降级成 `skipped`，检索照常返回。

## 4. 目录与常用命令

```
services/
  api/          FastAPI 入口、19 个路由模块、前端托管
  common/       模型、认证、任务、存储、Qdrant、对账
  ingest/       解析、切分、PII、坐标、版本、清理
  retrieval/    四条腿、融合、路由、精排、问答
  worker/       主循环、文档终态、八种 handler
  mcp/          JSON-RPC 协议层与四个工具
  visual_service/ 只做编码的常驻进程
web/            React 19 + Vite + Tailwind v4
migrations/     23 个迁移
eval/           契约检查、三套 HTTP 验收、检索评测
deploy/         起停、巡检、备份、恢复、蓝绿迁移
tests/          1335 项 pytest
```

| 命令 | 用途 |
|---|---|
| `uv run python -m services.api.scripts.create_user` | 建账号（自助注册默认开，对外部署应关） |
| `uv run python deploy/seed_photos.py` | 造一个持久照片库演示账号 |
| `uv run python deploy/monitor.py` | 十四项巡检，跳过不算健康 |
| `bash deploy/backup.sh` | 备份并自检 |
| `bash deploy/restore.sh --scratch <dir>` | 恢复到临时库并逐表对账 |
| `bash deploy/ci.sh` | CI 与本地共用的门禁 |
| `uv run python eval/contract_check.py` | 82 / 81 / 1 的契约对账 |
| `cd web && npm run build` | 改过前端要重新构建，`dev.sh` 不会替你构建 |

## 6. 已知限制

| 限制 | 具体表现 |
|---|---|
| 默认不做归纳 | 抽取式只给原句。配了外部 LLM 才能归纳，而那就意味着原文离开本机 |
| 文档没有可信撰写日期 | 文件名是编号或修订年份，mtime 是拷贝日期；事件日期来自 EXIF 或文件名，抽不到留空 |
| Late Chunking 受 512 token 限制 | 超出部分落在截断后的 span 里 |
| Contextual Chunking 需外部 LLM | 默认抽取式不外传，因此不生效，只记一条 note |
| 表格结构化只覆盖 PDF / CSV / XLSX | DOCX / HTML / PPTX 里的表格仍按纯文本处理 |
| 新增字段有重摄取欠账 | `table_json` / `updated_at` 只对之后摄取的文档生效 |
| 外部 LLM 不可用会降级 | 401 / 超时 / 5xx 退回抽取式，`done.degraded` 写原因，这一轮没有归纳 |
| 视觉服务没有鉴权 | 只绑 `127.0.0.1`。别指到 `0.0.0.0` |
| 不做 OCR | 扫描件交给视觉召回，不走 tesseract |
| 外部 LLM 只实测过一个厂商 | 一个 OpenAI 兼容网关，含自定义请求头的情况 |
| 存储只有本地盘 | `blobs.storage_path` 没有代码读它做分发 |
| PII 掩码按 chunk 检测 | 跨 chunk 边界的号码会漏检 |
| 检索连接数是并发瓶颈 | 一次 `hybrid` 最多 4 条连接，池按并发检索数 × 4 估 |
