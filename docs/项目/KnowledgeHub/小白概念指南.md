# 小白概念指南

> **阅读目标**: 先把正文里反复出现的八个术语弄懂，再去看架构与链路。这一篇只讲「是什么」，具体实现与数字都在正文章节里。

---

## 1. 向量与余弦

**向量 = 一串数字，表示一段文本的「方向」。** 两个向量的方向越接近，意思就越接近。

```
"报销流程怎么走"    →  [0.12, -0.53, 0.88, …]    512 个数
"费用报销需要几步"  →  [0.11, -0.49, 0.90, …]    方向几乎一样
"今天吃什么"        →  [-0.70, 0.21, -0.13, …]   方向差很远
```

检索就是在这堆方向里找最接近的那几个。度量方式叫**余弦相似度**：完全不相关是 0，方向一致是 1。余弦只关心方向不关心长度，所以文本长一点短一点不影响。

---

## 2. chunk：检索的最小单位

一份 PDF 不会整篇参与检索。它先被切成若干块，每块叫一个 **chunk**，入库、编码、打分、引用都以块为单位。

块的大小决定了两件事：切得太碎，一句话被切成两半，检索到也读不懂；切得太大，一块里混着五个主题，命中一个主题连带进来四段无关内容。这个项目的切分策略有六种，见《文档摄取》§3。

每条结论能点回原文，也是因为 chunk 记着自己在原文里的位置（见 §8）。

---

## 3. 四条腿：四种找法

「腿」就是一条独立的召回通道。同一个问题四条腿各找一遍，再合并。

| 腿 | 怎么找 | 擅长 |
|---|---|---|
| dense | 比向量方向 | 意思相近但用词不同的（「报销」↔「费用核销」） |
| sparse | 按词打分（BM25） | 人名、学号、错误码这类必须精确命中的词 |
| trgm | 按子串比对 | 不像词的字符串：`sk-pkh_…`、`v2.3.1`、`E4021` |
| visual | 比页图 | 扫描件、照片，没有可抽取文本的页 |

四条腿的盲区不一样。dense 搜不到工号，trgm 搜不到同义词，所以默认 `hybrid` 是三条文本腿一起跑，视觉腿由服务可用性决定。合并规则见 §5。

---

## 4. BM25：关键词怎么打分

BM25 是 sparse 腿的打分公式。三条直觉，全部来自同一件事：**一个词出现得多、但哪里都出现，就不该给高分。**

- **词频有上限**：一块里出现 20 次不比出现 10 次强一倍。多出来的部分被压低，防止关键词堆砌刷分。
- **越少见越值钱**：一个词在库里被越少的文档提到，它的区分度越高。「的」几乎零分，工号几乎满分。
- **块越长越吃亏**：长块天然更容易提到某个词，所以按块长相对平均长度打个折。

公式里对应的量是词频、逆文档频率（idf）与长度归一化系数，两个可调参数控制「饱和多快」与「打折多狠」。具体取值在 `services/retrieval/bm25.py`。

**为什么自己维护统计**：idf 依赖「全库有多个文档提到过这个词」，这份统计只能跟着入库、删除、重建一起改。所以它在 Postgres 里是两张表（`terms` 与 `corpus_stats`），不是 Qdrant 在检索时顺手算的。这也解释了为什么删文档要「把 token 从词表减回去」，漏了不会报错，只是检索慢慢变差。

---

## 5. RRF：分数没法相加，就只比名次

四条腿的分数不是一种东西：余弦是 0~1，BM25 能到几十，trgm 只在 0.25 以上有值。直接加权求和没有意义——哪条腿的数值天生大，哪条腿就说话。

**RRF 干脆不看分数，只看名次。** 每条腿给第 1 名一个分、第 2 名略少、第 3 名更少，然后把同一个结果在各条腿拿到的分加起来。被三条腿同时排在前面的结果自然排到最前面，只有一条腿吹捧的结果上不去。

那个「第 1 名比第 2 名多多少」的参数取 60，是让相邻名次的差距很小，避免某一条腿的头部优势压倒其他腿的共识。具体推导与取值见《检索与问答》§3。

## 6. late interaction 与 MaxSim：一页为什么留一组向量

一张扫描页如果压成一个向量，「页面上某个小表格」这个信息就没了——整页所有内容被平均掉。

colSmol 的做法是**一页留一组向量**，页面上每块区域一个。查询时每个词分别去这组向量里找最像的那个，再把这些最大值加起来打分，这就是 **MaxSim**。所以叫 late interaction：不是把两边压成一个点再比，而是保留细节，比到最后一步才交互。

代价是存储与计算都按「每页多少个向量」放大，编码一页的耗时也远高于编码一段文本（数字见《架构与进程》§4）。这就是为什么视觉腿单独分一个进程、单独限并发。

## 7. 点 ID：内容是地址

Qdrant 里每个点要有一个 id。这里不用自增序号，而是把 `(库 id, 文档 id, 第几块)` 三个数哈希成一个 64 位整数。

好处是**这个号可以随时重算**：

- 重建索引时不需要记住旧号，同一个 chunk 算出来还是同一个号；
- 三条腿（dense / sparse / visual）用同一套算法，同一个 chunk 在三个 collection 里的 id 相同，融合时直接对得上，不用维护映射表；
- 删除时不必先查「这个 chunk 当初存成了几号」。

页级点用负数占位区分：第 0 页传 `-1`、第 1 页传 `-2`，这样「第 0 页」不会和「第 0 块」算出同一个号。哈希、右移、负数的完整理由见《架构与进程》§3。

---

## 8. 三级坐标：引用能落到哪一级

引用的精度分三级：**L1 文档 → L2 页 → L3 框**。

代码只存最细的 L3。`chunks.locations` 里每条记录带 `page` 与 `bbox`：`page` 定位到页，`bbox` 定位到框，坐标已经归一化到 0~1，前端乘回页图像素就能画框。表格块更进一步，每个非空单元格一个框并带 `row` / `col`。

所以「每条结论都能点回原文」不是靠模型说得好，而是靠每个 chunk 都记着自己落在哪一页的哪个框里。

---

## 9. 软删与 30 天

删除分两步。用户点删除时只写一个 `deleted_at` 时间戳，检索立刻过滤掉它，但文件、向量、行都还在——这是回收站。

30 天后才走物理删除：先减词表统计，再删三个 collection 里的点，最后删行、减引用计数、清目录。顺序不能换，原因见《数据与一致性》§5。

## 10. 术语速查

| 术语 | 大白话 |
|---|---|
| 向量 | 一串表示含义的数字 |
| 余弦相似度 | 两个方向有多接近，0 到 1 |
| chunk | 检索的最小单位，原文里的一小块 |
| 腿 / leg | 一条独立的召回通道 |
| dense | 比语义方向的那条腿 |
| sparse | 按词打分的那条腿 |
| trgm | 按子串比对的那条腿（Postgres `pg_trgm`） |
| visual | 比页图的那条腿 |
| BM25 | 按词频、稀有度、块长打分的关键词公式 |
| df / idf | 提到这个词的文档数 / 由它算出的稀有度权重 |
| RRF | 只比名次、不看分数绝对值的融合方法 |
| multi-vector | 一个对象对应一组向量，而不是一个 |
| late interaction | 保留细粒度、到最后一步才比 |
| MaxSim | 每个词取最像的那块再相加 |
| 点 / point | Qdrant 里的一个向量记录 |
| 点 ID | 由三元组哈希出的稳定编号 |
| 内容寻址 | 用内容哈希当路径，同样内容只存一份 |
| L3 坐标 | 块在页面上的框，归一化到 0~1 |
| 软删 | 只打时间戳，检索过滤，30 天后真删 |
| fail-closed | 拿不到授权范围时把条件判成恒假，而不是不过滤 |
