# 前端架构

前端是一个 React 19 单页应用，运行时零 CDN、零 Web Font，内网离线也能使用。

本文讲整体架构，包括路由、功能区和设计意图。目录细节、本地工具以及“必须保住的坑”的权威说明在 `web/README.md`，两边冲突时以它为准。

## 1. 技术栈

| 层 | 选型 |
|---|---|
| 框架 | React 19、Vite 7、TypeScript |
| 样式 | TailwindCSS v4（`@tailwindcss/vite`，不用 PostCSS） |
| 组件 | 按 shadcn/ui 模式自建（`src/components/ui/*`），设计 token 和部分组件参考 RAGFlow |
| 图标 | `lucide-react` |
| 数据请求 | `@tanstack/react-query` |
| 路由 | `react-router-dom` v7 |
| 交互参考 | 对话页和外壳按 Open WebUI 的设计一比一还原，只还原设计，没有拷贝代码 |

设计 token 和部分组件（`button`、`badge`、`card`、`table`、`input`、`textarea`）来自 RAGFlow（Apache-2.0）。逐条出处和改动记录在 `web/THIRD-PARTY-NOTICES.md`。

## 2. 应用外壳

```
┌──┬─────────┬─────────────────────────┐
│图│ 二级面板 │ 内容区（自己滚动）        │
│标│ 288px   │ flex-1 min-w-0            │
│栏│         │                           │
└──┴─────────┴─────────────────────────┘
```

外壳有三条硬规矩：

1. 左侧图标栏分三区：对话、知识库、设置。对应的二级面板互斥渲染。
2. 内容区使用 `min-w-0 flex-1`，`<main>` 是 `overflow-hidden`，页面自己负责滚动。新增页面时不要假设 main 会滚动。
3. 移动端（宽度小于 768 像素）只有图标栏和内容区，二级面板放进左侧的 `Sheet`。桌面端和移动端是二选一渲染（`useMediaQuery`），不是用 CSS 藏起一个，否则同一个控件会在 DOM 里出现两次。

### 2.1 路由

| 路由 | 页面 |
|---|---|
| `/login` | 登录和注册 |
| `/chat`、`/chat/:sessionId` | 对话 |
| `/kb` | 知识库列表 |
| `/kb/:kbId` | 知识库详情，带多个 tab |
| `/settings` | 设置，共 7 个分区 |
| `*` | 回到 `/chat` |

旧路由 `/search`、`/debug`、`/timeline`、`/photos`、`/sessions` 已经删除，也没有做重定向。这些能力现在分布在会话、知识库的 tab 和检索面板里，知识库范围改成了多选。

## 3. 功能区

### 3.1 对话

主要文件在 `features/chat/`：

- `useAsk` 负责 SSE 事件流；
- `Composer` 是输入框和发送按钮；
- `MessageList` 和 `AnswerText` 负责消息渲染；
- `CitationDrawer` 是引用抽屉，逐条展示命中片段和原文出处；
- `PageOverlay` 在页图上叠加命中框。

SSE 有一个关键点：`/ask` 使用 POST，所以不能用 `EventSource`，要用 `fetch` 加 `ReadableStream` 手动解析 `\n\n` 分隔的帧。帧序是 `sources`、`delta`、`done`，`sources` 先到就先画引用卡片。

### 3.2 知识库

主要页面是 `KbListPage` 和 `KbDetailPage`。详情页有五个 tab：文档（上传、状态、进度）、检索、时间线、照片和设置。`strategy.ts` 负责切分策略在前端的投影，是纯逻辑，带单测。

切分策略卡片会明确提示每种策略的边界：六种策略分别适合什么，策略不会回溯，`contextual` 没有配置 LLM 时会降级，`late` 更慢，`semantic` 对 PDF 不生效。界面同时提供“重新解析全部 N 份”的入口。因为修改策略只对之后摄取的文档生效，没有这个入口，提示就没有实际作用。

### 3.3 设置

设置分为 7 个区，`sections.ts` 是唯一清单：

外观、账号资料、知识库默认、工作区与成员、外部大模型、用户管理、关于。

外部大模型分区对应 `GET/PUT /admin/llm` 和 `POST /admin/llm/test`，API Key 只显示掩码。用户管理分区仅超管可见。

### 3.4 登录

登录和注册页面不自动重登。每次登录都会新铸一把 Key，反复登录会把 `api_keys` 表塞满。只有在收到 401 时清除登录态。

## 4. `src/lib/`：纯逻辑核心

这些函数各自带单测，是前端最值得信赖的部分：

| 文件 | 职责 |
|---|---|
| `api.ts` | API 客户端，包括 `searchKbs` 等函数 |
| `sse.ts` | 解析 POST 请求返回的 SSE |
| `boxes.ts` | 把归一化坐标换算成矩形，并按 `locations` 的形状分派 |
| `progress.ts` | 进度判定，只读取 `jobs.progress` |
| `upload.ts` | 上传分批和结果汇总 |
| `trash.ts` / `containerTrash.ts` | 回收站的三种状态 |
| `timeline.ts` / `photos.ts` | 时间线和照片墙 |
| `kbScope.ts` / `kbStrategy.ts` | 知识库范围和策略的前端投影 |
| `theme.ts` | 主题三态和 DOM 操作薄层 |
| `settings.ts` | 设置项 |
| `thumb.ts` | 缩略图状态 |
| `pii.ts` | PII 报告展示 |

## 5. 样式系统与主题

样式有五条规矩，只在 `styles.css` 一处维护：

1. 颜色只出现在 `styles.css` 的 `:root` 和 `.dark` 两段里；
2. token 命名沿用 RAGFlow；
3. 优先使用原生控件；
4. `cn()` 要注册自定义字号；
5. `RichText` 负责渲染 `**粗体**`；危险操作使用原生 `confirm`。

这套实现还有三个特点：

- `styles.css` 使用 `@custom-variant dark (&:where(.dark, .dark *))`。从 RAGFlow 照搬的组件里有 `dark:` 变体，而 Tailwind v4 默认把它绑定到 `prefers-color-scheme`；如果不绑定到类，用户手动选择浅色时，那几处仍然是暗的。
- 圆角使用 v4 的默认刻度：控件用 `rounded-md` 或 `rounded-lg`，卡片用 `rounded-2xl`，气泡和输入条用 `rounded-3xl`。
- 主题存储键是 `localStorage["pkh.theme"]`，保存的是用户意图（`light`、`dark`、`system`），最终生效开关是 `<html class="dark">`。

主题判定有两份拷贝：`app/theme.ts` 和 `index.html` 首绘前的内联脚本。所以 `theme.test.ts` 用 6 条守卫扫描 `index.html`，确保两边一致。“只在设置的外观页修改”和“首绘不闪烁”是两条质量要求，不要动。

## 6. 必须避开的坑

| 坑 | 说明 | 权威出处 |
|---|---|---|
| 画框坐标 | `locations[].bbox` 是归一化到 0 到 1 的值，`toRect` 是唯一换算点。按 `locations` 的形状分派：有 `row` 和 `col` 画网格，`kind === "page"` 高亮整页，其余画单框。不要按 `kind` 判断 | `lib/boxes.ts`、`features/chat/PageOverlay.tsx` |
| 页图不能用 `<img src>` | 页图、缩略图和原图三个端点都需要 Bearer，一律先 `fetch` 再转成 objectURL | `features/chat/useBlobUrl.ts` |
| 进度 | 百分比只能来自 `jobs.progress`；没有 `jobs` 行就什么都不显示；`done` 和 `failed` 不画进度条 | `lib/progress.ts` |
| 上传 | 单个请求最多 20 份文件，超出的分批；上传阶段不显示百分比；汇总只算这一批，计算平均值时排除失败项 | `lib/upload.ts` |
| SSE | `/ask` 是 POST，不能用 `EventSource`；帧序是 `sources`、`delta`、`done` | `lib/sse.ts` |
| 历史消息的角标 | 后端只保存编号，不保存来源身份，所以历史里的 `[n]` 点不出原文。界面要如实说明，不要给死链 | `features/chat/types.ts` |
| 回收站与覆盖式更新 | 软删后 30 天内可恢复，有三种状态：restore、expired、blocked。“清空”是唯一不可撤销的端点，要先 `dry_run` 预览再确认 | `lib/trash.ts`、`lib/containerTrash.ts` |
| 时间线与照片墙 | `days` 是子集，“某天不在日历里”不等于“那天没有记录”；对 file 类型知识库不要发注定返回 400 的请求；照片墙不能丢掉没有日期的照片，放在最后一档；`page` 以 URL 为唯一真相 | `lib/timeline.ts`、`lib/photos.ts` |
| 结果正文 | 使用 `hit.text`，不要用 `snippets`。`snippets` 是字面子串匹配的产物，自然语言提问时通常为空，只适合用来打高亮 | `lib/api.ts` 的 `searchKbs` |

### 6.1 引用抽屉的绘制过程

1. 命中结果里带 `locations`，也就是归一化 bbox；
2. 页图端点需要 Bearer，所以先 `fetch` 拿 blob，再 `createObjectURL`；
3. `toRect` 把归一化坐标换算成百分比，铺在页图上。显示尺寸和坐标解耦，DPI 变了框也不会错位；
4. 表格块按 `row` 和 `col` 排成网格，或者直接用 `table_json` 渲染真表格；
5. 扫描页只高亮整页，因为没有文本层，画不出框。

## 7. 已知取舍

- 不引入 pdf.js。底图使用后端渲染的页图，与服务端 `render_page_with_boxes` 的框位同源。代价是页面不能选中文字。
- API Key 存在 localStorage 里。当前鉴权模型就是“每个客户端一把 Key”，而 Key 等同于密码，不要在共享机器上登录。
- 不自动重登。每次登录都会新铸一把 Key，只在收到 401 时清除登录态。
- 不新增依赖。不引入 zustand、i18n、Radix Select 或 Radix DropdownMenu。状态用 context，翻译函数自己写，下拉用原生 `<select>`，行操作菜单自己实现。
- 不维护 DOM 或 class 契约。唯一的自动化验收线是接口对齐，也就是 `src/types/api.ts` 与契约保持一致。

## 8. 开发与验收

```bash
cd web
npm install
npm run dev -- --host 127.0.0.1   # 端口 5173，/api 代理到 8010
npm test                          # vitest：核心纯逻辑和主题首绘守卫
npm run typecheck                 # tsc --noEmit
npm run build                     # tsc -b && vite build
```

开发期的手动工具不是 e2e 契约：

```bash
node scripts/screenshot.mjs /chat /kb '/kb/6133?tab=docs'   # 每条路由浅色和深色各截一张
node scripts/screenshot.mjs --mobile /chat                  # 移动视口
node scripts/screenshot.mjs /chat '--ask=这个库里有什么？'    # 真发一轮问答并打开引用抽屉
node scripts/smoke.mjs --login                              # 逐路由检查空白页、console error、4xx/5xx
```

使用系统 Chrome，因为 playwright-core 不自带浏览器。`demo-data.mjs` 会造一套合成演示数据，不要拿真实数据截图，那会随仓库一起公开。`smoke.mjs` 是开发期的安全网，用来抓白屏、未捕获异常和静默 401，不是 e2e，不要往里面加选择器断言。

`package.json` 里有 `"allowScripts": {"esbuild@0.28.2": true}`。npm 11 默认不执行依赖的安装脚本，如果不显式批准，esbuild 的二进制文件装不上，`vite` 直接起不来。
