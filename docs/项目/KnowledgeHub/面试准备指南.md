# 面试准备指南

> **阅读目标**: 用最短的话把这个项目讲清楚，并知道每个追问该回哪一篇。这一页只给指路和话术，数字与细节以正文为准。

数字统一以《架构与进程》§4-§5（模型、实测成本与并发预算）、《运维与验收》§6（测试分层）为源。正文改了参数，这里不需要跟着改。

## 1. 自我介绍

### 30 秒版

> 我做的是一个单机自部署的多租户知识库服务：把办公文档、聊天记录、照片收进同一个库，切成块建混合索引，检索结果每条都能点回原文的页和框。默认不把原文送出本机，生成层是抽取式。要接外部大模型得显式配置，失败就退回抽取式。

### 2 分钟版

> 这个项目的核心问题是**「找到」和「指回去」**，不是「生成得多漂亮」。
>
> 索引侧有四条腿：语义向量、BM25 关键词、Postgres 子串、页图视觉。四条腿的分数不可比，所以用 RRF 只按名次融合。融合后按 query 类型调权重，再做可选的精排。视觉腿单独一个进程，因为它常驻两个多 GB、编码一页要十几秒，放进 API 会把用户的问答排到编码后面。
>
> 引用侧靠坐标：每个 chunk 记着自己落在第几页的哪个框，坐标归一化后由前端乘回页图像素画出来。扫描件没有文本层，就整页走视觉索引，回的是页图。
>
> 数据侧 Postgres 是唯一真相，Qdrant 可重建。点是内容寻址的：由 `(库, 文档, 第几块)` 哈希出稳定 ID，三条腿天然对齐，重建不用换号。
>
> 工程侧三件事：任务用 Postgres 表而不是 Redis，巡检是三态而不是两态（跳过不算健康），备份只备事实、索引靠重建加点数对账。

## 2. 三条链路，各一句话

| 链路 | 一句话 | 详见 |
|---|---|---|
| 写入 | 上传 → 内容寻址存储 → 任务 → 解析 → 切分 → 嵌入 → 写三条腿 → `ready` | 《文档摄取》 |
| 读取 | 检索 → 四条腿并发 → RRF → 软删过滤 → 路由偏好 → 精排 → 证据组装 → 生成 → 引用校验 | 《检索与问答》 |
| 对外 | HTTP / MCP / A2A 三个入口，共用同一套检索与问答内核 | 《对外接口》 |

## 3. 高频追问

| 追问 | 一句话答 | 详见 |
|---|---|---|
| 为什么用 RRF 不做加权求和？ | 四条腿分数不同量纲，加权等于让数值天生大的那条腿说了算 | 《检索与问答》§3 |
| BM25 的 `k1` 和 `b` 各管什么？ | `k1` 控制词频饱和（调大接近线性，调到 0 退化成二值），`b` 控制长度归一化（`b=1` 时分数完全由块长决定） | 《小白概念指南》§2.4 |
| 为什么 RRF 的 `k` 取 60？ | 压头部差距，相邻名次只差 1.6%，奖励多腿共识而不是单腿的绝对分 | 《小白概念指南》§4.2 |
| 向量检索用的是什么索引？ | HNSW，`efSearch` 换召回率；召回率按精确 top-k 对拍 | 《小白概念指南》§3.2 |
| ColBERT 那种多向量的代价是什么？ | 每 token 一个向量，存储与打分都按 token 数放大，所以只对页级对象建索引 | 《小白概念指南》§6 |
| 精排能把召回漏掉的救回来吗？ | 不能，真值不在候选里就无从重排 | 《小白概念指南》§5 |
| 哈希出来的点 ID 撞了怎么办？ | 2^63 空间百万级概率 10^-8 量级；上十亿级换 UUID 或检测冲突后加盐 | 《小白概念指南》§7.3 |
| 混合检索怎么调权重？ | 不在融合层调，在路由层按 query 类型换权重；照片类的权重是实测出来的最小值 | 《检索与问答》§4 |
| 精排为什么按库启用、跨库不启用？ | 跨库排序取决于「哪些库碰巧配了模型」，结果不可解释 | 《检索与问答》§5 |
| 视觉腿为什么独立进程？ | 常驻内存大、单页编码十几秒，会挤占在线请求 | 《架构与进程》§1 |
| 多 worker 时视觉模型怎么放？ | 写侧走独立视觉服务，`VISUAL_WRITE_VIA_SERVICE=true`，否则每个 worker 各背一份 | 《架构与进程》§4 |
| 三条文本腿为什么要各自一个 DB 会话？ | 同一个 `AsyncSession` 并发 `execute` 直接抛错，四条腿会静默退化 | 《检索与问答》§2 |
| 点 ID 为什么不用自增？ | 重建后号会变，外部引用全错位；三条腿也得维护映射表 | 《架构与进程》§3 |
| 页级点怎么和块级点分开？ | 页的点用负数 `chunk_index`，第 0 页传 `-1` | 《架构与进程》§3 |
| 删除为什么分两步？ | 软删保住回收站与引用，30 天后才减词表、删点、删文件 | 《数据与一致性》§5 |
| 六步删除链漏一步会怎样？ | 都不报错：词表 df 只加不减，检索悄悄变差 | 《数据与一致性》§5 |
| 对账为什么不能取并集？ | 「只有一条腿坏了」会被报成一致，而那正是真实故障 | 《数据与一致性》§6 |
| 对账为什么不自动删？ | 摄取时点已写、行未提交，自动删会删掉正在写的点 | 《数据与一致性》§6 |
| 为什么任务不用 Redis？ | 任务与业务同库，`ON DELETE CASCADE` 能随文档清掉待办；规模是几个人的团队 | 《运维与验收》§1 |
| 巡检为什么有三态？ | 「跳过」不是「通过」，混淆会让没验过的项报成健康 | 《运维与验收》§3 |
| 权限怎么保证不越权？ | 三档可见性只在一个文件里判，检索只按 `kb_id` 过滤，其余范围来自 `readable_kb_ids` | 《多租户与权限》§2-§3 |
| 为什么错误码不区分「不存在」和「无权限」？ | 区分开就能被用来探测资源存在性 | 《多租户与权限》§4 |
| MCP 为什么无状态？ | 鉴权每请求自带，没有会话状态要维护 | 《对外接口》§3 |
| 扫描件没有 OCR 怎么办？ | 不 OCR，整页走视觉索引，引用回页图 | 《文档摄取》§6 |
| 抽取式和外部 LLM 怎么取舍？ | 默认抽取式，原文不出本机；接了外部模型失败会降级并写明原因 | 《检索与问答》§6-§7 |
| 一个 20 人团队能不能直接上线？ | 不能：没有细粒度 RBAC、视觉服务没有鉴权、存储只有本地盘，都是明写的不做 | 《导读》§6 |

## 4. 必须讲清楚的八个判断

这八条答不出「为什么是它、不是替代方案」，前面所有链路都只是背流程。它们的对照表在《架构与进程》§6。

1. 为什么是 Postgres 任务表，不是 Redis 或消息队列
2. 为什么三个进程，不是两个或一个
3. 为什么点 ID 是哈希，不是自增
4. 为什么用 RRF，不是加权求和
5. 为什么 dense 用 512 维的 small 模型，不是 base / large
6. 为什么精排按库启用，不是全局
7. 为什么软删 + 30 天，不是直接物理删除
8. 为什么装 pgvector 却不用

## 5. 追问到实现时的落点

被问「你怎么保证」时，答的应该是**守卫**，不是「我注意了」：

| 问题 | 答什么 |
|---|---|
| 怎么保证没越权？ | 真值表测试逐格比三档读写；AST 扫描检索层不出现可见性判定；Qdrant 过滤 key 白名单 |
| 怎么保证检索没退化？ | 每条腿返回 `n` / `ms` / `skipped`，`skipped` 与「零命中」分开；证据质量三档 |
| 怎么保证索引没漂？ | 三条腿分开对账，只报告不自动删；巡检 + worker 定期跑 |
| 怎么保证改动没弄坏接口？ | 契约检查对账「声明 / 实现 / 决议不做」三个数，只查路径与方法面 |
| 怎么保证能恢复？ | 备份后立刻自检；恢复到临时库再逐表对账、逐个校验 sha256 |
| 怎么保证重试不会无限重试？ | `attempts` 上限 3；明确声明不可重试的错误第一次就终态 |

## 6. 面试前自查

**必须能讲清楚**

- [ ] 四条腿各擅长什么，`hybrid` 默认跑哪几条
- [ ] 能写出 BM25 公式并说清 `k1` / `b` 的方向性影响
- [ ] 能说出 RRF 为什么只用名次、`k` 在调什么
- [ ] RRF 为什么可行（分数不可比 → 只比名次）
- [ ] 一个 chunk 从上传到可检索经过哪些步骤
- [ ] 引用框是怎么画出来的（L3 坐标 → 前端乘像素）
- [ ] 点 ID 为什么能重算，页级点怎么和块级点分开
- [ ] Postgres 与 Qdrant 谁是真相，Qdrant 丢了怎么办
- [ ] 删一份文档会动哪些东西，漏了会怎样
- [ ] 三档可见性里读写差的那一格

**必须能回答**

- [ ] 「你这个和普通 RAG 有什么不一样？」
- [ ] 「检索结果不准，你先看什么？」（`/search/debug` 的每腿 `skipped`）
- [ ] 「并发上来了先调什么？」（连接池、视觉并发、worker 数）
- [ ] 「为什么不用现成的向量库托管服务？」（默认不把原文送出本机）
- [ ] 「这个项目最大的取舍是什么？」（抽取式 vs 归纳质量）
- [ ] 「哪里还没做完？」（《导读》§6 已知限制，逐条说得出口）

## 7. 简历描述

> 单机自部署多租户知识库：四条召回通道（语义 / BM25 / 子串 / 页级视觉）经 RRF 融合与按意图路由的权重，检索结果带块级坐标，可点回 PDF 或扫描页的原始位置；Postgres 为唯一真相，Qdrant 按内容寻址的点 ID 可无损重建；1335 项 pytest 与 82 个端点的契约对账作为门禁。

可替换成三条短句，视版面取舍：

- **混合检索**：四条腿 + RRF + 路由偏好 + 按库精排，腿级 `skipped` 与「零命中」分开，降级可观测。
- **引用溯源**：chunk 记归一化 bbox，前端乘回页图像素画框；扫描件走视觉索引，回页图。
- **一致性**：内容寻址的点 ID 让重建不换号；三条腿分开对账、备份只备事实、恢复后按点数对账。
