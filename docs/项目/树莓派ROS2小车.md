按面试官会追问的顺序整理：为什么树莓派还要加一块 ESP32、ROS2 的节点发现走什么协议、UDP 与 TCP 各用在哪、PCA9685 为什么必要、PID 到底调没调。答不上来的地方也照实写了。

项目介绍：基于树莓派5 与ESP32 微控制器，设计开发适配医院场景的智能机器人小车，集成机器人运动控制、雷达避障、SLAM 实时建图、自主导航、机器视觉交互及物联网远程监控等核心功能。
项目职责：主导系统架构设计，完成树莓派5 与ESP32 的通信协议适配及硬件模块集成（含雷达、摄像头模块等），利用Flask 框架与ROS2 分布式通信机制搭建了远程监控系统。

项目介绍：
这是我在学校嵌入式课程中做的项目，我担任组长，项目目标是开发一个智能小车，我在其中的角色是进行系统设计，包括划分不同的模块，技术选型等，同时我主要负责小车监控系统后端的开发。

**请具体说明树莓派5与ESP32的分工逻辑。为什么选择这样的分工？**
考虑到电源问题，不能将所有模块都直接接入树莓派，因此引入ESP32。不能ESP32仅负责连接超声波驱动模块，ESP32 无法直接运行完整 ROS2，需用`micro-ROS`，micro-ROS 通过 UDP/TCP 与树莓派的 ROS2 节点通信，将 ESP32 模拟为 ROS2 节点，接入分布式网络。
发现机制（Discovery）：节点启动后会通过 UDP 组播（默认 239.255.0.0/16 网段）在局域网内广播自身信息（节点 ID、发布 / 订阅的 Topic、数据类型），同时监听其他节点的广播，自动完成 “节点发现” 和 “数据匹配”；
传输层适配：默认使用 UDP（低延迟，适配机器人运动控制、雷达数据传输），对关键数据（如导航指令）自动降级为 TCP（可靠传输），无需手动配置。

**电机驱动模块**
选择使用L298N控制电机，控制简单，方便学习基础的GPIO接口控制。

**请解释PID调参的方法。**
不怎么会。只知道为什么要调，因为- 机器人左右轮电机存在制造误差（转速、扭矩不一致），L298N 驱动模块的电压输出有波动，轮胎与医院地面的摩擦力会随地面材质（瓷砖 / 地毯）变化；
若直接用默认参数（如`Kp=1,Ki=0,Kd=0`）。

**摄像头的功能**
主要用于人脸识别和障碍识别，目前结合伺服电机目前实现了人脸追踪的功能。
树莓派难以维持多台伺服电机的稳定PWM输出，树莓派通过通过PCA9685 16路PWM驱动模块控制伺服电机。使用SG90舵机，适用于二自由度云台控制。在PCA9685控制板上分别连接两个舵机，通过PWM信号来调节其角度。

**Flask远程监控系统如何与ROS2集成？是通过ROS2的API（如rclpy）直接调用，还是通过中间件（如MQTT）？是否考虑了网络延迟与数据同步问题？**
在Flask框架中使用rclpy这个库，编写Node订阅小车发布的话题数据，通过websocket连接推送到前端。而小车上也只需要编写相应的ROS节点，接收相应的请求。
对于导航，通过Action来实现。
rclpy = ROS Client Library for Python，是 ROS 2 底层核心库（rcl，C 语言实现）的 Python 封装，作用是让 Python 代码能无缝接入 ROS 2 的分布式通信体系（DDS 协议），实现**节点创建、话题发布 / 订阅、服务 / 动作调用、参数管理**等所有 ROS 2 核心能力，同时兼顾 Python 易用性（对比 C++ 的 rclcpp）和 ROS 2 实时性 / 分布式特性。
 **Action（异步任务 + 反馈）**：如 Web 端下发 “导航到 3 楼病房”，Flask 调用 ROS2 的`/navigate_to_goal`动作，实时返回导航进度（如 “已到达走廊 / 剩余 5 米”），适配医院场景的长任务监控。
