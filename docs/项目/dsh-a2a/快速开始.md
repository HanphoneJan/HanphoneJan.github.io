# 快速开始

导读里说明了两个方向；这页把它们跑起来：安装、发布、第一条消息、第一条流、第一个出站工具，每一步都给可复制的命令和应看到的结果。读者是要在本机验证插件的人；不要求读过源码，但 `DSH`、`A2A`、`JSON-RPC`、`SSE`、`preset`、`AgentCard`、`artifact` 这几个词要先认识，没见过的看[导读的术语表](./导读.md#术语最小集)。前提是一个能重启的 DSH profile（DSH 的一套宿主配置，`--profile web` 是常用的那套），以及本机的 `curl`。

下文统一用 `http://127.0.0.1:3080`，这是 DSH web 的常用端口。没有配置 `baseUrl`（卡片对外地址）或宿主也没报端口时会回退到 `3000`。以实际监听为准。

## 安装并重启

```sh
dsh plugin --profile web add @hanphone/dsh-a2a
```

装完重启 `dsh web`。只刷新设置页不够：浏览器端的 bundle 在宿主启动时扫描，宿主没重启就不会加载新面板。

重启后打开设置，左侧应出现 **A2A 连接**。没有这一项时，先确认命令装进了当前使用的 profile，再看宿主启动日志里有没有 `a2a` 的加载错误。

## 发布一个入站 server

在 **设置 → A2A 连接 → 入站 Servers** 里新建一个实例，填名称、描述和版本。preset（DSH 的 agent 预设，决定会话的指令、工具和技能）留空就用部署默认，技能从该 preset 的技能目录派生，不需要手填。需要鉴权时在同一个表单里填 Bearer token（请求头 `Authorization: Bearer <token>`）。

也可以只用回环 API 建一个：

```sh
curl -sS -X POST http://127.0.0.1:3080/a2a/api \
  -H 'content-type: application/json' \
  -d '{
    "action": "inbound.create",
    "name": "reports",
    "description": "Reporting agent",
    "version": "0.1.0",
    "enabled": true
  }'
```

预期返回（`id` 是名称 slug 加 8 位十六进制，每次不同）：

```json
{
  "ok": true,
  "message": "inbound server \"reports\" created",
  "id": "reports-1a2b3c4d"
}
```

这个实例随后有两个地址：

| 用途 | 形态 |
|---|---|
| JSON-RPC 端点 | `http://127.0.0.1:3080/a2a/reports-1a2b3c4d` |
| AgentCard | `http://127.0.0.1:3080/a2a/reports-1a2b3c4d/agent-card.json` |

端点路径默认是 `/a2a/<id>`，卡片路径是端点加 `/agent-card.json`。先把卡片取回来，确认 `skills` 里有你打算调用的技能：

```sh
curl -sS http://127.0.0.1:3080/a2a/reports-1a2b3c4d/agent-card.json
```

没有配 token 时，请求可以不带 `Authorization`。配了 token 之后，请求必须带 `Authorization: Bearer <token>`。没带或值不对都会得到 `401`，响应头里有 `WWW-Authenticate: Bearer`。

## 发第一条 SendMessage

```sh
curl -sS http://127.0.0.1:3080/a2a/reports-1a2b3c4d \
  -H 'content-type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": "req-1",
    "method": "SendMessage",
    "params": {
      "message": {
        "messageId": "m-1",
        "role": "ROLE_USER",
        "parts": [{ "text": "统计这三个文件的行数" }],
        "metadata": { "skill": "chat" }
      },
      "configuration": { "historyLength": 2 }
    }
  }'
```

预期返回一个 `{task}` 信封。`task` 是 A2A 的任务对象；`artifacts` 是它的输出容器，`history` 是这次任务里被接受的可见输入加最终输出。

```json
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "result": {
    "task": {
      "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
      "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
      "status": { "state": "TASK_STATE_COMPLETED", "timestamp": "2026-11-18T02:10:11.482Z" },
      "artifacts": [
        { "artifactId": "result", "parts": [{ "text": "三个文件共 812 行。" }] }
      ],
      "history": [
        {
          "messageId": "m-1",
          "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
          "taskId": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
          "role": "ROLE_USER",
          "parts": [{ "text": "统计这三个文件的行数" }],
          "metadata": { "skill": "chat" }
        },
        {
          "messageId": "a2a-output-a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
          "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
          "taskId": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
          "role": "ROLE_AGENT",
          "parts": [{ "text": "三个文件共 812 行。" }]
        }
      ],
      "metadata": { "skill": "chat", "serverId": "reports-1a2b3c4d" }
    }
  }
}
```

回复文本在 `result.task.artifacts[]` 里找 `artifactId` 为 `result` 的那一条，读它的 `parts[].text`。`status.state` 是 `TASK_STATE_COMPLETED` 时任务已结算。如果这一轮只调用了工具、没有可见文本，任务仍会完成，但不会出现 `result` artifact，`status.message` 会说明没有可见输出。

`metadata.skill` 换成卡片里没有的技能会得到 `INVALID_PARAMS`（-32602），任务不会创建。`messageId` 是幂等键：用同一个 `messageId` 再发一次，返回原任务，不会多跑一轮。

## 订阅流式输出

```sh
curl -N http://127.0.0.1:3080/a2a/reports-1a2b3c4d \
  -H 'content-type: application/json' \
  -H 'accept: text/event-stream' \
  -d '{
    "jsonrpc": "2.0",
    "id": "req-2",
    "method": "SendStreamingMessage",
    "params": {
      "message": {
        "messageId": "m-2",
        "role": "ROLE_USER",
        "parts": [{ "text": "统计这三个文件的行数" }]
      },
      "configuration": { "historyLength": 0 }
    }
  }'
```

SSE（Server-Sent Events）是一串 `data:` 帧。示例里会依次出现五帧：当前任务、状态更新、artifact 追加、`lastChunk: true` 收尾、末帧任务快照。为便于阅读，示例只列关键字段。实际 `task` 还带 `contextId`、`history` 等，完整形状见 `SendMessage` 的响应。

```text
data: {"jsonrpc":"2.0","id":"req-2","result":{"task":{"id":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","status":{"state":"TASK_STATE_SUBMITTED","timestamp":"2026-11-18T02:10:09.001Z"},"artifacts":[]}}}

id: 12
data: {"jsonrpc":"2.0","id":"req-2","result":{"statusUpdate":{"taskId":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","status":{"state":"TASK_STATE_WORKING","timestamp":"2026-11-18T02:10:09.004Z"}}}}

id: 13
data: {"jsonrpc":"2.0","id":"req-2","result":{"artifactUpdate":{"taskId":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","artifact":{"artifactId":"result","parts":[{"text":"三个文件共 812 行。"}]},"append":true,"lastChunk":false}}}

id: 14
data: {"jsonrpc":"2.0","id":"req-2","result":{"artifactUpdate":{"taskId":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","artifact":{"artifactId":"result","parts":[]},"append":true,"lastChunk":true}}}

data: {"jsonrpc":"2.0","id":"req-2","result":{"task":{"id":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","status":{"state":"TASK_STATE_COMPLETED","timestamp":"2026-11-18T02:10:11.482Z"},"artifacts":[{"artifactId":"result","parts":[{"text":"三个文件共 812 行。"}]}],"metadata":{"skill":"chat","serverId":"reports-1a2b3c4d"}}}}
```

首帧和末帧是任务快照，没有 `id:` 行。中间的状态与 artifact 帧带 `id:`。`task` 的完整字段见上面 `SendMessage` 的响应。结算时还会有一帧带 `id:` 的终态 `task`，内容与末帧相同，以末帧为准。

断线不会取消任务。任务还没结算时，客户端可以拿首帧里的任务 id 重新订阅。已经终态时 `SubscribeToTask` 返回 `UNSUPPORTED_OPERATION`，改用 `GetTask` 读结果：

```sh
curl -N http://127.0.0.1:3080/a2a/reports-1a2b3c4d \
  -H 'content-type: application/json' \
  -H 'accept: text/event-stream' \
  -H 'last-event-id: 13' \
  -d '{
    "jsonrpc": "2.0",
    "id": "req-3",
    "method": "SubscribeToTask",
    "params": { "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10" }
  }'
```

`Last-Event-ID` 是 SSE 的事件编号，服务端用它补断点。它之后会补状态帧与结算时的任务帧，artifact 帧不补：首帧快照已经包含当时的 artifact，再补一次会让客户端把同一段文本追加两遍。事件日志只在当前进程里，每个任务最多 200 帧。

`configuration.returnImmediately` 只对非流式 `SendMessage` 生效。流式请求会一直流到任务结算或中断。

## 接到一个远端 agent

先读卡片，不建连接：

```sh
curl -sS -X POST http://127.0.0.1:3080/a2a/api \
  -H 'content-type: application/json' \
  -d '{
    "action": "outbound.discover",
    "agentCardUrl": "https://remote.example/a2a/x/agent-card.json"
  }'
```

预期返回远端名称、版本、端点与技能：

```json
{
  "ok": true,
  "message": "discovered \"remote\"",
  "preview": {
    "name": "remote",
    "version": "1.0.0",
    "description": "Remote agent",
    "endpoint": "https://remote.example/a2a/x",
    "skills": [{ "id": "chat", "name": "chat" }]
  }
}
```

核对技能后建连接：

```sh
curl -sS -X POST http://127.0.0.1:3080/a2a/api \
  -H 'content-type: application/json' \
  -d '{
    "action": "outbound.create",
    "name": "remote",
    "agentCardUrl": "https://remote.example/a2a/x/agent-card.json",
    "timeoutMs": 60000
  }'
```

预期返回：

```json
{
  "ok": true,
  "message": "agent \"remote\" connected",
  "id": "out-2c6d9dbdcf6a"
}
```

连接成功后，远端的每个技能都会变成一个模型工具。工具名的前缀是 `a2a`，后面接连接名和技能 id，三段用双下划线连起来。上面的连接名是 `remote`、技能 id 是 `chat`，拼出来就是 `a2a__remote__chat`。连接名里有空格或标点时，非 `[A-Za-z0-9_-]` 的字符会先换成 `_`，整个名字截到 64 字符。

## 验证与失败定位

在聊天窗口里跑：

```text
/a2a status
/a2a inbound list
/a2a outbound list
```

`status` 打印整个插件的快照。两个 `list` 分别打印入站与出站视图。出站视图里 `state` 应为 `connected`，`skillCount` 与 `toolCount` 都应大于 0。

| 现象 | 先查 |
|---|---|
| `401` | 实例配了 token，请求头没带或值不对。流式请求也一样，`401` 会先于 SSE 头返回。 |
| 卡片或端点 `404` | 实例是否启用。路径是否用了面板给出的 `/a2a/<id>`，而不是 `/.well-known/agent-card.json`。 |
| `TASK_STATE_COMPLETED` 但没有文本 | 这一轮没有可见 assistant 文本。看 `status.message`，再按[运维与排障](./运维与排障.md)的「任务完成但没有可见回复」逐项查。 |
| 出站连接 `failed` | 看 `lastError`：`HTTP 401` 是 token，`HTTP 404` 是卡片 URL，`invalid agent card` 是返回的不是卡片 JSON。 |
| 模型看不到工具 | 连接是否 `connected`、`toolCount` 是否大于 0。工具名是否被归一化过。 |
