# 架构与任务链路

这页接着[导读](./导读.md)的链路图，把每个部件落到代码里的对象。读者是维护者，需要判断改动会落到哪一层。`DSH`、`A2A`、`preset`、`facade`、`a2a` 域这些词见[导读的术语表](./导读.md#术语最小集)；后面第一次出现的实现名都会带一句解释。

## 一条插件行与两个 manager

`apply()`（Cordis 插件的入口函数）的骨架很短：打开 `a2a` 域，建两个 manager（`InboundServerManager` / `OutboundServerManager`，各自管自己的实例集合），注册 `ctx.a2a` facade（面板、命令和其他插件共用的控制入口），挂上面板 API 与 `/a2a` 命令。返回的 disposer（清理函数）负责拆实例、关域。

依赖声明里只有 `storageDomain`（DSH 的存储服务）是硬性的。其余用反射探测：`webServer`、`agents`、`agentPresets`、`skills`、`credentials`、`subagents`、`attachments`、`tools`、`commands`、`agentDefaultModel`。探测不到就把对应能力留空，插件照常加载。

`Config` 只装宿主级默认值。实例配置不在 YAML 里，而在域的 `inbound_servers` / `outbound_servers` 两张实例记录表。两个 manager 各自管自己的实例集合，互不共享生命周期。入站实例装配失败不会波及出站连接。

## 入站实例的组装

一条 `InboundServerRecord` 会展开成一个活实例，包含：

| 部件 | 作用 |
|---|---|
| `endpointPath` / `cardPath` | 端点默认 `/a2a/<id>`。卡片是端点去尾斜杠后加 `/agent-card.json` |
| `ScopedTaskStore` | 该实例看到的任务视图，按 `serverId` 过滤 |
| `A2AServer` | 方法分发、任务状态、SSE、限流、鉴权 |
| `A2aRoutes` | 卡片与端点的 HTTP 路由，可启停 |
| `ContextSessionPool` | 有 `agents` 时才建。它是 `contextId` → DSH 会话的句柄池；没有它执行器直接拒绝 |
| `ExecutorSet` | 技能到执行器的映射 |
| `LiveInboundRegistry` / `ContextSessionRegistry` | 对端与会话的活观察 |

有效 preset（DSH 的 agent 预设）取记录里的值。没有就用部署默认。技能不填表单，组装时向 `agentPresets.standingKeyFor` 要 preset 的 standing scope key（preset 在技能目录里的作用域键），再调 `ctx.skills.list({ scope })`。返回行里 `invocation.modelInvocable`（技能条目上的标记，`false` 表示模型不能直接调用）为 `false` 的丢掉，其余映射成 `AgentSkill`（A2A 卡片里的技能条目），`id` 与 `name` 都用技能名。服务缺失、挂载失败或目录为空，一律退回内置 `chat`。

门禁先看技能是否在派生集合里。不在就直接拒。通过后再进 `a2a/inbound-task` waterfall（一条事件瀑布，策略插件可以在其中否决任务），监听者可以写 `rejected.reason` 否决。每次裁决都落一行日志：哪个实例、什么技能、为什么被拒。

路由是运行时的：卡片 `exact`，端点 `prefix`。停用只撤路由。记录、技能、会话池都还在。实例 id 是名称 slug 加 8 位十六进制。

## 一次入站任务的管线

![一次入站任务从 HTTP 到会话与存储的分工](/img/dsh-a2a/inbound-task-pipeline.png)

1. `POST <endpointPath>` 进 `A2aRoutes`。先按 `maxBodyBytes` 读体。超限 `413`，读失败 `400`。
2. 看 `Accept`：含 `text/event-stream` 走 SSE，否则走普通 JSON-RPC。
3. `A2AServer.preflight`：先按来源地址做 60 秒滑动窗口，超限 `429` 加 `Retry-After`。再验 Bearer，失败 `401` 加 `WWW-Authenticate: Bearer`。
4. 检查 `A2A-Version`（只看主次号），再 `parseRpc` 解析 JSON-RPC 2.0。
5. `dispatch` 按方法名走。`SendMessage` 先看 `acceptedOutputModes`，再过技能门禁，最后 `ensureTask`。
6. `ensureTask` 要么新建，要么续接。记录来源实例、幂等键和首条输入。
7. `runTask` 检查并发配额，落 `WORKING`，按技能取执行器，跑完写状态与 artifact，广播终态帧并唤醒等待者。
8. 默认执行器是 `session`：一轮任务就是 `ContextSessionPool` 上的一次 turn。

任务访问始终带 `serverId` 过滤。不属于本实例的 id 与根本不存在的 id 得到同一个 `TASK_NOT_FOUND`，无法据此判断是否存在。并发配额和超时不走 RPC 错误：任务已经建了，直接落 `FAILED`，调用方从 `status.state` 与 `status.message` 看结果。

## 会话绑定与可见输出

![contextId 如何绑定到一个 DSH 会话](/img/dsh-a2a/session-binding.png)

会话 id 由实例 id 与 `contextId` 拼成：`a2a-<实例 id>-<contextId>`。把实例 id 放进去，两个实例才能各自使用相同的客户端 `contextId` 而不串会话。

`ContextSessionPool` 首次遇到某个 `contextId` 时调 `agents.create`，`meta` 带工作目录与 `agentPreset`，`setup` 里 `agentPresets.mount`。如果宿主报会话已存在（错误文本含 `already has`、`already owns` 或 `persisted`），改用 `agents.resume`。并发打开同一上下文时，单飞表只让一个请求进去建会话，其余等它的结果。

同一上下文的多轮按 Promise 串行，后一轮等前一轮收尾。返回的是本轮新产生的 assistant 文本，不是会话里最后一条全局消息。用户消息的来源写成 `{ kind: 'a2a' }`，这是插件自己的类型，不是已退役的共享 `plugin` 包装。

附件在进入 prompt 前处理：文本与 data part 直接拼。`raw` 图片或文件交给 `attachments.admitPromptContent` 落成持久引用。没有附件服务时退成可读占位。只有 `url` 的 file part 不抓取，按文本处理。

第一次打开某个上下文的会话时，`onSessionOpened`（会话首次打开时的回调）把绑定写进任务存储。`ScopedTaskStore` 会在键前加实例 id（`serverId`），落到表里是 `ctx:<serverId>:<contextId>`。写入出错只记日志，任务照常继续。

交付给 A2A 的只有 assistant 文本。`session` 执行器把 `text-delta` 写成 `result` artifact 的追加块，收尾发空 `lastChunk`，这样 `runTask` 不会再追加一份完整文本。没有可见文本时任务仍落 `COMPLETED`，只是没有 `result`，`status.message` 说明原因。reasoning 等非 text block 被过滤掉。

trace 走另一条 metadata 通道。开启后运行时监听 agent 作用域的 `session/event`：`tool/call` 记 call id、工具名、开始时间。`tool/result` 在结束时补状态和耗时。一轮收尾时仍没有结果的调用标记为 `unknown`。监听只写摘要，不读工具输出。

`SessionView`（会话视图）以 `(serverId, contextId)` 为键。任务数、活跃数、首末时间来自任务存储。`status` 为 `running` 时表示还有非终态任务，否则 `idle`。`streaming` 来自该实例的 SSE 订阅计数。`live` 表示会话池真的持有句柄。重启后行还在，`live` 变 false。没有 agent 循环的组合也能出这张表。

## 任务存储与作用域

![a2a 存储域的表、键与引用关系](/img/dsh-a2a/storage-model.png)

`openDomain` 在 `storageDomain` 上打开 `a2a` 域，版本 `1`。六张表都是字符串到字符串，值是 JSON：

| 表 | 键 | 存什么 |
|---|---|---|
| `tasks` | `task:<taskId>` | 任务记录 |
| `contexts` | `ctx:<serverId>:<contextId>` | 会话绑定 |
| `agents` | `out:<outboundId>` | 出站连接下的 agent 记录数组 |
| `identity` | `service` | 卡片身份字段。当前没有代码写它 |
| `inbound_servers` | `in:<id>` | 入站 server 的记录 |
| `outbound_servers` | `out:<id>` | 出站连接的记录 |

`DomainTaskStore`（在域上带内存视图的任务库）在域上叠了一层内存视图。域的写入走队列，但 `TaskStore`（任务库接口）的同步读要马上看到刚写的值。做法是先更新内存，再把写排进队列，读路径不碰表。启动时它把 `tasks` 与 `contexts` 读进内存。

`ScopedTaskStore` 是每个入站实例的任务入口。`get`、`list` 都按 `serverId` 过滤。写操作先 `require` 再转发。上下文键也会带实例前缀，两个实例即使用同一个客户端 `contextId` 也互不影响。

任务记录额外保存三样东西：`inputs`（按接受顺序的可见输入）、`statusText`（非错误状态文案）、`trace`（可选摘要）。旧记录没有 `inputs` 时，读历史用当前 `parts` 补一条，不改域版本。记录会随历史与 trace 增长。每条输入都保留，trace 最多 64 条观察。

删除实例写空字符串 tombstone（删除标记），不删键。两个域存储（`DomainInboundStore` / `DomainOutboundStore`）的 `list` 只接受非空且前缀匹配的值，坏 JSON 直接忽略。这样重启时删掉的实例不会复活。

## 出站半区

![模型工具、出站 registry、A2A 客户端与远端 agent 的调用顺序](/img/dsh-a2a/outbound-call-chain.png)

每条 `OutboundServerRecord`（出站连接记录）对应一个 `OutboundAgentRegistry`（出站连接下的 agent 记录与工具注销器）。registry 有自己的 agent 存储（键 `out:<id>`）和一组工具 disposer。

出站记录字段更少：卡片 URL、名称、preset、超时、token 托管名、被禁用的技能、技能覆盖、开关、上次成功读卡的时间。`preset` 现在只存不用。工具直接请求远端，没有从它组装本地会话。

几个容易踩的生命周期点：

- `add` 的顺序是先落记录、后连接。连上后注册工具并更新时间。连不上则保留记录，给出 `failed` 视图与 `lastError`，可编辑或刷新。
- `boot` 给每条记录建 registry。启用的实例异步 `loadAll` 并排刷新定时器。启动阶段连不上只记日志，视图显示 `disconnected`。
- `setEnabled` 停用时注销工具、dispose 活连接，视图落 `disconnected`；启用时如果没有活连接就重新连接。启动时已禁用的实例没有活连接，这一步只写记录。
- `refresh` 重读卡片并重建工具。`update` 写 patch、重建 registry、已启用就重连。`setAuth` 写凭据、换托管名、重建并重连。
- 删除向 `outbound_servers` 写 tombstone（删除标记）。重启只恢复记录，不恢复连接。

启用的远端技能各对应一个模型工具。拼法是前缀 `a2a`、连接名、技能 id，中间放双下划线。整体只留 `[A-Za-z0-9_-]`，基础名截 64 字符，重名时压到 56 再加短哈希。参数只有必填 `prompt` 与可选 `taskId`。

工具总是请求流式。`A2AClient`（出站 HTTP 客户端）只在远端 `capabilities.streaming === true` 时走 SSE，否则阻塞发送后轮询。调用方 abort 会传到客户端。已知任务 id 时补发 `CancelTask`。网络错误与 5xx 最多重试两次。流式重试带 `Last-Event-ID`（SSE 的事件编号）。

远端任务失败时工具抛错。`INPUT_REQUIRED` / `AUTH_REQUIRED` 返回带 `taskId` 的文本，模型可以拿 id 再调。渲染时优先 `result` artifact。没有就取其它可见 artifact 的文本 part。非 result artifact 的 `data` part 与 trace/诊断 artifact 不进模型结果。

## 浏览器半区与 facade

`src/client/` 通过 `ctx.slots.inject` 注册 `settings.section`（DSH 设置页的区块插槽），id `a2a`，标题「A2A 连接」，排序 90。它只读写 `/a2a/api`，不懂协议，也不直接访问 A2A 端点。

面板挂载后拉一次快照，之后每 3 秒一次。任务列表默认 50 条，加载更多每次加 50，后端上限 200。版本检查在挂载时发起一次，宿主缓存 6 小时。只有点按钮才带 `refresh=1` 重新请求。

样式在 `dashboard.css.ts`，用宿主的 `--dsw-alias-*` token 与 `@container`。面板、`/a2a` 命令、其它插件读的 `ctx.a2a` 都指向同一个 `A2AServiceImpl`，状态不会分叉。

### 代码地图

| 路径 | 职责 |
|---|---|
| `src/index.ts` | 装配入口。读 `Config`。探测可选服务。挂两个 manager、facade 与面板 API |
| `src/service.ts` | 把控制方法暴露成 `ctx.a2a` |
| `src/api.ts` | 只服务回环。快照、读取、动作分发 |
| `src/commands.ts` | 把聊天命令翻成 facade 调用 |
| `src/protocol.ts` | 协议常量与类型。parts 到文本的投影 |
| `src/jsonrpc.ts` | 解析与构造 RPC 帧。SSE 拼帧 |
| `src/events.ts` | 声明入站策略瀑布与 `ctx.a2a` 形状 |
| `src/servers/inbound-manager.ts` | 按记录搭入站实例。技能、token、路由、增删改 |
| `src/servers/outbound-manager.ts` | 按记录搭出站连接。刷新卡片。注册或注销工具 |
| `src/server/a2a-server.ts` | 按方法名分发。任务状态与 artifact。SSE 订阅。限额与 token |
| `src/server/routes.ts` | HTTP 入口。限制请求体。注册或撤销路由 |
| `src/server/card.ts` | 从记录与 base URL 生成卡片 |
| `src/server/store.ts` | 域与记录类型。内存、域、作用域三种任务库 |
| `src/server/trace.ts` | trace 的 URI、字段、脱敏、条数上限 |
| `src/server/exec/agent-runtime.ts` | 按 context 取会话。同上下文串行。附件转 prompt。采工具事件 |
| `src/server/exec/session.ts` | 一轮会话作为一次任务 |
| `src/server/exec/subagent.ts` | 把任务交给一次性子 agent |
| `src/server/executor.ts` | 执行器接口。技能到实现的映射 |
| `src/server/session-registry.ts` | 任务记录加活观察，折成会话行。SSE 计数 |
| `src/server/inbound-registry.ts` | 按来源记对端、活跃任务、流状态 |
| `src/server/metrics.ts` | 计数与固定长度的审计环 |
| `src/outbound/calls.ts` | 发现卡片。发送与订阅。轮询。取消。有限重试 |
| `src/outbound/registry.ts` | 远端 agent 记录与连接状态。保存工具 disposer |
| `src/outbound/tools.ts` | 把远端技能包成模型工具 |
| `src/client/` | 设置页 UI、样式、更新文案 |
