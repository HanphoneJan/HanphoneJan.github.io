# 开发与兼容

这页接着[架构与任务链路](./架构与任务链路.md)，讲改动该落在哪层测试、换 harness 要核对哪些接缝、打包发布前查什么。读者是维护这个插件的人。`harness`、`profile`、`a2a` 域这些词见[导读的术语表](./导读.md#术语最小集)；后面第一次出现的测试层名都会带一句解释。前提是同级目录下有 `../deepseek-harness`，本机 Node 24、pnpm 11。

插件按路径引用 harness，不按 npm 包引用。单元测试全绿也可能在真实宿主上失败，所以测试分成几层，兼容性靠一套固定动作维护。

## 测试分层

| 层 | 位置 | 能发现什么 | 需要先构建 harness |
|---|---|---|---|
| 编译期镜像检查（插件自己声明的宿主结构类型 vs 真实 DSH 声明） | `tests/types/mirrors.typecheck.ts` | 本地结构镜像与宿主声明的偏差 | 是，`lib/types` |
| 单元 / 组合 | `tests/unit`、`tests/composition` | 编解码、路由、任务库、注册表、假宿主上的装配 | 否 |
| 真实持久化（用真实 JSONL 会话后端跑的集成测试） | `tests/integration/persistence.spec.ts` | 会话 codec、`a2a` 来源、agent 循环、工具事件 | 是，JSONL addon（DSH 的 JSONL 会话持久化组件） |
| 双实例 e2e（两个临时 home + mock 模型，不碰真实用户环境） | `scripts/e2e-a2a.mjs` | 构建产物在两个真实宿主间的卡片、消息、工具与往返 | 是，宿主与插件 |

编译期镜像这层不能省。`agent-runtime.ts` 不 import 宿主类型，而是自己声明结构。普通构建看不出漂移。`mirrors.typecheck.ts` 把消息来源、会话切片、`tool/call` 与 `tool/result` 的字段逐个对到真实声明上，对不上就编译失败。

可见性另有四个单测守着：`agent-runtime.spec.ts` 管 reasoning 过滤与 trace 生命周期，`a2a-server.spec.ts` 管 history、空输出与扩展激活，`outbound-tools.spec.ts` 管出站结果选取，`subagent.spec.ts` 管子 agent 的文本过滤。

2026-11-18 实测：`pnpm test` 收集到 199 项、22 个文件。单独跑 `tests/integration` 是 6 项。

| 命令 | 实际动作 |
|---|---|
| `pnpm typecheck` | 宿主 `tsc -b`、客户端声明、镜像检查 |
| `pnpm test` | `vitest run`，含单元、组合、集成 |
| `pnpm test:integration` | 只跑 `tests/integration` |
| `pnpm build` | `tsc -b`、客户端 `tsc`、`tsdown`、`scripts/build-client.mjs` |
| `pnpm test:e2e` | `node scripts/e2e-a2a.mjs`，要求先 `build` |
| `pnpm test:all` | 依次跑 typecheck、test、build、e2e |
| `pnpm prepare` / `pnpm prepack` | 调 `scripts/ensure-lib.mjs`，`lib/` 缺失或比 `src/` 旧时重建 |

## e2e 与可视化实例

`scripts/e2e-a2a.mjs` 每次从零搭环境，结果可重复；它是 hermetic 的，不依赖外部网络或真实模型：

1. 建两个临时 home（`a`、`b`），各装一个 `web` profile。`a` 再加 `headless`。bundle 列表直接指向已构建插件，不经过 registry，也不碰真实用户目录。
2. 两个 home 各起一个脚本化 mock LLM（`@deepseek-ai/dsh-llm-mock-server`，一个按脚本回话的假模型服务）。`dsh web` 通过 `DEEPSEEK_BASE_URL` 与 `DEEPSEEK_API_KEY` 连过去。
3. 在 B 上建一个允许 trace 的入站实例。读卡片，确认扩展已宣告。带 `A2A-Extensions` 发 `SendMessage`，断言 `result` artifact 等于 mock 输出、扩展头被回显、artifact 列表里没有 `tool-call-*`。
4. 在 A 上建到 B 的出站连接。连接状态应为 `connected`，工具数至少 1。
5. 停掉 A 的 web，用 A 的 `headless` 跑一段脚本，让它调用 `a2a__b__chat`。stdout 应出现 B 的回复，远端任务里不应有工具 artifact。
6. 删掉两个 home 和全部子进程。

跑之前要满足：

- 插件已构建。没有 `lib/index.js` 时脚本直接退出。
- 同级有 `../deepseek-harness`，且宿主产物已构建。路径不同时设 `DSH_A2A_HARNESS_DIR`。
- 不需要真实模型。mock server 由脚本自己起。

加 `DSH_A2A_KEEP=1` 可以保留临时 home、日志和子进程，便于查失败。

`pnpm visual:a2a` 用同一套双实例，多开一个交互面板并打印回环地址。面板里有实例、任务时间线、对端、会话，以及两个按钮：**Inbound** 直接向 B 发 `SendMessage`。**Outbound** 让 A 的 headless 模型调 `a2a__b__chat`。它是给人看的演示，不是 CI 门禁。`Ctrl+C` 会清理子进程和临时目录。

## 加测试与 CI

按改动类型决定加在哪：

- **行为变化**：加单元或组合测试，撤掉改动应当失败。
- **新的宿主契约**：如果它适合做结构镜像，就补镜像检查。只能从真实运行里观察的，就加持久化或 e2e 断言。
- **新的 e2e 步骤**：写进 `scripts/e2e-a2a.mjs`，保持离线，默认只允许 mock LLM。
- **可见性或 trace**：断言空输出、reasoning 过滤、扩展头激活、`Task.metadata` 边界，不能只看最终文本。

CI 在 `.github/workflows/ci.yml`，分三个作业：

| 作业 | 何时跑 | 内容 |
|---|---|---|
| `check` | push、pull request | typecheck、单元、组合、真实持久化 |
| `e2e-pinned` | push、pull request | 对 `dsh-v0.2.2-rc.3` 跑 e2e |
| `e2e-matrix` | 每天 03:00 UTC、手动 dispatch | 对矩阵里的每个 tag 跑 e2e |

矩阵包含 7 个 tag：`dsh-v0.2.2-rc.3`、`dsh-v0.2.2-rc.1`、`dsh-v0.2.2-alpha.2`、`dsh-v0.2.1-rc.3`、`dsh-v0.2.1-rc.2`、`dsh-v0.2.1-alpha.2`、`dsh-v0.1.7-rc.2`。

CI 固定 Node 24 与 pnpm 11.28.5。放宽 peer 范围时，同一个提交里也要把矩阵补上，并把结果写进兼容记录。

## 五个耦合面

| 接缝 | 位置 | 断了会怎样 |
|---|---|---|
| 依赖范围 | `package.json` 的 `peerDependencies` | 运行版本落在范围外，预检（DSH 导入插件前检查 peer 版本范围）直接拒绝加载 |
| 构建布局 | 三个 `tsconfig*.json` 的 `references` | 被引用的包改名、拆分或不再 composite，`tsc -b` 还没读源码就失败 |
| 挂载与清单 | `cordis.patch.yml`、`dsh.bundle.patch`、`dsh.client.inject`、`scripts/build-client.mjs` | `- insert:` 写法、客户端注入列表或 `window.__ModuleLoader__.load({ id, factory })` 契约变了 |
| 运行时 API | `ctx.a2a`、`ctx.slots.inject('settings.section', …)`（设置页区块）、存储 `KvTable`（DSH 的键值表）、commands、preset/skill/subagent 数据 | 消费的方法签名或数据结构挪了位置 |
| 会话事件流 | `agent-runtime.ts` 对 `session/event` 的 `tool/call` / `tool/result` 监听 | trace 丢失 call id、错误标志或事件顺序。假宿主看不出来 |

按检查成本排序：前两项失败得早且明显。后两项要靠消费方 typecheck、真实持久化与 e2e。会话事件流最容易骗过 stub：假宿主上的顺序正确，不等于真实 harness 也按这个顺序发。

## 换 harness 版本

**先定位版本。** harness 没有 changelog。根 `package.json` 的 `version` 是版本号，发布 tag 形如 `dsh-v<semver>`。

```sh
cd ../deepseek-harness
grep -m1 '"version"' package.json
git status -sb && git log --oneline -3
git fetch origin --tags --prune
git ls-remote --tags origin | grep -v '\^{}' | awk -F/ '{print $NF}' | sort -V | tail -10
```

`git ls-remote` 查上游，不受本地已有 tag 影响。只看本地列表可能漏掉几条发布线。

**再重建产物。** harness 的 `lib/` 不进 git，切版本后旧文件还在，插件会对着上一版做类型检查。切版本还可能留下缺 manifest 的包目录，被 workspace 的 glob 扫进来。

```sh
pnpm install --frozen-lockfile
pnpm run clean
pnpm run build
```

**比对五面。**

```sh
cd ../deepseek-harness
git diff <from> <to> -- vendor/cordis vendor/schemastery | head -40
git diff <from> <to> -- packages/client/ui-settings packages/storage packages/interaction | head -40
git diff <from> <to> -- tsconfig.base.json tsconfig.base.client.json tsconfig.client.json tsconfig.host.json
```

**在新 checkout 上验证。**

```sh
cd ../dsh-a2a
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

`pnpm test` 不能单独当兼容证据：它跑在 stub 宿主上，看不到持久化 codec，也看不到清单与挂载漂移。镜像检查与 e2e 才能看见。

删掉 `lib/` 后重建却没有任何输出，通常是 TypeScript 增量缓存还在。清 `node_modules/.cache/dsh-a2a/`。`tsc -b` 信了旧 tsbuildinfo，tsdown 就找不到入口。

能改元数据就不要改源码。优先动项目引用、peer 范围、版本号。必须动源码时，同一个提交里补行为测试。

## peer 预检与发布

DSH 从 0.1.7 起，导入前会读插件的 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*` peer 声明，这一步叫 peer 预检。预发布号同样参与范围判断，`workspace:^`、`~`、`*` 都按运行版本解释。检查失败会给出 `incompatible-version` 与不满足的范围，registry 安装在 pnpm 执行前就被拦下。

预检只看 `@deepseek-ai/dsh-commands` 与 `@deepseek-ai/dsh-storage-domain`。`cordis` 与 `schemastery` 被跳过。前两个范围必须覆盖所有测过的 harness。后两个不参与评估，但声明时仍要把宿主自带的副本算进去，预发布版本也一样。

当前范围：

| 包 | 范围 |
|---|---|
| `@deepseek-ai/cordis` | `>=4.0.2 <4.2 || 4.0.5-alpha.1 || 4.0.6-alpha.1` |
| `@deepseek-ai/dsh-commands` | `>=0.1.3 <0.3` |
| `@deepseek-ai/dsh-storage-domain` | `>=0.1.3 <0.3` |
| `@deepseek-ai/schemastery` | `3.* || 3.18.5-alpha.1 || 3.18.6-alpha.1` |

确实遇到一次不匹配时，给精确豁免，别把范围写宽：

```sh
dsh plugin allow-version <pkg@version> --dsh-version <runtime> --accept-risk
dsh plugin version-exemptions
dsh plugin revoke-version <pkg@version> --dsh-version <runtime>
```

发布顺序：

1. 在同一个 commit 里改 `package.json` 的 `version`。
2. 提交消息写明验证过的 harness 版本。
3. 打包：`pnpm pack --pack-destination <dir>`。
4. 推到 npmjs。包名 `@hanphone/dsh-a2a`，`publishConfig.access: public`。

发布时遇到 `403`，先查 npm 凭据，不要怀疑包本身。没有明确要求不发布。

`lib/` 被 gitignore，构建后才存在。`prepare` 与 `prepack` 都会跑 `scripts/ensure-lib.mjs`：`lib/` 缺失或比 `src/` 旧时重新构建。没有这个钩子，从全新 clone 发布或从 git URL 安装时，`main` 会指向一个不存在的文件。脚本构建前清 TypeScript 增量缓存，避免 `tsc -b` 空转而 `lib/` 已经不在。

打包后检查两个入口：

```sh
tar tzf dsh-a2a-<version>.tgz | grep -E '^package/lib/(index|client)\.js$'
```

## 已知陷阱

- **`tsc -b` 显示成功，`lib/` 却空。** 旧 tsbuildinfo 在作怪。删 `node_modules/.cache/dsh-a2a/`。
- **客户端类型检查读到旧声明。** harness 的 `lib/types` 不进 git，reset 后仍留着。切版本后重建被引用的包。
- **harness 里残留缺 manifest 的包目录。** 重建前跑 `pnpm run clean`。否则 tsdown 的 `packages/*/*` glob 会打包残留 `lib/types`，报 `MISSING_EXPORT`。
- **两份 zod。** 宿主用自己的 zod 给存储 API 标类型。另一份副本的 schema 即使同为 4.x 也不能赋值。把边界按宿主签名声明（`src/server/store.ts` 的 `a2aDomainSpec`），不要跟着宿主 patch 号钉 `dependencies.zod`。
- **每个脚本前都报 `ERR_PNPM_NO_MATCHING_VERSION`。** harness peer 在 registry 里没有对应版本。pnpm 11 起从 `pnpm-workspace.yaml` 读 `autoInstallPeers: false` 与 `verifyDepsBeforeRun: false`。只写 `.npmrc` 不生效。
- **solution reference 报 TS6306。** 暴露 solution `tsconfig.json` 的 harness 包要经它的 `tsconfig.client.json` 或 `tsconfig.host.json` 叶子引用。
- **测试 import harness 源码报 Vite `SyntaxError`。** harness 用标准 TypeScript 装饰器。`vitest.config.ts` 加载了 harness 的 `standardDecoratorPlugin`。
- **spec 找不到 harness 的路径映射。** Vite 8 的 `resolve.tsconfigPaths` 只给 tsconfig include 范围内的文件套 `paths`。`tests/tsconfig.json` 需要继承构建配置，并把 spec 纳入 include。
- **冷启动时工具还没注册。** 出站工具要等重连时抓完卡片才出现，profile 挂载不等这次抓取。一次性 headless 运行可能在工具出现前就发出第一次请求。harness 会用 `tool-addition` developer 消息补宣告，模型可以重试，但第一次会报 `unknown tool`。e2e 在挂载完成后才写 stdin，就是为避开这个窗口。
