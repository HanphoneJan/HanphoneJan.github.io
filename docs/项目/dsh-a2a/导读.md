# 导读

你有一个 DeepSeek Harness（下称 DSH）里的 agent，想让别的 agent 通过 Agent2Agent（A2A）协议调用它；或者有一个远端 A2A agent，想让本机模型用上它的能力。这个插件把两个方向都做成实例，创建、启停、改鉴权都在设置页里，不写配置文件。这页写给第一次接触它的人：先看两个方向，再认术语，然后看一条任务怎么走，最后按你的目标选下一篇。

## 两个方向

入站是别人调你：远端 A2A 客户端按协议请求这个 DSH。每个被发布的 agent 是一个入站实例，有自己的端点、AgentCard（A2A 的自我介绍：名称、端点、技能）、preset（DSH 的 agent 预设，决定会话的指令、工具和技能）、可选的 Bearer token（请求头 `Authorization: Bearer <token>`）和启用开关。

出站是你调别人：本机模型通过工具去请求远端 A2A agent。每个远端连接有自己的卡片 URL、token、超时、可选的 preset 记录，以及逐技能的启用状态。

| 方向 | 调用方 | 被调用方 | 实例里放什么 |
|---|---|---|---|
| 入站 | 远端 A2A 客户端 | 本机 DSH | 端点、卡片、preset、token、启停 |
| 出站 | 本机模型（经工具） | 远端 A2A agent | 卡片 URL、token、超时、技能选择 |

两个方向的实例互不共享，启停也各自独立。一个入站实例没有组装成功，已经连上的出站连接不受影响。

## 术语最小集

下面这些词在其余六篇里会反复出现。第一次读时先扫一遍；后面的页面不再重复解释，只链接回这里。

| 术语 | 一句话 |
|---|---|
| DSH | DeepSeek Harness，这个插件运行的宿主。 |
| A2A | Agent2Agent，用 HTTP + JSON-RPC 让 agent 互相调用的协议。 |
| JSON-RPC | 用 JSON 表示请求和响应的 RPC；请求有 `method` 和 `params`，响应有 `result` 或 `error`。 |
| SSE | Server-Sent Events，服务器推的一串 `data:` 帧；本插件的流式响应走它。 |
| 入站 / 出站 | 入站是远端客户端调这个 DSH；出站是这个 DSH 调远端 agent。 |
| 实例 | 一个入站 server 或一个出站连接，带自己的 id、端点或卡片 URL、启用状态。 |
| 端点 / AgentCard | 端点是 `POST /a2a/<id>`；AgentCard 是 `GET /a2a/<id>/agent-card.json` 返回的自我介绍。 |
| preset | DSH 的 agent 预设，决定会话的指令、工具和技能；入站实例绑一个。 |
| 技能 | AgentCard 宣告的条目；入站技能来自 preset，出站技能来自远端卡片并变成模型工具。 |
| `contextId` | 对话键，同一实例内复用它就复用同一个 DSH 会话。 |
| `A2A-Version` | 请求头或查询参数里的协议版本；只比较主次号。 |
| 任务 / Task | 一次调用产生的记录，有 id、状态、输出和可见历史。 |
| artifact | 任务输出容器；本插件的可见回复写在 `artifactId` 为 `result` 的那一条。 |
| `history` | 任务里被接受的可见输入消息加最终输出，不是 DSH 的完整逐轮记录。 |
| 执行器 | 把任务跑完的部件；默认 `session`，在 `contextId` 对应的 DSH 会话上跑一轮。`subagent` 是另一种，把任务交给一次性子 agent，当前选不中。 |
| trace | 可选的工具调用观察通道，只发 metadata：工具名、阶段、状态、耗时、脱敏参数摘要。 |
| facade | `ctx.a2a`，插件对面板、`/a2a` 命令和其他插件暴露的统一入口。 |
| `a2a` 域 | 插件的持久化命名空间，六张表；任务、上下文绑定、实例记录都在这里。 |
| peer / 对端 | 入站侧的一个调用来源，按来源地址记录；它不是一个实例。 |
| profile | DSH 的一套宿主配置，`--profile web` 是常用的那套。 |
| harness | 这里指 DSH 的代码库/运行环境。 |

## 一次任务经过哪些部件

入站请求先到 DSH 的 web server。路由按路径分成卡片和 JSON-RPC 端点。请求先过来源限流与 Bearer 校验，再看 `A2A-Version`、解析 JSON-RPC、检查技能门禁，然后才建任务。任务落到 `a2a` 存储域，执行器在 `contextId` 对应的 DSH 会话上跑一轮，可见文本写成 `result` artifact，状态与 artifact 通过 SSE 推给订阅者。

出站方向反过来：模型调用注册好的工具，工具经远端连接发 `SendMessage` 或 `SendStreamingMessage`（A2A 的发送方法，见 [A2A 接口](./协议与接口.md)），把远端任务的 `result` 文本取回来。

## 版本与边界

插件版本 `0.5.5`，验证过的 harness 是 `0.2.2-rc.3`。协议面实现 A2A `1.0.1` 的 JSON-RPC 绑定，卡片宣告的协议版本是 `1.0`。

当前边界：

- 只有 JSON-RPC over HTTP。没有 gRPC，也没有 HTTP+JSON。
- 没有 push notification。四个配置方法返回 `PUSH_NOTIFICATION_NOT_SUPPORTED`。
- 没有 OAuth、mTLS 或按客户端凭据。鉴权是每个入站实例一份共享 Bearer。
- 插件本身不终止 TLS。把端点暴露到网络时，TLS 要在反向代理上做。
- trace 默认关闭，要部署开关、实例策略和请求头同时满足才生效。它只发 metadata。
- 进程在任务运行中退出时，这条任务不会自动续跑。重启后它仍停在 `WORKING`。
- 出站实例的 `preset` 只是持久化字段。工具直接请求远端，不会用它拼一个本地会话。
- `subagent` 执行器已经接好，但技能表里只有 `chat` 到 `session` 的映射，当前没有入口能选它。
