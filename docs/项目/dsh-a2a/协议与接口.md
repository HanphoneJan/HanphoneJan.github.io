# A2A 接口

这页接着[快速开始](./快速开始.md)里发出的第一条消息，把消息格式、方法和错误补全。读者是要对接这个端点的客户端作者，或要改协议层的维护者。前提是已经有一个启用的入站实例，拿得到它的端点与 AgentCard。`DSH`、`A2A`、`preset`、`artifact`、`contextId` 这些词在[导读的术语表](./导读.md#术语最小集)里已经定义，这里不再重复。

下面三个词先展开一次：**JSON-RPC** 是用 JSON 表示请求和响应的 RPC，请求有 `method` 和 `params`，响应有 `result` 或 `error`；**SSE** 是 Server-Sent Events，服务器推的一串 `data:` 帧；**AgentCard** 是 A2A 的自我介绍，包含名称、端点、技能和鉴权方案。

下文统一用 `http://127.0.0.1:3080`，这是 DSH web 的常用端口。没有配置 `baseUrl`（卡片对外地址）或宿主也没报端口时会回退到 `3000`。以实际监听为准。任务 id、`contextId` 和 SSE 事件序号都是示例值。

## 端点、卡片与鉴权

每个启用的入站实例对外提供两个地址：

| 路径 | 方法 | 内容 |
|---|---|---|
| `/a2a/<id>` | `POST` | JSON-RPC 端点 |
| `/a2a/<id>/agent-card.json` | `GET` | AgentCard |

端点路径来自实例的 `endpointPath`（实例记录里的路径字段），默认 `/a2a/<id>`。卡片地址从端点派生：去掉末尾斜杠，再拼 `/agent-card.json`。实例停用后，这两个地址都不再响应。

取卡片不需要 JSON-RPC：

```sh
curl -sS http://127.0.0.1:3080/a2a/reports-1a2b3c4d/agent-card.json
```

没有配 token 时，端点不要求 `Authorization`。配了之后，请求必须带：

```text
Authorization: Bearer <token>
```

没带或值不对时，HTTP 状态是 `401`，响应头有 `WWW-Authenticate: Bearer`，body 是码为 `-32040` 的 JSON-RPC 错误信封。流式请求的鉴权在写 `200` 之前完成，客户端拿到的是完整 `401` 响应，而不是中断的 SSE。

`A2A-Version` 可以放在请求头或查询参数里。比较时只看主次号，补丁号不参与。版本对不上时返回 `VERSION_NOT_SUPPORTED`（-32007），HTTP 仍是 `200`。JSON-RPC 的 POST 响应（无论结果是成功还是 JSON-RPC 错误）带 `A2A-Version: 1.0`。`401`、`429`、`413` 不带。卡片走单独的 exact 路由，也不承诺带这个头。

请求体上限由配置项 `maxBodyBytes` 控制，默认 1 MB（见[运维与排障的配置表](./运维与排障.md#配置与宿主服务)）。超限返回 `413`，读取失败返回 `400`，都是纯文本。插件不做 TLS。需要 HTTPS 时在反向代理终止。

## 消息与任务标识

端点和鉴权确定后，下面看一条请求里能放什么。`message` 的字段：

| 字段 | 作用 |
|---|---|
| `messageId` | 幂等键。同一个 id 再发一次返回原任务，不再跑一轮。 |
| `contextId` | 对话键。复用它就复用同一个 DSH 会话。省略时生成新的。 |
| `taskId` | 续接一个非终态、当前空闲的任务。不用于新建。 |
| `role` | `ROLE_USER` 或 `ROLE_AGENT`。入站请求用前者。 |
| `parts` | 内容块，见下表。 |
| `metadata.skill` | 选一个卡片里宣告的技能。缺省 `chat`。 |

`parts` 支持三种形状：

| 形状 | 处理 |
|---|---|
| `{ "text": "..." }` | 直接进 prompt。 |
| `{ "data": ... }` | 序列化成 JSON 文本后进 prompt。 |
| `{ "raw": "...", "mediaType": "...", "filename": "..." }` | 挂载附件服务时交给附件层落成持久引用。没有附件服务时退成可读占位文本。 |
| `{ "url": "..." }` | 服务端不下载，按文本处理。 |

`configuration` 里有三个字段会影响这次调用：

| 字段 | 作用 |
|---|---|
| `returnImmediately` | `true` 时任务启动后就返回，不等结算。**只对非流式 `SendMessage` 生效**。流式请求会一直流到结算或中断。 |
| `historyLength` | 裁剪返回的 `history`（任务的可见输入加最终输出）。`0` 不返回，未设置不裁剪。 |
| `acceptedOutputModes` | 只接受文本模式。不含 `text/*`、`text/plain` 或 `*/*` 时返回 `CONTENT_TYPE_NOT_SUPPORTED`。 |

`contextId` 和 `taskId` 是两件事。复用 `contextId` 是让下一轮落在同一个会话里。续接 `taskId` 是把新输入接到同一条任务上。任务已经终态、或者还在跑时，续接返回 `UNSUPPORTED_OPERATION`。续接时 `contextId` 与记录不一致返回 `INVALID_PARAMS`。

## 七个 JSON-RPC 方法

| 方法 | 参数 | 成功结果 | 会返回的错误 |
|---|---|---|---|
| `SendMessage` | `message`、`configuration?` | `{ task: Task }` | `INVALID_PARAMS`、`CONTENT_TYPE_NOT_SUPPORTED`、`TASK_NOT_FOUND`、`UNSUPPORTED_OPERATION`、`INTERNAL_ERROR` |
| `SendStreamingMessage` | `message`、`configuration?` | SSE：`task` → 状态/artifact 帧 → `task` | `INVALID_PARAMS`、`CONTENT_TYPE_NOT_SUPPORTED`、`TASK_NOT_FOUND`、`UNSUPPORTED_OPERATION`、`-32000`（门禁）、`METHOD_NOT_FOUND`、`VERSION_NOT_SUPPORTED` |
| `GetTask` | `id`、`historyLength?` | `Task` | `INVALID_PARAMS`、`TASK_NOT_FOUND` |
| `ListTasks` | `contextId`、`status`、`statusTimestampAfter`、`includeArtifacts`、`historyLength`、`pageSize`、`pageToken` | `{ tasks, nextPageToken, pageSize, totalSize }` | 无方法专用错误 |
| `CancelTask` | `id` | `Task` | `INVALID_PARAMS`、`TASK_NOT_FOUND`、`TASK_CANCEL_NOT_ALLOWED` |
| `SubscribeToTask` | `id` | SSE：当前 `task` → 状态帧 → 终态 `task` | `INVALID_PARAMS`、`TASK_NOT_FOUND`、`UNSUPPORTED_OPERATION`、`METHOD_NOT_FOUND` |
| `GetExtendedAgentCard` | 无 | `AgentCard` | 无方法专用错误 |

鉴权、版本与坏 JSON 的错误对所有方法都适用，表里不再重复。两条路径接受的方法不同：

- 非流式路径只处理 `SendMessage`、`GetTask`、`ListTasks`、`CancelTask`、`GetExtendedAgentCard` 和四个 push 配置方法。其它方法名返回 `METHOD_NOT_FOUND`。
- 流式路径只接受 `SendStreamingMessage` 与 `SubscribeToTask`。在 SSE 请求里发 `SendMessage` 会收到一帧 `METHOD_NOT_FOUND`。不带 `Accept: text/event-stream` 的 `SendStreamingMessage` 也返回 `METHOD_NOT_FOUND`。

### SendMessage

**用途**：建任务或续接任务。默认等到终态或中断态才回包。

**请求**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "method": "SendMessage",
  "params": {
    "message": {
      "messageId": "m-1",
      "role": "ROLE_USER",
      "parts": [{ "text": "统计这三个文件的行数" }],
      "metadata": { "skill": "chat" }
    },
    "configuration": { "historyLength": 2 }
  }
}
```

**响应**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "result": {
    "task": {
      "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
      "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
      "status": { "state": "TASK_STATE_COMPLETED", "timestamp": "2026-11-18T02:10:11.482Z" },
      "artifacts": [
        { "artifactId": "result", "parts": [{ "text": "三个文件共 812 行。" }] }
      ],
      "history": [
        {
          "messageId": "m-1",
          "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
          "taskId": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
          "role": "ROLE_USER",
          "parts": [{ "text": "统计这三个文件的行数" }],
          "metadata": { "skill": "chat" }
        },
        {
          "messageId": "a2a-output-a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
          "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
          "taskId": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
          "role": "ROLE_AGENT",
          "parts": [{ "text": "三个文件共 812 行。" }]
        }
      ],
      "metadata": { "skill": "chat", "serverId": "reports-1a2b3c4d" }
    }
  }
}
```

`result` 一定是 `{ task }`。`SendMessageResponse` 里那个 `message` 分支入站不产生。`status.timestamp` 取记录的 `updatedAt`。`artifacts` 是累积结果。`history` 为空时整个字段不出现。

**错误**：

| 条件 | 码 |
|---|---|
| `params.message` 缺失 | `INVALID_PARAMS` -32602 |
| `acceptedOutputModes` 排除文本 | `CONTENT_TYPE_NOT_SUPPORTED` -32005 |
| 技能不在派生集合，或 `a2a/inbound-task` 设置了 `rejected` | `INVALID_PARAMS` -32602 |
| `message.taskId` 不存在或属于别的实例 | `TASK_NOT_FOUND` -32001 |
| `message.contextId` 与任务记录不一致 | `INVALID_PARAMS` -32602 |
| 续接终态任务，或续接仍在运行的任务 | `UNSUPPORTED_OPERATION` -32004 |
| 分发中未预期异常 | `INTERNAL_ERROR` -32603 |

### SendStreamingMessage

**用途**：建或续接任务，用 SSE 推状态与 artifact。只有 `Accept` 含 `text/event-stream` 时才进这条路径。

**请求**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-2",
  "method": "SendStreamingMessage",
  "params": {
    "message": {
      "messageId": "m-2",
      "role": "ROLE_USER",
      "parts": [{ "text": "统计这三个文件的行数" }]
    },
    "configuration": { "historyLength": 0 }
  }
}
```

**响应**：

为便于阅读，`task` 帧只列 `id` 与 `status`。实际还带 `contextId`、`artifacts`、`metadata`，完整形状见 `SendMessage` 的响应。

```text
data: {"jsonrpc":"2.0","id":"req-2","result":{"task":{"id":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","status":{"state":"TASK_STATE_SUBMITTED","timestamp":"2026-11-18T02:10:09.001Z"}}}}

id: 12
data: {"jsonrpc":"2.0","id":"req-2","result":{"statusUpdate":{"taskId":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","status":{"state":"TASK_STATE_WORKING","timestamp":"2026-11-18T02:10:09.004Z"}}}}

id: 13
data: {"jsonrpc":"2.0","id":"req-2","result":{"artifactUpdate":{"taskId":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","artifact":{"artifactId":"result","parts":[{"text":"三个文件共 812 行。"}]},"append":true,"lastChunk":false}}}
```

`task` 的形状见上面 `SendMessage` 的响应。上面只贴了三帧，后面还会发生：

- 一帧 `artifactUpdate` 带 `lastChunk: true`，`parts` 为空数组，用来收尾。
- 结算时先有一帧带 `id:` 的终态 `task`，再有一帧不带 `id:` 的当前 `task`。两帧内容通常相同，以最后一帧为准。

示例用 `historyLength: 0` 关掉了历史。不传时任务快照会带上可用的 `history`。

**错误**：

| 条件 | 码 |
|---|---|
| `params.message` 缺失 | `INVALID_PARAMS` -32602 |
| `acceptedOutputModes` 排除文本 | `CONTENT_TYPE_NOT_SUPPORTED` -32005 |
| 技能门禁拒绝 | `-32000` |
| `message.taskId` 不存在或属于别的实例 | `TASK_NOT_FOUND` -32001 |
| `contextId` 与任务记录不一致 | `INVALID_PARAMS` -32602 |
| 续接终态或仍在运行的任务 | `UNSUPPORTED_OPERATION` -32004 |
| 非 SSE 请求，或方法名不是这两个之一 | `METHOD_NOT_FOUND` -32601 |
| `A2A-Version` 主次不匹配 | `VERSION_NOT_SUPPORTED` -32007 |

鉴权与限流在写 `200` 之前处理，失败仍是普通 HTTP `401` / `429`，不会出现半截流。

### GetTask

**用途**：按任务 id 读一条记录。`historyLength` 只影响 `history` 的条数。

**请求**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-3",
  "method": "GetTask",
  "params": {
    "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
    "historyLength": 1
  }
}
```

**响应**（`result` 直接是 `Task`）：

```json
{
  "jsonrpc": "2.0",
  "id": "req-3",
  "result": {
    "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
    "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
    "status": { "state": "TASK_STATE_COMPLETED", "timestamp": "2026-11-18T02:10:11.482Z" },
    "artifacts": [
      { "artifactId": "result", "parts": [{ "text": "三个文件共 812 行。" }] }
    ],
    "history": [
      {
        "messageId": "a2a-output-a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
        "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
        "taskId": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
        "role": "ROLE_AGENT",
        "parts": [{ "text": "三个文件共 812 行。" }]
      }
    ],
    "metadata": { "skill": "chat", "serverId": "reports-1a2b3c4d" }
  }
}
```

`historyLength` 为 `0` 时没有 `history`。不传时不裁剪。任务没有可见输入也没有输出时，`history` 也可能整个不出现。

**错误**：`id` 缺失是 `INVALID_PARAMS`。任务不存在或属于别的实例是 `TASK_NOT_FOUND`。

### ListTasks

**用途**：按上下文、状态和时间过滤任务，按最近更新分页。

**请求**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-4",
  "method": "ListTasks",
  "params": {
    "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
    "status": ["TASK_STATE_COMPLETED"],
    "pageSize": 50,
    "includeArtifacts": true,
    "historyLength": 0
  }
}
```

**响应**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-4",
  "result": {
    "tasks": [
      {
        "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
        "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
        "status": { "state": "TASK_STATE_COMPLETED", "timestamp": "2026-11-18T02:10:11.482Z" },
        "artifacts": [
          { "artifactId": "result", "parts": [{ "text": "三个文件共 812 行。" }] }
        ],
        "metadata": { "skill": "chat", "serverId": "reports-1a2b3c4d" }
      }
    ],
    "nextPageToken": "",
    "pageSize": 50,
    "totalSize": 1
  }
}
```

规则：

- `status` 收字符串或字符串数组。空数组表示不按状态过滤。
- `statusTimestampAfter` 与记录的 `updatedAt` 做字符串比较。
- `includeArtifacts` 默认 `false`。不传时任务里没有 `artifacts`。
- `historyLength` 默认不裁剪。
- 排序按 `updatedAt` 倒序，同值再按 `taskId` 倒序。
- `pageSize` 默认 50，范围 1 到 100。`pageToken` 是上一页返回的偏移量编码。`nextPageToken` 为空串表示没有下一页。

**错误**：没有方法专用错误。鉴权、版本、坏 JSON 仍按通用路径返回。

### CancelTask

**用途**：取消一条非终态任务。先中止执行器的 signal，再落 `CANCELED`、广播状态帧、唤醒等待者。

**请求**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-5",
  "method": "CancelTask",
  "params": { "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10" }
}
```

**响应**（`result` 直接是 `Task`，不带 `history`）：

```json
{
  "jsonrpc": "2.0",
  "id": "req-5",
  "result": {
    "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
    "contextId": "0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31",
    "status": {
      "state": "TASK_STATE_CANCELED",
      "timestamp": "2026-11-18T02:11:02.117Z",
      "message": {
        "messageId": "a2a-status-a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10",
        "role": "ROLE_AGENT",
        "parts": [{ "text": "Task canceled by caller" }]
      }
    },
    "artifacts": [],
    "metadata": { "skill": "chat", "serverId": "reports-1a2b3c4d" }
  }
}
```

**错误**：`id` 缺失是 `INVALID_PARAMS`。任务不存在是 `TASK_NOT_FOUND`。任务已经终态是 `TASK_CANCEL_NOT_ALLOWED`（-32002）。

### SubscribeToTask

**用途**：订阅一条非终态任务的后续帧。先给当前快照，再跟到终态或中断。

**请求**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-6",
  "method": "SubscribeToTask",
  "params": { "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10" }
}
```

**响应**：

为便于阅读，`task` 帧只列 `id` 与 `status`。实际还带 `contextId`、`artifacts`、`metadata`，完整形状见 `SendMessage` 的响应。

```text
data: {"jsonrpc":"2.0","id":"req-6","result":{"task":{"id":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","status":{"state":"TASK_STATE_WORKING","timestamp":"2026-11-18T02:10:09.004Z"}}}}

id: 21
data: {"jsonrpc":"2.0","id":"req-6","result":{"statusUpdate":{"taskId":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","status":{"state":"TASK_STATE_WORKING","timestamp":"2026-11-18T02:10:10.120Z"}}}}
```

`task` 的形状见上面 `SendMessage` 的响应。随后是后续状态帧、结算时先一帧带 `id:` 的终态 `task`、最后一帧不带 `id:` 的当前 `task`。带 `Last-Event-ID` 时，首帧之后会补状态帧与结算时的任务帧，artifact 帧跳过。中断态不是终态，所以对 `INPUT_REQUIRED` 的任务可以订阅。这种任务会以当前中断状态收尾，不会一直挂着。

**错误**：`id` 缺失是 `INVALID_PARAMS`。任务不存在是 `TASK_NOT_FOUND`。任务已终态是 `UNSUPPORTED_OPERATION`（-32004）。非 SSE 请求是 `METHOD_NOT_FOUND`。

### GetExtendedAgentCard

**用途**：取回当前实例的 AgentCard。入参被忽略，内容与卡片路由一致。

**请求**：

```json
{
  "jsonrpc": "2.0",
  "id": "req-7",
  "method": "GetExtendedAgentCard",
  "params": {}
}
```

**响应**（`result` 直接是卡片）：

```json
{
  "jsonrpc": "2.0",
  "id": "req-7",
  "result": {
    "name": "reports",
    "description": "Reporting agent",
    "version": "0.1.0",
    "provider": { "url": "https://deepseek.com", "organization": "DeepSeek" },
    "capabilities": {
      "streaming": true,
      "pushNotifications": false,
```

## SSE 帧与重连

同步方法讲完，下面看流式路径怎么推帧，以及断线后怎么补。

![SSE 连接断开后按事件编号续传](/img/dsh-a2a/sse-stream-sequence.png)

重连请求：

```sh
curl -N http://127.0.0.1:3080/a2a/reports-1a2b3c4d \
  -H 'content-type: application/json' \
  -H 'accept: text/event-stream' \
  -H 'last-event-id: 41' \
  -d '{
    "jsonrpc": "2.0",
    "id": "req-8",
    "method": "SubscribeToTask",
    "params": { "id": "a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10" }
  }'
```

服务端先发当前快照，再补断点之后的状态帧。后面还会有一帧带 `id:` 的终态 `task` 和一帧不带 `id:` 的末帧 `task`。下面只贴前两帧，其余省略。为便于阅读，`task` 帧只列 `id` 与 `status`。实际还带 `contextId`、`artifacts`、`metadata`，完整形状见 `SendMessage` 的响应：

```text
data: {"jsonrpc":"2.0","id":"req-8","result":{"task":{"id":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","status":{"state":"TASK_STATE_WORKING","timestamp":"2026-11-18T02:10:09.004Z"}}}}

id: 42
data: {"jsonrpc":"2.0","id":"req-8","result":{"statusUpdate":{"taskId":"a2a-1f7c9a2e-4b6d-4f1a-9c3e-2d5b8a7c6e10","contextId":"0f3b6c2a-8d41-4e77-9a10-5c6b7e8f2a31","status":{"state":"TASK_STATE_WORKING","timestamp":"2026-11-18T02:10:10.120Z"}}}}
```

每帧都是 `data: ` 加一个 JSON-RPC 信封：正常帧用 `result`，出错帧用 `error`。

| 帧 | 形状 | 带不带 `id:` | 出现时机 |
|---|---|---|---|
| `task` | `{ "task": Task }` | 首帧与末帧不带，结算广播的终态帧带 | 首帧、结算时广播的终态任务、最后一帧 |
| `statusUpdate` | `{ "statusUpdate": { taskId, contextId, status, metadata? } }` | 是 | 状态变化。trace 激活时 `metadata` 里带事件 |
| `artifactUpdate` | `{ "artifactUpdate": { taskId, contextId, artifact, append?, lastChunk? } }` | 是 | 可见文本增量或收尾块 |
| `message` | `{ "message": Message }` | 否 | 类型存在，入站不产生 |
| 错误 | `{ "jsonrpc": "2.0", "id": ..., "error": { code, message, data? } }` | 否 | 出错后关闭流 |

`append: true` 或缺省时，把这一块的 `parts` 追加到同 `artifactId` 的已存 artifact。只有显式 `append: false` 才替换。`lastChunk: true` 是本段文本的收尾，不代表任务结束。任务是否结束看 `status.state`。

重连边界：

- `Last-Event-ID` 之后会补状态帧与结算时的任务帧，artifact 帧不补。首帧快照已经包含当时的 artifact，补 artifact 会让客户端把同一段文本再追加一次。
- 事件序号是进程内全局递增，不是每个任务从 1 开始。
- 每个任务保留最近 200 帧。日志最多记 1000 个任务。都只在当前进程内。
- 客户端断开不会让任务停下：执行器继续跑，结果照样写进存储，SSE 只负责投递。
- 对终态任务发 `SubscribeToTask` 返回 `UNSUPPORTED_OPERATION`。任务只在当前进程的事件日志里可重放，重启后补不了。

## 任务状态机

帧讲完，下面看服务端怎么记录任务状态。

![入站任务实际会走的状态、取消与失败落点](/img/dsh-a2a/task-state-machine.png)

| 状态 | 是否终态 | 说明 |
|---|---|---|
| `TASK_STATE_SUBMITTED` | 否 | 已写入存储，执行器还没接手 |
| `TASK_STATE_WORKING` | 否 | 执行器正在跑这一轮 |
| `TASK_STATE_INPUT_REQUIRED` | 否，中断 | 等调用方补输入 |
| `TASK_STATE_AUTH_REQUIRED` | 否，中断 | 等调用方补鉴权 |
| `TASK_STATE_COMPLETED` | 是 | 已结算。可能有 `result`，也可能没有 |
| `TASK_STATE_FAILED` | 是 | 已结算。`status.message` 写错误 |
| `TASK_STATE_CANCELED` | 是 | 已结算。调用方或面板中止 |
| `TASK_STATE_REJECTED` | 是 | 词表保留。入站不会产生 |

迁移：

1. 新建任务先落 `SUBMITTED`。
2. `runTask` 先看并发配额。超配额直接落 `FAILED`，错误码 `quota`，不经过 `WORKING`。
3. 配额通过后落 `WORKING`，执行器开始跑。
4. 执行器返回 `INPUT_REQUIRED` 或 `AUTH_REQUIRED` 时停在中状态。这一轮结束，任务仍可续接。
5. 执行器返回普通结果时落 `COMPLETED`。没有可见文本也落 `COMPLETED`，只是没有 `result` artifact。
6. 执行器抛错落 `FAILED`，错误码 `executor`。超过 `inboundTimeoutMs` 也落 `FAILED`，错误码 `timeout`。
7. `CancelTask` 或面板取消落 `CANCELED`。终态任务不能再取消。
8. 对中断态续接，任务回到 `WORKING`，再走上面的落点。

`REJECTED` 不会出现：技能门禁在任务记录创建之前就裁决了。非流式路径返回 `INVALID_PARAMS`，流式路径返回 `-32000`。两种都不留下任务。终态任务不再接受续接。仍在运行的任务也不接受，返回 `UNSUPPORTED_OPERATION`。

## 错误码与拒绝点

状态之外，调用方还会遇到拒绝。下面按码归位。错误响应与结果共用同一个信封，只是把 `result` 换成 `error`：

```json
{
  "jsonrpc": "2.0",
  "id": "req-1",
  "error": {
    "code": -32602,
    "message": "unknown skill \"coding\""
  }
}
```

| 码 | 名称 | 触发条件 |
|---|---|---|
| `-32700` | `PARSE_ERROR` | 不发出。坏 JSON 走 `-32600` |
| `-32600` | `INVALID_REQUEST` | body 不是合法的 JSON-RPC 2.0 请求 |
| `-32601` | `METHOD_NOT_FOUND` | 方法名未知，或流式/非流式路径用错 |
| `-32602` | `INVALID_PARAMS` | 缺 `message` / `id`。`contextId` 与任务不一致。非流式技能门禁 |
| `-32603` | `INTERNAL_ERROR` | 分发过程中的未预期异常 |
| `-32001` | `TASK_NOT_FOUND` | 任务不存在，或不属于这个实例 |
| `-32002` | `TASK_CANCEL_NOT_ALLOWED` | 取消已终态的任务 |
| `-32003` | `PUSH_NOTIFICATION_NOT_SUPPORTED` | 四个 push 配置方法 |
| `-32004` | `UNSUPPORTED_OPERATION` | 续接终态/运行中任务。订阅终态任务 |
| `-32005` | `CONTENT_TYPE_NOT_SUPPORTED` | `acceptedOutputModes` 排除文本 |
| `-32006` | `STREAMING_NOT_SUPPORTED` | 不发出 |
| `-32007` | `VERSION_NOT_SUPPORTED` | `A2A-Version` 主次版本不匹配 |
| `-32008` | `INVALID_AGENT_RESPONSE` | 客户端侧使用。入站不发出 |
| `-32000` | 无常量名 | 限流拒绝。流式路径技能门禁。客户端也用它表示超时/限流/远端失败 |
| `-32040` | 无常量名 | HTTP `401` 的 body |

两个门禁码不要混：

- 非流式 `SendMessage` 的技能门禁拒绝是 `INVALID_PARAMS`（-32602）。
- 流式 `SendStreamingMessage` 的技能门禁拒绝是 `-32000`。
- 限流是 HTTP `429`，body 是 `-32000`，响应头带 `Retry-After`。
- 鉴权失败是 HTTP `401`，body 是 `-32040`。

并发配额和超时不返回 RPC 错误：任务已经创建，直接落 `FAILED`，调用方从 `status.state` 与 `status.message` 读结果。

## AgentCard 与 trace 扩展

一个允许 trace 的卡片：

```json
{
  "name": "reports",
  "description": "Reporting agent",
  "version": "0.1.0",
  "provider": { "url": "https://deepseek.com", "organization": "DeepSeek" },
  "capabilities": {
    "streaming": true,
    "pushNotifications": false,
    "extendedAgentCard": true,
    "stateTransitionHistory": false,
    "extensions": [
      {
        "uri": "https://github.com/hanphone/dsh-a2a/blob/main/docs/extensions/dsh-trace/v1.md",
        "description": "Optional tool-call trace metadata. Disabled unless the client activates this extension.",
        "required": false,
        "params": {
          "carrier": "metadata",
          "default": "off",
          "args": "redacted-preview",
          "maxCalls": 64
        }
      }
    ]
  },
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [
    { "id": "chat", "name": "chat", "description": "Conversational assistance over a DSH agent session." }
  ],
  "supportedInterfaces": [
    {
      "url": "http://127.0.0.1:3080/a2a/reports-1a2b3c4d",
      "protocolBinding": "JSONRPC",
      "protocolVersion": "1.0"
    }
  ]
}
```

| 字段 | 来源 |
|---|---|
| `name` / `description` / `version` | 实例记录的三个字段 |
| `provider` | 固定为 `DeepSeek` 与 `https://deepseek.com` |
| `capabilities.streaming` | 固定 `true` |
| `capabilities.pushNotifications` | 固定 `false` |
| `capabilities.extendedAgentCard` | 固定 `true` |
| `capabilities.stateTransitionHistory` | 固定 `false` |
| `capabilities.extensions` | 实例 trace 策略生效时，多一个可选的 trace 扩展 |
| `defaultInputModes` | 默认 `text/plain`。挂载附件服务时再加 `image/png`、`image/jpeg`、`image/webp`、`image/gif`、`application/octet-stream` |
| `defaultOutputModes` | 默认 `text/plain` |
| `skills` | preset 技能目录里模型可调的条目。`id` 与 `name` 都取技能名。目录为空时回退 `chat` |
| `supportedInterfaces` | 一个 JSONRPC 接口，`protocolVersion` 为 `1.0` |
| `securitySchemes` / `securityRequirements` | 配了 token 才出现。只写方案，不写 token 值 |

卡片的名称、描述、版本与端点来自实例记录、对外 base URL 和端点路径。技能来自实例绑定的 preset，不来自运行中的工具表。trace 宣告与鉴权方案由实例策略决定。客户端要用面板给出的完整卡片地址，`/.well-known/agent-card.json` 不是这个实例的入口。

### trace 激活

三个条件同时满足才会产生 trace：

1. 部署配置 `inboundTrace` 为 `true`。
2. 实例记录允许 trace。记录里没写时跟随部署值。
3. 请求头带完整 URI：

```text
A2A-Extensions: https://github.com/hanphone/dsh-a2a/blob/main/docs/extensions/dsh-trace/v1.md
```

响应会用同一个头把已激活的 URI 带回来。没有请求扩展的客户端，响应里不会多出字段。只有在启动任务的那次请求上激活才算数。给已经跑起来的任务补一个订阅，不会补开 trace。

实时观察放在状态帧的 metadata 里：

```json
{
  "metadata": {
    "https://github.com/hanphone/dsh-a2a/blob/main/docs/extensions/dsh-trace/v1.md": {
      "event": {
        "callId": "call-1",
        "tool": "read_file",
        "phase": "start",
        "status": "running",
        "argsPreview": "{\"path\":\"a.txt\"}",
        "timestamp": "2026-11-18T02:10:10.000Z"
      }
    }
  }
}
```

任务结算后，`Task.metadata[URI]` 里会有一份有上限的摘要：

```json
{
  "calls": [
    {
      "callId": "call-1",
      "tool": "read_file",
      "phase": "start",
      "status": "running",
      "argsPreview": "{\"path\":\"a.txt\"}",
      "timestamp": "2026-11-18T02:10:10.000Z"
    },
    {
      "callId": "call-1",
      "tool": "read_file",
      "phase": "end",
      "status": "ok",
      "durationMs": 12,
      "timestamp": "2026-11-18T02:10:10.012Z"
    }
  ]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `callId` | string | 这次调用的关联标识 |
| `tool` | string | 被调用的工具名。拿不到时写 `tool` |
| `phase` | `start` / `end` | 开始或结束 |
| `status` | `running` / `ok` / `error` / `unknown` | 开始帧是 `running`。结束时按结果给 `ok` 或 `error`，没收到结果的给 `unknown` |
| `durationMs` | number，可选 | 从会话事件时间算出的毫秒数 |
| `argsPreview` | string，可选 | 参数预览。敏感键已替换，长度有限。只在开始帧出现 |
| `timestamp` | string | ISO 8601 时间 |
| `truncated` | boolean，可选 | 为 `true` 时表示更早的记录已被丢弃 |

上限与脱敏：一个任务最多记 64 条观察。参数先按 JSON 解析。解析不了就写成 `[unparseable arguments]`。能解析时，键名命中 token、secret、password、passwd、api-key、authorization、cookie、credential、private-key 的值替换成 `[redacted]`，字符串超过 120 字符会截断，整个预览不超过 200 字符。

trace 的载体只有 metadata。`artifacts`、`history` 和模型工具的输出里都不会出现它。`subagent` 路径不观察子工具。能读任务的调用方都能读到 `Task.metadata` 里的摘要，因此只对可信对端开启。

## 模型工具契约（出站）

下面说的是本机模型看到的工具，不是 A2A 线协议。连接启用后，远端每宣告一个未被禁用的技能，本机就多一个模型工具。

工具名：`a2a__<连接名>__<技能 id>`。先按 `[^A-Za-z0-9_-]` 替换为 `_`，基础名截到 64 字符。同一个连接内重名时，把基础名压到 56 字符再拼一段短哈希。

参数 schema：

```json
{
  "type": "object",
  "properties": {
    "prompt": {
      "type": "string",
      "description": "The task or instruction to send to the remote agent."
    },
    "taskId": {
      "type": "string",
      "description": "Continue an existing interrupted remote task (use the id reported by a previous INPUT_REQUIRED/AUTH_REQUIRED result)."
    }
  },
  "required": ["prompt"]
}
```

调用时：

- 每次生成新的 `messageId`。带 `taskId` 就只带 `taskId`，否则带一个按调用方 agent 稳定的 `contextId`。
- 总是请求流式。远端卡片宣告 `capabilities.streaming: true` 时走 SSE，否则阻塞发送后轮询。
- 调用方中止时，信号会传到客户端。如果已经拿到任务 id，客户端会再发一次 `CancelTask`。
- 网络错误与 5xx 最多重试两次。流式重试会带上已知的 `Last-Event-ID`。

结果选取：

1. 先找 `artifactId` 为 `result` 的 artifact，把它的 parts 渲染成文本。
2. 没有 `result` 时，只取其它可见 artifact 的文本 part。
3. trace 与诊断 artifact 不参与拼接。非 result artifact 的 `data` part 也不进模型可见结果。

失败与中断的返回文本：

| 远端状态 | 工具行为 |
|---|---|
| `TASK_STATE_FAILED` | 抛错，文本是 `Remote agent task failed: <详情>` |
| `TASK_STATE_INPUT_REQUIRED` | 不抛错，返回 `[remote agent TASK_STATE_INPUT_REQUIRED task=<id>] <问题>` |
| `TASK_STATE_AUTH_REQUIRED` | 不抛错，返回 `[remote agent TASK_STATE_AUTH_REQUIRED task=<id>] <问题>` |
| 完成但没有可见输出 | 返回 `(remote agent returned no output)` |

模型拿到中断文本里的 `taskId` 后，可以用同一个工具再调一次，把 `taskId` 放进参数。
