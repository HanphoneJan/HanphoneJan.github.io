# 数据中心接入设计方案

---

## 1. 设计要求

以下要求来自运营对齐决议，是设计的硬约束：

| # | 要求 | 来源 | 含义 |
|---|------|------|------|
| A | 实时数据 5-10 分钟刷新 | 示例业务 | 今日累计付费金额、日监控 KPI 卡片需要近实时 |
| B | 流水数据按小时刷新 | 示例业务 | 分时活跃、付费小时分布等当日按小时数据 |
| C | 其他数据 T+1 | 示例业务 | 留存、LTV、渠道 ROI 等历史趋势，T+1 可接受 |
| D | 离线数据最迟次日 9 点 | 示例业务 | ETL 截止时间 |
| E | 日环比：0 点到 0 点完整周期 | 示例业务 | start_date/end_date 按整日对齐 |
| F | 当日对比需时间窗口对齐 | 示例业务 | 今日数据不完整，对比时往日数据截断到同一时刻 |

### 2.2 分层原则

| 层级 | 职责 | 依赖规则 |
|------|------|---------|
| Router | 参数校验、scope 解析、响应封装 | 只调 Service |
| Service | 业务编排、衍生指标计算 | 只依赖 Repo 接口 |
| RepoFactory | 根据 scope 组装 Repo 实现 | 不暴露给 Router |
| Repo 实现 | 具体数据访问（HTTP/SQL） | 只被 Factory 创建 |
| Redis | 缓存装饰 | 通过 CachedRepo 透明接入 |

**核心约束**：Service 层只依赖 Repo 接口，不感知底层是 HTTP 还是 SQL。

### 2.3 Repo 接口定义

```python
# app/modules/dashboard/repos/protocol.py

class DashboardRepo(Protocol):
    """看板数据访问接口。Service 层唯一依赖的数据源抽象。"""

    async def query_scalar(
        self, scope: Scope, metrics: list[str], date_range: DateRange
    ) -> dict[str, MetricResult]:
        """标量查询：返回每指标每日期一个值"""

    async def query_dimension(
        self, scope: Scope, metrics: list[str], dimension: str, date_range: DateRange
    ) -> dict[str, list[DimensionResult]]:
        """维度查询：返回每指标按维度拆分的数据"""

    async def query_series(
        self, scope: Scope, metrics: list[str], date_range: DateRange, granularity: str
    ) -> dict[str, list[TimeSeriesPoint]]:
        """时序查询：返回趋势数据"""


@dataclass
class MetricResult:
    value: float | int
    available: bool
    is_final: bool
    reason: str | None = None
    source: str = ""  # "datacenter" | "local_pg" | "fallback"
```

### 2.4 Repo 实现

| Repo | 职责 | 底层 |
|------|------|------|
| `DatacenterRepo` | 调 DC `/aggregate` | HTTP Client |
| `LocalPGRepo` | 查 `datacenter_metric_daily` | PG Session |
| `HybridRepo` | 双轨合并（历史 LocalPG + 当日 DC） | 组合两个 Repo |
| `CachedRepo` | 装饰器，加 Redis 缓存 | 包裹任意 Repo |

```python
# app/modules/dashboard/repos/hybrid_repo.py

class HybridRepo:
    """双轨 Repo：历史数据走 LocalPGRepo，当日数据走 DatacenterRepo。"""

    def __init__(self, local: LocalPGRepo, dc: DatacenterRepo):
        self._local = local
        self._dc = dc

    async def query_scalar(self, scope, metrics, date_range):
        history_range, today_range = date_range.split_at_today()
        results = {}
        if history_range:
            results.update(await self._local.query_scalar(scope, metrics, history_range))
        if today_range:
            results.update(await self._dc.query_scalar(scope, metrics, today_range))
        return results


# app/modules/dashboard/repos/cached_repo.py

class CachedRepo:
    """缓存装饰器。包裹在 HybridRepo 外层，对 Service 完全透明。"""

    def __init__(self, inner: DashboardRepo, redis: Redis):
        self._inner = inner
        self._redis = redis

    async def query_scalar(self, scope, metrics, date_range):
        # 用户主动刷新：跳过缓存读，直接回源 + 写缓存
        if scope.skip_cache:
            result = await self._inner.query_scalar(scope, metrics, date_range)
            if any(v.available for v in result.values()):
                key = _cache_key("scalar", scope, metrics, date_range)
                ttl = _resolve_ttl(date_range)
                await self._redis_setex(key, ttl, json.dumps(serialize(result), default=str))
            return result

        key = _cache_key("scalar", scope, metrics, date_range)
        ttl = _resolve_ttl(date_range)

        # 1. 读缓存
        cached = await self._redis_get(key)
        if cached:
            parsed = _parse_cached(cached)
            if parsed is not None:
                return parsed

        # 2. 互斥锁防击穿（uuid token 标识锁归属，防误删）
        lock_key = f"{key}:lock"
        lock_token = uuid.uuid4().hex[:16]
        lock = await self._redis_set(lock_key, lock_token, nx=True, ex=10)

        if not lock:
            # 指数退避重试读缓存（最多 3 次，最长等 3.5s）
            for attempt in range(3):
                await asyncio.sleep(0.5 * (2 ** attempt))
                cached = await self._redis_get(key)
                if cached:
                    parsed = _parse_cached(cached)
                    if parsed is not None:
                        return parsed
            # 降级为直接回源
            return await self._inner.query_scalar(scope, metrics, date_range)

        try:
            # 3. 回源
            result = await self._inner.query_scalar(scope, metrics, date_range)
            # 全不可用时跳过缓存写入
            if all(not v.available for v in result.values()):
                return result
            # 4. 写缓存（部分不可用 TTL 减半）
            cache_ttl = ttl // 2 if any(not v.available for v in result.values()) else ttl
            await self._redis_setex(key, cache_ttl, json.dumps(serialize(result), default=str))
            return result
        finally:
            # 条件删除：仅当锁仍属于本进程时才删除
            current_val = await self._redis_get(lock_key)
            if current_val == lock_token:
                await self._redis_delete(lock_key)
```

### 2.5 RepoFactory 路由

```python
class DashboardRepoFactory:
    """Repo 工厂：根据 Scope.dc_enabled 和 game_id 自动选择数据源策略。"""

    def __init__(self, session: AsyncSession, redis) -> None:
        self._session = session
        self._redis = redis

    async def create(self, scope: Scope) -> DashboardRepo:
        local_pg = LocalPGRepo(self._session)

        if not scope.dc_enabled or not scope.game_id:
            # 数据中心未启用或缺少 game_id：仅本地 PG
            return CachedRepo(local_pg, self._redis)

        # 数据中心启用：按 project_id 动态解析 DC 配置
        config = await DatacenterConfigResolver(self._session).resolve(scope.project_id)
        if not config or not config.is_active or not config.base_url or not config.api_key:
            # 解析失败或配置不完整：降级为本地 PG
            return CachedRepo(local_pg, self._redis)

        # 配置完整：Hybrid（本地历史 + DC 实时）+ 缓存
        dc_client = DatacenterClient(
            base_url=config.base_url, api_key=config.api_key, auth_mode=config.auth_mode
        )
        dc = DatacenterRepo(dc_client, scope)
        hybrid = HybridRepo(local_pg, dc)
        return CachedRepo(hybrid, self._redis)
```

class DashboardService:

    async def get_daily_monitor(self, scope: Scope, date: str, channel_id: str = "") -> DailyMonitorData:

## 3. 固定看板数据流

### 3.1 查询链路

```
Router(project_id) → ScopeResolver → DashboardService → RepoFactory → [Cached]HybridRepo
```

**ScopeResolver** 职责：
- 查 `sys_project_config` 得 `game_id`, `region`
- 查 `sys_datacenter_game_source` 得 DC 配置（game_id × region_code 复合主键）
- 返回 `Scope(project_id, game_id, region_code, dc_enabled, dc_config)`

### 3.2 日监控 Tab 为例

日监控 Tab 只查 3 个标量指标（dau, revenue, pay_rate），是验证端到端链路的最佳起点。

### 3.3 时间对齐

**日对齐（要求 E）**：DC `/aggregate` 的 `start_date`/`end_date` 为 YYYY-MM-DD 日期级，完整日周期由查询参数保证。

**当日对比对齐（要求 F）**：放在 `DatacenterRepo` 层。

```python
class DatacenterRepo:
    async def query_scalar(self, scope, metrics, date_range):
        today = datetime.now(ZoneInfo(scope.timezone)).date().isoformat()
        if self._is_today_comparison(date_range, scope.timezone):
            # 今日数据：按当前小时截断
            cutoff_hour = self._get_current_cutoff_hour(scope.timezone)
            raw = await self._client.aggregate(scope.game_id, metrics, date_range)
            return self._apply_cutoff(raw, cutoff_hour)
        elif self._is_comparison_date(date_range, today):
            # 对比日（昨日/上周同日）：也按相同 cutoff_hour 截断，保证时间窗口对齐
            cutoff_hour = self._get_current_cutoff_hour(scope.timezone)
            raw = await self._client.aggregate(scope.game_id, metrics, date_range)
            return self._apply_cutoff(raw, cutoff_hour)
        return await self._client.aggregate(scope.game_id, metrics, date_range)
```

Service 层拿到的是已对齐的数据。

当前 `QueryService.query_login` / `QueryService.query_order` 被前端页面和 Agent 工具共用。

class DatacenterLoginRepo(LoginDetailRepo):

## 5. ETL 与本地存储

### 5.1 ETL 职责

每日 08:00 执行：
1. 拉取 T-1 全部指标（标量 + 维度）
2. 写入 `datacenter_metric_daily`（PG）
3. 标记 `is_final=true`
4. 清理对应日期范围的 Redis 缓存

### 5.2 存储方案：PG 新表 `datacenter_metric_daily`

```sql
CREATE TABLE datacenter_metric_daily (
    project_id VARCHAR(64) NOT NULL,
    stat_date DATE NOT NULL,
    metric_name VARCHAR(64) NOT NULL,
    metric_value DECIMAL(18, 4),
    dimensions JSONB DEFAULT '{}',
    available BOOLEAN DEFAULT true,
    is_final BOOLEAN DEFAULT true,
    source VARCHAR(32) DEFAULT 'datacenter',
    reason VARCHAR(128),
    as_of TIMESTAMP,
    imported_at TIMESTAMP DEFAULT NOW(),

    PRIMARY KEY (project_id, stat_date, metric_name, dimensions)
);

CREATE INDEX idx_dc_metric_project_date ON datacenter_metric_daily(project_id, stat_date);
CREATE INDEX idx_dc_metric_name ON datacenter_metric_daily(metric_name);
CREATE INDEX idx_dc_metric_dimensions ON datacenter_metric_daily USING GIN(dimensions);
```

**ETL 写入（幂等 UPSERT）**：

```sql
INSERT INTO datacenter_metric_daily
  (project_id, stat_date, metric_name, metric_value, dimensions, available, is_final, source, as_of)
VALUES
  ('proj_xxx', '2026-06-01', 'dau', 29046.0, '{}', true, true, 'events', '2026-06-01T09:43:48')
ON CONFLICT (project_id, stat_date, metric_name, dimensions)
DO UPDATE SET
  metric_value = EXCLUDED.metric_value,
  available = EXCLUDED.available,
  is_final = EXCLUDED.is_final,
  source = EXCLUDED.source,
  as_of = EXCLUDED.as_of,
  imported_at = NOW();
```

**选型理由**：
- 数据量小（每天每项目 ~3600 行，10 个项目 = 3.6 万行/天），PG 完全胜任
- JSONB 维度灵活，不需要为每个维度组合加列
- 与 `sys_project_config` 等配置表同库，便于关联和事务
- 强一致性，`ON CONFLICT DO UPDATE` 天然幂等

### 5.3 ETL Worker 流程

```python
class DatacenterETLWorker:
    async def sync_daily_metrics(self, project_id: str, date: str):
        scope = await scope_resolver.resolve(project_id)

        # 1. 标量指标
        scalar = await self._dc_client.aggregate(
            game_id=scope.game_id,
            metrics=ALL_SCALAR_METRICS,  # ~80 个标量指标
            start_date=date, end_date=date,
            dimensions=[],
        )
        await self._save_to_pg(project_id, date, scalar)

        # 2. 维度指标
        for dim in ["hour", "channel"]:
            dim_result = await self._dc_client.aggregate(
                game_id=scope.game_id,
                metrics=ALL_DIMENSION_METRICS,
                start_date=date, end_date=date,
                dimensions=[dim],
            )
            await self._save_to_pg(project_id, date, dim_result)

        # 3. 清理缓存
        await self._invalidate_cache(project_id, date)
```

## 7. Redis 缓存策略

### 7.1 缓存分层

| 层级 | 数据 | TTL | 用途 |
|------|------|-----|------|
| L1 内存 | 指标目录 | 1 小时 | `/aggregate/metrics` 不常变 |
| L2 Redis | DC 响应 | 2-5 分钟 | 当日数据短期缓存 |
| L2 Redis | 历史查询 | 1-24 小时 | 历史数据长期缓存 |
| L3 本地 DB | ETL 结果 | 永久 | T-1 及以前 |

### 7.2 缓存 Key 规范

```
dc:catalog:{game_id}:{region}              → 指标目录
dc:scalar:{game_id}:{region}:{metrics_hash}:{start}:{end}:{dim_hash}  → 标量
dc:series:{game_id}:{region}:{metrics_hash}:{start}:{end}:{granularity} → 时序
dc:dim:{game_id}:{region}:{metric}:{dimension}:{start}:{end} → 维度
```

### 7.3 TTL 动态策略

```python
def resolve_ttl(date_range: DateRange) -> int:
    """动态 TTL：含当日最短，历史数据逐渐增长。"""
    if date_range.includes_today():
        return 120      # 2 分钟，当日数据变化快
    if date_range.days <= 7:
        return 300      # 5 分钟
    if date_range.days <= 30:
        return 900      # 15 分钟
    return 3600         # 1 小时，历史数据已固定
```

### 7.4 缓存穿透/击穿防护

- **互斥锁**：热点指标加分布式锁（Redis `SET NX EX 10`），避免并发穿透
- **空值缓存**：DC 返回 `available=False` 也缓存，TTL 减半
- **异步回源**：缓存过期后异步刷新，不阻塞请求

### 7.5 缓存清理

| 场景 | 清理方式 |
|------|---------|
| ETL 完成写入 | 清理对应日期的 `dc:scalar:*` 和 `dc:series:*` key |
| DC 数据质量告警 | 清空该项目全部缓存，强制回源 |
| 运营手动刷新 | 管理接口 `POST /admin/cache/invalidate` |
| Redis 内存紧张 | LRU 淘汰（Redis 自带） |

## 16. 用户分群 & 事件分析 DC 接入

### 16.1 与 Dashboard 接入的差异

Dashboard 数据是聚合指标（DAU、收入等），需要 ETL 落库 + 双轨合并（历史 PG + 当日 DC）。

用户分群和事件分析不同：

| 特征 | Dashboard | 用户分群 | 事件分析 |
|------|-----------|---------|---------|
| DC 接口 | `/aggregate` | `/player-events/filter` + `/behavior` + `/segments/{id}` | `/player-events/aggregate` + `/player-events/catalog` |
| 数据粒度 | 聚合值 | player_id 列表 | 聚合行 |
| ETL | 需要（`datacenter_metric_daily`） | **不需要** | **不需要** |
| 本地存储 | PG 缓存历史数据 | PG 配置表存 `segment_id` 引用 | PG 配置表存分析参数 |
| HybridRepo | 是（历史 PG + 当日 DC） | **不需要** | **不需要** |

### 16.2 架构总览

```
UserSegmentService                  EventAnalysisService
    │                                    │
    ▼                                    ▼
SegmentRepo (Protocol)              EventRepo (Protocol)
    │                                    │
    ├── DCSegmentRepo                  ├── DCEventRepo
    │   ├── POST /filter               │   ├── POST /catalog → Redis 1h
    │   ├── POST /behavior             │   └── POST /aggregate
    │   └── GET /segments/{id}         │
    │                                    │
    └── PG SegmentDefinitionRepo        └── PG EventAnalysisConfigRepo
        (segment_id 引用)                   (config JSON, 纯 CRUD)
```

核心原则：
- **不需要 ETL** —— 分群结果由 DC 管理（`segment_id`），我们只存储 `segment_id` 引用到 PG 配置表
- **不需要 LocalPGRepo 和 HybridRepo** —— Dashboard 的历史缓存 + 双轨合并模式不适用于分群和事件分析
- **Redis 缓存事件目录** —— `/player-events/catalog` 结果 1 小时有效
- **DC 不可用时** —— 检查 `available` 字段，`false` 时前端展示空状态 + `reason`
- **分群引用** —— 创建分群时调用 `/filter` 生成 `segment_id`，事件分析传 `segment_id` 给 `/aggregate`

#### 事件分析已知限制

- 当前 `/aggregate` 最大查询窗口 30 天，跨月分析建议按月份拆分后由前端合并。
- 维度字段按 `indexed`/`safe`/`expensive`/`sensitive` 分级，前端选择维度时应隐藏/提示 expensive 维度。
- 事件漏斗与路径分析不在本期范围，依赖 DC 后续接口支持。

class DCEventRepo:
    """DC /player-events 实现的事件分析数据访问。"""

    def __init__(self, dc_client: DatacenterClient, cache: Redis):
        self._dc = dc_client
        self._cache = cache

    async def get_catalog(self, scope: Scope, event_name: str | None = None) -> EventCatalog:

        cache_key = f"dc:event-catalog:{scope.game_id}:{scope.region}:{event_name or 'all'}"

            region=scope.region,
            event_name=event_name,

4. **行为条件预处理**：`behavior_conditions` 中的 `lookback_days` 使用默认值（login 30 天 / payment 30 天 / last_* 90 天）

5. **事件条件映射**：`scope` + `field` → `event_conditions`（如 `{"scope": "login", "field": "login_days"}` → `{"event_name": "login", "calculation": "count", "operator": ...}`）

### 16.8 不需要的组件

与 Dashboard 方案相比，以下组件在分群和事件分析中**不需要**：
- **ETL Worker** — 分群结果由 DC 管理，事件聚合实时执行
- **LocalPGRepo** — 不需要本地历史缓存
- **HybridRepo** — 不需要双轨合并
- **`datacenter_metric_daily` 表** — 不需要额外落库

仅 ERD 层面的 PG 表继续使用：`segment_definitions`（存储 `segment_id` 引用）和 `event_analysis_configs`（存储分析参数）。
