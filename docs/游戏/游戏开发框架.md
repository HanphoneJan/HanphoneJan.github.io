选引擎不是选「最强的那个」，是选**发行渠道、2D 还是 3D、团队会什么语言**三个约束的交点。先把这三件事定下来，答案通常只剩一个。

想找现成的做法，[awesome-open-source-games](https://github.com/michelpereira/awesome-open-source-games#readme) 是一份收录得很全的开源游戏源码清单，读别人的实现比只读文档快。

## 选引擎先定三件事

| 要发的渠道 | 2D / 3D | 团队语言 | 结论 |
|---|---|---|---|
| 微信 / 抖音 / 快手小游戏 | 2D 为主 | TypeScript | **Cocos Creator** |
| Steam / 独立小体量 | 2D 为主 | 无所谓 | **Godot** |
| 商业手游 / 跨平台 3D | 3D | C# | **Unity** |
| 网页点开就玩 | 都行 | JS/TS | **Phaser / PixiJS**，或引擎导出 WebGL |

反向判断更实用：**目标平台有没有官方支持**。小游戏对包体和 API 卡得极死，Unity 要转换插件才能上；Godot 主机支持最弱。这些比语法顺不顺手重要得多。

## Unity

商业项目里最稳，也是坑最多、最需要工程纪律的。

### 基本盘

- **语言**：C#。编辑器重度依赖可视化操作，纯代码能做的有限。
- **渲染**：内置管线已淘汰，现在分 **URP**（移动/中低端）与 **HDRP**（高端）。管线选错是后期返工的大头——换管线等于材质、Shader、后处理全部重做。
- **性能**：`DOTS`（ECS + Burst + Job System）能压榨出很高性能，学习曲线陡峭，绝大多数项目不该上。
- **资产**：Asset Store 是最宽的护城河，付费插件常常能省几个月。
- **授权**：按年收入分档（Personal / Pro / Enterprise）。2023 年那次 Runtime Fee 风波 2024 年已取消，但**条款会变，立项时去官网核对**，别凭记忆写预算。

### 缺点

空项目打包就几十 MB；WebGL 导出体积大、首屏慢、移动端浏览器兼容差；引擎升级经常破坏插件。

### 2D 骨骼动画：Spine / DragonBones

- [Spine](https://zh.esotericsoftware.com/) —— 商业 2D 骨骼动画工具，运行时便宜、性能好，Unity/Cocos 都有官方 runtime。角色动作、Q 版立绘基本都走它。
- [DragonBones](https://www.loongbones.com/) —— 免费开源的同类工具，功能少一些，但零成本、也能导出到主流引擎。

两者的取舍：Spine 贵但省心（工具链、运行时、社区都成熟），DragonBones 便宜但要自己啃坑。

### 工程化要点

- 场景拆分 + 异步加载，别把所有东西塞一个 Scene
- 配置表外置（JSON/CSV），改数值不该触发重新构建
- 版本管理：`Library/`、`Temp/`、`obj/` 必须进 .gitignore，`.meta` 必须提交

## Godot

MIT 协议，引擎和编辑器全开源，没有抽成、没有授权条款。

### 基本盘

- **语言**：GDScript（类 Python，专为引擎设计）+ C#（.NET 版）。**C# 目前不能导出 Web**，网页版只能用 GDScript。
- **心智模型**：一切都是**节点**，节点组成**场景**，场景可以像类一样被实例化。这套组合比 Unity 的「组件挂 GameObject」更直观，2D 尤其顺手。
- **2D**：原生 2D 渲染器，不是「3D 加正交相机」，2D 项目体验明显好于 Unity。
- **体积**：产物小，桌面端几十 MB 起，Web 版比 Unity 小一个量级。
- **协议**：MIT，商用无限制，改引擎源码也不用开源游戏。

### 缺点

3D 性能和大场景管理不如 Unity；主机（Switch/PS/Xbox）要第三方移植；插件生态小，冷门问题基本靠自己读源码。

### 网页导出注意

需要浏览器支持 WebGL2；开多线程还要服务端发 `COOP`/`COEP` 头（`SharedArrayBuffer` 的要求），否则只能跑单线程版。

## Cocos Creator

国内小游戏渠道的事实标准。优势不在引擎本身，而在**把「小游戏」这条链路打通了**：包体控制、分包加载、平台 API、热更新、广告与内购。

### 基本盘

- **语言**：TypeScript，前端转过来几乎零门槛；编辑器是 Electron 做的，工作流接近 Web 前端。
- **包体**：这是它存在的理由。微信小游戏主包有硬限制（4MB 量级），整包靠分包叠加（20MB 量级），数值随平台政策变，以官方为准。Cocos 的构建产物和分包策略就是围着它设计的。
- **2D / 3D**：3.x 是 3D 优先、2D 也能做，但小游戏项目绝大多数是 2D。
- **生态**：微信、抖音、快手、OV 快应用等渠道文档齐全，登录/支付/录屏分享有现成封装。

### 缺点

离开国内小游戏生态优势不明显；大型 3D 与 Unity 差距明显；社区比前两者小。

## 网页小游戏

「网页小游戏」是三条完全不同的路，别混。

### 一、纯 Web 引擎（Phaser / PixiJS / Three.js）

- 适合：网页休闲游戏、营销互动页、教学演示
- 优点：`npm install` 就开工，和前端工具链无缝；产物是静态文件，扔哪都能跑
- 代价：物理、动画、场景管理自己拼，复杂项目会重新发明引擎

PixiJS 只做渲染，Phaser 自带场景/物理/输入，Three.js 是 3D。

### 二、引擎导出 WebGL（Cocos / Unity / Godot）

适合已有引擎项目顺便发网页版。Unity 包体大、首屏是硬伤；Godot 见上面 COOP/COEP 那段。

### 三、平台小游戏（微信 / 抖音）

不是「网页」，是**跑在超级 App 里的运行时**：自己的包体限制、自己的 API、自己的审核。技术上还是 JS + Canvas/WebGL，但**不能用 DOM**，很多浏览器 API 也没有。

首屏和包体是核心工程问题：

- 主包只放启动必需（首场景、基础 UI、字体子集）
- 其余关卡、音频、图集走**分包**，按章节懒加载
- 图片图集化 + 压缩（WebP/ASTC 看平台），音频低码率
- 首屏必须有个可交互的加载页，不能白屏等资源

## 横向对比

| | Unity | Godot | Cocos Creator | Phaser / PixiJS |
|---|---|---|---|---|
| 语言 | C# | GDScript / C# | TypeScript | JS / TS |
| 授权 | 按收入分档 | MIT 全免费 | 免费 | MIT |
| 2D 体验 | 一般 | 好 | 好 | 看自己拼 |
| 3D | 强 | 中 | 中 | 弱（配 Three.js） |
| 包体 | 大 | 小 | 小 | 最小 |
| 小游戏渠道 | 需转换插件 | 不成熟 | **原生支持** | 自己接 SDK |
| 主机 | 支持 | 需第三方 | 不支持 | 不支持 |
| 上手 | 中 | 低 | 低（前端友好） | 低（但要造轮子） |
| 生态 | 最大 | 中 | 国内强 | 中 |

## AI 在游戏开发里能帮上什么

按「已经能用的」和「还不靠谱的」分开看：

**能用**：代码补全与重构、Shader/配置表这类模板化代码、概念图与贴图草稿、配音（TTS）、本地化翻译、策划案与数值表初稿。

**谨慎**：直接生成可用 3D 模型与绑定骨骼（重拓扑和绑骨还得人做）、让 LLM 实时驱动 NPC 对话（延迟、成本、跑偏都难控）、AI 生成的素材直接商用（授权与版权归属要逐个确认）。

一个务实的用法：**AI 负责「第一版」，人负责「能上线」**。生成的东西一律当草稿，进项目前要过一遍质量与授权。

## 学习路径

不管选哪个，顺序都是同一套：

1. **最小闭环**：一个角色、一次输入、一次碰撞、一次胜负判定。别一上来做菜单和存档。
2. **资源管线**：图集、音频、字体子集、打包与加载。这一步决定后期会不会崩。
3. **工程化**：场景拆分、状态机、事件总线、配置表外置。

一个能长期维护的结构：

```text
assets/
├── scenes/        启动、关卡、UI
├── scripts/
│   ├── core/      状态机、事件总线、存档
│   ├── gameplay/  角色、敌人、关卡逻辑
│   └── ui/
├── art/           图集、字体、Shader
├── audio/
└── config/        数值表（JSON / CSV，构建时校验）
```

## 坑

- **先做引擎再选引擎**：拿一个能跑通的 Demo 验证渠道，比读十篇对比文有用。微信小游戏尤其——先确认包能过审、能加载。
- **中途换管线**：Unity 换 URP、Cocos 从 2D 换 3D，都是重做级成本，立项时定死。
- **配置写进代码**：数值、关卡、文本全部外置成表。
- **忽略首屏**：网页和小游戏里加载时间就是留存率，包体/图集/音频码率第一天就要管。
- **素材授权**：字体、音乐、贴图的授权范围要看清，商用与小游戏分发常常是两套授权。
