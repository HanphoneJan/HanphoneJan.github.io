# 前端系列导读

> 这一组的顺序不是「从入门到精通」，而是「一个新项目真正会碰到的顺序」：先会说这门语言，再搭工程，再选框架，最后才是各种端和上线。

## 一条线

```text
语言与运行时：HTML / CSS / JS 速查 → CommonJS 与 ES 模块 → TypeScript
                              │
                              ↓
                        浏览器原理（渲染、缓存、事件循环）
                              │
                              ↓
工程化：包管理 → 构建工具 → 浏览器 API 与前端工程（组件库 / PWA / 测试）
                              │
                    ┌─────────┴─────────┐
                    ↓                   ↓
              Vue / React           Node.js（服务端）
                    ↓
              Next.js（SSR / SSG）
                              ↓
端：小程序与 Uniapp · 浏览器扩展与脚本 · Android · 网页里的 2D 与 3D
                              ↓
上线：SEO 排查清单
```

## 和「计算机基础」怎么分工

- **网络与操作系统本身**在 [计算机基础（通用篇）](../计算机基础/导读.md)：TCP、进程、fd 这些概念不绑定浏览器。
- **浏览器这一层**在这里的 [浏览器原理](./浏览器原理.md)：多进程架构、渲染流水线、缓存策略、事件循环——都是浏览器自己加在操作系统之上的东西，换个运行时就不成立（和 Java / Python 两套视角的定位一样，只是这里的运行时是浏览器）。
- **框架与工程**没有对应的「基础篇」，它们是这一行的手艺，只有怎么用和怎么踩坑。

## 三条使用建议

1. **侧边栏按文件名排，不是阅读顺序。** 真正的顺序是上面那张流程图。
2. **不是所有东西都属于 Web。** Qt（C++ 桌面）、Flutter（Dart 跨端）和 Android 原生只是借住在这里，它们和 HTML/CSS/JS 没有继承关系，按需跳读。
3. **体例不统一是正常的。** 有的按主题整理过（构建工具、浏览器原理、SEO），有的是边做边记的（Android、小程序、UI 设计）；`CommonJS 与 ES 模块` 那篇是转载，来源标在开头。
