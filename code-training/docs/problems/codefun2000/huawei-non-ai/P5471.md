# P5471. 时窗巡回最短

> 场次：2026年9月18日-非AI方向 · 来源：[CodeFun2000 P5471](https://codefun2000.com/p/P5471)

## 题目描述

身为快递员，你每天都得离开仓站，把货送到若干客户处。各位客户各自给出可收货时段，货必须落在该时段内交到（早到可以停着等，晚到不行）。货都送完后，还得回到仓站。交通导致任意两处之间的行驶耗时已经给出（正反向未必相同）。请排出一条访问顺序，在所有可收货时段都满足的条件下，让离开仓站直到再次回到仓站所花的时长（把等候也算进去）尽量短。若怎样走都做不到，输出 $-1$。

一共给出 $m$ 处站点，编号写成 $0$ 到 $m-1$，其中 $0$ 处就是仓站。

站点 $p$ 各自对应可到达闭区间 $[lo_p,hi_p]$，意思是抵达该站的时刻必须落在 $lo_p$ 与 $hi_p$ 之间，两端都算合法。

仓站的可作业时段覆盖整天 $[0,1440]$（单位：分钟）。你在时刻 $0$ 离开仓站；途中允许在任意站点停着等（这段等候要算进总时长）。每位客户处必须经过且只经过一次，末了再回到仓站。行驶耗时表 $dur[p][q]$ 给出从站点 $p$ 走到站点 $q$ 要花多少分钟（$dur[p][p]=0$，正反向可以不同）。

请给出尽量短的总时长（也就是再次抵达仓站的那个时刻）；若无可行走法，输出 $-1$。

## 输入格式

首行给出一个整数 $m$（$2\le m\le15$），即站点一共有多少处（仓站也算在内）。

随后连续 $m$ 行，每行两个整数 $lo_p$ 与 $hi_p$（$0\le lo_p\le hi_p\le1440$），对应第 $p$ 处站点的可到达闭区间。

再随后 $m$ 行，每行 $m$ 个整数，构成行驶耗时表 $dur$；第 $p$ 行第 $q$ 列就是从 $p$ 走到 $q$ 的耗时（$0\le dur[p][q]\le1440$）。

## 输出格式

输出一个整数：尽量短的总时长（分钟）。若全部客户处无法按规则走完，输出 $-1$。

## 示例

### 示例 1

**输入：**

```
4
0 1440
6 18
20 45
14 28
0 4 18 8
6 0 9 20
10 12 0 7
9 16 11 0
```

**输出：**

```
36
```

**说明：**

四处站点：仓站 $0$ 的可作业时段 $[0,1440]$，客户 $1$ 为 $[6,18]$，客户 $2$ 为 $[20,45]$，客户 $3$ 为 $[14,28]$。

最优走法 $0\to 1\to 2\to 3\to 0$：

- 去 $1$：耗时 $4$，抵达时刻 $4$，等到 $6$
- 去 $2$：耗时 $9$，抵达时刻 $15$，等到 $20$
- 去 $3$：耗时 $7$，抵达时刻 $27$，落在 $[14,28]$
- 回仓站：耗时 $9$，抵达时刻 $36$

另一条可行走法 $0\to 1\to 3\to 2\to 0$ 会在时刻 $47$ 才回到仓站，更长。故答案为 $36$。

**输出：**

**说明：**

## 解题思路

### 输出的到底是什么：一条闭合行程的结束时刻

题目问的不是「一共开了多少分钟」，而是**再次回到仓站的那个时刻**。把时间轴摊开看：时刻 $0$ 从仓站出发，路上花时间，早到就在客户处等着，最后驶回仓站，抵达仓站的那一刻就是答案。由此有四条判定标准：

- 等候计入总时长。早到客户 $1$ 两分钟就要多花两分钟，它不会凭空消失；
- 每个客户 $1 \sim m-1$ 必须经过且只经过一次，最后必须回到 $0$ 号仓站；
- 抵达任何站点 $p$ 的时刻都要落在闭区间 $[lo_p, hi_p]$ 内，两端都合法。题面给的仓站窗口是 $[0,1440]$，覆盖整天，回程只要不超过 $1440$ 就可收工 —— 代码里最后的 `back <= hi[0]` 就是这一条，行程拖得太长、回程越过 $1440$ 同样算无解；
- 一条合法走法都不存在时输出 $-1$。

于是问题变成：在所有客户的一次排列里，挑出时间窗全部满足的闭合行程，让终点时刻最小。判定一条候选行程只需要沿路把时刻推下去，麻烦之处在于排列太多。

### 为什么是状态压缩 DP：$m \le 15$ 把 $14!$ 压成 $2^{14}$ 个子集

客户最多 $14$ 位。直接枚举访问顺序有 $14! \approx 8.7 \times 10^{10}$ 种排列，每种还要沿路走一遍，任何写法都跑不完。

再看问题结构。一条走法走到中途时，对「后面还能怎么走」有影响的只有两件事：**已经送完了哪些客户**、**此刻停在哪个客户**。至于这些客户是按什么顺序送完的，只在「当前时刻」上留下一个痕迹。于是把「客户集合 + 最后位置」当作状态，集合用二进制位表示：$14$ 位客户共 $2^{14}$ 个子集，每个子集再乘 $14$ 个可能的终点，状态数约 $2.3 \times 10^{5}$。每个状态枚举「下一个送谁」，转移 $O(m)$，总量是 $O(2^{m-1} m^2)$。这就是哈密顿回路式的状压 DP（Held–Karp）。

### 为什么每个状态只留一个时刻：早到支配晚到

同一个「已送集合 + 当前站点」可能有许多到达时刻。若其中两个是 $t_1 < t_2$，那么 $t_1$ 那条走法一定不比 $t_2$ 差：它可以在原地等到 $t_2$ 再出发，把 $t_2$ 之后的所有走法原样复现；反过来 $t_2$ 变不回 $t_1$，因为时间不能倒流。所以**只保留最早时刻不会丢掉任何可行解**，这就是 `dp[mask][u]` 只存一个数的依据。

同一条道理让「等待」也不必枚举：到达客户 $v$ 的时刻是 $arrive$，能做的只有等到 $lo_v$，多停只会把后面越推越晚，于是送达时刻直接取 $\max(arrive, lo_v)$；一旦它超过 $hi_v$，这条转移当场作废。转移函数 $\max(t + dur, lo_v)$ 关于 $t$ 单调不减，也保证了「用更小的 $t$ 出发，得到的新时刻只会更小」，最小化才有意义。

### 四个关键动作在代码里的位置

- **状态与编号**：`dp[mask][u]` 的 $u$ 是客户下标 $0 \sim m-2$，对应站点 `u + 1`。所有耗时表访问都写成 `dur[u + 1][v + 1]`、`dur[0][v + 1]`、`dur[u + 1][0]`，这个偏移是客户编号与站点编号之间的唯一换算。
- **初始化**（`for v in range(nc)`）：从仓站直接开往第一位客户，`t = max(dur[0][v + 1], lo[v + 1])`，超过 `hi[v + 1]` 就不设初值，这一位客户的单元素集合直接不可达。
- **枚举未送客户**（`rest = full ^ mask`）：`full` 是全集，异或取补集；`bit = rest & (-rest)` 取出最低位的 $1$，`v = bit.bit_length() - 1` 还原客户编号，这是状压里标准的「遍历未访问点」写法。
- **收尾**（最后的 `for u in range(nc)`）：`dp[full][u]` 是送完所有客户、停在 $u$ 的最早时刻，加上 `dur[u + 1][0]` 驶回仓站，再与 `lo[0]`、`hi[0]` 核对；若 `ans` 始终是 `INF`，说明没有任何合法走法，输出 `-1`。

## 完整代码实现

```python
"""
P5471. 时窗巡回最短 - 状态压缩动态规划（哈密顿回路 + 时间窗等待）

快递员从仓站（0 号站）出发，把客户 1..m-1 各送一次，最后回到仓站。
到达任何站点 p 的时刻必须落在窗口 [lo_p, hi_p] 内：早到要等到 lo_p（等待计入总时长），
晚到则这条走法作废。求"回到仓站的时刻"的最小值；无合法走法输出 -1。

输入格式：
- 第 1 行：站点数 m（2 <= m <= 15）；
- 接下来 m 行：每行两个整数 lo_p、hi_p（仓站是 [0, 1440]）；
- 再接下来 m 行：耗时表 dur，第 p 行第 q 列为 p -> q 的分钟数。

核心思路：
1. 每位客户只有"送过 / 没送过"两种状态，m-1 位客户共 2^(m-1) 个子集；
   状压 DP 的状态 dp[mask][u] = 送完 mask 里的客户、正停在客户 u 时
   "离开 u 的最早时刻"（即该站的送达时刻，已扣掉必要的等待）。
2. 到达下一个客户 v 时，实际送达时刻 = max(到达时刻, lo_v)；超过 hi_v 就剪掉。
   等待贪心发生在"能等就等到 lo"这一点上：送完一站后立刻下一站的走法里，
   早到的等待全部折算在下一站上，任何多余的滞留只会把后续越推越晚，贪足即最优。
3. 全部客户送完后，从 dp[full][u] 加 dur[u][0] 回仓站，按题面"同样卡 [lo0, hi0]"
   校验回程时刻，取最小；一个合法走法都没有则输出 -1。

时间复杂度：O(2^m * m^2)，m = 15 时约 7.4e5 次转移
空间复杂度：O(2^m * m)
"""

# https://codefun2000.com/p/P5471
import sys

INF = 10 ** 9

# @sample-start
"""
样例输入 1:
4
0 1440
6 18
20 45
14 28
0 4 18 8
6 0 9 20
10 12 0 7
9 16 11 0

样例输出 1:
36
"""
# @sample-end

# @sample-start
"""
样例输入 2:
4
0 1440
5 12
5 12
5 12
0 4 4 4
4 0 10 10
4 10 0 10
4 10 10 0

样例输出 2:
-1
"""
# @sample-end


def solve():
    data = sys.stdin.buffer.read().split()
    it = iter(data)
    m = int(next(it))

    lo = [0] * m
    hi = [0] * m
    for p in range(m):
        lo[p] = int(next(it))
        hi[p] = int(next(it))

    # dur[p][q]：从站点 p 到站点 q 的行驶分钟数，正反向未必相同
    dur = [[int(next(it)) for _ in range(m)] for _ in range(m)]

    nc = m - 1  # 客户数（站点 1..m-1）
    full = (1 << nc) - 1

    # dp[mask][u]：送完 mask 的客户、停在客户 u（站点 u+1）时的最早离开时刻。
    # 存的是"送达时刻"（早到已等到 lo），它是后续所有转移的唯一时间基准。
    dp = [[INF] * nc for _ in range(1 << nc)]

    # 起点：时刻 0 从仓站出发，直接驶向第一个客户
    for v in range(nc):
        t = max(dur[0][v + 1], lo[v + 1])
        if t <= hi[v + 1]:
            dp[1 << v][v] = t

    for mask in range(1 << nc):
        row = dp[mask]
        for u in range(nc):
            t0 = row[u]
            if t0 >= INF:
                continue
            # 枚举还没送的客户 v（取 mask 的补集里逐个低位）
            rest = full ^ mask
            while rest:
                bit = rest & (-rest)
                rest ^= bit
                v = bit.bit_length() - 1
                t = max(t0 + dur[u + 1][v + 1], lo[v + 1])
                if t <= hi[v + 1] and t < dp[mask | bit][v]:
                    dp[mask | bit][v] = t

    # 回到仓站：回程时刻同样要落在仓站窗口 [lo[0], hi[0]] 内
    ans = INF
    for u in range(nc):
        if dp[full][u] < INF:
            back = max(dp[full][u] + dur[u + 1][0], lo[0])
            if back <= hi[0] and back < ans:
                ans = back

    sys.stdout.write(str(ans if ans < INF else -1) + "\n")


def run_tests():
    """运行嵌入的官方样例与补充用例，方便本地自测。"""
    test_cases = [
        # 官方样例 1：最优 0->1->2->3->0，含两次等待，回程 36
        (
            "4\n0 1440\n6 18\n20 45\n14 28\n0 4 18 8\n6 0 9 20\n10 12 0 7\n9 16 11 0\n",
            "36",
        ),
        # 官方样例 2：客户互走 10 分钟必超窗，所有排列都不可行
        (
            "4\n0 1440\n5 12\n5 12\n5 12\n0 4 4 4\n4 0 10 10\n4 10 0 10\n4 10 10 0\n",
            "-1",
        ),
        # 最小规模 m=2：单客户送达后立即返回
        (
            "2\n0 1440\n3 9\n0 5\n5 0\n",
            "10",
        ),
        # 等候算进总时长：到得早必须停到 lo
        (
            "2\n0 1440\n5 10\n2 3\n3 2\n",
            "8",
        ),
        # 送达没问题但回到仓站超出仓站窗口上界 1440 -> 无可行走法
        (
            "2\n0 1440\n0 1440\n0 200\n1400 0\n",
            "-1",
        ),
        # 正反向耗时不同：0->1->2->0（6 分钟）远优于 0->2->1->0（27 分钟）
        (
            "3\n0 1440\n0 1440\n0 1440\n0 2 9\n9 0 2\n2 9 0\n",
            "6",
        ),
        # 时间窗把顺序卡死：先送窗口早关的客户 1，再等客户 2 的窗口开启
        (
            "3\n0 1440\n0 6\n10 30\n0 1 5\n1 0 2\n5 2 0\n",
            "15",
        ),
    ]

    for i, (inp, expected) in enumerate(test_cases, 1):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io_text(inp)
        sys.stdout = io_string()
        try:
            solve()
            output = sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout
        status = "✓" if output == expected else "✗"
        print(f"样例 {i}: 期望={expected}, 实际={output} {status}")

    # 随机小规模对拍：状压 DP 结果必须与全排列暴力一致
    import random
    from itertools import permutations

    rng = random.Random(20260918)
    for case in range(60):
        m = rng.randint(2, 8)
        lo = [0] + [rng.randint(0, 30) for _ in range(m - 1)]
        hi = [1440] + [lo[k] + rng.randint(0, 40) for k in range(1, m)]
        dur = [[0] * m for _ in range(m)]
        for a in range(m):
            for b in range(m):
                if a != b:
                    dur[a][b] = rng.randint(1, 7)

        def brute():
            best = INF
            for perm in permutations(range(1, m)):
                t = 0
                prev = 0
                ok = True
                for v in perm:
                    t = max(t + dur[prev][v], lo[v])
                    if t > hi[v]:
                        ok = False
                        break
                    prev = v
                if ok:
                    back = max(t + dur[prev][0], lo[0])
                    if back <= hi[0]:
                        best = min(best, back)
            return -1 if best >= INF else best

        def fast(lo, hi, dur, m):
            nc = m - 1
            full = (1 << nc) - 1
            dp = [[INF] * nc for _ in range(1 << nc)]
            for v in range(nc):
                t = max(dur[0][v + 1], lo[v + 1])
                if t <= hi[v + 1]:
                    dp[1 << v][v] = t
            for mask in range(1 << nc):
                row = dp[mask]
                for u in range(nc):
                    t0 = row[u]
                    if t0 >= INF:
                        continue
                    rest = full ^ mask
                    while rest:
                        bit = rest & (-rest)
                        rest ^= bit
                        v = bit.bit_length() - 1
                        t = max(t0 + dur[u + 1][v + 1], lo[v + 1])
                        if t <= hi[v + 1] and t < dp[mask | bit][v]:
                            dp[mask | bit][v] = t
            ans = INF
            for u in range(nc):
                if dp[full][u] < INF:
                    back = max(dp[full][u] + dur[u + 1][0], lo[0])
                    if back <= hi[0]:
                        ans = min(ans, back)
            return -1 if ans >= INF else ans

        got = fast(lo, hi, dur, m)
        want = brute()
        if got != want:
            print(f"对拍失败 case {case}: 期望={want}, 实际={got}")
            print(f"m={m}\nlo/hi={list(zip(lo, hi))}")
            for r in dur:
                print(r)
            return
    print("对拍: 60 组随机用例与全排列暴力一致 ✓")


def io_text(s):
    import io

    return io.TextIOWrapper(io.BytesIO(s.encode("utf-8")))


def io_string():
    import io

    return io.StringIO()


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

以官方样例 1 为例：$m = 4$，仓站 $0$ 的窗口是 $[0,1440]$，客户 $1,2,3$ 的窗口分别是 $[6,18]$、$[20,45]$、$[14,28]$，耗时表为

| $dur$ | 去 0 | 去 1 | 去 2 | 去 3 |
| --- | --- | --- | --- | --- |
| 从 0 | 0 | 4 | 18 | 8 |
| 从 1 | 6 | 0 | 9 | 20 |
| 从 2 | 10 | 12 | 0 | 7 |
| 从 3 | 9 | 16 | 11 | 0 |

客户 $1,2,3$ 依次对应二进制位 $0,1,2$，全集 `full = 0b111`。

**初始化：时刻 $0$ 从仓站直接出发**

- 去客户 $1$：耗时 $4$，$4 < 6$，等到 $6$，$6 \le 18$ ✓，`dp[001][客户1] = 6`
- 去客户 $2$：耗时 $18$，$18 < 20$，等到 $20$，$20 \le 45$ ✓，`dp[010][客户2] = 20`
- 去客户 $3$：耗时 $8$，$8 < 14$，等到 $14$，$14 \le 28$ ✓，`dp[100][客户3] = 14`

**两个客户的集合**

- 从 `001`（停在客户 1，$t = 6$）：
  - 去客户 2：$6 + 9 = 15$，等到 $20$，$20 \le 45$ ✓ → `dp[011][客户2] = 20`
  - 去客户 3：$6 + 20 = 26$，$26 \le 28$ ✓ → `dp[101][客户3] = 26`
- 从 `010`（停在客户 2，$t = 20$）：
  - 去客户 1：$20 + 12 = 32 > 18$ ✗，客户 1 的窗口已经关了
  - 去客户 3：$20 + 7 = 27 \le 28$ ✓ → `dp[110][客户3] = 27`
- 从 `100`（停在客户 3，$t = 14$）：
  - 去客户 1：$14 + 16 = 30 > 18$ ✗
  - 去客户 2：$14 + 11 = 25$，$25 \ge 20$ 不必等，$25 \le 45$ ✓ → `dp[110][客户2] = 25`

同一个集合 `110` 下有两个格子，分别对应两条不同的行程：停在客户 2 的那条是 $0 \to 3 \to 2$（$t = 25$），停在客户 3 的那条是 $0 \to 2 \to 3$（$t = 27$）。它们互不覆盖，因为下一步从哪个客户出发，耗时完全不同。

**三个客户全送完**

- 从 `011`（停在客户 2，$t = 20$）→ 客户 3：$20 + 7 = 27 \le 28$ ✓ → `dp[111][客户3] = 27`
- 从 `101`（停在客户 3，$t = 26$）→ 客户 2：$26 + 11 = 37 \le 45$ ✓ → `dp[111][客户2] = 37`
- 从 `110`（停在客户 2，$t = 25$）→ 客户 1：$25 + 12 = 37 > 18$ ✗
- 从 `110`（停在客户 3，$t = 27$）→ 客户 1：$27 + 16 = 43 > 18$ ✗

客户 1 的窗口 $[6,18]$ 窄到只允许它排在行程最前面，所以能走完的排列只剩两条。

**回仓站**

- 停在客户 2（$t = 37$）：$37 + 10 = 47$，$47 \le 1440$ ✓，候选 $47$
- 停在客户 3（$t = 27$）：$27 + 9 = 36$，$36 \le 1440$ ✓，候选 $36$

取较小者得 $36$，与官方输出一致。对应行程是 $0 \to 1 \to 2 \to 3 \to 0$：纯行驶 $4 + 9 + 7 + 9 = 29$ 分钟，在客户 1 处等 $6 - 4 = 2$ 分钟，在客户 2 处等 $20 - 15 = 5$ 分钟，$29 + 2 + 5 = 36$。题面说明里提到的另一条 $0 \to 1 \to 3 \to 2 \to 0$ 正是上表的 $47$。

样例 2 的失败也能从同一张表读出来：三位客户的窗口都是 $[5,12]$，从仓站到任意客户耗时 $4$，第一位最早在时刻 $5$ 送达；客户之间互走要 $10$ 分钟，第二位最早 $5 + 10 = 15 > 12$。第二层转移全部被 `hi` 卡掉，`dp` 永远到不了 `full`，`ans` 保持 `INF`，输出 `-1`。

## 易错点总结

### 1. 初始化漏掉「等到 $lo$」

第 92 行 `t = max(dur[0][v + 1], lo[v + 1])` 里的 `max` 一旦退化成只取 `dur[0][v + 1]`，早到就被当成已经送达，等待时间凭空消失。代码自带的第 4 组用例（客户窗口 $[5,10]$，$0 \to 1$ 耗时 $3$，$1 \to 0$ 耗时 $3$）期望 `8`，漏掉等待会输出 `6`。

### 2. 闭区间判定写成开区间

第 93 行、第 109 行、第 117 行的 `<=` 都在比较窗口上界，窗口两端都合法，写成 `<` 就会把「卡着上界抵达」的行程判成非法。把客户窗口取成 $lo = hi = 5$（输入 `2 / 0 1440 / 5 5 / 2 3 / 3 2`）时，时刻 $5$ 送达完全合法、期望输出 `8`，改成 `<` 后整题输出 `-1`。

### 3. 客户下标与站点下标之间的 `+1`

第 108 行的 `dur[u + 1][v + 1]`、第 116 行的 `dur[u + 1][0]` 把客户编号换算成站点编号。若照抄成 `dur[u][v]`、`dur[u][0]`，读到的是整张表错位的格子（客户 1 自己到自己的 $0$ 被当成 $0 \to 1$ 的耗时），样例 1 的正确输出 `36` 会变成 `42`，而且不会抛任何异常。

## 扩展思考

本题的状压只存一个时刻，靠的是「早到可以等」。若规则改成「必须准点到达、不许等候」，早到反而非法，同一组 $(mask, u)$ 就得保留若干个互不支配的时间点，`dp` 的值不再是一个整数。另一处可换的目标是「最多能送多少客户」：此时时间仍然是必须保留的维度，但更新准则从「取更早」变成「取送得更多」。
