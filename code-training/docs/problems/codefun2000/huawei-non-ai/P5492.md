# P5492. 代码总量回落

> 场次：2026年10月22日-非AI方向 · 来源：[CodeFun2000 P5492](https://codefun2000.com/p/P5492)

> 题面为 CodeFun2000 会员内容，本文依据官方题解与公开信息整理；输入输出格式以原题为准，示例为说明性示例。

## 题目描述

有一份按天记录的代码总量，第 $i$ 天的总量存在 `loads[i]` 里（$i$ 从 0 开始）。

任选两天 $p < q$，把这两天的总量之差 `loads[p] - loads[q]` 称为**回落幅度**。请在所有满足 $p < q$ 的日期对里，求回落幅度的最大值。

若整份记录从未下降（即所有 $p<q$ 都满足 `loads[p] <= loads[q]`），返回 0。

## 输入格式

本题按**接口形式**作答，不读标准输入：实现类 `Solution` 的方法 `maxLoadDrop(self, loads: List[int]) -> int`，判题程序构造一个 `Solution` 实例并把 `loads` 传进去。

- `loads`：一个整数数组，长度记为 $n$，按天的顺序排列。

## 输出格式

返回一个整数，即所有 $p<q$ 的 `loads[p] - loads[q]` 里的最大值；没有回落时返回 0（因此结果一定非负）。

## 示例

### 示例 1

**输入：**

```
loads = [7,1,5,3,6,4]
```

**输出：**

```
6
```

### 示例 2

**输入：**

```
loads = [1,2,3]
```

**输出：**

```
0
```

## 解题思路

### 判定对象是「一对有序的日子」，不是两个数

这题要最大化的不是「数组里最大的数减最小的数」，而是**先出现的那天减后出现的那天**。$p$ 必须更早，$q$ 必须更晚，两个数的位置被绑死了。

位置约束不是形式上的。`loads = [2,1,5,4]` 里最大是 5、最小是 1，相减得 4；但 1 在下标 1、5 在下标 2，$p<q$ 反了，这一对根本不合法。六个合法数对之差分别是 $2-1=1$、$2-5=-3$、$2-4=-2$、$1-5=-4$、$1-4=-3$、$5-4=1$，最大值是 1。那个 5 是中途冒出来的新高，它左边没有任何比它大的值可以让它「回落」，于是它对答案毫无贡献——「最大减最小」把这种位置关系整个忽略了。

所以问题要换个问法：**扫到某个 $q$ 时，$p$ 选谁最好？**

### 走到 $q$ 时，$p$ 的最佳选择就是「之前见过的最大值」

固定 $q$，$p$ 只能在 $[0, q-1]$ 里挑。让 `loads[p] - loads[q]` 最大等价于让 `loads[p]` 最大——$q$ 那项与 $p$ 无关。所以每个位置只需要知道一件事：**它左边（不含自己）出现过的最大值**，记作 `peak`。

这就把 $O(n^2)$ 的对枚举压成了一次扫描：从左往右走，走到 $q$ 时先拿 `peak - loads[q]` 更新答案，再把 `loads[q]` 并进 `peak`。先算后更新这个顺序，保证参与减法的一定是严格更早的元素。

```python
from typing import List


class Solution:
    def maxLoadDrop(self, loads: List[int]) -> int:
        peak = loads[0]        # 已经扫过的前缀最大值
        best = 0               # 不下降时答案就是 0
        for q in range(1, len(loads)):
            # 此刻的 peak 来自 [0, q-1]，满足 p < q
            if peak - loads[q] > best:
                best = peak - loads[q]
            # 把当前值并进前缀最大值，供后面的日子使用
            if loads[q] > peak:
                peak = loads[q]
        return best
```

三行关键动作各自对应一个判定：

- `peak = loads[0]` 与 `range(1, len(loads))`：第 0 天自己没有左边的日子，只能当 `p` 的候选，不能当 `q`，所以循环从 1 开始；
- `best = 0`：题面把答案定义成非负，回落幅度全为负时（记录单调上升）答案取 0，用 0 当初值就同时覆盖了「全部相等」和「完全上升」两种情形；
- 「先算差、再更新 `peak`」：如果反过来先更新，`peak` 可能变成 `loads[q]` 自己，减法就成了 $0$，等价于允许 $p=q$。对本题的答案没有影响（0 本来就在取值范围内），但它悄悄抹掉了「必须严格更早」这条约束。

### 为什么不需要更多状态

目标是 $\max_{p<q}\big(loads[p]-loads[q]\big)$，它的「最优子结构」很薄：每个位置只依赖一个数（左侧最大值），没有区间长度、没有次数限制、没有第二条边。这类结构适合一次扫描、常数个变量，`peak` 与 `best` 从 0 号位推到末尾就完事，不需要 DP 表，也不需要排序——排序反而会把「谁在前」这个唯一的约束破坏掉。

## 完整代码实现

```python
from typing import List


class Solution:
    def maxLoadDrop(self, loads: List[int]) -> int:
        peak = loads[0]        # 已经扫过的前缀最大值
        best = 0               # 不下降时答案就是 0
        for q in range(1, len(loads)):
            # 此刻的 peak 来自 [0, q-1]，满足 p < q
            if peak - loads[q] > best:
                best = peak - loads[q]
            # 把当前值并进前缀最大值，供后面的日子使用
            if loads[q] > peak:
                peak = loads[q]
        return best
```

## 示例推演

### 示例 1：`loads = [7,1,5,3,6,4]`

`peak` 初值取 `loads[0] = 7`，`best` 初值 0。

| $q$ | `loads[q]` | `peak`（更新前） | 候选 $peak - loads[q]$ | `best` | `peak`（更新后） |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 7 | 6 | 6 | 7 |
| 2 | 5 | 7 | 2 | 6 | 7 |
| 3 | 3 | 7 | 4 | 6 | 7 |
| 4 | 6 | 7 | 1 | 6 | 7 |
| 5 | 4 | 7 | 3 | 6 | 7 |

`peak` 之后一直是 7（后面没有再超过它），最大候选出现在 $q=1$，答案 6，对应第 0 天的 7 回落到第 1 天的 1。

注意 $q=2$ 的候选也值得一看：拿 7 减 5 得 2，而拿 1 减 5 得 $-4$。同一个 $q$ 上，`p` 选得越靠左、数值越大越有利——这正是「只需前缀最大值」的直观形态。

### 示例 2：`loads = [1,2,3]`

| $q$ | `loads[q]` | `peak`（更新前） | 候选 | `best` | `peak`（更新后） |
| --- | --- | --- | --- | --- | --- |
| 1 | 2 | 1 | -1 | 0 | 2 |
| 2 | 3 | 2 | -1 | 0 | 3 |

两个候选都是负数，`best` 保持在初值 0，返回 0。

## 复杂度分析

$n$ 为 `loads` 的长度。

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 枚举所有 $p<q$ 的数对 | $O(n^2)$ | $O(1)$ | 两层循环直接比，$n$ 到 $10^5$ 时约 $5\times10^9$ 对，跑不完 |
| 前缀最大值一次扫描（最优） | $O(n)$ | $O(1)$ | 每个位置只做一次减法与一次比较，`peak`、`best` 两个变量 |

## 易错点总结

### 1. 用「全局最大减全局最小」代替扫描

把扫描整段删掉、写成 `return max(loads) - min(loads)`，只在最小值恰好在最大值右边时才对。`loads = [2,1,5,4]` 会返回 $5-1=4$，而合法答案是 $2-1=1$：5 在下标 2，1 在下标 1，顺序反了。这类错误不会报错、也不会越界，只是答案偏大，且越是有「后期新高」的数据偏得越多。

### 2. 把 `peak` 无条件覆盖成当前值

把循环里那个 `if loads[q] > peak:` 写成无条件的 `peak = loads[q]`，历史最大值就丢了。`loads = [10,5,9,1]` 上：$q=1$ 用 10 减 5 得 5、`peak` 变成 5；$q=2$ 的 9 把 `peak` 抬到 9；$q=3$ 得 $9-1=8$，返回 8。正确答案是 $10-1=9$——那个 10 在第 1 步就被覆盖了。现象是答案偏小，而且只在「先出现峰值、中间夹一个较小值、末尾再跌」的输入上才暴露。
