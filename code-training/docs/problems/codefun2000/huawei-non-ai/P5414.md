# P5414. 奖励清单：最优四件礼品组合

> 场次：2026年9月9日-非AI方向 · 来源：[CodeFun2000 P5414](https://codefun2000.com/p/P5414)

## 题目描述

小华因为过去一年的突出表现，被部门树为标杆员工，主管决定允许他在一份礼品清单中挑选**恰好四件**作为奖励。清单中的每一件礼品都有唯一的编号和一个售价，不同礼品的售价可能相同。小华选出的四件礼品，其售价之和不能超过 `10000` 元。

他在选择时首先考虑让四件礼品的总售价尽可能接近 `10000` 元，有多种选法的时候他会选择排序后字典序最小的编号序列。

约束条件
- 清单中的礼品件数 $m$ 至少为 `1`，最多为 `2000`。
- 每件礼品的编号 $b_i$ 和售价 $w_i$ 均为不超过 `10000` 的正整数。

## 输入格式

第一行包含一个整数 $m$，表示礼品清单中的礼品件数。
接下来 $m$ 行，每行包含两个以空格分隔的整数 $b_i$ 和 $w_i$，分别表示某件礼品的编号和售价。

## 输出格式

如果不存在合法的四件礼品组合，输出 `0`。
否则，输出四个整数，表示所选四件礼品的编号；这些编号必须按升序排列，并用单个空格分隔。

## 示例

### 示例 1

**输入：**

```
3
1 100
2 200
3 300
```

**输出：**

```
0
```

**说明：**

清单中只有 `3` 件礼品，少于需要的 `4` 件。

因此不存在任何合法的四件组合，输出 `0`。

### 示例 2

**输入：**

```
4
10 1000
20 2000
30 3000
40 4000
```

**输出：**

```
10 20 30 40
```

**说明：**

清单中恰有 `4` 件礼品，因此只能将这四件全部选出。

总售价为 $1000+2000+3000+4000=10000$，没有超过预算 `10000`，所以编号升序输出为 `10 20 30 40`。

### 示例 3

**输入：**

```
5
1 2000
2 2000
3 2000
4 2000
5 2000
```

**输出：**

```
1 2 3 4
```

**说明：**

清单中共有 `5` 件礼品，任意选取 `4` 件时，由于每件售价均为 `2000`，总售价都是 $2000+2000+2000+2000=8000$。

这个总售价不超过预算 `10000`。所有组合的总售价相同，因此比较编号升序后的字典序；排除编号 `5` 后的 `[1,2,3,4]` 字典序最小，所以输出 `1 2 3 4`。

### 示例 4

**输入：**

```
6
1 3000
2 3000
3 3000
4 3000
5 1000
6 1000
```

**输出：**

```
1 2 3 5
```

**说明：**

四件售价均为 `3000` 的礼品总价为 $3000+3000+3000+3000=12000$，超过预算 `10000`，不合法。

可行的最高总价来自三件售价 `3000` 的礼品加一件售价 `1000` 的礼品`[1,2,3,5]`，总价为 $3000+3000+3000+1000=10000$。

## 解题思路

### 双级判定标准先把输出钉死

题面要求两种情况的特殊输出：件数不足 4、或任何四件组合总价都超过 10000，都输出 `0`。正常情况输出四个编号，判定标准是两级字典序：总价最接近 10000（在不超过 10000 的前提下最大）的组合优先；总价并列时，「编号升序排列后」字典序最小的组合胜出。样例 3 里五件全是 2000 元，所有四件组合总价都是 8000，胜负完全落在字典序上——输出不是「随便一组可达总价」，这决定了下面的搜索顺序必须天然按编号递增进行。

### 数据范围把枚举排除、把总价集合请进来

`m <= 2000` 时四件组合约 `C(2000,4) ≈ 2.7e12` 个，逐个枚举必挂。换一个视角：售价 `w_i <= 10000` 且总价上限 10000，所以「可达总价」是 `0..10000` 这个很小的值域上的一个集合。恰好四件能凑出的总价集合，可以用大整数的第 `v` 位表示「总价 v 可达」，逐件转移 `集合 |= 前缀集合 << w`——这正是 01 背包「记可行性」的位掩码写法，只是它同时要回答**区间到区间的查询**，所以按「后缀」再建一遍。

### 贪心为什么能还原字典序最小的方案

记四件总价的最优值为 `S*`（可达集合不超过 10000 的最高位）。贪心按编号从小到大逐位确定答案，循环不变量是：已选前缀用了 `s` 元，还需 `r` 件，且它们全部来自编号比上一件大的后缀。第 k 步在候选里挑第一个满足下式的 `c`：

$$s + w_c + \text{remain\_best} == S^*$$

其中 `remain_best` 是「从 c 之后的后缀恰好选 `r-1` 件、总价不超过剩余预算」的最大总价。比 `c` 小的候选都被逐一证伪（要么选了它剩余预算凑不出合法总价，要么剩余件数不够），所以选中 `c` 后最优总价仍是 `S*`，且答案是逐位最小化的。

### 到实现上的映射

- `suffix1/suffix2/suffix3[k]`：倒序扫一遍编号建出的「从下标 k 起恰好选 1/2/3 件」的可达总价集合。转移取 `suffix1[k+1] << w` 而不是 `suffix1[k] << w`——其余件必须来自 `k` 之后的后缀，同一件不能被算两次。
- `best(mask, cap)`：把掩码截到 `0..cap` 位后取 `bit_length()-1`，一次大整数按位与就回答「不超过预算的最大总价」。候选超支时靠显式的 `left_need < 0` 分支挡住，否则 `-1 == -1` 的巧合会把超支方案放过。
- 恰好四件的全局集合由 `best4 |= suffix3[k+1] << w` 拼出，最高不超过预算的位就是 `S*`；集合为空说明四件任意组合都超预算，输出 0。

## 完整代码实现

```python
"""
P5414. 奖励清单：最优四件礼品组合 - 位掩码后缀背包 + 按编号贪心

题面要点：
- 从 m 件礼品（唯一编号 b_i、售价 w_i）中恰好挑 4 件，总价不超过 10000。
- 双级判定标准：先让总价尽可能大（接近 10000）；总价并列时，取
  「编号升序排列后」字典序最小的组合，输出这 4 个编号。
- m < 4，或任何 4 件组合的总价都超过 10000 时，输出 0。

输入格式：
- 第 1 行：m（1 <= m <= 2000）；
- 接下来 m 行：每行两个整数 b_i、w_i（均 <= 10000，编号互不相同）。

输出格式：合法组合的 4 个编号（升序、空格分隔）；不存在则输出 0。

核心思路（为什么不用背包 DP 而用位掩码）：
1. 双级判定标准决定了「只记录可达总价集合」就够：最优总价 S* 是
   「恰好 4 件、总价 <= 10000」可达总价里的最大值，不需要 O(m^4) 枚举
   也无需记方案——方案由后面的贪心重建。
2. 贪心按编号从小到大逐位确定答案，不变量是「已选前缀用了 s 元，
   还需 r 件，全部来自编号比上一件大的后缀」。在候选里挑第一个 c 使
       s + w_c + remain_best == S*
   其中 remain_best 是「从 c 之后的后缀恰好选 r-1 件、总价不超过剩余
   预算」的最大总价。若这样的 c 存在，最优解里下一件就取 c：
   更小的 c 都已被检查并证伪，取 c 后复合不变量仍然成立。
3. remain_best 与 S* 都靠位掩码一次算好：把「总价 v 可达」编码成
   大整数的第 v 位。倒序扫一遍编号得到 suffix1/suffix2/suffix3[k]，
   分别是「从下标 k 起恰好选 1/2/3 件能达到的总价集合」；恰好 4 件的
   全局集合由 suffix3 拼出。把不超过预算的位段截出来读最高位，就是
   「不超过预算的最大总价」。C(2000,4) ~ 2.7e12 的枚举被压成
   几千次大整数移位，Python 里毫秒级完成。

时间复杂度：O(m * W / 64)（W = 10000 位宽，大整数按机器字并行运算）
空间复杂度：O(m * W / 64)
"""

# https://codefun2000.com/p/P5414
import sys

BUDGET = 10000

# @sample-start
"""
样例输入 1:
3
1 100
2 200
3 300

样例输出 1:
0
"""
# @sample-end

# @sample-start
"""
样例输入 2:
4
10 1000
20 2000
30 3000
40 4000

样例输出 2:
10 20 30 40
"""
# @sample-end

# @sample-start
"""
样例输入 3:
5
1 2000
2 2000
3 2000
4 2000
5 2000

样例输出 3:
1 2 3 4
"""
# @sample-end

# @sample-start
"""
样例输入 4:
6
1 3000
2 3000
3 3000
4 3000
5 1000
6 1000

样例输出 4:
1 2 3 5
"""
# @sample-end


def solve():
    """输出最优四件组合的编号，或 0。"""
    data = sys.stdin.buffer.read().split()
    if not data:
        print(0)
        return
    it = iter(data)
    m = int(next(it))
    # 按编号升序排好，答案序列天然是升序，贪心扫描的顺序就是字典序。
    items = sorted((int(next(it)), int(next(it))) for _ in range(m))
    ids = [b for b, _ in items]
    prices = [w for _, w in items]
    n = len(items)
    if n < 4:
        print(0)
        return

    # 只保留 0..BUDGET 这些位——总价一旦超过预算就没有意义。
    cap_mask = (1 << (BUDGET + 1)) - 1

    # suffix_k[k]：从下标 k 起（编号更大的剩余部分）恰好选 k 件
    # 能达到的总价集合。把下标 k 自己作为「其中一件」时，其余件来自
    # k+1 之前算好的后缀，天然保证四件互不相同。
    suffix1 = [0] * (n + 1)
    suffix2 = [0] * (n + 1)
    suffix3 = [0] * (n + 1)
    best4 = 0
    for k in range(n - 1, -1, -1):
        w = prices[k]
        suffix1[k] = suffix1[k + 1] | (1 << w)
        suffix2[k] = suffix2[k + 1] | (suffix1[k + 1] << w)
        suffix3[k] = suffix3[k + 1] | (suffix2[k + 1] << w)
        # 下标 k 作第一件，剩下三件取自 k+1 之后的后缀：恰好四件的集合。
        best4 |= suffix3[k + 1] << w

    # 不超过预算的最高可达总价；空集时 bit_length 得 0，target <= 0 即无解。
    target = (best4 & cap_mask).bit_length() - 1
    if target <= 0:
        print(0)
        return

    def best(mask, cap):
        """mask 里不超过 cap 的最高总价；返回 -1 表示没有可行总价。"""
        return (mask & ((1 << (cap + 1)) - 1)).bit_length() - 1

    # 贪心逐位确定答案：used 是已选总价，remaining 是还要选的件数，
    # pos 之后的后缀是候选来源（编号都比上一件大）。
    chosen = []
    used = 0
    pos = 0
    remaining = 4
    while remaining:
        picked = False
        for c in range(pos, n):
            new_used = used + prices[c]
            if new_used > BUDGET:
                continue
            left_need = target - new_used
            if left_need < 0:
                continue
            need = remaining - 1
            if need == 0:
                # 最后一件：总价必须正好落在 S* 上。
                if new_used != target:
                    continue
            else:
                # 再从 c 之后选 need 件，其不超过剩余预算的最大总价
                # 必须正好补到 S*——差一点都不行。
                extra = best((suffix3, suffix2, suffix1)[3 - need][c + 1], left_need)
                if extra != left_need:
                    continue
            chosen.append(ids[c])
            used = new_used
            pos = c + 1
            remaining -= 1
            picked = True
            break
        if not picked:
            # 不变量保证上方总能找到一件；走到这里只可能是防御性路径。
            print(0)
            return
    print(" ".join(map(str, chosen)))


def run_tests():
    """运行嵌入的官方样例与自加用例，方便本地自测。"""
    import io
    import itertools
    import random

    def run(stdin_text):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        # solve() 用 sys.stdin.buffer 快速读取，这里提供带 buffer 的文本流。
        sys.stdin = io.TextIOWrapper(io.BytesIO(stdin_text.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            return sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout

    test_cases = [
        # 官方样例 1：件数不足 4
        ("3\n1 100\n2 200\n3 300\n", "0"),
        # 官方样例 2：恰好 4 件全选，总价正好 10000
        ("4\n10 1000\n20 2000\n30 3000\n40 4000\n", "10 20 30 40"),
        # 官方样例 3：总价全部并列时取编号字典序最小的组合
        ("5\n1 2000\n2 2000\n3 2000\n4 2000\n5 2000\n", "1 2 3 4"),
        # 官方样例 4：四件 3000 超预算，改取三 3000 + 一 1000
        ("6\n1 3000\n2 3000\n3 3000\n4 3000\n5 1000\n6 1000\n", "1 2 3 5"),
        # 恰好 4 件但总价 12000 超预算：任何组合都含全部 4 件，无解
        ("4\n1 3000\n2 3000\n3 3000\n4 3000\n", "0"),
        # 件数够但小编号是 9000 的大件：第一件就必须跳过它，
        # 选 3000+3000+2000+1000 = 9000，输出字典序为 2 3 4 5
        ("5\n1 9000\n2 3000\n3 3000\n4 2000\n5 1000\n", "2 3 4 5"),
    ]

    failures = 0
    for i, (inp, expected) in enumerate(test_cases, 1):
        output = run(inp)
        ok = output == expected
        if not ok:
            failures += 1
        print(f"样例 {i}: 期望={expected}, 实际={output} {'✓' if ok else '✗'}")

    # 随机对照（小规模）：与 C(m,4) 全枚举取「总价最大、字典序最小」的
    # 暴力比对 150 组，覆盖编号乱序、总价打平等贪心容易写错的分支。
    rng = random.Random(20260909)
    rand_bad = 0
    for _ in range(150):
        m = rng.randint(1, 9)
        id_list = rng.sample(range(1, 100), m)
        price_list = [rng.randint(1, 4000) for _ in range(m)]
        inp = f"{m}\n" + "\n".join(
            f"{b} {w}" for b, w in zip(id_list, price_list)
        ) + "\n"
        items = sorted(zip(id_list, price_list))
        best_sum, best_seq = 0, None
        for combo in itertools.combinations(range(m), 4):
            s = sum(items[i][1] for i in combo)
            if s <= BUDGET and s > best_sum:
                best_sum, best_seq = s, [items[i][0] for i in combo]
        expected = "0" if best_seq is None else " ".join(map(str, best_seq))
        output = run(inp)
        if output != expected:
            rand_bad += 1
            print(f"随机对照失败: 输入={inp!r} 期望={expected} 实际={output}")
    if rand_bad == 0:
        print("随机对照 150 组: 全部一致 ✓")
    failures += rand_bad

    # 极端规模：m=2000 必须瞬时跑完且输出格式为 4 个整数（方法可行性）。
    big = "2000\n" + "\n".join(
        f"{i} {(i * 37) % 10000 + 1}" for i in range(1, 2001)
    ) + "\n"
    output = run(big)
    parts = output.split()
    if len(parts) == 4 and all(p.isdigit() for p in parts):
        print(f"规模 2000: 输出 {output} ✓")
    else:
        failures += 1
        print(f"规模 2000: 输出格式异常 {output!r} ✗")

    if failures:
        raise SystemExit(1)


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

以官方样例 4 为例，六件礼品的售价按编号排好是 `[3000, 3000, 3000, 3000, 1000, 1000]`，预算 10000。恰好四件的可达总价集合里不超过 10000 的最高总价 `S* = 10000`（三件 3000 加一件 1000）。

逐位贪心：

| 步骤 | 已用 s | 还需 | 候选 c | remain_best 查询 | 结论 |
| ---- | ------ | ---- | ------ | ---------------- | ---- |
| 1 | 0 | 4 | 编号1（3000） | 后缀 {3000×3, 1000×2} 里选 3 件 ≤ 7000 的最大值 = 7000 | 0+3000+7000 = 10000，选中 |
| 2 | 3000 | 3 | 编号2（3000） | 后缀 {3000,3000,1000,1000} 里选 2 件 ≤ 4000 的最大值 = 4000 | 6000+4000 = 10000，选中 |
| 3 | 6000 | 2 | 编号3（3000） | 后缀 {3000,1000,1000} 里选 1 件 ≤ 1000 的最大值 = 1000 | 9000+1000 = 10000，选中 |
| 4 | 9000 | 1 | 编号4（3000） | 剩余预算 1000 < 3000，跳过 | 不选 |
| 4 | 9000 | 1 | 编号5（1000） | 9000+1000 = 10000 | 最后一件，命中 |

输出 `1 2 3 5`，与官方一致。第 4 步是贪心的关键动作：编号 4 同样让「剩余三件合法」，但它补不进总价 10000——`left_need` 为负被显式跳过，方案自动拐向编号 5。

样例 3 演示平局：五件全 2000，可达总价集合只有 `{8000}`，`S* = 8000`。第 1 件逐个试，编号 1 即满足（后缀四件里选 3 件总价 6000），第 2、3、4 件同理各取最小编号，输出 `1 2 3 4`——总价全并列时字典序规则接管一切。

样例 2 是没有选择的特例：恰好四件、总价正好 10000，`S* = 10000` 与四件之和相等，四个编号依次被强制选出。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 四重循环枚举四件组合 | $O(m^4)$ | $O(1)$ | `m = 2000` 时约 2.7e12 个组合，超时 |
| 01 背包记可行性，方案重建时回扫全表 | $O(4 \cdot m \cdot W)$ | $O(W)$ | 可行总价算得出，但贪心每步都要回扫状态 |
| 位掩码后缀集合 + 按编号贪心（最优） | $O(m \cdot W / 64)$ | $O(m \cdot W / 64)$ | 建三个后缀位集 + 至多 `4m` 次常数级查询，本题采用 |

## 易错点总结

### 1. 「还需几件」到后缀集合的映射写反

贪心查询处 `best((suffix3, suffix2, suffix1)[3 - need][c + 1], left_need)` 的下标由 `3 - need` 决定：还差 3 件查 `suffix3`、还差 1 件查 `suffix1`。若顺着直觉写成 `need - 1`，还差 1 件时会去查「选 3 件」的集合，查询几乎永远返回 -1，全部候选被丢弃，像样例 2 这种必然有解的数据也会输出 `0`。

### 2. 后缀集合允许同一件被选两次

`suffix2[k]` 的转移必须取 `suffix1[k+1] << w`：另一件来自 `k` 之后。取 `suffix1[k] << w` 会把下标 k 自己也放进伴侣集合，同一件被计两次，可达总价集合里混入「选了它两次」的非法总价，贪心重建的组合按件求和便对不上输出总价。

### 3. 剩余预算的负值拦截

候选总价一旦超出 `S*`，`left_need` 变负，而 `best()` 对负上限返回 -1；若缺少 `left_need < 0` 的显式分支，`extra == left_need` 会在 `-1 == -1` 时侥幸通过，超支的组合被当成合格方案输出。样例 4 的编号 4（3000 元差 1000 预算）就是走到这条分支的实例。

---

## 扩展思考

贪心框架与位掩码都不依赖「4」：恰好 k 件时把后缀集合做到 `suffix_{k-1}` 即可，`k` 变大后位集宽度仍是 `W`，层数才是主要开销。若判定标准改成「字典序最大」或要求输出费用不化编号，只需翻转候选扫描方向或在选件时同时记下方案；「至多 k 件」的版本则把叶子判定从总价相等改成「不超过预算的最大化」，后缀集合退化为普通 01 背包。
