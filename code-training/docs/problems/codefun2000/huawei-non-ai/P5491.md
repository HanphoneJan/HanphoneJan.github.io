# P5491. 数字串拆积

> 场次：2026年10月22日-非AI方向 · 来源：[CodeFun2000 P5491](https://codefun2000.com/p/P5491)

> 题面为 CodeFun2000 会员内容，本文依据官方题解与公开信息整理；输入输出格式以原题为准，示例为说明性示例。

## 题目描述

给定一个由数字字符组成的字符串 $s$。把它从**中间某个位置**切成前后两段，两段都要求非空，然后各自读成一个十进制整数，求「两数之积」的最大值。

切出的两段按字面转成整数：前导零不影响数值，`"007"` 读作 7，`"0"` 读作 0。

## 输入格式

一行，一个只由数字字符组成的字符串 $s$，长度不小于 2。

## 输出格式

输出一个整数，为所有切法中两数乘积的最大值。

## 示例

### 示例 1

**输入：**

```
123
```

**输出：**

```
36
```

### 示例 2

**输入：**

```
909
```

**输出：**

```
810
```

## 解题思路

### 输出是什么：$n-1$ 个乘积里取最大的那个

长度为 $n$ 的串只有 $n-1$ 个合法切点。用 $k$ 表示「左段取前 $k$ 个字符」，那么 $k$ 只能取 $1,2,\dots,n-1$——$k=0$ 左段为空，$k=n$ 右段为空，都被「两段非空」挡掉。候选集就这么大，题目要的是这 $n-1$ 个数里的最大值。

这一步把题意彻底定死了：**没有「怎么切更好」的策略问题，只有「每个切点算一遍」。** 官方题解给的做法正是枚举全部切点。

### 为什么不能只试「对半切」

一个看似聪明的想法是：两数乘积在位数接近时更大，所以只在中间切就行。数字串里只要出现 0，这个直觉就失效。

`909` 的长度是 3，中间切点是 $k=1$，得到 $9 \times 9 = 81$；而 $k=2$ 得到 $90 \times 9 = 810$，是它的 10 倍。前导零同样会捣乱：`1001` 上 $k=2$ 得 $10 \times 1 = 10$、$k=3$ 得 $100 \times 1 = 100$，最好的切点贴着右端。**乘积大小取决于两段的数值，而数值取决于每段自己的位数与内容**，没有一条只看长度的规则能定下最优切点，所以老老实实枚举。

### 枚举的写法：切点走一遍，两段各转一次整数

```python
def max_split_product(s: str) -> int:
    """枚举每个切点 k：左段取前 k 个字符，右段取剩下 n-k 个。"""
    n = len(s)
    best = 0
    for k in range(1, n):          # k 取 1..n-1，保证两段都非空
        left = int(s[:k])
        right = int(s[k:])
        if left * right > best:
            best = left * right
    return best
```

三个细节都对得上题面：

- `range(1, n)` 的上下界就是「两段非空」：`1` 让左段至少 1 个字符，`n` 不取到让右段至少 1 个字符；
- `s[:k]` 与 `s[k:]` 正好把串切成「前 $k$ 个」和「后 $n-k$ 个」，两段拼起来就是原串，一个字符不重不漏；
- `int()` 会自动吃掉前导零，与「按字面转换」一致，不需要额外处理。

`best` 从 0 起：两段都是非负整数，乘积不可能小于 0，用 0 当初值就把「全零串」这种极端输入一并覆盖了（`"00"` 只有 $k=1$，得 $0 \times 0=0$）。

### 数据范围由算法反推

官方题解直接枚举全部切点，说明 $n$ 的量级允许「每个切点都重转两段」：每个切点要扫 $n$ 个字符做转换，$n-1$ 个切点合计是 $O(n^2)$ 的字符处理。字符串转换的这一步就是本题的全部开销，没有别的环节会盖过它。

## 完整代码实现

```python
import sys


def max_split_product(s: str) -> int:
    """枚举每个切点 k：左段取前 k 个字符，右段取剩下 n-k 个。"""
    n = len(s)
    best = 0
    for k in range(1, n):          # k 取 1..n-1，保证两段都非空
        left = int(s[:k])
        right = int(s[k:])
        if left * right > best:
            best = left * right
    return best


def solve():
    s = sys.stdin.read().strip()
    if not s:
        return
    print(max_split_product(s))


if __name__ == "__main__":
    solve()
```

## 示例推演

### 示例 1：`123`

$n=3$，切点 $k$ 取 1、2。

| $k$ | 左段 | 左段值 | 右段 | 右段值 | 乘积 | `best` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `1` | 1 | `23` | 23 | 23 | 23 |
| 2 | `12` | 12 | `3` | 3 | 36 | 36 |

输出 `36`。切在两数位数接近的位置，得到 $12 \times 3$。

### 示例 2：`909`

| $k$ | 左段 | 左段值 | 右段 | 右段值 | 乘积 | `best` |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `9` | 9 | `09` | 9 | 81 | 81 |
| 2 | `90` | 90 | `9` | 9 | 810 | 810 |

输出 `810`。第 1 行里 `int("09")` 得到 9，前导零被吃掉；而「对半切」只试到 $k=1$，会停在 81。

## 复杂度分析

$n$ 为数字串长度。

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 预先把每个切点的左右两段值都存成数组 | $O(n^2)$ | $O(n^2)$ | 存了 $n$ 个大整数、每个最长 $n$ 位；换来的只是省掉重复转换，空间却翻倍 |
| 逐切点现转两段再比较（最优） | $O(n^2)$ | $O(n)$ | 官方题解做法：$n-1$ 个切点，每个切点扫两段共 $n$ 个字符；临时大整数随用随丢 |

时间里的 $O(n^2)$ 与 $n-1$ 次「把 $n$ 个字符转成整数」对应，比较与乘法都在这之上，不改变量级。空间不算乘积本身（它是返回值，不是存储），`s[:k]`、`s[k:]` 各是 $O(n)$ 的临时串。

## 易错点总结

### 1. 右段下标写成 `s[k+1:]`

把 $k$ 当成「左段最后一位的下标」而不是「左段长度」，两个切片就会差一位：`s[:k]` 与 `s[k+1:]` 之间漏掉了第 $k$ 个字符。输入 `1234` 时 $k=1$ 拿到 $1 \times 34=34$、$k=2$ 拿到 $12 \times 4=48$，输出 48，而正确答案是 $k=1$ 的 $3 \times 124=372$。切点同时被用作切片上界与起始下标，差一位只有对照原始数字串才看得出来。

### 2. 切点范围写成 `range(n)`

`for k in range(1, n)` 少写一个 `1`（写成 `range(n)`）或上界写成 `n+1`，就会产生空段。`range(n)` 在 `123` 上会执行到 $k=3$，此时 `s[3:]` 是空串，`int('')` 直接抛 `ValueError: invalid literal for int() with base 10: ''`——示例 1 就跑不过。范围的两端分别对应「左段非空」和「右段非空」，是题面两个约束的直接翻译。
