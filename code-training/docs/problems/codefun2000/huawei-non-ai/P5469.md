# P5469. 主机灰度分批

> 场次：2026年9月18日-非AI方向 · 来源：[CodeFun2000 P5469](https://codefun2000.com/p/P5469)

## 题目描述

云上要给一大批计算节点做版本滚动。为了把风险压住，升级会拆成若干波次，也就是常说的灰度放量。

越靠前的波次越希望把各类机型都点到，好尽早把隐患暴露出来。

### 任务描述

手里有 $p$ 台主机，每台带着 $d$ 个维度的标签（比如板型、系统发行版）。某一维上标签相同，就认定这两台在该维属于同一类。

请按下面的规则排出分波方案：越靠前的波次，标签种类要尽量铺得开。

### 核心规则

1. 波次容量：

   主机总数记为 $p$，波次总数记为 $b$。

   - 基准容量 $q=\lfloor p/b\rfloor$。
   - 余数 $r=p\bmod b$。
   - 前 $b-r$ 个波次容量都是 $q$，最后 $r$ 个波次容量都是 $q+1$。

2. 增量尽量大：

   填当前波次时，只能从未入选的主机里挑。看哪一台还能给本波次补进最多尚未出现的标签。

   - 增量：该机某个维度上的标签，若本波次已入选的机器里还没出现过，就记一分。
   - 先比增量，越大越先拿。
   - 增量打平则拿 $nid$ 更小的那台。

3. 执行顺序：

   从第 $1$ 波填到第 $b$ 波，每波填满为止。某台一旦进了某一波，后面的波次不再考虑它。

## 输入格式

1. 首行两个整数 $p$ 和 $d$，即主机台数与标签维度。$(1\le p\le 2\times 10^{2},\ 1\le d\le 2)$

2. 随后 $p$ 行：每台主机一行，格式为

   `nid tag_1 tag_2 ... tag_d`

3. 末行一个整数 $b$，即波次总数。$(1\le b\le 2\times 10^{1})$

## 输出格式

输出 $b$ 行。第 $i$ 行给出该波次里的 $nid$，同一行按数值升序，相邻编号用空格隔开。

## 示例

### 示例 1

**输入：**

```
4 1
10 A
11 A
12 A
13 A
2
```

**输出：**

```
10 11
12 13
```

**说明：**

- $4\div 2=2$ 余 $0$，两波容量都是 $2$。
- 标签全是 $A$，第一台进波次后其余增量都变成 $0$。
- 增量打平时按 $nid$ 从小到大，故第一波 $10\ 11$，其余进第二波。

### 示例 2

**输入：**

```
6 2
1 X P
2 X Q
3 Y P
4 Y Q
5 Z Q
6 Z R
2
```

**输出：**

```
1 4 6
2 3 5
```

**说明：**

- $6\div 2=3$ 余 $0$，两波容量都是 $3$。
- 第一波：空盘先拿 $nid=1$（增量 $2$）；已有 $\{X,P\}$ 后再拿 $nid=4$（增量 $2$）；已有 $\{X,Y,P,Q\}$ 后再拿 $nid=6$（增量 $2$）。
- 剩下 $2,3,5$ 进第二波。

## 提示

1. 多样性按各维标签种类相加；越靠前的波次越优先把种类铺开。
2. 容量：总数 $p$、波次 $b$，基准是 $\lfloor p/b\rfloor$，多出来的台数摊到最后若干波。

## 解题思路

### 这不是优化题：规则已经把每一步挑哪台写死了

题面把选机过程逐条规定完毕——容量怎么摊、增量怎么算、平手拿谁，每条都唯一决定下一步取哪台。所以正确做法是**照着规则模拟**，把三条规则各翻译成一处代码。任何「自己设计一个更合理的分批策略」的念头都会直接答错：判题比对的是这套规则跑出来的编号序列。

### 规则一：容量前少后多

```python
q, r = divmod(p, b)
caps = [q] * (b - r) + [q + 1] * r
```

$q = \lfloor p/b \rfloor$ 是基准容量，余数 $r = p \bmod b$ 只摊在**最后** $r$ 个波次上，前面的波次一台都不多。比如 $p=5$、$b=2$ 时 `caps = [2, 3]`；极端些 $p=1$、$b=20$ 时是十九个 $0$ 加一个 $1$，前十九波各输出一个空行。

### 规则二：增量相对「本波次」，且逐维计算

一台主机的增量 = 它 $d$ 个维度里，标签**在本波已入选机器的同一维度**上还没出现过的维数。两个关键词都不能丢：

- **本波次**：每进入新的一波，已见标签要清空重来。`dim_seen` 必须建在波循环体内：

  ```python
  for wave in range(b):
      dim_seen = [set() for _ in range(d)]   # 本波各维已出现过的标签
      picked = []
      for _ in range(caps[wave]):
          ...
  ```

- **逐维**：每个维度一个集合。把所有维度合并成一个大集合是另一种常见写法，但口径会变——已见第 0 维的 $X$、第 1 维的 $P$，此时一台 $(P, X)$ 的主机在本口径下增量是 $2$（两个维度的标签都是新的），合并集合却算成 $0$（$P$、$X$ 都「出现过」）。选机顺序随之改变，编号分组也就变了。

增量与已选状态的落点是一行：

```python
gain = sum(1 for j in range(d) if tags[j] not in dim_seen[j])
```

选中之后要把它的标签补进各维集合：

```python
for j in range(d):
    dim_seen[j].add(hosts[best][1][j])
```

### 规则三：平手拿 nid 更小的那台

```python
if gain > best_gain or (gain == best_gain and nid < best_nid):
    best, best_gain, best_nid = h, gain, nid
```

扫描用「更优才替换」，比较增量时严格大于、比较 nid 时严格小于。这样结果与输入顺序无关：把 `20 A` 写在 `10 A` 前面，第一波仍然拿 $10$。反过来用「先到先得」（只写 `gain > best_gain`），分组就会跟着输入顺序飘。

### 为什么不能「先排一次序」

增量不是固定权重：每选走一台，本波已见标签就多几个，剩下机器的增量可能变小。所以按初始增量排一次序、再照单抓是错的。它确实是「只减不增」的，理论上可以挂一个大顶堆做惰性更新；但每次弹出仍要重算，$p \le 200$ 时堆的常数与代码量都不划算，每次老老实实扫一遍反而最短。

模拟的代价由数据范围兜底：$p \le 200$、$b \le 20$、$d \le 2$。总共恰好挑选 $p$ 台（容量之和就是 $p$），每次扫一遍还没入选的主机、每台做 $d$ 次集合查询，合计 $p^2 \cdot d \approx 8\times10^4$ 次查询，纯列表加集合足够。

### 输出格式的两个细节

- 波内是「按增量优先」选出来的，与 nid 升序没有关系，所以每波收尾要显式 `picked.sort()`；
- 容量为 $0$ 的波要输出**空行**，`"\n".join(out_lines)` 对空字符串正好给出一个空行。

## 完整代码实现

```python
"""
P5469. 主机灰度分批 - 贪心规则模拟

p 台主机各带 d（<= 2）个维度的标签，要切成 b 波灰度。规则由题面写死，
本质是按规则模拟，不另寻最优划分：
1. 容量：q = p // b，r = p % b；前 b-r 波容量 q，最后 r 波容量 q+1。
2. 每波从空集开始，逐台从未入选主机里挑「增量」最大者：该机某一维的
   标签若在本波已入选机器中还没出现过记 1 分；增量打平拿 nid 更小者。
   增量相对的是「本波次」已见标签，换波即清空。
3. 某台进过一波后不再参与。输出每波成员，行内按 nid 数值升序。

输入格式：
- 第 1 行：p d（1<=p<=2e2，1<=d<=2）；
- 随后 p 行：nid tag_1 [tag_2]；
- 末行：b（1<=b<=2e1）。

输出格式：
- b 行：每波 nid 升序、空格分隔（容量为 0 的波输出空行）。

时间复杂度：O(p^2 * d)（每波每选一台扫全部未选主机）
空间复杂度：O(p * d)
"""

# https://codefun2000.com/p/P5469
import sys

# @sample-start
"""
样例输入 1:
4 1
10 A
11 A
12 A
13 A
2

样例输出 1:
10 11
12 13
"""
# @sample-end

# @sample-start
"""
样例输入 2:
6 2
1 X P
2 X Q
3 Y P
4 Y Q
5 Z Q
6 Z R
2

样例输出 2:
1 4 6
2 3 5
"""
# @sample-end


def solve():
    """按题面规则逐波模拟：容量前少后多，波内挑增量最大且 nid 最小者。"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    p = int(next(it))
    d = int(next(it))
    hosts = []  # (nid, tags 元组)
    for _ in range(p):
        nid = int(next(it))
        tags = tuple(next(it) for _ in range(d))
        hosts.append((nid, tags))
    b = int(next(it))
    used = [False] * p

    # 容量分布：基准 q，余数 r 摊到最后的 r 个波次，后面的波只大不小
    q, r = divmod(p, b)
    caps = [q] * (b - r) + [q + 1] * r

    out_lines = []
    for wave in range(b):
        dim_seen = [set() for _ in range(d)]  # 本波已出现过的各维标签
        picked = []
        for _ in range(caps[wave]):
            best = -1
            best_gain = -1
            best_nid = None
            for h in range(p):
                if used[h]:
                    continue
                nid, tags = hosts[h]
                gain = sum(1 for j in range(d) if tags[j] not in dim_seen[j])
                if gain > best_gain or (gain == best_gain and nid < best_nid):
                    best, best_gain, best_nid = h, gain, nid
            used[best] = True
            picked.append(hosts[best][0])
            for j in range(d):
                dim_seen[j].add(hosts[best][1][j])
        picked.sort()
        out_lines.append(" ".join(map(str, picked)))
    print("\n".join(out_lines))


def run_tests():
    """运行官方样例与边界用例，方便本地自测。"""
    import io

    test_cases = [
        # 官方样例 1：全同标签，增量全 0，按 nid 顺次进波
        (
            "4 1\n10 A\n11 A\n12 A\n13 A\n2\n",
            "10 11\n12 13",
        ),
        # 官方样例 2：两波各 3 台，第一波三连增量 2
        (
            "6 2\n1 X P\n2 X Q\n3 Y P\n4 Y Q\n5 Z Q\n6 Z R\n2\n",
            "1 4 6\n2 3 5",
        ),
        # b=1：所有主机进同一波，行内按 nid 升序
        (
            "3 1\n30 A\n10 B\n20 A\n1\n",
            "10 20 30",
        ),
        # 余数 r>0：p=5、b=2，前波容量 2、后波容量 3
        (
            "5 1\n1 A\n2 A\n3 A\n4 A\n5 A\n2\n",
            "1 2\n3 4 5",
        ),
        # 增量对照本波次而非全局：第二波里标签 A 应重新计分，
        # 于是 nid 2（A，增量 1）先于 nid 9（C，增量 1）按平手 nid 取 2
        (
            "4 1\n1 A\n2 A\n3 B\n9 C\n2\n",
            "1 3\n2 9",
        ),
        # nid 与输入顺序相反：平手时应拿 nid 更小的那台
        (
            "2 1\n20 A\n10 A\n2\n",
            "10\n20",
        ),
        # 两波之间标签集清空：第二波第一台增量恢复为满 d
        (
            "4 2\n1 X X\n2 Y Y\n3 X X\n4 Y Y\n2\n",
            "1 2\n3 4",
        ),
    ]

    for i, (inp, expected) in enumerate(test_cases, 1):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io.TextIOWrapper(io.BytesIO(inp.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            output = sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout

        status = "✓" if output == expected else "✗"
        print(f"样例 {i}: 期望={expected!r}, 实际={output!r} {status}")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

样例 2：$p=6$、$b=2$，两波各 $3$ 台。六台分别是 $1(X,P)$、$2(X,Q)$、$3(Y,P)$、$4(Y,Q)$、$5(Z,Q)$、$6(Z,R)$。

第一波从空集合开始，所有主机两个维度都还没出现过，增量全是 $2$，平手取最小 nid，选中 $1$，集合变成第 $0$ 维 $\{X\}$、第 $1$ 维 $\{P\}$：

| 未选主机 | 第 0 维 | 第 1 维 | 增量 |
| -------- | ------- | ------- | ---- |
| $2(X,Q)$ | $X$ 已见 | $Q$ 新 | $1$ |
| $3(Y,P)$ | $Y$ 新 | $P$ 已见 | $1$ |
| $4(Y,Q)$ | $Y$ 新 | $Q$ 新 | $2$ |
| $5(Z,Q)$ | $Z$ 新 | $Q$ 新 | $2$ |
| $6(Z,R)$ | $Z$ 新 | $R$ 新 | $2$ |

增量为 $2$ 的是 $4$、$5$、$6$，平手取最小的 $4$。集合变为 $\{X,Y\}$ 与 $\{P,Q\}$：主机 $2$、$3$ 增量归 $0$，$5$ 只剩 $Z$ 一分，$6$ 的 $Z$、$R$ 两维全新，增量 $2$ 直接入选。第一波 $1,4,6$，按 nid 升序落成 `1 4 6`。

第二波清空集合重算。剩下 $\{2,3,5\}$，空集下三家增量都是 $2$，平手按 nid 依次取 $2$、$3$、$5$，输出 `2 3 5`。与题面一致。

样例 1 是全同标签的极简对照：$p=4$、$b=2$，容量 $[2,2]$。第一台入选后其余增量全归 $0$，整场只剩平手裁决，两波按 nid 顺次填出 `10 11` 与 `12 13`。这组数据专门钉住「平手拿小 nid」，而不是任何标签驱动的选择。

再看一个波次口径错位的例子（$p=6$、$b=3$，容量 $[2,2,2]$，六台分别是 $1{:}A$、$2{:}A$、$3{:}B$、$4{:}B$、$5{:}C$、$6{:}C$）。按规则：第一波空集下全部增量 $1$，取 $1$，之后 $2$ 增量归 $0$、$3$ 仍为 $1$，取 $3$；第二波清空重算，$\{2,4,5,6\}$ 增量都是 $1$，取 $2$、$4$；第三波剩下 $5$、$6$。输出 `1 3` / `2 4` / `5 6`。若把已见标签跨波累计，第二波起始集合是 $\{A,B\}$，$2$、$4$ 增量归 $0$ 而 $5$（$C$）还有一分，于是第二波变成 $\{2,5\}$、第三波 $\{4,6\}$——两组的**成员**都变了，而不只是顺序。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 不维护已选标记，每波重扫全部主机 | $O(b \cdot p^2 \cdot d)$ | $O(p)$ | 前面波次已入选的机器在每个后续波次里还会被再扫一遍 |
| 已选标记 + 每次现算增量（最优） | $O(p^2 \cdot d)$ | $O(p)$ | 全程恰好挑选 $p$ 台，每次扫 $O(p)$ 台、每台 $d$ 次集合查询 |

$p=200$、$d=2$ 时上界约 $8\times10^4$ 次集合查询。增量对每台机器是「只减不增」的，理论上可以用大顶堆做惰性更新，但在这个规模下堆的常数与维护成本都不划算。

## 易错点总结

### 1. 余数摊到了前面的波次

容量是「前 $b-r$ 波为 $q$，最后 $r$ 波为 $q+1$」。写成 `[q + 1] * r + [q] * (b - r)` 把余数放到了前面，行数不变但归属整体前移：$p=5$、$b=2$、五台全同标签时，正确输出是 `1 2` / `3 4 5`，错写会输出 `1 2 3` / `4 5`。

### 2. `dim_seen` 建在了波循环之外

这两个集合记录的是「**本波**已经出现过哪些标签」，所以必须在 `for wave in range(b):` 内部重建。挪到循环外跨波累计，第二波起步时上一波的标签全部占位，增量被普遍压低，选出的人也随之改变：示例推演里那六台 $A/A/B/B/C/C$ 会从 `1 3` / `2 4` / `5 6` 变成 `1 3` / `2 5` / `4 6`。

### 3. 平手裁决交给了输入顺序

比较条件必须是 `gain > best_gain or (gain == best_gain and nid < best_nid)`。只写 `gain > best_gain` 就成了「先到先得」，而 nid 与输入顺序没有必然关系：输入写成 `20 A`、`10 A` 两行（$b=2$），第一波会输出 $20$，正确结果是 $10$。

## 扩展思考

规则里「增量相对本波」这一句换掉，题目就变了一副面孔——若改成「相对全局已出现过的标签」，同一个 $\{A,B,C\}$ 的样例会得到完全不同的分组，示例推演里那组数据可以直接拿来复验。真实灰度调度里，余数怎么摊、增量取本波还是历史，都是从需求侧来的自由度，实现时对照规则逐条落位即可。
