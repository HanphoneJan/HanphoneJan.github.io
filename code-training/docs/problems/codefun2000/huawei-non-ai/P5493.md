# P5493. 简易日志轮转

> 场次：2026年10月22日-非AI方向 · 来源：[CodeFun2000 P5493](https://codefun2000.com/p/P5493)

> 题面为 CodeFun2000 会员内容，本文依据官方题解与公开信息整理；输入输出格式以原题为准，示例为说明性示例。

## 题目描述

某在线服务把日志按模块分别写入文件，磁盘空间有限，需要一个「日志轮转器」。设定如下：

- 每份日志文件只属于一个模块，同一模块每新开一份文件，序号加一（从 $1$ 开始）。
- $totalCap$ 是**所有**日志文件的体积之和上限；$fileCap$ 是**单份**文件的体积上限。
- 每次写入都通过 `putLog(mid, nbytes)` 完成：模块 $mid$ 追加 $nbytes$ 字节，接口返回该模块**当前文件**写入后的体积。

每次调用的处理顺序固定为下面三步：

1. **总额**：若「当前总占用 $+\ nbytes$」超过了 $totalCap$，就按文件的生成顺序，从**最早生成**的那份开始删除，直到放得下；被删掉的文件如果正好是某个模块的当前文件，该模块的「当前文件」指针随之失效（下次写入要新开一份）。
2. **单文件限**：若该模块没有当前文件，或当前文件再写 $nbytes$ 就会超过 $fileCap$，就新开一份文件（序号用该模块的下一序号），作为它的当前文件。
3. 把 $nbytes$ 追加进当前文件，同时更新全局占用，返回这份文件的体积。

### 需要实现的接口

```python
class LogRotator:
    def __init__(self, totalCap: int, fileCap: int) -> None:
        """初始化：全局容量与单份文件容量。"""

    def putLog(self, mid: int, nbytes: int) -> int:
        """模块 mid 写入 nbytes 字节，返回它当前文件写入后的体积。"""
```

判分程序会构造一个 `LogRotator`，按给定顺序调用 `putLog`，逐次核对返回值。

## 输入格式

本题是**接口题**，判分程序直接调用方法，没有标准输入的格式约定。为了能在本地跑通、也让本文的示例可复现，下面的示例使用这样一个说明性的驱动：

- 第一行两个整数 $totalCap$、$fileCap$；
- 第二行一个整数 $m$，表示调用次数；
- 接下来 $m$ 行，每行两个整数 $mid$、$nbytes$，表示一次 `putLog(mid, nbytes)`。

## 输出格式

$m$ 行，第 $i$ 行是第 $i$ 次 `putLog` 的返回值。

## 示例

### 示例 1

**输入：**

```text
10 4
6
1 3
1 2
2 4
1 3
2 1
1 2
```

**输出：**

```text
3
2
4
3
1
2
```

**说明：**

全局上限 $10$、单文件上限 $4$。

1. `putLog(1, 3)`：模块 1 没有当前文件，新建 `1-1` 写入 $3$ 字节，返回 $3$。
2. `putLog(1, 2)`：`1-1` 已有 $3$ 字节，再写 $2$ 会超过 $4$，新建 `1-2`，返回 $2$。
3. `putLog(2, 4)`：模块 2 新建 `2-1`，正好装满，返回 $4$；此时总占用 $9$。
4. `putLog(1, 3)`：$9+3 > 10$，先删掉最早生成的 `1-1`（$3$ 字节），总占用回到 $6$；模块 1 的当前文件 `1-2` 装不下 $3$，新建 `1-3`，返回 $3$。
5. `putLog(2, 1)`：$9+1 = 10$ 不超，`2-1` 已满，新建 `2-2`，返回 $1$；总占用正好 $10$。
6. `putLog(1, 2)`：$10+2 > 10$，删掉 `1-2`（$2$ 字节）；`1-3` 装不下 $2$，新建 `1-4`，返回 $2$。

### 示例 2

**输入：**

```text
5 5
4
1 2
2 2
1 2
1 1
```

**输出：**

```text
2
2
2
3
```

**说明：**

全局上限与单文件上限都是 $5$，所以只有「总量淘汰」会触发。

1. `putLog(1, 2)`：新建 `1-1`，返回 $2$。
2. `putLog(2, 2)`：新建 `2-1`，返回 $2$；总占用 $4$。
3. `putLog(1, 2)`：$4+2 > 5$，先删最早生成的 `1-1`——而它**正是模块 1 的当前文件**，指针必须一起清掉；随后模块 1 新建 `1-2`，返回 $2$。
4. `putLog(1, 1)`：$4+1 = 5$ 不超；当前文件 `1-2` 有 $2$ 字节，$2+1 \le 5$，直接写进同一份，涨到 $3$，返回 $3$。

## 解题思路

### 接口题先看状态：三张表各回答一个问题

这题没有算法，只有一本要记清楚的账。把「随时可能被问到的问题」列出来，数据结构就自己定下来了：

| 问题 | 谁回答 |
| --- | --- |
| 最早生成的那份文件是哪个？ | 按生成顺序排的队列（先进先出） |
| 模块 $mid$ 现在写的是哪份文件？ | 哈希表 `current：模块号 → 文件` |
| 模块 $mid$ 下一份文件编号几？ | 哈希表 `next_seq：模块号 → 序号` |

三处必须指向**同一个文件对象**。文件用一个小列表 `[模块号, 序号, 体积]` 表示，队列里放它、`current[mid]` 里也放它，于是「加了多少字节」只有一份记录：写进去之后，队列那头立刻看得到。若图省事在队列里另存一份体积，淘汰时算出来的总量就会和真实占用对不上。

```python
def __init__(self, total_cap, file_cap):
    self.total_cap = total_cap
    self.file_cap = file_cap
    self.total_size = 0
    self.files = deque()      # 按生成先后排队：[模块号, 序号, 体积]
    self.current = {}         # 模块号 -> 该模块当前在写的那份文件
    self.next_seq = {}        # 模块号 -> 下一份文件的序号
```

### 淘汰阶段：先腾空间，再决定往哪写

淘汰的判据是「写入之后会不会超标」。既然判的是**写入后**，腾空间就必须发生在真正加字节之前——否则会撞上一个很隐蔽的局面：文件 $F$ 是某个模块的当前文件，同时也是队列里最早的一份；先往 $F$ 里加字节，再回头看总量超标，于是一路从队首删，第一个被删的正是刚刚写完的 $F$。返回值给了一份已经不存在的文件的体积，账面彻底对不上。

所以顺序是固定的：先按 `total_size + nbytes > total_cap` 反复出队，再去挑选或新建文件。

```python
while self.files and self.total_size + nbytes > self.total_cap:
    old = self.files.popleft()          # 最早生成的那份
    self.total_size -= old[2]           # 账要跟着减
    if self.current.get(old[0]) is old:
        del self.current[old[0]]        # 指针失效，下次重开一份
```

`while` 的条件里带上 `self.files` 是防御：如果 $nbytes$ 本身比 $totalCap$ 还大，怎么删都放不下，靠这个条件退出，不会空转。

### 淘汰的连带动作：删掉的若是「当前文件」，指针要一起清掉

这是本题唯一真正容易漏的一处。删文件时只把体积从总量里减掉、却把 `current[mid]` 留在原处，下一次 `putLog(mid, ...)` 会拿到一个已经不在队列里的文件，接着往里写：接口返回值是它的历史累计体积（示例 2 第 3 次会返回 $4$，而正确值是 $2$），而 `total_size` 与队列里各文件体积之和从此不再相等——之后每一次淘汰判断都建立在错误的账上。

判定用的是**对象身份**（`is`），不是 `==`：两份不同的文件本来就不该被认成同一份。清掉之后，`current` 里没有这个模块的条目，建文件那一步自然会走「新开一份」的分支，序号照常递增。

### 建文件阶段：什么时候开新文件，返回什么

新开的条件是两条之一：该模块没有当前文件（从没写过，或刚被淘汰），或者当前文件再写就超过 $fileCap$。判据用的是**严格大于**：`size + nbytes == fileCap` 恰好写满，仍然留在同一份文件里，不算越界。

```python
def putLog(self, mid, nbytes):
    # ……淘汰那一段见上一节，这里只写选文件、写入与返回……
    cur = self.current.get(mid)
    if cur is None or cur[2] + nbytes > self.file_cap:
        seq = self.next_seq.get(mid, 1)     # 第一次开文件时序号是 1
        self.next_seq[mid] = seq + 1
        cur = [mid, seq, 0]
        self.files.append(cur)              # 新文件排在队尾，最晚被淘汰
        self.current[mid] = cur

    cur[2] += nbytes
    self.total_size += nbytes
    return cur[2]                            # 返回这份文件写入后的体积
```

`next_seq` 与 `current` 是两张不同的表：`current` 会因为淘汰被清空，序号却要继续往下走——模块 1 的 `1-1` 被删掉之后，下一份是 `1-2` 而不是重新回到 `1-1`。把这两件事混用一张表，淘汰一次就会让序号回退、文件名撞车。

### 均摊 O(1)：每份文件只入队、出队各一次

每次 `putLog` 里，队列可能一口气弹出好几项，单次调用的耗时不是常数；但把 $m$ 次调用合起来看，每份文件只被创建一次、删除一次，总弹出次数不超过创建次数，也就不会超过 $m$。所以总量是 $O(m)$，均摊到每次调用是 $O(1)$。

这里对容器的选择有一个实际差别：`list.pop(0)` 每次都要把后面的元素整体前移，单次淘汰 $O(F)$（$F$ 是在册文件数），最坏总量退成 $O(m\cdot F)$；`collections.deque` 的 `popleft()` 是 $O(1)$。

## 完整代码实现

```python
import sys
from collections import deque


class LogRotator:
    """日志轮转器：total_cap 是全部日志文件的总容量，file_cap 是单份文件的容量。"""

    def __init__(self, total_cap, file_cap):
        self.total_cap = total_cap
        self.file_cap = file_cap
        self.total_size = 0
        self.files = deque()      # 按生成先后排队：[模块号, 序号, 体积]
        self.current = {}         # 模块号 -> 该模块当前在写的那份文件
        self.next_seq = {}        # 模块号 -> 下一份文件的序号

    def putLog(self, mid, nbytes):
        # 第 1 步：总量不够就先按生成顺序删掉最早的文件
        while self.files and self.total_size + nbytes > self.total_cap:
            old = self.files.popleft()
            self.total_size -= old[2]
            if self.current.get(old[0]) is old:
                # 删掉的正是某个模块的当前文件：指针必须清掉，
                # 否则下一次会往一份已经不存在的文件里接着写
                del self.current[old[0]]

        # 第 2 步：没有当前文件，或这份文件装不下，就新开一份
        cur = self.current.get(mid)
        if cur is None or cur[2] + nbytes > self.file_cap:
            seq = self.next_seq.get(mid, 1)
            self.next_seq[mid] = seq + 1
            cur = [mid, seq, 0]
            self.files.append(cur)
            self.current[mid] = cur

        # 第 3 步：写进当前文件，返回它写入后的体积
        cur[2] += nbytes
        self.total_size += nbytes
        return cur[2]


def main():
    """说明性驱动：按顺序调用 putLog，把每次的返回值逐行打印出来。"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    total_cap = int(data[0])
    file_cap = int(data[1])
    m = int(data[2])
    rotator = LogRotator(total_cap, file_cap)

    out = []
    pos = 3
    for _ in range(m):
        mid = int(data[pos])
        nbytes = int(data[pos + 1])
        pos += 2
        out.append(str(rotator.putLog(mid, nbytes)))
    sys.stdout.write("\n".join(out) + "\n")


if __name__ == "__main__":
    main()
```

## 示例推演

### 示例 1：$totalCap = 10$，$fileCap = 4$

| 调用 | 淘汰（按生成顺序） | 模块的当前文件 | 返回 | 总占用 |
| --- | --- | --- | --- | --- |
| `1 3` | 无（$0+3 \le 10$） | 无 → 新建 `1-1`，$0\to3$ | 3 | 3 |
| `1 2` | 无（$3+2 \le 10$） | `1-1` 有 $3$，$3+2 > 4$ → 新建 `1-2`，$0\to2$ | 2 | 5 |
| `2 4` | 无（$5+4 \le 10$） | 无 → 新建 `2-1`，$0\to4$ | 4 | 9 |
| `1 3` | $9+3 > 10$ → 删 `1-1`（$3$），总占用 $6$ | `1-2` 有 $2$，$2+3 > 4$ → 新建 `1-3`，$0\to3$ | 3 | 9 |
| `2 1` | 无（$9+1 \le 10$） | `2-1` 有 $4$，$4+1 > 4$ → 新建 `2-2`，$0\to1$ | 1 | 10 |
| `1 2` | $10+2 > 10$ → 删 `1-2`（$2$），总占用 $8$ | `1-3` 有 $3$，$3+2 > 4$ → 新建 `1-4`，$0\to2$ | 2 | 10 |

第 4 步值得停一下：触发淘汰的是「总量」，但被删的 `1-1` 并不是模块 1 当时的当前文件（那时是 `1-2`），所以指针不需要清；淘汰之后仍然放不下的原因在单文件限——`1-2` 只剩 $2$ 字节的空间，写不进 $3$ 字节。

### 示例 2：$totalCap = fileCap = 5$

| 调用 | 淘汰（按生成顺序） | 模块的当前文件 | 返回 | 总占用 |
| --- | --- | --- | --- | --- |
| `1 2` | 无 | 无 → 新建 `1-1`，$0\to2$ | 2 | 2 |
| `2 2` | 无（$2+2 \le 5$） | 无 → 新建 `2-1`，$0\to2$ | 2 | 4 |
| `1 2` | $4+2 > 5$ → 删 `1-1`（$2$），总占用 $2$；`1-1` 是模块 1 的当前文件，指针清空 | 无 → 新建 `1-2`，$0\to2$ | 2 | 4 |
| `1 1` | 无（$4+1 \le 5$） | `1-2` 有 $2$，$2+1 \le 5$ → 留在同一份，$2\to3$ | 3 | 5 |

第 3 步是「淘汰 + 指针失效 + 重开」三件事在同一次调用里发生的完整样本：删掉的是模块 1 的当前文件，所以它不能接着往旧文件里写，必须开 `1-2`（序号顺延，不回退到 `1-1`）。第 4 步则验证了「恰好写满之前不切分」：$2+1=3$ 小于 $fileCap = 5$，继续写同一份。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 用 `list` 当队列（`pop(0)` 删队首） | 总量 $O(m\cdot F)$ | $O(F)$ | 每次淘汰都要把列表整体前移，$F$ 为在册文件数 |
| `deque` + 两张哈希表（最优） | 总量 $O(m)$，单次均摊 $O(1)$ | $O(F)$ | 每份文件只创建一次、删除一次，总弹出次数不超过 $m$ |

$F$ 的范围由容量与最小写入量决定：最坏情况下每个文件只写 $1$ 字节，在册文件数可以到 $totalCap$。空间只需要「当前在册的文件」这一份记录，被淘汰的文件对象直接丢弃。

## 易错点总结

### 1. 淘汰时忘了把体积从 `total_size` 里减掉

`while` 里只写了 `self.files.popleft()`、漏掉 `self.total_size -= old[2]`，总量就只增不减：示例 2 到第 3 次调用结束时账面已经是 $6$（正确值是 $4$），第 4 次于是先删 `1-2`、再新开一份，返回 $1$ 而不是 $3$；再往后每次调用都会被判成「超标」，`totalCap` 形同虚设（账面可以超过上限），所有文件被反复删光重开，返回值恒等于 `nbytes`。

### 2. 删掉了当前文件却不清指针

`if self.current.get(old[0]) is old: del ...` 这两行缺了，示例 2 第 3 次调用会认为模块 1 还有当前文件 `1-1`（$2$ 字节），$2+2 \le 5$ 于是直接续写，返回 $4$。表面上只是数值不对，本质上是往一份已经从队列里删掉的文件里写数据，此后 `total_size` 与各文件体积之和永久失配。

### 3. 单文件限写成 `>=` 而不是 `>`

判断应从 `cur[2] + nbytes > self.file_cap` 出发：恰好写满不算越界。改成 `>=` 之后，`fileCap = 4` 时连续两次写 $2$ 字节会在第二次切分出一份新文件，返回 $2$ 而不是 $4$；文件总数也跟着翻倍——每一次「刚好填满」的写入都会被切成两份。
