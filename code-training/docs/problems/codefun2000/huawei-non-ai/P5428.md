# P5428. 作业限放接单

> 场次：2026年9月11日-非AI方向 · 来源：[CodeFun2000 P5428](https://codefun2000.com/p/P5428)

## 题目描述

云计算里一条 CI/CD 流水线由若干作业排成队列，用数组 $arr$ 表示，格子里的值是该作业耗时。

资源不够，不能把队列里每一项都跑完，约定如下：

1. 从队列最左侧开始依次审阅
2. 对当前作业，可以选择跑掉或者放掉
3. 选择跑掉时，把对应耗时累加进去
4. 选择放掉时，不加耗时，并继续看后面的作业
5. 硬性限制：连续被放掉的作业个数不能大于 $lim$
6. 目标：在上述限制下刚好跑完 $t$ 个作业，且累加耗时尽可能小

## 输入格式

- $arr$: 作业耗时数组，格子里的值是该项耗时
- $t$: int - 必须刚好跑完的作业个数
- $lim$: int - 连续放掉的最大个数

参数约束：

- $0 \le arr.length \le 1000$
- $1 \le arr_i \le 10000$
- $0 \le t \le arr.length$
- $0 \le lim \le 1000$

## 输出格式

int - 最小累加耗时；队列为空（$arr.length==0$）时输出 $0$；若无法刚好跑完 $t$ 个作业，返回 $-1$

## 示例

### 示例 1

**输入：**

```
9 8 7 6 11 12 10
2
1
```

**输出：**

```
-1
```

**说明：**
队列长 $7$，要刚好跑 $2$ 项，$lim=1$。即使尽量分散放掉，连续放掉上限也撑不住剩下的 $5$ 项，因此给出 $-1$。

### 示例 2

**输入：**

```
11 4 15 6 8
4
3
```

**输出：**

```
29
```

**说明：**
一种跑法：跑 $11$、$4$，放掉 $15$，再跑 $6$ 与 $8$。

- 刚好跑了 $4$ 项（$11,4,6,8$）
- 累加耗时 $= 11+4+6+8=29$
- 各段连续放掉长度均不超过 $3$

其余合法跑法都至少要带上 $15$，耗时更大，因此答案是 $29$。

### 示例 3

**输入：**

```
4 80 4 80 4 80 4
4
2
```

**输出：**

```
16
```

**说明：**
跑第 $1$、$3$、$5$、$7$ 项，三处 $80$ 各自单独放掉。

- 刚好跑了 $4$ 项
- 累加耗时 $= 4+4+4+4=16$
- 连续放掉长度均为 $1$（$\le 2$）

把任何一项 $80$ 跑进来都会让耗时变大，故最小值是 $16$。

### 示例 4

**输入：**

```

0
4
```

**输出：**

```
0
```

**说明：**
队列里没有任何作业，按约定给出 $0$。

## 解题思路

### 三种输出各自的判定口径

答案有三种形态：空队列直接 `0`（优先级最高，`t` 约束下必为 0）；无法恰好跑完 `t` 个输出 `-1`；正常情况输出「恰好跑完 t 个且总耗时最小」的那个数。`t=0` 是一个需要单独定口径的角：一项不接、整段队列全部放掉，总耗时 0 但整段连续放掉的长度就是 `n`，所以 `n <= lim` 才是 0，否则 `-1`。

### 第一条关键观察：连续放掉翻译成下标条件

设接下的 `t` 项下标为 `p1 < p2 < ... < pt`。被放掉的 `n - t` 项落在 `t + 1` 个空隙里——队首 `p1` 个、相邻接单项之间 `p_{j+1} - p_j - 1` 个、队尾 `n - 1 - p_t` 个。「每个连续放掉段不超过 lim」于是等价于三条下标条件：

$$p_1 \le \lim,\qquad p_{j+1} - p_j \le \lim + 1,\qquad n - 1 - p_t \le \lim$$

放掉的项数是定数，`t + 1` 个空隙每个至多 `lim` 个，所以 `n - t > (t + 1)·lim` 时一步判 `-1`（样例 1 的 7 项跑 2 项、`lim=1`：5 个放掉项塞不进 3 个空隙）。数空隙这个视角把「连续段的分布」从模糊描述变成可编码的不等式，是整个 DP 的地基。

### 第二条关键观察：逐层选择 + 窗口递推

「恰好跑 t 个」让问题按接单次数分层：`dp[j][i]` = 已接 `j` 项、最后一项下标为 `i` 的最小耗时。转移只关心「上一项离得多远」：

$$dp[j+1][\text{nxt}] = arr[\text{nxt}] + \min\bigl(dp[j][\,i\,]\bigr),\quad i \in [\text{nxt}-1-\lim,\ \text{nxt}-1]$$

朴素实现里每层对每个 `nxt` 扫一遍窗口，最坏 `O(n·t·lim)`≈1e9 层次太贵；窗口随 `nxt` 每步**右移一格**（右端加 `nxt-1`、左端淘汰 `nxt-1-lim` 之外的下标），正是单调队列滑动最小值的标准场景，压到 `O(n·t)`，1000×1000 一秒内跑完。

### 到实现上的映射

- 第 1 层初始化只保留 `i <= lim` 的位置——队首空隙那一条不等式；其余为不可达。
- 主循环跑 `t - 1` 次，单调队列存下标且对应 `dp` 值从小到大；`dp[i]` 为不可达的值不入队。
- 收尾只在 `i >= n - 1 - lim` 的位置取最小——队尾空隙那条不等式；一个位置都没有则 `-1`。`n - t > (t+1)·lim` 的提前判定只是把必然空集的情形从循环里省出来。
- 输入按行解析：第 1 行（可以为空行）是数组，后两行是 `t`、`lim`，空队列的样例 4 就由空首行表达。

## 完整代码实现

```python
"""
P5428. 作业限放接单 - 分层 DP + 单调队列滑动窗口最小值

题面要点：
- 作业队列 arr，从左到右逐个审阅，跑掉就把耗时累加，放掉不累加。
- 硬约束：连续放掉的作业个数 <= lim。
- 目标：恰好跑完 t 个作业，累加耗时最小。队列为空输出 0；
  无法恰好跑完 t 个输出 -1。

输入格式（三行，行数固定）：
- 第 1 行：数组 arr 的全部元素（0 <= len <= 1000），为空表示空队列；
- 第 2 行：整数 t（恰好要跑的作业数）；
- 第 3 行：整数 lim（连续放掉的上限）。

输出格式：最小累加耗时 / 0（空队列）/ -1（无解）。

核心思路：
1. 先把「连续放掉 <= lim」翻译成下标条件：接下的 t 项下标为
   p1 < p2 < ... < pt，被放掉的 n-t 项落在 t+1 个空隙里——队首 p1 个、
   相邻两接单项之间 p_{j+1}-p_j-1 个、队尾 n-1-p_t 个。于是合法解
   当且仅当 p1 <= lim、p_{j+1}-p_j <= lim+1、n-1-p_t <= lim；
   总空位数不够（n - t > (t+1)*lim）时直接无解，这是最快的 -1 判定。
2. 这是一个「段间间隔受限的隔项最小和」问题：min 转移叠加在更小的
   前缀上，逐层做没问题。dp[j][i] = 已接 j 项、最后一项下标为 i 的
   最小耗时，dp[j+1][nxt] = arr[nxt] + min(dp[j][i])，i 的窗口是
   [nxt-1-lim, nxt-1]——窗口随 nxt 单调右移，用单调队列维护最小值，
   总复杂度从 O(n*t*lim) 压到 O(n*t)。
3. t=0 单独处理：一项不接、整段放掉，n <= lim 才是 0 否则 -1；
   空队列直接给 0（t 约束下必为 0，n <= lim 自然成立）。

时间复杂度：O(n * t)（单调队列，每个下标至多进队、出队一次）
空间复杂度：O(n)
"""

# https://codefun2000.com/p/P5428
import sys
from collections import deque

# @sample-start
"""
样例输入 1:
9 8 7 6 11 12 10
2
1

样例输出 1:
-1
"""
# @sample-end

# @sample-start
"""
样例输入 2:
11 4 15 6 8
4
3

样例输出 2:
29
"""
# @sample-end

# @sample-start
"""
样例输入 3:
4 80 4 80 4 80 4
4
2

样例输出 3:
16
"""
# @sample-end

# @sample-start
"""
样例输入 4:

0
4

样例输出 4:
0
"""
# @sample-end


def solve():
    """读入 arr / t / lim，输出最小累加耗时。"""
    text = sys.stdin.read()
    lines = text.split("\n")

    # 第 1 行是数组；它可以是空行（样例 4 的空队列约定）。
    first = lines[0].strip() if lines else ""
    arr = [int(tok) for tok in first.split()] if first else []

    # 第 2、3 行是 t 与 lim；t、lim 各占一行，多余空行忽略。
    tail = [int(tok) for line in lines[1:] for tok in line.split()]
    t = tail[0] if len(tail) > 0 else 0
    lim = tail[1] if len(tail) > 1 else 0

    n = len(arr)
    if n == 0:
        # 空队列：按约定输出 0。
        print(0)
        return
    if t == 0:
        # 一项不接：整段队列全部连续放掉，n <= lim 才放得下。
        print(0 if n <= lim else -1)
        return
    if n < t or n - t > (t + 1) * lim:
        # 跑满了 n 项都不够 t；或被放掉的 n-t 项塞不进 t+1 个空隙。
        print(-1)
        return

    INF = float("inf")
    # 第 1 层：队首空隙是 p1 个被放掉的作业，p1 <= lim。
    dp = [arr[i] if i <= lim else INF for i in range(n)]

    # 逐层加接：dp[j][nxt] 依赖 dp[j-1][nxt-1-lim .. nxt-1] 的最小值。
    for _ in range(t - 1):
        ndp = [INF] * n
        window = deque()  # 存下标，对应 dp 值从小到大
        for nxt in range(n):
            i = nxt - 1  # 上一接单项最多是 nxt-1
            if i >= 0 and dp[i] != INF:
                while window and dp[window[-1]] >= dp[i]:
                    window.pop()
                window.append(i)
            # 上一项到当前项之间最多放 lim 个空位 → 下标差 <= lim+1。
            while window and window[0] < nxt - 1 - lim:
                window.popleft()
            if window:
                ndp[nxt] = arr[nxt] + dp[window[0]]
        dp = ndp

    # 队尾空隙 n-1-p_t <= lim：最后一项至少是 n-1-lim。
    start = max(0, n - 1 - lim)
    candidates = [dp[i] for i in range(start, n) if dp[i] != INF]
    print(min(candidates) if candidates else -1)


def run_tests():
    """运行嵌入的官方样例与自加用例，方便本地自测。"""
    import io
    import random

    def run(stdin_text):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io.StringIO(stdin_text)
        sys.stdout = io.StringIO()
        try:
            solve()
            return sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout

    test_cases = [
        # 官方样例 1：7 项里只跑 2 项、lim=1，空隙总数塞不下
        ("9 8 7 6 11 12 10\n2\n1\n", "-1"),
        # 官方样例 2：把 15 放掉，其余全跑
        ("11 4 15 6 8\n4\n3\n", "29"),
        # 官方样例 3：三个 80 各自单独放掉
        ("4 80 4 80 4 80 4\n4\n2\n", "16"),
        # 官方样例 4：空队列直接 0
        ("\n0\n4\n", "0"),
        # t=0：全放掉，n <= lim 才合法
        ("1 2\n0\n2\n", "0"),
        ("1 2 3\n0\n2\n", "-1"),
        # n= t：全接没有任何放掉的段，lim 再小也合法
        ("5\n1\n0\n", "5"),
        # 空隙正好顶着 lim：跳 1 个（lim=1），间隔 2 项合法
        ("1 9 1\n2\n1\n", "2"),
        # lim=0 时跳任何一项都非法：n=3、t=2 必须恰好空 1 格
        ("1 9 1\n2\n0\n", "-1"),
        # 同一轮里 cheaper 的方案胜：只跳 80，不跳 4
        ("80 4\n1\n1\n", "4"),
    ]

    failures = 0
    for i, (inp, expected) in enumerate(test_cases, 1):
        output = run(inp)
        ok = output == expected
        if not ok:
            failures += 1
        print(f"样例 {i}: 期望={expected}, 实际={output} {'✓' if ok else '✗'}")

    # 随机对照：与 2^n 逐掩码枚举的暴力比对 400 组，覆盖 t=0、lim=0、
    # 大 lim、以及「 cheaper 靠后的项被安排上」这类边界。
    rng = random.Random(20260911)

    def brute(arr, t, lim):
        n = len(arr)
        if n == 0:
            return 0
        best = None
        for mask in range(1 << n):
            if bin(mask).count("1") != t:
                continue
            run_len = 0
            ok = True
            for i in range(n):
                if (mask >> i) & 1:
                    run_len = 0
                else:
                    run_len += 1
                    if run_len > lim:
                        ok = False
                        break
            if not ok:
                continue
            cost = sum(arr[i] for i in range(n) if (mask >> i) & 1)
            best = cost if best is None else min(best, cost)
        return -1 if best is None else best

    rand_bad = 0
    for _ in range(400):
        n = rng.randint(1, 11)
        arr = [rng.randint(1, 30) for _ in range(n)]
        t = rng.randint(0, n)
        lim = rng.randint(0, 5)
        expected = brute(arr, t, lim)
        output = run(" ".join(map(str, arr)) + f"\n{t}\n{lim}\n")
        if output != str(expected):
            rand_bad += 1
            print(f"随机对照失败: arr={arr} t={t} lim={lim} 期望={expected} 实际={output}")
    if rand_bad == 0:
        print("随机对照 400 组: 全部一致 ✓")
    failures += rand_bad

    # 极端规模：n=1000、t=500、lim=250（贴着无解边界），必须秒级返回
    import time

    rng.seed(42)
    big_arr = [rng.randint(1, 10000) for _ in range(1000)]
    inp = " ".join(map(str, big_arr)) + "\n500\n250\n"
    start = time.time()
    output = run(inp)
    cost = time.time() - start
    ok = output.lstrip("-").isdigit() and cost < 5
    if not ok:
        failures += 1
    print(f"规模 1000: 实际={output} 耗时 {cost:.2f}s {'✓' if ok else '✗'}")

    if failures:
        raise SystemExit(1)


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

以官方样例 3 为例，`arr = [4, 80, 4, 80, 4, 80, 4]`，`t = 4`，`lim = 2`。空隙检查：放掉 3 项 ≤ (4+1)×2，可能合法。

第 1 层（接 1 项，队首空隙 `p1 <= 2`）：

| i | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
| ------ | --- | --- | --- | --- | --- | --- | --- |
| dp 值 | 4 | 80 | 4 | ∞ | ∞ | ∞ | ∞ |

第 2 层：`dp[nxt] = arr[nxt] + 第 1 层窗口 [nxt-3, nxt-1] 的最小值`：

| i | 1 | 2 | 3 | 4 | 5 | 6 |
| ------ | --- | --- | --- | --- | --- | --- |
| dp 值 | 80+4 | 4+4 | 80+4 | 4+4 | 80+4 | 4+80 |

即 `[∞, 84, 8, 84, 8, 84, 84]`。下标 2 的 8 来自「接 0、2 两项」；下标 4 的 8 同样来自接 0、2 后再接 4。

第 3 层（窗口 `[nxt-3, nxt-1]` 内取上一层最小）：

| i | 2 | 3 | 4 | 5 | 6 |
| ------ | --- | --- | --- | --- | --- |
| dp 值 | 4+84 | 80+8 | 4+8 | 80+8 | 4+8 |

第 4 层只在最终检查需要的范围内看：`i >= n-1-lim = 4`，最后接在 6 时取第 3 层窗口 `[3, 5]` 的最小值 8（下标 4 处的两项方案），得 `4 + 8 = 16`——正是 `0, 2, 4, 6` 四项全跑、三个 80 各自单独放掉的路径。三层窗口一路把「间隔必须 ≤ 3」编码进了候选筛选，最优路径不需要任何回溯寻找。

样例 2（`t=4, lim=3`）的钥匙在下标 2：放掉 15 是唯一能降耗的动作，第 4 层填出 `8 + 21 = 29`；样例 1（`t=2, lim=1`）在提前判定处直接 `-1`：放掉 5 项 > 3 个空隙 × 1。样例 4 由空首行走进空队列分支，输出 0。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 逐掩码枚举跑/放组合 | $O(2^n)$ | $O(n)$ | `n = 1000` 时 2^1000 个方案，不可行 |
| 分层 DP，每层逐候选线性扫窗口 | $O(n \cdot t \cdot \lim)$ | $O(n \cdot t)$ | 上限 1e9 级比较，Python 超时 |
| 分层 DP + 单调队列滑动窗口（最优） | $O(n \cdot t)$ | $O(n)$ | 每个下标至多进队、出队一次，本题采用 |

## 易错点总结

### 1. 「连续放掉 ≤ lim」写错成「下标差 ≤ lim」

下标条件是 `p_{j+1} - p_j <= lim + 1`（中间空了 `p_{j+1} - p_j - 1` 个），队首是 `p1 <= lim`。单调队列的过期检查写成 `window[0] < nxt - 1 - lim` 与第 1 层的 `i <= lim` 是这两条的直接编码；若把 +1 丢掉，间隔恰好顶满 `lim` 的合法方案会被误杀——`1 9 1 / 2 / 1`（跳过中间 9 的最优解）会错误输出 `-1`。

### 2. 第 1 层漏掉队首空隙约束

初始化 `[arr[i] if i <= lim else INF]` 里的 `i <= lim` 对应「跑第一项之前连续放掉 `p1` 个」。漏掉它后，队首插进超限长度的放掉段照样算合法：输入 `5 1 1` / `t=1` / `lim=0` 本应因「p1 ≤ 0 与队尾空隙 0 同时成立」无解输出 `-1`，漏约束会输出 `1`。

### 3. 「恰好 t 个」滑成「至多 t 个」

DP 是逐层推进的，若在每一层结束都顺手取全局最小，第 1 层就能抢答：样例 2 会在只接 1 项（耗时 4）时就输出，而不是恰好 4 项的 29。层数必须跑满 `t - 1` 次，收尾只在最后一层上取值。

## 扩展思考

这条 DP 的形状是「逐件决策 + 相邻选择间隔下界」，与「带冷却期的股票买卖」「不能连选 k 个的最大子序列和」同族。若需求反过来变成「连续放掉合计耗时 ≤ cap」，窗口的键从下标换成已累计的放掉耗时，状态多一维但骨架不变；「恰好 t 个」换成「至多」，则把最后一层换成逐层累计取最小。
