# P5614. 双十一最低实付

> 场次：2026年10月10日-非AI方向 · 来源：[CodeFun2000 P5614](https://codefun2000.com/p/P5614)

## 题目描述

临近双十一，小明打算采买一批货物。其中 $a$ 件属于非买不可，另外 $b$ 件是可加可不加的凑单货。他手里同时还攥着 $c$ 张券，每一张都标明了种类（减钱或者打折）以及启用条件。请算出小明把账结清时，实际掏出的钱最少能压到多少。

规则说明：

1、货物怎么买：

- 凡是非买不可的货，都要一件不落地全部拿下。
- 凑单货由你决定放进或不放进购物车，同一件至多放进一次。

2、券怎么启用：

- 每一张券至多启用一次，也可以整张弃用。
- 启用的先后允许自行排列，应当找出让实付最小的那种次序。
- 每张券带一个启用条件 $g$（正整数）。意思是，套用它的前一刻，订单现价得满足 $\geq g$，不然这张就不能套用。

3、券分成哪两类：

- $f = 0$：减钱券。套用之后，把现价立刻扣掉 $d$（正整数）。
- $f = 1$：打折券。套用之后，现价改写成 $\text{floor}(\text{现价} \times d / 100)$，也就是把小数直接舍掉。
- 注意：一张券生效完毕，算出来的新现价，会变成后面其余券的对照基准。

## 输入格式

第一行给出三个整数 $a$、$b$、$c$（$1 \le a \le 10$，$0 \le b \le 10$，$0 \le c \le 5$）。

紧随其后单独一行，写下 $a$ 个整数，依次是非买不可那些货的标价（单个标价 $\le 1000$）。

再往后一行，写下 $b$ 个整数，依次是凑单货的标价（单个标价 $\le 1000$）。当 $b = 0$ 时，这一行直接省掉。

最后还有 $c$ 行，每一行对应一张券，书写次序是 $f$、$g$、$d$。

$f$ 只允许取 $0$ 或者 $1$。

$g$ 和 $d$ 都得是正整数（若该券属于打折，则 $d$ 代表折扣比例，比如写 $80$ 就是按八折计）。

## 输出格式

交出一行，里面只放一个整数，代表结账最少要掏的钱。

## 提示

提示

1、要是全部选定的券都套完后，现价掉成了负数，交卷时改记成 $0$。

## 示例

### 示例 1

**输入：**

```
2 1 2
80 40
30
0 150 40
1 100 80
```

**输出：**

```
88
```

**说明：**

只拿非买不可的两件，标价相加是 $80 + 40 = 120$。减钱券要现价至少 $150$，此刻用不上；打折券可以套，$120 \times 80 / 100 = 96$。

把标价 $30$ 的凑单货也放进去，现价变成 $150$。先扣掉 $40$ 得到 $110$，再按八折得到 $\lfloor 110 \times 80 / 100 \rfloor = 88$。若先打八折得到 $120$，就够不着减钱券的条件，实付停在 $120$。只扣不折是 $110$，只折不扣是 $120$。这几种结法里最小的是 $88$。

### 示例 2

**输入：**

```
2 1 2
60 40
20
0 100 30
1 80 50
```

**输出：**

```
45
```

**说明：**

非买不可的两件合计 $60 + 40 = 100$。这时先按五折计算得到 $50$，减钱券的条件就达不到；先扣掉 $30$ 得到 $70$，五折券要求现价至少 $80$，同样套不上。所以只拿这些必买货，最好是 $50$。

再放入标价 $20$ 的凑单货，现价升到 $120$。先扣掉 $30$ 得到 $90$，接着按五折得到 $\lfloor 90 \times 50 / 100 \rfloor = 45$。先按五折会得到 $60$，减钱券要求的 $100$ 够不着。因此实付最少是 $45$。

## 解题思路

### 输出的判定标准：先选货、再定券的次序，取最小实付

题目要的是一个整数：结账时最少掏多少钱。影响答案的决定有两层：

1. 凑单货每一件「放」或「不放」，必买货必须全放；
2. 每张券「用」或「不用」，用的那些还要排一个次序。

现价是一条随次序变化的链：先把选中的商品标价相加，之后每启用一张券，现价就更新一次，而更新后的数字就是下一张券的门槛判断基准。减钱券要求启用前现价 $\ge g$，再减去 $d$；打折券要求启用前现价 $\ge g$，再把现价改成 $\lfloor \text{现价} \times d / 100 \rfloor$。所有想用的券走完后，若现价为负，按 $0$ 记账。

这里最容易被忽略的是「次序本身是答案的一部分」。同样两张券，先减后折和先折后减不仅结果不同，还可能让后一张券直接够不着门槛。样例 1 中 150 元先减 40 得 110，再八折得 88；若先八折得 120，减钱券要求 150，反而用不了了。所以不能把券当成一个可以随意排序的集合来算，必须把次序纳入搜索。

### 凑单货只改变起点的总价

凑单货最多 10 件，每件只有「放/不放」两种状态，枚举量是 $2^b \le 1024$。更重要的是，它们对后面所有券的影响完全压缩成一个数：起点的现价 = 必买总价 + 选中凑单货的标价之和。至于具体选了哪几件，券并不关心。

于是可以先把这个起点集合算出来：

- 从 `base`（必买总价）出发；
- 每遇到一件凑单货 `p`，把「原来的每个总价」和「原来的每个总价 + p」都并进集合；
- 用集合去重，相同总价只处理一次。

这一步在代码里是 `sums |= {s + p for s in sums}`：集合推导式先按旧的 `sums` 算完，再整体并回去，所以每件凑单货恰好把集合翻一倍，不会漏掉「不放」的那一支。

有了起点集合，每个起点就可以独立地走券的流程，最后在所有起点的结果里取最小。这里不能只留最小的起点：起点小意味着更容易被券的门槛卡住。样例 1 里起点 120 最好只能到 96，而起点 150 能到 88——多花 30 元买凑单货反而更省。

### 为什么是「已用券集合」上的状态展开

券最多 5 张。如果直接枚举「用哪些券 + 按什么顺序」，有序子集的总数是 $\sum_{k=0}^{c} \frac{c!}{(c-k)!}$，$c=5$ 时等于 $1+5+20+60+120+120=326$，每个起点模拟一遍也完全跑得动。

代码采用的是等价、但会合并重复过程的做法：用二进制 `mask` 记录「已经用了哪些券」，`states[mask]` 保存「用这个集合里的券、以各种顺序走到的所有现价」。

- 从 `mask` 出发，任选一张还没用过的券 `k`；现价满足门槛就套用，把新现价放进 `mask | (1 << k)`；
- `mask` 从 $0$ 递增到 $2^c-1$，而 `mask | (1 << k)` 一定严格大于 `mask`，所以按整数递增遍历时，任何状态被处理之前，能走到它的前驱都已经处理完，一遍扫描即可，不需要队列；
- 每个 `mask` 都是合法终态（剩下的券全部弃用），所以答案是所有 `mask` 下所有现价的最小值，负数记 0。

关键点在于「每个 `mask` 要保留全部可达现价，不能只留最小的那个」。门槛让「现价更大」有时反而更有用。比如起点 150 元，券 A 是满 50 打五折、券 B 是满 90 打五折、券 C 是满 60 减 30：

- 先 B 再 C：$150 \to 75 \to 45$，此时 A 要 50，45 过不去；
- 先 C 再 B：$150 \to 120 \to 60$，60 能过 A 的 50，五折后是 30。

同样是「B 和 C 都用过」的集合，现价 45 和 60 并存，只留较小的 45 就把 30 这条路剪掉了。代码把 `states[mask]` 定义成 `set`，就是为了不丢这些看似更差的中间值。

### 到代码的映射

- 读入用 `sys.stdin.buffer.read().split()` 一次取完所有 token（69 行），`b = 0` 时第三行整行不存在，按 token 顺序读不会错位；
- 起点：74~76 行累加必买总价，79~82 行用集合倍增求出所有凑单子集和；
- 状态展开：93 行 `states = {0: {start}}`，94~110 行按 `mask` 递增推进，104 行 `if price < g` 是门槛，106~109 行分别计算减钱与打折，110 行把新现价并入对应的 `mask`；
- 终态：112~116 行遍历每个 `mask` 下的每个现价，114 行 `cand = p if p > 0 else 0` 负责把负数压成 0。

## 完整代码实现

```python
"""
P5614. 双十一最低实付 - 子集枚举 + 已用券集合上的动态规划

小明必买 a 件商品（标价给定），凑单货 b 件可选可不选，手上有 c 张券。
结账时先相加选中的商品价得到"现价"，再按选定次序启用若干张券：
- f=0 减钱券：现价减 d，启用前要求现价 >= g；
- f=1 打折券：现价改为 floor(现价 * d / 100)，启用前同样要求现价 >= g；
- 每张券至多启用一次，也可以整张不用；券的新现价是后续券的对照基准。
求实付最少的钱；全部用完后若现价为负按 0 结账。

输入格式：
- 第一行 a b c（a<=10, b<=10, c<=5）；
- 第二行 a 个必买标价；第三行 b 个凑单标价（b=0 时省略）；
- 最后 c 行，每行 f、g、d。

输出格式：
- 一个整数：结账最少要付的钱。

核心思路：
1. 数据范围就是提示：a+b<=20、c<=5。凑单货只有"选/不选"，它们的
   总贡献完全体现在"现价"这一个数上，所以先把 2^b 个子集收敛成
   不同的现价和（最多 2^b 个），再对每个现价单独处理券。
2. 券的数量 <= 5，启用顺序影响结果（同样两张券，先减钱再打折与
   先打折再减钱、以及减钱是否凑到 g 之上都会改变后一张能否启用），
   因此用"已启用券集合"的状态做展开：states[mask] 是用集合 mask 里
   的券、以某个现价起点能到达的全部现价。同一 mask 下现价越小
   未必更好——打折券要求现价 >= g，低现价可能锁死高折扣，
   所以状态保留全部可达现价，不能贪心剪枝。
3. 终态取所有 mask 的所有可达现价的最小值（含 mask=空，即一张券
   都不用），负数按题面记 0。

时间复杂度：O(2^b * 2^c * c) 次状态展开，c<=5 时再乘可达现价的小常数
空间复杂度：O(2^b * 2^c)
"""

# https://codefun2000.com/p/P5614
import sys

# @sample-start
"""
样例输入 1:
2 1 2
80 40
30
0 150 40
1 100 80

样例输出 1:
88
"""
# @sample-end

# @sample-start
"""
样例输入 2:
2 1 2
60 40
20
0 100 30
1 80 50

样例输出 2:
45
"""
# @sample-end


def solve():
    data = sys.stdin.buffer.read().split()
    it = iter(data)
    a, b, c = int(next(it)), int(next(it)), int(next(it))

    # 必买商品全部拿下；现价起点是它的总价
    base = 0
    for _ in range(a):
        base += int(next(it))

    # 凑单货的 2^b 个子集只通过"现价和"影响结果；起点 = 必买总价 + 子集和
    opt = [int(next(it)) for _ in range(b)]
    sums = {base}
    for p in opt:
        sums |= {s + p for s in sums}

    coupons = []
    for _ in range(c):
        f, g, d = int(next(it)), int(next(it)), int(next(it))
        coupons.append((f, g, d))

    INF = float("inf")
    best = INF
    for start in sums:
        # mask -> 用启用集合 mask 后所有的可达现价
        states = {0: {start}}
        for mask in range(1 << c):
            if mask not in states:
                continue
            for price in states[mask]:
                if price <= 0:
                    continue  # 现价已到 0/负：现价 < 任何正整数 g，无券可再启用
                for k in range(c):
                    if mask & (1 << k):
                        continue
                    f, g, d = coupons[k]
                    if price < g:
                        continue  # 启用条件：套用前一刻现价 >= g
                    if f == 0:
                        nxt = price - d
                    else:
                        nxt = price * d // 100
                    states.setdefault(mask | (1 << k), set()).add(nxt)
        # 任何一张券都可以弃用：每个 mask 都是合法终态
        for prices in states.values():
            for p in prices:
                cand = p if p > 0 else 0
                if cand < best:
                    best = cand

    print(best)


def run_tests():
    """官方样例 + 边界/变形用例。"""
    import io

    test_cases = [
        # 官方样例 1：凑单到 150 先减后折 = 88
        ("2 1 2\n80 40\n30\n0 150 40\n1 100 80\n", "88"),
        # 官方样例 2：凑单到 120，先减 30 再打五折 = 45
        ("2 1 2\n60 40\n20\n0 100 30\n1 80 50\n", "45"),
        # b=0：无第二行凑单货；无券可用 -> 原价
        ("2 0 1\n60 40\n0 200 10\n", "100"),
        # 减钱券直接把现价扣成负数，按 0 结账
        ("2 0 1\n60 40\n0 1 500\n", "0"),
        # 现价 0 时任何券都不能启用（g 为正整数）：先减到 0，打折券被门槛卡死
        ("2 0 2\n50 50\n0 1 100\n1 1 100\n", "0"),
        # 同一 mask 有多个可达现价时，"只留最小现价"会剪掉能过后续门槛的那条：
        # mask{减钱,打折} 下 70（减完）与 80（先折）并存，减钱第 2 张要现价 80 才能到 30
        ("1 0 3\n100\n0 100 30\n1 100 80\n0 80 50\n", "30"),
        # 顺序决定胜负：先打折跌穿减钱券的门槛（50<60），先减钱再打折 = 35
        ("2 0 2\n55 45\n0 60 30\n1 50 50\n", "35"),
        # 折一先扣后折：先减 20 到 110 打九折 = 99；先折到 117 反而扣不动
        ("2 0 2\n80 50\n0 125 20\n1 100 90\n", "99"),
    ]

    for i, (inp, expected) in enumerate(test_cases, 1):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io.TextIOWrapper(io.BytesIO(inp.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            output = sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout
        status = "✓" if output == expected else "✗"
        print(f"样例 {i}: 期望={expected}, 实际={output} {status}")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

以样例 1 为例：$a=2,\ b=1,\ c=2$，必买货 80、40，凑单货 30；券 0 是「满 150 减 40」，券 1 是「满 100 打八折」。

1. 必买总价 `base = 80 + 40 = 120`。凑单货只有一件，起点集合是 `{120, 150}`——不放是 120，放是 150。
2. 起点 120：
   - 券 0 要求 150，$120 < 150$，跳过；
   - 券 1 要求 100，$120 \ge 100$，$\lfloor 120 \times 80 / 100 \rfloor = 96$；
   - 从 96 出发，券 0 仍然要求 150，过不去；券 1 已经用过。
   - 这个起点能到达的现价是 `{120, 96}`，最好 96。
3. 起点 150：
   - 券 0：$150 \ge 150$，$150 - 40 = 110$；
   - 券 1：$150 \ge 100$，$\lfloor 150 \times 80 / 100 \rfloor = 120$；
   - 从 110 出发用券 1：$110 \ge 100$，$\lfloor 110 \times 80 / 100 \rfloor = 88$；
   - 从 120 出发用券 0：$120 < 150$，过不去；
   - 从 88 出发已经没有没用过的券。
   - 这个起点能到达的现价是 `{150, 110, 120, 88}`，最好 88。
4. 所有起点取最小：$\min(96, 88) = 88$。

这里最关键的一步是「先减后折」：减完剩 110，仍然在八折券要求的 100 以上，所以第二张券还能用；如果先打八折得到 120，虽然 120 也够 100，但再想用减钱券时 $120 < 150$，减钱券就废了。同一组券换个顺序，能走通的路完全不同。

样例 2 是同样的结构：只买必买货时起点 100，先减 30 到 70 够不着五折券的 80，先五折到 50 又够不着减钱券的 100，最好 50；加上 20 的凑单货把起点抬到 120，先减 30 到 90、再五折得 45。多买一件反而少付 5 元。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 每个 mask 只留最小现价（贪心剪枝） | $O(2^b \cdot 2^c \cdot c)$ | $O(2^b + 2^c)$ | 更快，但门槛会让更大的中间现价通向更小的终值，反例见易错点 2 |
| 子集和 + 保留全部可达现价的状态展开（最优） | $O(2^b \cdot 2^c \cdot c \cdot c!)$ | $O(2^b + 2^c \cdot c!)$ | 每个 mask 至多 $c!$ 个现价，本题采用 |

$b \le 10$、$c \le 5$ 时，$2^b = 1024$、$2^c = 32$、$c! = 120$，上界约两千万次状态操作，实际可达现价远少于上界。

## 易错点总结

### 1. 门槛比较写成 `<=`

104 行 `if price < g: continue` 用的是严格小于：现价恰好等于 $g$ 时券可以使用。若写成 `price <= g`，样例 1 里起点 150 刚好卡在减钱券的门槛 150 上，这张券会被判成不可用，答案从 88 变成 96。

### 2. 每个 `mask` 只保留最小现价

110 行 `states.setdefault(mask | (1 << k), set()).add(nxt)` 把同一个 `mask` 下的所有现价都留在集合里。若改成只存一个最小值，下面这组数据会算错：

```
2 0 3
100 50
1 50 50
1 90 50
0 60 30
```

起点 150。正确的一条路是 C→B→A：$150 \to 120 \to 60 \to 30$（C 减 30、B 五折、A 五折）。走到「B、C 都用过」时，现价有 45 和 60 两个：45 过不了 A 的门槛 50，60 可以。只留最小现价会把 60 丢掉，最后输出 37 而不是 30。

### 3. 只在「所有券都用过」时更新答案

112~116 行遍历的是 `states` 里的**每一个** `mask`，因为每张券都可以弃用。若只检查 `states[(1 << c) - 1]`，当没有一张券能用时（比如 `2 0 1 / 60 40 / 0 200 10`，唯一的券要求现价 200），满 `mask` 根本不存在，`best` 停留在 `float("inf")`，最后打印出 `inf` 而不是 100。

## 扩展思考

$c$ 再大一些（比如 15），$2^c$ 个 `mask` 和每个 `mask` 下的 $c!$ 种现价都装不下，这时要换思路；本题把 $c$ 限制在 5，就是在告诉你枚举可行。若 $b$ 放大到 20 以上，凑单子集和要改成折半枚举（meet-in-the-middle），但券的处理方式不变。
