# P5918. 落选加价成交额

> 场次：2026年10月14日-非AI方向 · 来源：[CodeFun2000 P5918](https://codefun2000.com/p/P5918)

## 题目描述

证券交易所里，买进与卖出两方递出的委托单，要依照开价高低和递单早晚完成配对，配上了才记入成交。本所执行的配对办法如下：

1. **买方配对办法：** 买方委托单按递出的先后，逐笔进入配对。选中的卖方，开价不得超过这位买方的出价，而且要和该出价**隔得最近**。倘若卖方开价全部高于这位买方的出价，这位买方的委托单就先跳过。
2. **卖方权益：** 若仍有开价比本笔成交价更便宜的卖方委托单，只因隔得更远而本轮未被挑中，这些未被挑中的低开价卖方委托单可以把开价上调，每错过一轮上调 $w$ 元。
3. **配对数量：** 双方按手数更少的一边成交，尚未配对的剩余手数留到后一轮继续（后一轮一样要执行上面第 $2$ 条）。

请根据所给的卖方委托单与买方委托单，求出**最终计入的成交额**：每笔配对成功的「开价乘以手数」全部累加。

**补充说明：** 卖方权益还有一类错过但不许上调的情形——两笔卖方开价相同，没被挑中的那笔同价卖方委托单**不许**上调。多笔开价并列且都是当前最高时，取更早递出的那一笔。

## 输入格式

数据经由标准输入进入程序。

- 首行给出整数 $w$（$0 \le w \le 10^9$），表示每错过一轮的上调幅度。
- 次行给出整数 $a$（$0 \le a \le 10^4$），表示卖方委托单有多少笔。
- 其后 $a$ 行，一行写两个整数，依次是这笔卖方委托单的**开价**与**手数**。
- 然后一行给出整数 $b$（$0 \le b \le 10^4$），表示买方委托单有多少笔。
- 其后 $b$ 行，一行写两个整数，依次是这笔买方委托单的**开价**与**手数**。

开价和手数都位于区间 $[1, 10^9]$。

## 输出格式

- 打印一个整数，即最终计入的成交额，也就是每笔配对成功的「开价乘以手数」之和。

## 示例

### 示例 1

**输入：**

```
5
3
6 2
6 1
2 1
1
15 4
```

**输出：**

```
30
```

**说明：**

- 卖方甲：开价 $6$，手数 $2$
- 卖方乙：开价 $6$，手数 $1$
- 卖方丙：开价 $2$，手数 $1$
- 买方：出价 $15$，手数 $4$，上调幅度 $5$

**配对过程：**

- **第 $1$ 轮：** 甲、乙开价都是 $6$，取更早的甲。成交价 $6$，成交 $2$ 手。乙同价不上调，丙上调到 $7$
- **第 $2$ 轮：** 乙隔了 $9$，丙隔了 $8$，丙更近，成交价 $7$。乙上调到 $11$
- **第 $3$ 轮：** 乙开价 $11$，成交价 $11$
- **合计：** $6 \times 2 + 7 + 11 = 30$

### 示例 2

**输入：**

```
2
4
5 4
9 2
14 1
30 1
3
8 3
16 1
12 4
```

**输出：**

```
60
```

**说明：**

1. 出价 $8$、手数 $3$ 的买方，配上开价 $5$、手数 $4$ 的卖方，成交 $3$ 手，开价 $5$，金额 $15$。该卖方还剩 $1$ 手，没有更便宜的开价需要上调。
2. 出价 $16$、手数 $1$ 的买方，配上开价 $14$ 的卖方，成交 $1$ 手，金额 $14$。开价 $5$ 与 $9$ 都低于 $14$，各上调 $2$，变成 $7$ 与 $11$。
3. 出价 $12$、手数 $4$ 的买方，先配开价 $11$、手数 $2$ 的卖方，成交 $2$ 手，金额 $22$。开价 $7$ 再上调 $2$，变成 $9$。
4. 该买方还剩 $1$ 手，再配开价 $9$ 的剩余 $1$ 手，成交价 $9$，金额 $9$。开价 $30$ 高于出价，配不上。

合计 $15 + 14 + 22 + 9 = 60$。

## 解题思路

### 把配对办法逐条翻译成判定标准

这题的困难不在算法在规则。把题面拆成四条可执行的判定：

1. **选谁**：每一轮在「开价 $\le$ 该买方出价」的卖方里挑开价最贵的一笔——开价离出价隔着最近；开价并列且同为当前最高时，**递单更早**的胜出。
2. **记多少**：成交手数取双方剩余手数的较小值；成交额按**成交那一刻卖出方的当前开价**入账，示例 1 第三轮按上调后的 11 记账，说明一定是当前价而不是买方出价。
3. **谁进下一轮**：谁还有剩余手数谁继续；某买方在某一轮挑不到任何开价不超过其出价的卖方，整笔委托就此跳过。
4. **上调**：每一轮（每一次成交）结束后，所有**仍有手数**且开价**严格低于**成交价的卖方 $+w$；同价落选的不许上调，开价更高的不动。

第 4 条里「买方手数已经耗尽但上调照做」在示例 2 第二步有明证：出价 16 的买方只成交 1 手就整笔结束，而开价 5、9 仍比照规则上调成 7、11——上调跟着**这一轮**走，不跟买方的下一轮走。

### 关键观察：轮次有上界，线性扫描够用

一笔配对消耗「买方剩余与卖方剩余的较小值」。消耗后买方剩余归零，或卖方手数用尽从此退场——**每一轮必然终结一个买方或一笔卖方**，总轮数不超过 $a+b$。轮内动作是「在卖方列表里挑合法的最高价」，一趟线性扫描即可，整体 $O((a+b)\cdot a)$，对 $a, b \le 10^4$ 的机考规模畅通无阻。有序表、堆这些更精致的结构在这里只是增加出错面积：挑最高价与批量上调各扫一趟，比维护有序结构便宜得多。

### 实现映射

- 卖方池**保持递单顺序**：挑人比较用严格大于（`s[0] > best[0]`），先扫描到的就是更早递单的——并列裁定就落在这一个不等号上；
- 上调循环被两个条件同时把守：`s[1] > 0` 且 `s[0] < 成交价`；$w = 0$ 时整段直接跳过；
- 性能上的最后一处是惰性压缩：配完的卖方不立刻删，计数压过半时一次性把它们清出列表，扫描长度不虚长；删的只是尾部，顺序不变，并列裁定不受影响。

"""
P5918. 落选加价成交额 - 按规则逐轮模拟

买方委托按递单先后依次配对。每一轮在「开价不超过该买方出价」的
卖方里，挑开价最高的那笔（与出价隔得最近）；开价并列且都是当前
最高时取更早递出的。双方按手数较少的一边成交，成交额累加
「成交价 × 手数」。每轮结束后，所有仍有手数、且开价严格低于本笔
成交价的卖方把开价上调 w 元；同价没被挑中的不上调，开价高于成交价
的不动。某买方一轮里挑不到任何开价不高于其出价的卖方时跳过。

输入格式：
- 第 1 行：w（每错过一轮的上调幅度）；
- 第 2 行：a，随后 a 行「开价 手数」；
- 然后一行：b，随后 b 行「开价 手数」（买方按递单先后）。

输出格式：
- 一个整数：全部配对成功的「开价乘手数」之和。

核心思路：
每笔买方委托在剩余手数用完或无可配卖方之前反复进入下一轮；每轮
挑一次、成一次交、上调一次。每收掉一整笔卖方或耗完一个买方才
进入下一轮，总轮数不超过 a + b，逐轮线性扫描卖方列表即可。

时间复杂度：O((a + b) * a) 次卖方扫描；现实数据规模下绰绰有余
空间复杂度：O(a + b)
"""

def match_total(w, sellers, buyers):
    """按配对办法逐轮模拟，返回最终成交额。sellers/buyers 为 (开价, 手数)。"""
    pool = [[p, q] for p, q in sellers]  # [当前开价, 剩手数]，保持递单顺序
    total = 0
    died = 0  # 自上次压缩起配完卖出的笔数，只堆不压缩会让扫描越来越长

    for buy_price, buy_qty in buyers:
        while buy_qty > 0:
            # 挑开价不超过出价且最高的卖方；先扫描到的（递单更早）
            # 在同价时胜出
            best = None
            for s in pool:
                if s[1] > 0 and s[0] <= buy_price:
                    if best is None or s[0] > best[0]:
                        best = s
            if best is None:
                break  # 剩余卖方开价全部高于出价，本买方跳过

            deal = buy_qty if buy_qty < best[1] else best[1]
            total += best[0] * deal
            buy_qty -= deal
            best[1] -= deal

            # 本轮错过且开价严格低于成交价的卖方上调 w；同价不上调
            if w:
                price = best[0]
                for s in pool:
                    if s[1] > 0 and s[0] < price:
                        s[0] += w

            if best[1] == 0:
                died += 1
                if died >= 64 and died * 2 >= len(pool):
                    pool = [s for s in pool if s[1] > 0]
                    died = 0
    return total


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    pos = 0
    w = int(data[pos]); pos += 1
    a = int(data[pos]); pos += 1
    sellers = []
    for _ in range(a):
        sellers.append((int(data[pos]), int(data[pos + 1])))
        pos += 2
    b = int(data[pos]); pos += 1
    buyers = []
    for _ in range(b):
        buyers.append((int(data[pos]), int(data[pos + 1])))
        pos += 2
    print(match_total(w, sellers, buyers))

def run_case(text):
    """把一段输入喂给 solve()，取回输出。"""
    old_stdin, old_stdout = sys.stdin, sys.stdout
    sys.stdin = io.TextIOWrapper(io.BytesIO(text.encode("utf-8")))
    sys.stdout = io.StringIO()
    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin, sys.stdout = old_stdin, old_stdout


def reference_total(w, sellers, buyers):
    """独立实现：每轮都用完整排序表重新挑，逻辑同题面但写法不同。"""
    book = [[p, q, i] for i, (p, q) in enumerate(sellers)]
    total = 0
    for buy_price, buy_qty in buyers:
        while buy_qty > 0:
            alive = [s for s in book if s[1] > 0 and s[0] <= buy_price]
            if not alive:
                break
            # 开价最高者胜；并列时递单序号最小者胜
            pool_price = max(s[0] for s in alive)
            chosen = min((s for s in alive if s[0] == pool_price), key=lambda s: s[2])
            deal = min(buy_qty, chosen[1])
            total += chosen[0] * deal
            buy_qty -= deal
            chosen[1] -= deal
            if w:
                for s in book:
                    if s[1] > 0 and s[0] < chosen[0]:
                        s[0] += w
    return total


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()

## 示例推演

样例 1：卖方甲 $(6,2)$、乙 $(6,1)$、丙 $(2,1)$，买方出价 15、手数 4，$w=5$。

| 轮 | 候选（当前开价） | 选谁 | 成交 | 上调 |
| -- | --------------- | ---- | ---- | ---- |
| 1 | 甲 6、乙 6、丙 2 | 甲（同价取更早） | $6\times2$，买剩 2 | 乙同价不动；丙 $2<6$ 升到 7 |
| 2 | 乙 6、丙 7 | 丙 | $7\times1$，买剩 1 | 乙 $6<7$ 升到 11 |
| 3 | 乙 11 | 乙 | $11\times1$，双方耗尽 | 无更低价者 |

合计 $12+7+11=30$。第 2 轮最能看出上调的字面效果：丙的成交价用的是**上调后**的 7，乙被丙这一轮挤下去后才涨到 11、在第 3 轮按新价成交。

样例 2 的关键节点：出价 8 的买方先按 5 配走 3 手（卖方还剩 1 手）；出价 16、只买 1 手的买方与开价 14 的卖方整笔两清后，手数为零——但开价 5、9 仍**低于本笔成交价**，照规则各涨 2 变 7、11。之后出价 12 的买方先按 11 配 2 手（22），再按涨到 9 的那笔配 1 手（9）；30 那笔从头到尾无人可配。合计 $15+14+22+9=60$。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 每轮把卖方重新完整排序再挑 | $O((a+b) \cdot a \log a)$ | $O(a)$ | 结论不变，重复排序纯属浪费 |
| 保持递单顺序的线性扫描轮（最优） | $O((a+b) \cdot a)$ | $O(a+b)$ | 总轮数 $\le a+b$，每轮一趟扫描；本题采用 |

## 易错点总结

### 1. 并列裁定用对不等号

挑人比较应写严格大于 `s[0] > best[0]`。写成 `>=` 时，同价并列里**更晚**递单的一笔反而胜出——示例 1 第一轮的甲/乙直接互换，本轮总额未必变，但剩余的手数落在谁头上全变，多轮样例立刻算错。

### 2. 上调把「同价落选」也涨了

上调条件是 `s[0] < 成交价`。写成 `<=` 时同价没被挑中的卖方违规上调：示例 1 第一轮乙 6 升成 11，第二轮的最高开价被 11 抢走，总额从 30 变成 $12+11=23$。

### 3. 成交额按买方出价记账

总额记的是卖方**当前开价**（可能被上调过）。误写成 `total += buy_price * deal` 时，样例 1 的四手全部按出价 15 入账，输出 $60$——与正确答案 30 的差额逐笔对得上，一看就知道错在记账价。

## 扩展思考

若买方委托不是静态队列而是随到随配，或上调幅度按错过的轮数累积，规则第 1、4 条会复杂一些，但「每轮终结一个买方或一笔卖方」的轮次上界仍然成立，逐轮扫描的骨架可以沿用。真正要扩到场外规模（$10^6$ 级委托）时，才值得把卖方放进恰当的有序结构里做后继查询与懒标记上调。
