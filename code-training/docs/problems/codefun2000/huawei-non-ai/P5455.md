# P5455. 推理设备覆盖

> 场次：2026年9月16日-非AI方向 · 来源：[CodeFun2000 P5455](https://codefun2000.com/p/P5455)

## 题目描述

要把大模型推理服务拉起来，先得把业务跑通。台数越少，开销和运维负担越轻。

业务侧会点名一批能力条目；机架上的每台机器也会自带若干能力条目。入选集合必须让业务点名的每一条，都出现在至少一台机器上。

资源紧张时，请给出仍能凑齐全部条目的最小台数。

## 输入格式

首行三个正整数 $d$、$w$、$t$，依次为机器台数、每台登记的条目个数、业务点名的条目个数（$d \le 30$，$w \le 10$，$t \le 20$）。

随后 $d$ 行，每行 $w$ 个整数，即该台机器具备的条目编号。

末行 $t$ 个互异整数，即业务点名的条目编号。

$d,w,t$ 都取正整数。

## 输出格式

输出一个整数：最少要启用几台。若怎样挑都凑不齐，输出 $0$。

## 示例

### 示例 1

**输入：**

```
4 2 3
2 8
3 5
8 9
5 2
2 5 8
```

**输出：**

```
2
```

**说明：**

四台机器的条目分别是 $\{2,8\}$、$\{3,5\}$、$\{8,9\}$、$\{5,2\}$，业务点名 $\{2,5,8\}$。

- 单台都缺至少一条
- 第 $1$ 台加上第 $4$ 台正好凑齐，台数为 $2$

### 示例 2

**输入：**

```
2 3 4
1 2 3
4 5 6
10 11 12 13
```

**输出：**

```
0
```

**说明：**

两台机器只有 $1$ 到 $6$，业务点名 $10$ 到 $13$，任意组合都缺条目，故为 $0$。

### 示例 3

**输入：**

```
3 1 1
9
8
9
9
```

**输出：**

```
1
```

**说明：**

三台各带一条；业务只要 $9$，第 $1$ 台或第 $3$ 台单独即可，最少台数是 $1$。

## 解题思路

### 判定标准：带无解出口的最小覆盖

题面要两个东西：最少启用几台；怎样挑都凑不齐时输出 0。这是标准的最小集合覆盖——每台机器提供一个条目集合，业务点名的 $t$ 条必须全部被盖住，目标是最小化启用台数——外加一个显式的无解出口：某条点名条目可能任何机器都没登记过，此时不能报错、也不能给一个凑合的数，只能输出 0。

### 数据范围决定把状压放在哪一侧

机器侧 $d\le30$：枚举机器子集是 $2^{30}\approx10^9$，不可行。条目侧 $t\le20$：一个方案「已覆盖了哪些点名条目」只有 $2^{20}\approx10^6$ 种。两侧只有一边装得下——把覆盖集合做成状态、机器逐台往里并，就是状压 DP 的方向。这条分界同样划掉了自然的第一反应「每轮挑新覆盖条目最多的机器」：集合覆盖的贪心只有对数近似保证，覆盖结构相错的输入会多启用台数（易错点里有一个两台就够、贪心要三台的反例）。

### 为什么按层扩展能拿到最小台数

每台机器对覆盖集合的贡献是按位并 $s \mapsto s\mid c$：只增不减，而且幂等（$c\mid c=c$，同一台并两次不新增任何覆盖，不存在重复计费）。于是用 $k$ 台机器能凑出的覆盖集合，就是「$k-1$ 层的每个状态并上每台机器掩码」的并集；按层扩展，$full=(1\ll t)-1$ 第一次出现在第几层，答案就是几。某层扩展不出任何新状态而 $full$ 仍缺席，说明缺席的比特从未被任何机器提供，输出 0。

### 实现落点

- 条目编号不连续（样例 1 里同时出现 2、3、5、8、9），点名条目到比特的映射集中在 `bit_of` 一处；扫机器条目时 `bit_of.get(v)` 拿不到就丢弃——与业务无关的条目不占比特、不参与判定。
- `masks` 用集合收集非零掩码：条目集合相同的机器只留一份，最少台数不受影响，状态却少扩展一层。
- 主循环 `nxt = {s | c ...}` 与 `new = nxt - visited` 分别对应「逐层扩展」与「终止判定」两句话。

## 完整代码实现

```python
"""
P5455. 推理设备覆盖 - 集合覆盖 · 状压 DP

d 台机器各登记若干能力条目，业务点名 t 条互异条目；入选集合必须让
每一条点名条目都出现在至少一台启用的机器上，求最少启用台数。
怎样挑都凑不齐时输出 0。

输入格式：
- 第 1 行：d w t（机器台数 <= 30，每台条目数 <= 10，点名条目数 <= 20）；
- 随后 d 行：每行 w 个整数，该台机器具备的条目编号；
- 末行：t 个互异整数，业务点名的条目编号。

输出格式：
- 一个整数：最少台数；无解输出 0。

核心思路：
1. 条目编号不连续（示例里出现 8、9），先把点名的 t 条映射到比特
   0..t-1；机器条目只保留落在点名集合里的部分，得到覆盖掩码 c。
   与业务无关的条目直接丢掉，不占比特。
2. 最少台数 = 覆盖住全集 full=(1<<t)-1 的最少机器数，是经典集合
   覆盖。d<=30 无法枚举 2^d 个机器子集，反过来对「已覆盖集合」
   状压：从空集出发，每用一台机器就把掩码并进去，按层数 BFS，
   第几层第一次出现 full，答案就是几。
3. 按位并满足幂等性（c|c=c），一台机器重复使用不带来新覆盖，
   天然不会重复计费。无解时 BFS 不再产出新状态，输出 0。

时间复杂度：O(可达状态数 * d)，可达状态最多 2^t 个
空间复杂度：O(2^t)
"""

# https://codefun2000.com/p/P5455
import sys

# @sample-start
"""
样例输入 1:
4 2 3
2 8
3 5
8 9
5 2
2 5 8

样例输出 1:
2
"""
# @sample-end

# @sample-start
"""
样例输入 2:
2 3 4
1 2 3
4 5 6
10 11 12 13

样例输出 2:
0
"""
# @sample-end

# @sample-start
"""
样例输入 3:
3 1 1
9
8
9
9

样例输出 3:
1
"""
# @sample-end


def solve():
    """读入机器条目与点名条目，BFS 求覆盖全集的最少台数。"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    d = int(next(it))
    w = int(next(it))
    t = int(next(it))

    # 机器条目在点名条目之前进入，先整行收下再说
    machine_items = []
    for _ in range(d):
        machine_items.append([int(next(it)) for _ in range(w)])

    # 点名条目 -> 比特位。编号不连续，必须显式映射。
    bit_of = {}
    for k in range(t):
        bit_of[int(next(it))] = k
    full = (1 << t) - 1

    # 每台机器的覆盖掩码：只统计点名的条目，无关条目一律忽略
    masks = set()
    for row in machine_items:
        c = 0
        for v in row:
            b = bit_of.get(v)
            if b is not None:
                c |= 1 << b
        if c:
            masks.add(c)  # 重复掩码只留一份，不影响最少台数

    # 按层数 BFS：layer k = 恰好用 k 台机器能凑出的覆盖集合。
    # full 第一次出现在第 k 层，说明最少台数为 k。
    visited = {0}
    frontier = [0]
    layer = 0
    while True:
        layer += 1
        nxt = {s | c for s in frontier for c in masks}
        if full in nxt:
            print(layer)
            return
        new = nxt - visited
        if not new:
            print(0)  # 有条目从未被任何机器提供，凑不齐
            return
        visited |= new
        frontier = new


def run_tests():
    """运行官方样例与边界用例，方便本地自测。"""
    import io

    test_cases = [
        # 官方样例 1：第 1 台 + 第 4 台凑齐 {2,5,8}
        (
            "4 2 3\n2 8\n3 5\n8 9\n5 2\n2 5 8\n",
            "2",
        ),
        # 官方样例 2：点名条目任何机器都没有 -> 0
        (
            "2 3 4\n1 2 3\n4 5 6\n10 11 12 13\n",
            "0",
        ),
        # 官方样例 3：单台单独够用
        (
            "3 1 1\n9\n8\n9\n9\n",
            "1",
        ),
        # 无关条目混在机器里：机器 1 带 9 个环境条目和点名条目 1，
        # 机器 2 带点名条目 2，答案仍是 2
        (
            "2 3 2\n9 9 1\n7 2 7\n1 2\n",
            "2",
        ),
        # 机器内条目重复：掩码去重后单台即够
        (
            "1 4 2\n5 5 5 5\n5 5\n",
            "0",  # 点名 5 之外还有条目 6，永远凑不齐
        ),
        # 单台覆盖全部点名条目
        (
            "1 3 3\n1 2 3\n1 2 3\n",
            "1",
        ),
        # 贪心反例：先拿覆盖最多的机器会多启用一台。
        # 机器 A={1,2,3,4}，B={1,2,5}（外加无关条目 7），C={3,4,6}（加 8），
        # 点名 1..6：贪心先拿 A，再各补 5、6 共 3 台；最优 B+C 两台。
        (
            "3 4 6\n1 2 3 4\n1 2 5 7\n3 4 6 8\n1 2 3 4 5 6\n",
            "2",
        ),
        # 必须三台的链式结构：A={1,2}，B={3,4}，C={5,6}
        (
            "3 2 6\n1 2\n3 4\n5 6\n1 2 3 4 5 6\n",
            "3",
        ),
    ]

    for i, (inp, expected) in enumerate(test_cases, 1):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io.TextIOWrapper(io.BytesIO(inp.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            output = sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout

        status = "✓" if output == expected else "✗"
        print(f"样例 {i}: 期望={expected}, 实际={output} {status}")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

### 样例 1：两台并出全集

点名 $\{2,5,8\}$ 按输入顺序映射成比特 0、1、2，四台机器的掩码：

| 机器 | 条目 | 比特集 | 掩码整数 |
| ---- | ---- | ---- | ---- |
| 1 | $\{2,8\}$ | $\{0,2\}$ | 5 |
| 2 | $\{3,5\}$ | $\{1\}$ | 2 |
| 3 | $\{8,9\}$ | $\{2\}$ | 4 |
| 4 | $\{5,2\}$ | $\{1,0\}$ | 3 |

机器 3 的条目 9 不在点名里，被 `bit_of.get` 丢弃，掩码只剩 8 那一位——无关条目全程不占状态。

- 第 1 层（1 台）：$\{5,2,4,3\}$，最满的 5（比特 0、2）也差位 1，不是全集 7。
- 第 2 层（2 台）：$5\mid3=7=full$，机器 1 与机器 4 并起来盖满 → 答案 2，与输出一致。

样例 2：点名 $\{10,11,12,13\}$ 与两台机器的 $\{1..6\}$ 无一交集，掩码全 0，`masks` 为空；第 1 层扩展不出新状态，输出 0。样例 3：点名 $\{9\}$ 映射到比特 0，机器 1 与 3 的掩码都是 1，第 1 层就出现 $full=1$，输出 1。

### 贪心反例的走位

自测第 7 组：机器 $\{1,2,3,4\}$、$\{1,2,5\}$、$\{3,4,6\}$，点名 1..6。按层扩展第 2 层即有 $mask(\{1,2,5\})\mid mask(\{3,4,6\})=full$，答案 2；贪心第一轮先拿 4 覆盖的 $\{1,2,3,4\}$，之后 5、6 各补一台，共 3 台——两种做法从第一轮就分岔。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 枚举机器子集逐一验证覆盖 | $O(2^d \cdot t)$ | $O(d)$ | $d=30$ 时 $2^{30}$ 个子集，不可行 |
| 每轮挑新增条目最多的贪心 | $O(d \cdot t)$ | $O(t)$ | 集合覆盖的贪心只有对数近似，可多启用 |
| 状压 DP 按层扩展覆盖集合（最优） | $O(d \cdot 2^t)$ | $O(2^t)$ | $t\le20$ 时状态上界 $10^6$，实际只扫可达层 |

$t=20$、$d=30$ 的上界约 $30\times10^6$ 次按位并；按层扩展只在可达状态上推进、并可在凑齐 $full$ 的那层提前结束，实际远小于上界。

## 易错点总结

### 1. 条目编号直接当比特位

机器条目编号不连续（样例 1 里同一批出现 2、3、5、8、9）。把编号本身当掩码位（`1 << v`）意味着低三位之外的比特永远空置，$t=3$ 的 $full$ 与真实覆盖对不上；编号超出 $t$ 时更会越界。`bit_of` 的映射一步不能省，机器条目要先过 `bit_of.get` 过滤再并进掩码——否则样例 1 第 3 台的无关条目 9 会把无关比特记进状态，覆盖判定整体失真。

### 2. 无解出口漏掉或写成 -1

凑不齐的判定不在答案计算里，而在层次终止处（`if not new` 时输出 0）。把它实现成「最后取 dp[full] 的最小值，取不到返回 -1」，样例 2 就会给出 -1 而题面要 0。

### 3. 贪心在这里不保证最少

集合覆盖的贪心（每轮拿新增条目最多的机器）本输入反例就能让它吃亏：机器 $\{1,2,3,4\}$、$\{1,2,5\}$、$\{3,4,6\}$，点名 1..6，贪心启用 3 台而最少的方案是 2 台（$\{1,2,5\}$ 与 $\{3,4,6\}$ 并满）。自测第 7 组就是这一例，贪心实现会输出 3。

## 扩展思考

- 集合覆盖是 NP-hard，这题能精确解是因为 $t\le20$ 把「目标侧」压成了状态维；点名条目再多，就要转向参数化搜索或直接接受对数近似。
- 机器侧还有一层免费剪枝：两台机器掩码互为包含时，被包含的那台换成覆盖它的大掩码不会更差。本题 $d\le30$ 没做这层裁剪；输入放宽后可以先删被支配掩码再状压。
