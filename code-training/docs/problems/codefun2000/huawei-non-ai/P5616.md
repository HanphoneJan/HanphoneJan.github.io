# P5616. 旧街爆破预算

> 场次：2026年10月10日-非AI方向 · 来源：[CodeFun2000 P5616](https://codefun2000.com/p/P5616)

## 题目描述

云小核领下一份清拆委托，要做的事是把这条老街重新修起来，所以沿街还留着的旧房得一间不剩地清完。他手上有一张坐标图，每间旧房落在哪个刻度，图上都标了出来。爆破弹也备了很多，不过落点只能挑在某一间旧房里面，而且每一枚都带着自己的覆盖半径；弹种不一样，覆盖半径也不一样，点响其中一枚所付出的资源数目，正好等于这一枚自己的覆盖半径。只要某间旧房到落点的间距没有超过该覆盖半径，这间旧房就会跟着被清掉。经费并不宽裕，请算出把全部旧房清完，最少要付出多少资源数目。

拿下面这份数据来看，最少付出的资源数目是 $20$。

## 输入格式

第 $1$ 行给出两个整数 $P$ 和 $Q$。其中 $1 \le P \le 100$，写的是旧房一共有多少间；$1 \le Q \le 10$，写的是爆破弹一共有多少种规格。

第 $2$ 行给出 $P$ 个两两不同的整数 $x_1,x_2,\ldots,x_P$。其中 $0 \le x_i \le 1000000000$，写的是各间旧房所在的坐标。

第 $3$ 行给出 $Q$ 个两两不同的整数 $r_1,r_2,\ldots,r_Q$。其中 $1 \le r_i \le 1000000000$，写的是每一种规格对应的覆盖半径。

## 输出格式

输出一行，里面只有一个整数，也就是把全部旧房清完时最少要付出的资源数目。

## 示例

### 示例 1

**输入：**

```
3 3
0 12 40
8 12 30
```

**输出：**

```
20
```

**说明：**

在坐标 $0$ 投放覆盖半径为 $12$ 的爆破弹，坐标 $0$ 与 $12$ 这两间旧房都会被清掉；再在坐标 $40$ 投放覆盖半径为 $8$ 的爆破弹。两边相加是 $12 + 8 = 20$。若改在坐标 $12$ 投放半径 $30$ 的弹，三间可以一次清完，但要付出 $30$。每间单独用半径 $8$，则要付出 $24$。

### 示例 2

**输入：**

```
8 3
0 3 6 50 54 58 100 130
3 4 10
```

**输出：**

```
13
```

**说明：**

在坐标 $3$ 投放半径 $3$ 的爆破弹，坐标 $0$、$3$、$6$ 三间都会被清掉。在坐标 $54$ 投放半径 $4$ 的爆破弹，坐标 $50$、$54$、$58$ 三间都会被清掉。坐标 $100$ 与 $130$ 相距 $30$，现有规格里没有哪一种能同时罩住这两间，于是各投放一枚半径 $3$ 的爆破弹。四枚加在一起是 $3 + 4 + 3 + 3 = 13$。

## 解题思路

### 判定标准里藏着的三个前提

输出只有一个数：最少资源总数。题面里有三个读岔就会全错的设定：其一，**落点只能挑在某一间旧房上**，空白刻度不能投放；其二，覆盖判据是「间距**不超过** $r$」，恰好等于半径也算盖住；其三，每发弹的资源数等于它自己的半径、与盖住几间无关，且同一规格可以重复投放——所以「小弹拆几发」与「大弹一锤子」的成本结构完全不同，必须全局权衡，拍脑袋的贪心随时会输。

### 关键观察：排序之后，答案是「连续区间拼接」

坐标抻成一条数轴。落在排序后第 $j$ 间、半径 $r$ 的一发弹，盖住的旧房恰好是**下标连续的一段**——右端最远推到 $x_j + r$，左端对称到 $x_j - r$。于是「清完全部」等价于「选若干连续区间盖满下标 $0..P-1$，每段花自身的半径」。

设 $dp[k]$ 为前 $k$ 间（下标 $0..k-1$）已清完的最少花费。轮到最左未清的第 $i$ 间时，下一发弹必须盖住它，否则它永远等不到后续弹顺手带走。从 $dp[i]$ 出发枚举一切盖得住 $i$ 的（落点 $j$，半径 $r$）：需 $r \ge x_j - x_i$，这发弹向右推进到 `hi + 1`，转移 $dp[hi+1] = \min(dp[hi+1], dp[i] + r)$。

**落点只需枚举 $j \ge i$**：落点在 $x_i$ 左边（$x_{j'} \le x_i$）的那发换成同半径放在第 $i$ 间上，右端覆盖从 $x_{j'}+r$ 变成 $x_i+r$ 只多不少，左边多盖的全是已清区——任何用到更靠左落点的方案都能换成不更差的方案，枚举砍半不漏解。

数据范围把方案钉死：$P \le 100$、$Q \le 10$，(落点，半径) 至多一千种组合，对每个 $i$ 过一遍共 $10^5$ 次转移；按 $2^P$ 枚举子集在 $P=100$ 下天方夜谭。区间数少、状态沿一条下标线排开、每步从已定左端向右推进，这是区间线性 DP 的标准形态。

### 实现映射

- 覆盖右端点表 `reach[j][k]`：对固定落点，半径越大右端越远，按半径**升序**双指针一次推完，主循环变成 $O(1)$ 查表；
- 转移方向永远是从 $i$ 指向更大的 $hi+1$，主循环自左向右一趟即是完整 DP；
- `dp[0] = 0`，第 $i$ 间与自身距离为 0 被任何半径罩住，$dp[P]$ 必可达，直接取为答案。

## 完整代码实现

```python
"""
P5616. 旧街爆破预算 - 排序 + 区间线性 DP

一条坐标轴上有 P 间两两不同坐标的旧房，Q 种覆盖半径的爆破弹。
弹的落点必须挑在某一间旧房里，覆盖半径为 r 的一发清掉与落点间距
不超过 r 的所有旧房，付出的资源数目恰好等于 r。求把全部旧房清完
的最少总资源数。

输入格式：
- 第 1 行：P Q；
- 第 2 行：P 个两两不同的坐标 x_i；
- 第 3 行：Q 个两两不同的半径 r_i。

输出格式：
- 一个整数：最少付出的资源数目。

核心思路：
把旧房按坐标升序排好，一枚弹盖得住的旧房在排序后是连续下标段。
设 dp[k] 为「前 k 间（下标 0..k-1）已清完」的最少花费。轮到最左
还没清的第 i 间时，必须有一枚弹盖住它：落点取坐标不小于 x_i 的
第 j 间（落点更靠左的那发可被同半径落在 x_i 的弹完全替代，右端
覆盖只多不少），半径 r 不小于 x_j - x_i。这发弹向右一路盖到坐标
不超过 x_j + r 的最后一间，即用 dp[i] + r 推 dp[hi+1]。落点×半径
的右端覆盖可以按半径从大到小的单调性用双指针一次算好，主循环
自左向右松弛一遍。

时间复杂度：O(P * P * Q)，P ≤ 100、Q ≤ 10 时约 1e5 次转移
空间复杂度：O(P * Q)（落点×半径的覆盖右端点表）
"""

# https://codefun2000.com/p/P5616
import io
import sys

# @sample-start
"""
样例输入 1:
3 3
0 12 40
8 12 30

样例输出 1:
20
"""
# @sample-end

# @sample-start
"""
样例输入 2:
8 3
0 3 6 50 54 58 100 130
3 4 10

样例输出 2:
13
"""
# @sample-end


def min_cost(P, Q, xs, radii):
    """返回清完全部旧房的最少资源数；xs 升序，radii 在此升序处理。"""
    INF = float("inf")
    radii = sorted(radii)

    # reach[j][k]：以第 j 间为落点、半径 radii[k] 的弹能向右盖到的
    # 最大下标。对固定落点，半径越大右端越远，双指针单调推进。
    reach = []
    for j in range(P):
        row = []
        start = j
        for r in radii:
            limit = xs[j] + r
            while start + 1 < P and xs[start + 1] <= limit:
                start += 1
            row.append(start)
        reach.append(row)

    dp = [INF] * (P + 1)
    dp[0] = 0
    for i in range(P):
        base = dp[i]
        if base == INF:
            continue
        xi = xs[i]
        for j in range(i, P):
            need = xs[j] - xi  # 把第 i 间罩进来所需的最小半径
            row = reach[j]
            for k in range(Q):
                if radii[k] < need:
                    continue
                cost = base + radii[k]
                if cost < dp[row[k] + 1]:
                    dp[row[k] + 1] = cost
    return dp[P]


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    P, Q = int(data[0]), int(data[1])
    xs = sorted(int(x) for x in data[2:2 + P])
    radii = sorted(int(x) for x in data[2 + P:2 + P + Q])
    print(min_cost(P, Q, xs, radii))


def run_tests():
    """运行嵌入的官方样例与边界/随机对拍用例，方便本地自测。"""
    import random

    run_cases = [
        # 官方样例 1：半径 12 放坐标 0，半径 8 放坐标 40，合计 20
        ("3 3\n0 12 40\n8 12 30\n", "20"),
        # 官方样例 2：小团各自罩住，100 与 130 距离 30 只能各发一发
        ("8 3\n0 3 6 50 54 58 100 130\n3 4 10\n", "13"),
        # 单间旧房：最小半径的那一发足够，落点就是它自己
        ("1 3\n7\n100 5 9\n", "5"),
        # 两间相距 10、只有半径 5：谁也罩不住对方，只能各发一发
        ("2 1\n0 10\n5\n", "10"),
        # 两间相距 10、半径 10：一发罩住两端，落点任选其一
        ("2 1\n0 10\n10\n", "10"),
        # 小街全长 4：半径 3 放在中间那间上就能一发罩住全部
        ("5 2\n0 1 2 3 4\n100 3\n", "3"),
        # 半径大到正好卡住整条街：一发放中间的旧房上
        ("3 1\n0 50 100\n50\n", "50"),
    ]

    for i, (inp, expected) in enumerate(run_cases, 1):
        output = run_case(inp)
        status = "✓" if output == expected else "✗"
        print(f"用例 {i}: 期望={expected}, 实际={output} {status}")

    # 随机对拍：与「枚举全部(落点,半径)区间 + 区间 DP」的独立实现比对
    random.seed(20261027)
    fails = 0
    for t in range(300):
        P = random.randint(1, 6)
        Q = random.randint(1, 3)
        xs = sorted(random.sample(range(0, 60), P))
        radii = random.sample(range(1, 40), Q)
        expect = interval_dp(P, Q, xs, radii)
        got = min_cost(P, Q, xs, radii)
        if got != expect:
            fails += 1
            print(f"对拍不一致: xs={xs} radii={radii} got={got} expect={expect}")
    print(f"随机对拍 300 组: {'全部一致 ✓' if fails == 0 else f'{fails} 组不一致 ✗'}")

    # 极端规模：P=100、Q=10、坐标与半径都顶到 1e9，验证限时内跑完
    big_xs = sorted(random.sample(range(0, 10**9), 100))
    big_radii = random.sample(range(1, 10**9), 10)
    import time

    start = time.time()
    answer = min_cost(100, 10, big_xs, sorted(big_radii))
    print(f"极端规模 P=100 Q=10: 最少资源数={answer}, 耗时 {time.time() - start:.2f}s")


def run_case(text):
    """把一段输入喂给 solve()，取回输出。"""
    old_stdin, old_stdout = sys.stdin, sys.stdout
    sys.stdin = io.TextIOWrapper(io.BytesIO(text.encode("utf-8")))
    sys.stdout = io.StringIO()
    try:
        solve()
        return sys.stdout.getvalue().strip()
    finally:
        sys.stdin, sys.stdout = old_stdin, old_stdout


def interval_dp(P, Q, xs, radii):
    """独立实现：暴力扫出每枚弹的覆盖区间 [L, R]，区间 DP 松弛。"""
    INF = float("inf")
    dp = [INF] * (P + 1)
    dp[0] = 0
    for j in range(P):
        for r in radii:
            lo, hi = j, j
            while lo > 0 and xs[lo - 1] >= xs[j] - r:
                lo -= 1
            while hi + 1 < P and xs[hi + 1] <= xs[j] + r:
                hi += 1
            dp2 = dp[:]
            # 这枚弹盖住的连续段是 [lo, hi]；把它接在任意
            # 「左边界已被清完」的状态后面
            for k in range(P, -1, -1):
                if dp[k] == INF:
                    continue
                if lo <= k <= hi + 1:
                    t = hi + 1
                    if dp[k] + r < dp2[t]:
                        dp2[t] = dp[k] + r
            dp = dp2
    return dp[P]


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

样例 2 的坐标排序后是 $0, 3, 6, 50, 54, 58, 100, 130$，半径库 $\{3, 4, 10\}$。

- **前 3 间**：落点 $x=3$、半径 3 盖住 $[0,6]$ 全部，花 3；半径 10 的覆盖右端仍停在 6 那一间（下一间远在 50），代价反而贵 7；
- **中段 3 间**：落点 $x=54$、半径 4 盖住 $[50,58]$，花 4，半径 10 同理更贵；
- **末尾两间**：$100$ 与 $130$ 相距 30，半径库最大 10，谁也罩不住谁，各发一发半径 3，落点分别在各自房上，花 $3+3=6$。

四段合计 $3+4+3+3=13$。两条「看似更好」的路在 DP 里都会被比较后淘汰：想把三间一锅端要花 30，想把 100 与 130 合并要花 30，都比拆分贵。

样例 1（坐标 $0, 12, 40$，半径 $\{8, 12, 30\}$）同法：$x=0$ 半径 12 盖 $[0,12]$ 花 12，$x=40$ 半径 8 盖 $[40]$ 花 8，合计 20；一发半径 30 全盖花 30，每间单独半径 8 花 24——20 胜出，输出 20。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 枚举投放方案（子集清法） | $O(2^P \cdot P)$ | $O(P)$ | $P=100$ 时方案数是天文数字，不可行 |
| 排序 + 区间线性 DP（最优） | $O(P^2 \cdot Q)$ | $O(P \cdot Q)$ | $P \le 100, Q \le 10$ 约 $10^5$ 次转移；本题采用 |

## 易错点总结

### 1. 覆盖右端点表未按半径升序构建

`reach[j][k]` 依赖「半径越大右端越远」的单调推进。若沿用读入顺序构建，`start` 指针会跨过尚未遍历的更小半径、再也无法回退，右端点被系统性算大——输出不报错而是普遍**偏大**，规模小的用例照样通过，只有在含大量边缘间距的数据上才会显形。

### 2. 覆盖判据写成严格不等

「间距不超过 $r$」的覆盖条件实现成 `xs[start + 1] < limit`（漏掉相等）时，恰好落在半径边缘的那间旧房被这一发漏盖——它下一发只能独自买单，答案偏大且没有任何报错，只有距离恰好等于半径的用例能暴露。

### 3. 状态按坐标值开桶

坐标上限 $10^9$。若把 dp 数组按坐标值开（长度 $10^9$ 的桶），内存直接撑爆；状态必须落在排序后的 $P$ 个**下标**上——`reach` 表与全部转移也都是按下标推进的，这一层不能混。

## 扩展思考

若输出还要给出每一发的落点表，dp 转移时同步记录「从哪个 $i$、由哪个（落点，半径）推来」，沿 $dp[P]$ 回溯即可，骨架不变。若落点放宽到数轴任意位置（不必在旧房上），区间仍连续，做法照旧；换成房在平面上、弹盖圆盘时，连续区间拼接不再成立，就要换覆盖问题的另一套算法了。
