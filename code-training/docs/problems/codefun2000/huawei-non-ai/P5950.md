# P5950. 黄金限次收益

> 场次：2026年10月28日-非AI方向 · 来源：[CodeFun2000 P5950](https://codefun2000.com/p/P5950)

## 题目描述

一家投资企业准备调整黄金买卖方案，以尽量增加最终利润。企业已经掌握一段时期的逐日报价，可以选择某日购入黄金，并在之后的日期将其出售，通过价差赚取收益。该时期内允许反复买卖，不过每轮交易都有手续费，起始本金也有上限。另外，每次购入的黄金数量相同，完整交易的总轮数不得突破规定额度。

任务：

根据每日报价、起始本金、每轮手续费以及可用交易额度，求出能够实现的最高净利润。

注意：

- 一轮交易必须先购入，再于更晚的日期出售。
- 整个时期内可安排多轮交易，但各轮不得重叠。尚有黄金未售出时，不能再次购入；出售时必须将当前持仓全部清空。
- 每轮由一次购入和一次出售构成，仅在出售时收取一份手续费，且这笔费用与黄金数量无关。
- 此前获利可以补充后续本金。执行购入时，可用现金必须不小于该批黄金的总价，否则该次购入不合法。可以选择全程不交易，最终只统计已经完成买卖的净利润。

## 输入格式

- 首行给出整数 $N$，代表已知报价的天数，$2 \le N \le 500$。
- 次行给出 $N$ 个以空格分隔的整数 $a_1,a_2,\ldots,a_N$，按日期顺序表示黄金单价，$1 \le a_i \le 1000$。
- 第三行给出整数 $F$，代表完成一轮买卖所收取的费用，$0 < F \le 1000$。
- 第四行给出整数 $C$，代表最初可用的现金，$0 < C \le 10000$。
- 第五行给出整数 $K$，代表允许完成的买卖轮数上限，$0 < K \le 100$。
- 第六行给出整数 $Q$，代表每次必须购入的黄金单位数，$1 \le Q \le 30$。

## 输出格式

输出一个整数，表示最优方案的净利润，即最终空仓时的现金减去起始本金。若所有可行交易均不能带来正利润，则输出 $0$。

## 示例

### 示例 1

**输入：**

```
5
8 6 9 3 11
2
12
1
3
```

**输出：**

```
22
```

**说明：** 在第 $4$ 天购入 $3$ 单位黄金，需支付 $3 \times 3=9$，本金 $12$ 足够覆盖费用。

第 $5$ 天全部售出，收到 $11 \times 3=33$，再扣除手续费 $2$，这一轮净赚 $33-9-2=22$。

因此最高利润为 $22$。整个方案仅完成 $1$ 轮买卖，符合额度要求。

### 示例 2

**输入：**

```
7
5 2 6 7 4 9 8
3
4
3
2
```

**输出：**

```
14
```

**说明：** 第 $2$ 天购入 $2$ 单位，支付 $2 \times 2=4$，恰好用完本金。

第 $4$ 天售出，扣费后得到 $7 \times 2-3=11$，这一轮赚得 $7$，可用现金变为 $11$。

第 $5$ 天再购入 $2$ 单位，需付 $4 \times 2=8$，此时已有现金足以支持。第 $6$ 天清仓，该轮利润为 $9 \times 2-8-3=7$。

两轮累计利润为 $7+7=14$。

## 解题思路

### 输出到底是什么：已完成的买卖带来的净利润

先把「利润」的口径钉死。整笔资金一直待在账户里，起始有 $C$，中途每一轮买进花掉 $a_{\text{买}}Q$、卖出收到 $a_{\text{卖}}Q$、卖出时再扣 $F$，最后要求空仓。于是最终现金是

$$C + \sum_{\text{每一轮}} \big(a_{\text{卖}}Q - a_{\text{买}}Q - F\big)$$

而题目要的净利润就是这个和：

$$\text{净利润} = \sum_{\text{每一轮}} \big((a_{\text{卖}} - a_{\text{买}})\cdot Q - F\big)$$

两条推论直接影响后面的状态设计：

1. **单轮的收益只取决于买入日与卖出日的价差**，与当时手里有多少钱无关。买卖的数量恒为 $Q$，手续费恒为 $F$，一轮要么赚要么亏，金额是固定的。
2. **宏观上看，选方案就是挑若干组「买日 $i$ < 卖日 $j$」**，组与组之间不重叠（卖完才能再买），组数不超过 $K$。目标是把这些组的收益加起来最大。

题面又规定「若所有可行交易均不能带来正利润，则输出 $0$」，所以答案要在最终结果上做一次 $\max(0,\cdot)$ —— 空仓不交易永远是一个合法方案。

### 一条价格上藏着的约束：买入时必须付得起

如果只有价差，那就成了「在序列上挑 $K$ 个不重叠的上升段」的纯贪心。真正把难度抬起来的是这句：

> 执行购入时，可用现金必须不小于该批黄金的总价。

因为本金 $C$ 有限，某些看起来很赚的买入其实**做不了**。示例 1 里前两天报价 $8$ 与 $6$，买 $3$ 单位要 $24$ 与 $18$，而本金只有 $12$ —— 贵得买不起；只有第 $4$ 天的 $3 \times 3 = 9$ 才付得起。

于是「选哪些轮」不能脱离「当时还剩多少钱」独立决定，而这又正好是状态的定义之处：现金 = $C +$ 已实现利润，**已实现利润是唯一需要携带的现金信息**。

### 状态：完成 $r$ 轮、空仓时的最大利润

按天推进。定义

$$dp[r] = \text{处理到今天收盘、恰好完成 } r \text{ 轮、当前空仓时的最大利润}$$

「空仓」是必须写进状态的前提：题面不允许持仓时再买入，所以任何时刻只有两种可能 —— 手里没货（可以买、也可以什么都不做），或者手里有货（只能等卖）。$dp$ 只管前一种。

状态能这样压缩，靠的是一条支配关系：**同样的轮数下，利润更多的人一定不比利润少的人差**。他能买得起的东西只多不少，能赚到的钱也只多不少。所以每个 $r$ 只需要保留最大值，丢掉其余。

一天里有两种事会发生，于是两条转移：

```python
for a in price:                     # 逐日推进
    cur = dp[:]                     # 今天什么都不做
    for r in range(1, k_max + 1):
        if best_buy[r - 1] != NEG:
            cand = best_buy[r - 1] + a * qty - fee   # 今天卖出，结束第 r 轮
            if cand > cur[r]:
                cur[r] = cand
```

`cur[r]` 一开始拷贝自 `dp[r]`，表示这一天既没买也没卖；卖出的候选值来自下面要讲的 `best_buy`。

### 把「买入价」折进一个辅助量

按上面的转移，卖出时需要知道「这一轮是什么价位买的」，可 $dp$ 里并没有这个信息。若把它也塞进状态，状态就成了 $O(K \cdot N)$ 种买入价，复杂度立刻失控。

换个角度：卖出那天的收益是

$$\big(dp_{\text{买入日前}}[r-1] - a_{\text{买}}Q\big) + a_{\text{卖}}Q - F$$

括号里的部分只跟买入日有关，跟卖出日无关。于是可以对每个 $r$ 维护一个「历史最优买入」：

$$best\_buy[r] = \max_{\text{买得起的日子 } b}\big(dp_{\text{第 } b \text{ 天开盘}}[r] - a_b Q\big)$$

卖出时直接查表，$O(1)$ 拿到最优的那次买入。登记今天的买入就一行：

```python
    for r in range(k_max):
        if dp[r] != NEG and cash + dp[r] >= a * qty:  # 买得起：本金 + 已赚利润
            val = dp[r] - a * qty
            if val > best_buy[r]:
                best_buy[r] = val
    dp = cur
```

注意条件写的是 `cash + dp[r] >= a * qty`：净利润 `dp[r]` 要加回起始本金 $C$，才是此刻手里的现金。

### 一天之内的顺序：先结算卖出，再登记买入

上面两段代码的先后不能颠倒，原因是题面那句「一轮交易必须先购入，再于**更晚的日期**出售」。

- 算 `cur` 时用的是**旧的** `best_buy`，里面只登记了今天以前的买入 —— 今天买、今天卖凑不出合法的一轮；
- 登记今天的买入时用的是**旧的** `dp`（今天开盘前的状态，也就是昨天收盘的状态），而不是刚算出的 `cur`。如果用了 `cur`，等于允许把今天卖出赚到的钱立刻再投进去，并且同一天再卖一次。

`dp = cur` 放在最后，一天只推进一次。

### 实现落点

- `NEG = float("-inf")` 标记「这个轮数还不可达」，让 `max` 直接跳过；
- `dp[0] = 0`：零轮、零利润，从第一天开盘就成立；
- 每天先拷贝 `cur = dp[:]`，就是「今天什么都不做」这条转移；
- 卖出只遍历 $r \ge 1$（第 $r$ 轮需要前 $r-1$ 轮的成绩做基础），买入只遍历 $r \le K-1$（买完这一轮最多用到 $K$）；
- 收尾 `print(max(0, max(dp)))` 同时处理「可以不做交易」和「所有交易都亏」。

## 完整代码实现

```python
"""
P5950. 黄金限次收益 - 按天推进、轮数做维度的 DP

有 N 天报价 a[i]，起始本金 C，每轮手续费 F，最多 K 轮，
每轮买入并卖出固定 Q 单位（卖出时收一次 F，买入时现金必须够付）。
求最终空仓时的最大净利润，非正则输出 0。

输入格式：
- 第 1 行：N
- 第 2 行：N 个整数，日报价
- 第 3 行：F（每轮手续费）
- 第 4 行：C（起始本金）
- 第 5 行：K（轮数上限）
- 第 6 行：Q（每轮固定数量）

输出格式：
- 一个整数：最大净利润（不小于 0）。

核心思路：
dp[r] = 今天收盘、恰好完成 r 轮、空仓时的最大利润。
同一轮数下利润越大越不会更差，所以每个 r 只留最大值。
卖出的收益只跟买入日有关，把 (dp[r] - 买入价*Q) 的最大值记进 best_buy[r]，
卖出时 O(1) 查到最优买入；买入时要求 C + dp[r] >= 买入价*Q。
每天先结算卖出（用旧 best_buy），再登记买入（用旧 dp），保证不同日成交。

时间复杂度：O(N * K)
空间复杂度：O(K)
"""

# https://codefun2000.com/p/P5950
import sys

NEG = float("-inf")

# @sample-start
"""
样例输入 1:
5
8 6 9 3 11
2
12
1
3

样例输出 1:
22
"""
# @sample-end

# @sample-start
"""
样例输入 2:
7
5 2 6 7 4 9 8
3
4
3
2

样例输出 2:
14
"""
# @sample-end


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    p = 0
    n = int(data[p]); p += 1
    price = [int(x) for x in data[p:p + n]]; p += n
    fee = int(data[p]); p += 1
    cash = int(data[p]); p += 1
    k_max = int(data[p]); p += 1
    qty = int(data[p])

    dp = [NEG] * (k_max + 1)
    dp[0] = 0                           # 0 轮、0 利润
    best_buy = [NEG] * (k_max + 1)      # best_buy[r] = max(dp[r] - 买入价*Q)

    for a in price:
        cur = dp[:]                     # 今天什么都不做
        for r in range(1, k_max + 1):
            if best_buy[r - 1] != NEG:
                cand = best_buy[r - 1] + a * qty - fee   # 今天卖出，第 r 轮结束
                if cand > cur[r]:
                    cur[r] = cand
        for r in range(k_max):
            # 买得起：手里的现金 = 本金 + 已实现利润
            if dp[r] != NEG and cash + dp[r] >= a * qty:
                val = dp[r] - a * qty
                if val > best_buy[r]:
                    best_buy[r] = val
        dp = cur

    print(max(0, max(dp)))


def run_tests():
    """运行嵌入的示例与边界用例，方便本地自测。"""
    import io

    cases = [
        ("5\n8 6 9 3 11\n2\n12\n1\n3\n", "22"),
        ("7\n5 2 6 7 4 9 8\n3\n4\n3\n2\n", "14"),
        # 一路下跌：最好的选择是全程不交易
        ("3\n9 5 1\n1\n100\n2\n1\n", "0"),
        # 买得起、但价差不够手续费：同样输出 0
        ("2\n10 11\n5\n100\n1\n1\n", "0"),
        # 轮数足够时抓住深坑：4 -> 10 与 1 -> 20 各赚一笔，胜过一路持有
        ("4\n4 10 1 20\n1\n10\n5\n1\n", "23"),
    ]

    for i, (inp, expected) in enumerate(cases, 1):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io.TextIOWrapper(io.BytesIO(inp.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            output = sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout

        status = "✓" if output == expected else "✗"
        print(f"用例 {i}: 期望={expected!r}, 实际={output!r} {status}")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

### 示例 1：$N=5$，报价 $8,6,9,3,11$，本金 $12$，$K=1$，$Q=3$

只有一轮，`dp` 只有 $r=0,1$ 两格。每天先看能不能买，再看能不能卖。

| 天 | 报价 | 买 $3$ 单位需 | 现金 $=12+dp[0]$ | 买得起 | 卖出候选 $best\_buy[0] + 3a - 2$ | $dp[1]$ |
| -- | ---- | ------------- | ---------------- | ------ | -------------------------------- | ------- |
| $1$ | $8$ | $24$ | $12$ | 否 | — | $-\infty$ |
| $2$ | $6$ | $18$ | $12$ | 否 | — | $-\infty$ |
| $3$ | $9$ | $27$ | $12$ | 否 | — | $-\infty$ |
| $4$ | $3$ | $9$ | $12$ | 是 | — | $-\infty$ |
| $5$ | $11$ | $33$ | $12$ | 否 | $-9 + 33 - 2 = 22$ | $22$ |

第 $4$ 天登记买入：`best_buy[0] = dp[0] - 3*3 = 0 - 9 = -9`。第 $5$ 天卖出：$22$。

答案 $\max(0, 22) = 22$，与官方一致。注意前三天不是「价格不好」，而是**本金不够**：第 $1$ 天 $8\times3=24>12$，这条路径在示例里根本不存在。

### 示例 2：$N=7$，报价 $5,2,6,7,4,9,8$，本金 $4$，$F=3$，$K=3$，$Q=2$

买入成本是 $2a$，逐日表如下（`best_buy[r]` 表示「已用 $r$ 轮、该买入价对应的价值」）：

| 天 | 报价 | 买 $2$ 单位需 | 现金 $=4+dp[0]$ | $best\_buy[0]$ | $dp[1]$ | $best\_buy[1]$ | $dp[2]$ |
| -- | ---- | ------------- | --------------- | -------------- | ------- | -------------- | ------- |
| $1$ | $5$ | $10$ | $4$ | — | $-\infty$ | — | $-\infty$ |
| $2$ | $2$ | $4$ | $4$ | $-4$ | $-\infty$ | — | $-\infty$ |
| $3$ | $6$ | $12$ | $4$ | $-4$ | $5$ | — | $-\infty$ |
| $4$ | $7$ | $14$ | $4$ | $-4$ | $7$ | — | $-\infty$ |
| $5$ | $4$ | $8$ | $4$ | $-4$ | $7$ | $-1$ | $-\infty$ |
| $6$ | $9$ | $18$ | $4$ | $-4$ | $11$ | $-1$ | $14$ |
| $7$ | $8$ | $16$ | $4$ | $-4$ | $11$ | $-1$ | $14$ |

挑三行细看：

- **第 $2$ 天**：$2\times2=4$ 正好等于本金，买得起，`best_buy[0] = 0 - 4 = -4`；
- **第 $3$ 天**：用第 $2$ 天的买入卖出，$(-4) + 12 - 3 = 5$，这是「一次买卖赚 $7$」的另一种写法；第 $3$ 天自己买不起（需 $12$，现金只有 $4$）；
- **第 $5$ 天**：$dp[1]=7$，现金 $4+7=11 \ge 8$，于是 `best_buy[1] = 7 - 8 = -1`。第 $6$ 天卖出得 $(-1)+18-3=14$，这就是官方的「两轮各赚 $7$，合计 $14$」。

第 $6$ 天想再买一轮（$dp[2]=14$，现金 $18 \ge 18$ 恰好够）也登记了 `best_buy[2] = -2`，但第 $7$ 天卖出只有 $(-2)+16-3=11$，低于已有的 $14$，不采用。

答案 $14$。它和官方解释里的方案一致：第 $2$ 天买、第 $4$ 天卖；第 $5$ 天买、第 $6$ 天卖。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 枚举所有「买日/卖日」组合 | $O\!\left(N^{2K}\right)$ | $O(K)$ | $K$ 轮就有 $K$ 对日期，$N=500$、$K=100$ 时完全不可行 |
| 按天推进、轮数做维度（最优） | $O(N\cdot K)$ | $O(K)$ | 每天对 $r = 0 \dots K$ 各做一次 $O(1)$ 转移，$500\times100 = 5\times10^4$ |

每天的两次内层循环都是 $O(K)$：一次算「今天卖出」，一次算「今天买入」。空间只有两个长度为 $K+1$ 的数组，报价表本身占 $O(N)$。

## 易错点总结

### 1. 本金检查漏掉起始现金 $C$

把 `cash + dp[r] >= a * qty` 写成 `dp[r] >= a * qty`，等于假设账户一开始是空的。示例 1 里 `dp[0] = 0` 而第 $4$ 天的买入价是 $9$，判定「买不起」，于是 `best_buy[0]` 永远是 $-\infty$、`dp[1]` 也永远是 $-\infty$，输出 $0$ 而不是 $22$；示例 2 同样输出 $0$ 而不是 $14$。两组合法的样例直接归零，是这条最典型的症状。

### 2. 卖出时忘了扣手续费 $F$

把 `best_buy[r - 1] + a * qty - fee` 里的 `- fee` 删掉，每一轮都多算一份手续费。示例 1 输出 $24$（$33-9$）而不是 $22$；轮数多的用例偏得更多，因为漏掉的是「每轮一次」。

### 3. 收益公式漏乘数量 $Q$

把 `best_buy[r - 1] + a * qty - fee` 写成 `best_buy[r - 1] + a - fee`（买入侧按 $aQ$ 扣、卖出侧按 $a$ 收），单轮收益被算成「一份价差」。示例 1 输出 $0$（$-9+11-2=0$，刚好被 $\max(0,\cdot)$ 兜住，看不出报错）、示例 2 输出 $2$ 而不是 $14$ —— 这类错误在小 $Q$ 上不明显，把 $Q$ 调大才会暴露。
