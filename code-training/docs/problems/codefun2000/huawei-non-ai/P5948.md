# P5948. 运输中转站计数

> 场次：2026年10月28日-非AI方向 · 来源：[CodeFun2000 P5948](https://codefun2000.com/p/P5948)

## 题目描述

一家物流企业共有 $N$ 座中转站，各站依次标记为 $1$ 至 $N$。站点间铺设了若干运输线路，每条线路都只支持指定方向的运输。

现已获得该网络的全部线路资料，需要回答一次运输路径计数问题。

请统计从中转站 $S$ 启程、沿线路移动恰好 $L$ 次后停在中转站 $T$ 的路径总数。同一站点可以在途中反复到访，已经走过的线路也能够再次使用。只要经过的站点序列有一处不同，就视为两条不同路径。

## 输入格式

- 首行给出两个整数 $N$、$M$，依次代表站点总数和线路总数。
- 下一行给出三个整数 $S$、$T$、$L$，依次代表出发站、目的站和必须使用的线路条数。
- 随后有 $M$ 行，各行给出整数 $u$、$v$，说明存在一条由站点 $u$ 驶向站点 $v$ 的线路。

**数据范围：**

- $1 \le N \le 20$；
- $1 \le M \le 200$；
- $1 \le L \le 10$；
- $1 \le u,v \le N$，$1 \le S,T \le N$；
- $u \ne v$，即线路不会连接站点自身；
- 任意一对有序站点之间至多存在一条线路。

## 输出格式

输出一个整数，表示符合要求的路径总数；若没有可行路径，则输出 $0$。答案无需取模。

## 解题思路

### 要数的东西：长度恰好的有向走法

一条合规路径就是一个站点序列

$$S = v_0 \to v_1 \to v_2 \to \dots \to v_L = T$$

其中每一对相邻站点 $v_{i-1} \to v_i$ 都必须是一条真实存在的线路。判定的两个条件是「长度为 $L$」和「终点是 $T$」，中间怎么绕都不受限制：站点可以重访，线路可以重复使用。

题面还多加了一句「任意一对有序站点之间至多存在一条线路」。这句话的作用是让「站点序列」与「线路序列」一一对应：两站之间没有第二条边可挑，所以只要站点序列不同，路径就一定不同，计数时不必再考虑同一对站点之间的多重边。建图时每条线路只存一次就够了。

### 数据范围给出的信号：$20^{10}$ 不行，但每一步只有 $N$ 种状态

先看最直白的做法：从 $S$ 出发做 DFS，每到一个站点就把它的所有出边都试一遍，走满 $L$ 步时检查是否落在 $T$。每个站点最多有 $N-1$ 条出边，所以搜索树最多展开

$$(N-1)^L \le 19^{10} \approx 6.1 \times 10^{12}$$

条分支。$N$、$L$ 都很小，这个数字却大得离谱 —— 因为搜索树里绝大多数分支在**重复走同一条路**。

真正决定「后面还能怎么走」的信息只有一件：**现在站在哪个站点，已经走了几步**。至于前面是怎么绕过来的，对后续的可选线路没有任何影响。于是可以把「所有可能的走法」折叠成 $L \times N$ 个格子，每个格子只记一个数：走到这一步、停在这个站点的路径有多少条。

这就是「状态压缩」在这里的全部含义 —— 不是技巧，而是发现大量路径在「当前站点」这一维度上完全等价。

### 状态与转移：一条边把计数搬过去

记 $dp_k[v]$ 为「恰好走 $k$ 步后停在中转站 $v$」的路径条数。初始时一步都还没走，只有 $S$ 是可达的：

$$dp_0[S] = 1,\qquad dp_0[v] = 0\ (v \ne S)$$

每走一步，就是把 $dp_k[u]$ 里的每一条路径延伸出 $u$ 的一条出边：

$$dp_{k+1}[v] = \sum_{u \to v} dp_k[u]$$

这个式子读起来就是「所有能一步走到 $v$ 的站点，把它们各自的路径数加起来」。写成代码时**沿边推进**比按站点枚举更省事：

```python
dp = [0] * (n + 1)
dp[s] = 1                       # 第 0 步：只有起点有 1 条空路径

for _ in range(steps):          # 走 steps 步
    nxt = [0] * (n + 1)         # 下一步的计数，先清零
    for u in range(1, n + 1):
        cnt = dp[u]
        if cnt:                 # 这个站点在当前步不可达就跳过
            for v in graph[u]:  # 枚举 u 的每一条出边
                nxt[v] += cnt   # 同一对站点只有一条边，直接加
    dp = nxt

print(dp[t])
```

`graph[u]` 里存的是 $u$ 能直接驶向的站点，所以内层循环的次数等于当前步真正可达的那些站点的出边数之和，最坏是 $M$。

### 为什么要用一个新数组 `nxt`

转移式左边的下标是 $k+1$、右边是 $k$，两者必须分开存放。如果偷懒就地累加：

```python
for u in range(1, n + 1):
    if dp[u]:
        for v in graph[u]:
            dp[v] += dp[u]      # 就地改，会把下一步的计数混进这一步
```

那么本次循环里刚写进 `dp[v]` 的数，会在后面某个 $u = v$ 的时刻被当成「当前步的计数」继续往下搬。走 $L$ 步的循环实际上允许路径无限延长，答案会明显偏大：示例 2 会输出 $7$ 而不是 $3$，示例 1 会输出 $106$ 而不是 $2$。

正确的做法是每轮新开一个数组、算完再整体换过去，这也是上面代码里 `nxt` 与 `dp = nxt` 的作用。

### 实现落点

- `dp[s] = 1`：第 $0$ 步的空路径。$S$ 与 $T$ 允许相同，此时「绕一圈回到起点」也被正常计入；
- `if cnt:` 只是省掉不可达站点的空转，删掉也不影响正确性；
- 外层 `for _ in range(steps)` 走满 $L$ 次，中途不提前判断「到 $T$ 了没有」—— 提前停在 $T$ 就变成「至多 $L$ 步」，那是对题意的误读；
- 最后打印 `dp[t]`，没有路径时它自然就是 $0$。

## 完整代码实现

```python
"""
P5948. 运输中转站计数 - 按步数滚动的图上路径计数

给定 N 座中转站与 M 条有向线路，统计从 S 出发、恰好走 L 条线路后
停在 T 的路径条数。站点与线路都可以重复经过，站点序列不同即不同路径。

输入格式：
- 首行两个整数 N、M；
- 次行三个整数 S、T、L；
- 随后 M 行，每行两个整数 u、v，表示一条 u -> v 的线路。

输出格式：
- 一个整数：符合条件的路径条数；无解输出 0。

核心思路：
dp[v] 表示"恰好走完当前步数后停在 v"的路径条数。走一步就是沿每条出边
把计数搬到邻居上，滚动 L 次。起点在第 0 步有 1 条空路径。
每一步都用新数组承接，绝不能就地累加（那会让同一步的结果被反复使用）。

时间复杂度：O(L * (N + M))
空间复杂度：O(N)
"""

# https://codefun2000.com/p/P5948
import sys

# @sample-start
"""
样例输入 1:
5 7
2 5 4
2 3
3 2
3 4
4 3
3 5
2 5
5 1

样例输出 1:
2
"""
# @sample-end

# @sample-start
"""
样例输入 2:
6 6
2 6 2
2 1
1 6
2 4
4 6
2 5
5 6

样例输出 2:
3
"""
# @sample-end

# @sample-start
"""
样例输入 3:
5 4
4 1 1
4 2
2 1
1 5
5 3

样例输出 3:
0
"""
# @sample-end


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    it = iter(data)
    n = int(next(it))
    m = int(next(it))
    s = int(next(it))
    t = int(next(it))
    steps = int(next(it))

    graph = [[] for _ in range(n + 1)]
    for _ in range(m):
        u = int(next(it))
        v = int(next(it))
        graph[u].append(v)          # 有向边：只记 u -> v

    dp = [0] * (n + 1)
    dp[s] = 1                       # 第 0 步：只有起点有 1 条空路径

    for _ in range(steps):
        nxt = [0] * (n + 1)
        for u in range(1, n + 1):
            cnt = dp[u]
            if cnt:                 # 不可达的站点直接跳过
                for v in graph[u]:
                    nxt[v] += cnt   # 有序站点对之间至多一条边，无需乘重数
        dp = nxt

    print(dp[t])


def run_tests():
    """运行嵌入的示例，方便本地自测。"""
    import io

    cases = [
        (
            "5 7\n2 5 4\n2 3\n3 2\n3 4\n4 3\n3 5\n2 5\n5 1\n",
            "2",
        ),
        (
            "6 6\n2 6 2\n2 1\n1 6\n2 4\n4 6\n2 5\n5 6\n",
            "3",
        ),
        (
            "5 4\n4 1 1\n4 2\n2 1\n1 5\n5 3\n",
            "0",
        ),
        # 起点即终点：绕一条自环走不出去，但可以 1->2->1 走 2 步回来
        ("2 2\n1 1 2\n1 2\n2 1\n", "1"),
        # 同样的图走 3 步：1->2->1->2 到不了 1
        ("2 2\n1 1 3\n1 2\n2 1\n", "0"),
    ]

    for i, (inp, expected) in enumerate(cases, 1):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io.TextIOWrapper(io.BytesIO(inp.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            output = sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout

        status = "✓" if output == expected else "✗"
        print(f"用例 {i}: 期望={expected!r}, 实际={output!r} {status}")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

### 示例 1：$N=5$，从 $2$ 出发走 $4$ 步到 $5$

图里的边是 $2\to 3$、$3\to 2$、$3\to 4$、$4\to 3$、$3\to 5$、$2\to 5$、$5\to 1$。

第 $0$ 步只有起点有计数：

| 步数 | $dp[1]$ | $dp[2]$ | $dp[3]$ | $dp[4]$ | $dp[5]$ |
| ---- | ------- | ------- | ------- | ------- | ------- |
| $0$ | $0$ | $\mathbf{1}$ | $0$ | $0$ | $0$ |

第 $1$ 步：$2$ 的出边是 $3$ 与 $5$，各搬过去 $1$ 条 → $(0,0,1,0,1)$。

第 $2$ 步：$3$ 的出边是 $2$、$4$、$5$，各搬 $1$；$5$ 的出边是 $1$，搬 $1$：

| 步数 | $dp[1]$ | $dp[2]$ | $dp[3]$ | $dp[4]$ | $dp[5]$ |
| ---- | ------- | ------- | ------- | ------- | ------- |
| $2$ | $1$ | $1$ | $0$ | $1$ | $1$ |

第 $3$ 步：$2$ 搬给 $3$、$5$；$4$ 搬给 $3$；$5$ 搬给 $1$；$1$ 没有出边。于是 $dp[3] = 1 + 1 = 2$，其余各 $1$：

| 步数 | $dp[1]$ | $dp[2]$ | $dp[3]$ | $dp[4]$ | $dp[5]$ |
| ---- | ------- | ------- | ------- | ------- | ------- |
| $3$ | $1$ | $0$ | $2$ | $0$ | $1$ |

第 $4$ 步：$dp[3]=2$ 分别搬给 $2$、$4$、$5$，各 $2$；$dp[5]=1$ 搬给 $1$：

| 步数 | $dp[1]$ | $dp[2]$ | $dp[3]$ | $dp[4]$ | $dp[5]$ |
| ---- | ------- | ------- | ------- | ------- | ------- |
| $4$ | $1$ | $2$ | $0$ | $2$ | $\mathbf{2}$ |

答案 $dp[5] = 2$。这 $2$ 条正是题面列出的两条：

- 第 $3$ 步停在 $3$ 的路径有两条（$2\to 3\to 2\to 3$ 与 $2\to 3\to 4\to 3$），它们各自沿 $3\to 5$ 走到 $5$，就是 $2\to 3\to 2\to 3\to 5$ 与 $2\to 3\to 4\to 3\to 5$；
- 第 $3$ 步停在 $5$ 的那 $1$ 条是 $2\to 3\to 5$，它只剩一条出边 $5\to 1$，走不到 $T$，所以不计入答案。

这个对比正好说明了 DP 在做什么：两条不同前缀在第 $3$ 步「停在同一站」之后就完全等价，只需记一个「$2$」，不必记住它们各自长什么样。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| DFS 枚举所有走法 | $O\!\left((N-1)^L\right)$ | $O(L)$ | $N=20$、$L=10$ 时约 $6.1\times10^{12}$ 条分支，必然超时 |
| 按步滚动的路径计数（最优） | $O(L\cdot(N+M))$ | $O(N)$ | 每轮遍历一遍站点与全部出边，$L \le 10$、$M \le 200$ |

时间里的 $N$ 来自每轮扫一遍「哪些站点有计数」，$M$ 来自把所有出边各走一次；空间只有两个长度为 $N+1$ 的数组，与 $M$、$L$ 都无关。

## 易错点总结

### 1. 就地累加，没有另开数组

把 `nxt = [0] * (n + 1)` 删掉、直接把 `nxt[v] += cnt` 写成 `dp[v] += cnt`，程序照样跑完，但同一步里刚加进去的计数会被后续站点继续搬运，等效于允许路径在 $L$ 步之内无限延长。按站点编号从小到大推进时，示例 1 输出 $106$（正确 $2$），示例 2 输出 $7$（正确 $3$）—— 结果偏大，且样例 3 仍然是 $0$，很容易被误判成「只错了个别情况」。

### 2. 转移用赋值而不是累加

写成 `nxt[v] = dp[u]` 时，同一个 $v$ 有多条入边就只留下最后一条的计数。示例 2 中站点 $6$ 的入边来自 $1$、$4$、$5$，三份计数被覆盖成一份，输出 $1$ 而不是 $3$；示例 1 因为每条入边只承载 $1$ 或 $2$ 条路径，错得更隐蔽 —— 输出 $0$。

### 3. 把「恰好 $L$ 步」做成「至多 $L$ 步」

在循环末尾补一句 `ans += dp[t]`，最后打印 `ans` 而不是 `dp[t]`，就把「第 $k$ 步停在 $T$」的所有 $k \le L$ 都算了进去。示例 1 中第 $1$、$2$、$3$、$4$ 步的 $dp[5]$ 分别是 $1,1,1,2$，累加得 $5$，官方答案是 $2$ —— 多出来的三条路径都是「提前到达、还没走满 $4$ 步」的走法。
