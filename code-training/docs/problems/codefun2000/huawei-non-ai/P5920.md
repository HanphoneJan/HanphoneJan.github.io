# P5920. 方阵唯一补齐

> 场次：2026年10月14日-非AI方向 · 来源：[CodeFun2000 P5920](https://codefun2000.com/p/P5920)

## 题目描述

这是一种靠逻辑把空位补全的古典益智。源头可追溯到十八世纪，瑞士人当时研究的是拉丁方；这套玩法后来传入日本，名称才固定下来。

九阶正方形上，每一条横行、每一条竖列，以及每一个三乘三的小宫（一共九个），都要正好放入 $1$ 到 $9$，彼此不能一样。

补全之后，上面三条同时成立。

名叫超级数独的加强版本，不再把阶数锁死在九。本题的边长只取 $4$、$9$、$16$ 三种，盘面即边长乘边长的方阵；小宫的边长是 $\sqrt{\text{边长}}$。

请编写程序，自动把盘面上的空位补成一组合法结果。

## 输入格式

首行给出盘面边长，取值只可能是 $4$、$9$、$16$。例如首行写 $9$，就说明后面紧跟一张九乘九的方阵。随后的行数与边长相同，每一行含有同样多个整数，彼此以空格隔开。整数 $0$ 代表该格仍空着，其余整数都在 $1$ 与边长之间。格式如下：

```text
9
0 0 0 5 8 0 3 0 0
0 3 4 0 0 0 8 1 0
2 8 6 0 1 0 9 0 7
4 2 0 0 6 0 0 7 0
8 0 0 0 7 0 4 6 5
7 6 1 4 5 8 2 3 9
0 5 2 0 4 0 0 0 0
9 4 7 1 2 5 0 8 3
0 0 0 0 3 0 5 0 4
```

## 输出格式

把填好的方阵逐行写出，同一行的整数以空格隔开，原来空着的格子都换成符合规则的数。例如：

```text
1 7 9 5 8 2 3 4 6
5 3 4 6 9 7 8 1 2
2 8 6 3 1 4 9 5 7
4 2 5 9 6 3 1 7 8
8 9 3 2 7 1 4 6 5
7 6 1 4 5 8 2 3 9
3 5 2 8 4 6 7 9 1
9 4 7 1 2 5 6 8 3
6 1 8 7 3 9 5 2 4
```

**输出约定**：若合法补法**唯一**，输出补全后的方阵（边长行，每行边长个整数，空格分隔）；若合法补法多于一组，或一组都不存在，只输出一行 `0`，不要输出任何方阵。

## 解题思路

### 输出是「全有或全无」，要先回答的其实是唯一性

三种结局摆在题面里：恰好一组合法补法就输出整盘；一组都没有、或者多于一组，都只输出一个 $0$。这意味着搜索的目标不是「找出一组解」，而是「**确认没有第二组**」。由此得到两条硬约束：

- 找到第一组**不能停**，必须继续搜；
- 但也**不必数清**有几组——第二组一露头就能作废，所以只需要保存前两组，收线条件写成 `len(solutions) >= 2`。

### 约束只有「不重复」：三组位掩码把它压成一次位运算

行、列、宫三处的要求都是「同一组里数字不重复」。给每一行、每一列、每一个小宫各挂一个 $s$ 位掩码（第 $v$ 位为 $1$ 表示 $v$ 已用过），判重与取候选都只剩位运算：

```python
bit = 1 << v
bi = (r // b) * b + (c // b)     # 小宫编号，b = √s
if (rows[r] | cols[c] | boxes[bi]) & bit:
    return []                    # 给定数之间已经有冲突
rows[r] |= bit
cols[c] |= bit
boxes[bi] |= bit
```

宫编号是「按 $b$ 分块」：`r // b` 是行块号、`c // b` 是列块号，乘 $b$ 把行块号放回高位，两者拼起来正好是 $0 \sim s-1$ 的唯一编号。$s$ 是平方数，`b = int(round(s ** 0.5))` 得到 $2/3/4$。

有了掩码，一个空格的候选集合就是「全集去掉已用」：

```python
cand = full & ~(rows[r] | cols[c] | boxes[(r // b) * b + (c // b)])
```

`full = (1 << (s + 1)) - 2` 是第 $1 \sim s$ 位全为 $1$ 的掩码。逐行逐列扫也能判重，但 16 阶时一格要扫 $3 \times 16 = 48$ 个数字；而 MRV 需要反复比较多个格子的候选**个数**，每次都扫一遍就太贵了。

把给定数先压进掩码这一步是**正确性要求**而不是加速：位掩码的「或」会把重复吸收掉（把 `1 1` 压进去和压一个 `1` 没有区别），一旦进了搜索体，这处冲突就再也发现不了。少了这段预检，一张「填满但第 1 行有两个 $1$」的 4 阶盘会被当成零个空格的合法解原样打印出来，而不是输出 `0`。

### 搜索顺序：每次挑候选最少的空格（MRV）

按行列顺序填，等于把分叉押在「第一个空格」上。更好的做法是每一步重新挑**候选最少**的那个：

```python
bj = -1
bc = 0
bn = s + 1
for j in range(depth, n_empty):
    r, c = empties[j]
    cand = full & ~(rows[r] | cols[c] | boxes[(r // b) * b + (c // b)])
    cnt = cand.bit_count()
    if cnt == 0:
        return                            # 某个空格已经没有候选，这条分支死局
    if cnt < bn:
        bn, bj, bc = cnt, j, cand
        if cnt == 1:
            break
empties[depth], empties[bj] = empties[bj], empties[depth]
```

三点好处都在这一小段里：候选为 $0$ 的空格立刻把分支剪掉（不必等填到它才发现）；候选为 $1$ 的格子是纯推导，不会产生任何分叉；分叉只留给真正不确定的格子。选中之后把 `empties` 里的它**交换**到当前层头部，省掉一个「已填」标记数组，回溯时再换回去。

### 枚举候选、递归、对称回退

```python
while masks and len(solutions) < 2:
    bit = masks & -masks                     # 低位优先 = 数值从小到大
    masks ^= bit
    grid[r][c] = bit.bit_length() - 1        # 1<<v 的 bit_length 是 v+1
    rows[r] |= bit
    cols[c] |= bit
    boxes[bi] |= bit
    dfs(depth + 1)
    rows[r] ^= bit
    cols[c] ^= bit
    boxes[bi] ^= bit
```

`bit.bit_length() - 1` 才是真正的数值。回退用异或把刚「或」上去的那一位抹掉，三处必须与设置时完全对称——这一行的对称性是多解判定的命门，漏一处就会把错误的状态带进兄弟分支。

### 数据范围说明「指数级」为什么也能过

数独搜索最坏是指数级，但这里有两层保险：

- 递归深度等于空格数，$s \le 16$ 时最多 $256$ 层，离 `setrecursionlimit(5000)` 很远；
- 搜索只需要「最多两组解」。唯一解的盘面靠候选为 $1$ 的推导一路走完，几乎不分叉；多解的盘面**恰恰更省时间**——第二组解很快出现，`len(solutions)` 一到 $2$ 就整棵收线。$4$ 阶空盘一共有 $288$ 组解，而代码只会走到第二组。

### 实现映射

- `find_solutions(s, grid)`：建三组掩码 → 校验给定数 → 收集空格 → 跑 DFS，返回前两组解；
- `dfs(depth)`：入口先看解够没够两组；满了就存一份盘面快照；否则 MRV 选格、按位枚举候选、递归、回退；
- `solve()`：读边长与 $s$ 行，只有解数**恰为 $1$** 才打印盘面，其余情况打印 `0`。

"""
P5920. 方阵唯一补齐 - 位掩码 + MRV 回溯

超级数独：盘面边长 s ∈ {4, 9, 16}（即 t 的平方）。每条横行、每条
竖列、每个 √s×√s 的小宫都要恰好放 1..s 且互不相同。给定盘面中
0 表示空格，其余为 1..s。要求补全盘面；合法补法恰有一组时输出
整盘，多于一组或一组都没有时只输出 0。

输入格式：
- 第 1 行：盘面边长 s；
- 随后 s 行、每行 s 个整数（空格分隔），0 为空格。

输出格式：
- 恰有一组合法补法时逐行输出整盘（同行空格分隔）；
  否则输出一行 0。

核心思路：
解数独的唯一性判定 = 「找到第一组解后继续搜，看有没有第二组」。
实现上用三个位掩码数组记录每行、每列、每个小宫已用过的数字，
空格集合交给回溯；每一步不按固定顺序走，而是在剩余空格里挑
「行×列×宫相交后候选最少」的那个格子（MRV）先试，从候选最少处
分叉能把无解与多解的分支剪得最干净。候选按从小到大枚举，
第一组完整命中即保存，命中第二组立即整棵搜索收线。

时间复杂度：指数级最坏，但 MRV + 位掩码使本题数据规模
（4/9/16 阶）下瞬时可解
空间复杂度：O(s²)

def find_solutions(s, grid):
    """返回前两组合法补法（至多两组），用于区分唯一/多解/无解。

    givens 与给定数冲突或填数下界不对时返回空列表。
    """
    b = int(round(s ** 0.5))
    full = (1 << (s + 1)) - 2  # 第 1..s 位各对应一个数字

    rows = [0] * s
    cols = [0] * s
    boxes = [0] * s
    for r in range(s):
        for c in range(s):
            v = grid[r][c]
            if v == 0:
                continue
            if not 1 <= v <= s:
                return []
            bit = 1 << v
            bi = (r // b) * b + (c // b)
            if (rows[r] | cols[c] | boxes[bi]) & bit:
                return []
            rows[r] |= bit
            cols[c] |= bit
            boxes[bi] |= bit

    empties = [(r, c) for r in range(s) for c in range(s) if grid[r][c] == 0]
    n_empty = len(empties)
    solutions = []

    sys.setrecursionlimit(5000)

    def dfs(depth):
        if len(solutions) >= 2:
            return
        if depth == n_empty:
            solutions.append([row[:] for row in grid])
            return
        # MRV：挑候选数最少的空格先试
        bj = -1
        bc = 0
        bn = s + 1
        for j in range(depth, n_empty):
            r, c = empties[j]
            cand = full & ~(rows[r] | cols[c] | boxes[(r // b) * b + (c // b)])
            cnt = cand.bit_count()
            if cnt == 0:
                return  # 这条分支已经死局
            if cnt < bn:
                bn = cnt
                bj = j
                bc = cand
                if cnt == 1:
                    break
        empties[depth], empties[bj] = empties[bj], empties[depth]
        r, c = empties[depth]
        bi = (r // b) * b + (c // b)
        masks = bc
        while masks and len(solutions) < 2:
            bit = masks & -masks
            masks ^= bit
            grid[r][c] = bit.bit_length() - 1
            rows[r] |= bit
            cols[c] |= bit
            boxes[bi] |= bit
            dfs(depth + 1)
            rows[r] ^= bit
            cols[c] ^= bit
            boxes[bi] ^= bit
        empties[depth], empties[bj] = empties[bj], empties[depth]
        grid[r][c] = 0

    dfs(0)
    return solutions


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    s = int(data[0])
    grid = []
    pos = 1
    for _ in range(s):
        grid.append([int(x) for x in data[pos:pos + s]])
        pos += s

    solutions = find_solutions(s, grid)
    if len(solutions) == 1:
        print("\n".join(" ".join(map(str, row)) for row in solutions[0]))
    else:
        print(0)

## 示例推演

样例 1（$s=4$，$b=2$）有四个空格，逐个算候选（行、列、宫三者求交）：

| 空格 | 本行已有 | 本列已有 | 本宫已有 | 候选 |
| ---- | -------- | -------- | -------- | ---- |
| $(0,3)$ | $2,1,4$ | $2,4,1$ | $4,1,2$ | $\{3\}$ |
| $(1,1)$ | $3,1,2$ | $1,3,2$ | $2,1,3$ | $\{4\}$ |
| $(2,2)$ | $1,3,4$ | $4,1,3$ | $4,3,1$ | $\{2\}$ |
| $(3,0)$ | $2,3,1$ | $2,3,1$ | $1,3,2$ | $\{4\}$ |

四个空格的候选数都是 $1$：MRV 每次都挑到唯一候选，一路纯推导、零分叉，填完即为一组解；此时 `depth == n_empty`，把盘面存进 `solutions`。回退后没有任何格子还有别的候选，`len(solutions)` 停在 $1$，于是打印这张唯一的盘面。

多解分支换一张 $4$ 阶空盘看。$(0,0)$ 的候选是 $\{1,2,3,4\}$，从 $1$ 开始试，代码落出的第一组解是：

```text
1 2 3 4
3 4 1 2
2 1 4 3
4 3 2 1
```

搜索**不在这里停**，而是退回最近一个还有剩余候选的格子，换下一个数继续。第二组解很快就出现了：

```text
1 2 3 4
3 4 1 2
2 3 4 1
4 1 2 3
```

`len(solutions)` 到 $2$，整棵搜索收线，`solve()` 走 `else` 分支打印 `0`。$4$ 阶空盘其实有 $288$ 组解，代码只走到第二组——这正是「只需要判断有没有第二组」省下的全部工作。

样例 2（$s=9$）用来说明 MRV 为什么有效：这张盘上散布着一批候选数恰为 $1$ 的空格，MRV 每一步都先挑到它们，整盘几乎是一路推导走完。举两处：

- $(0,0)$：本行已有 $\{3,5,8\}$、本列已有 $\{2,4,7,8,9\}$、本宫（左上那个 $3\times3$）已有 $\{2,3,4,6,8\}$，三者的可用数字取交只剩 $\{1\}$；
- $(4,1)$：本行已有 $\{4,5,6,7,8\}$、本列已有 $\{2,3,4,5,6,8\}$、本宫（行 $3\sim5$、列 $0\sim2$）已有 $\{1,2,4,6,7,8\}$，取交只剩 $\{9\}$。

两处推出来的 $1$ 与 $9$，与题面输出里对应格子完全一致。这类格子一旦被选中就不产生任何分叉，所以 9 阶盘的实际搜索量远小于「空格数」给人的印象。

无解分支不经过搜索：像 `1 1 0 0` 开头的盘面，压掩码时第二行的 $1$ 撞上第一行已有的 $1$，`find_solutions` 直接返回空列表，输出 `0`。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 固定顺序的朴素回溯 | 指数级 | $O(s^2)$ | 每格判重要扫 $3s$ 个数；顺序固定，唯一候选的推导也会被拆成分叉 |
| 位掩码 + MRV 回溯（最优） | 指数级（本题规模下毫秒级） | $O(s^2)$ | 判重是一次位或；候选最少者先试；第二组一出现即收线 |

指数级是数独本身的难度，不是实现的缺陷；MRV 与「最多两组」两个剪枝把本题的实际搜索量压到了很小。空间里最重的是盘面与三组长度 $s$ 的掩码，递归深度不超过空格数 $256$。

---

## 易错点总结

### 1. 找到第一组解就收工

收线条件必须是 `len(solutions) >= 2`。写成 `>= 1`（或者干脆改成「找到一个就 `print` 并 `return`」），唯一解的盘面照样正确，多解的盘面却会**打印出一张盘面**：整空 $4$ 阶盘共有 $288$ 组解，程序给了第一张就结束，输出本该是 `0`。

### 2. 回退只回了两处

填数时 `rows[r] |= bit`、`cols[c] |= bit`、`boxes[bi] |= bit` 三处同时设置，回退就必须三处同时异或。只漏掉 `boxes[bi] ^= bit` 这一行，兄弟分支会继承一个「这个数字在本宫已经用过」的假状态，候选被凭空砍掉：整空 $4$ 阶盘会变成「只找到一组解」，输出一张盘面而不是 `0`。

### 3. 小宫编号的乘系数写错

`bi = (r // b) * b + (c // b)` 里，`r // b` 必须先取整再乘 $b$。写成 `r * b + (c // b)`，$s=4$ 时第 4 行算出 $6$，直接 `IndexError: list index out of range`；写成 `(c // b) * b + (r // b)`（行列颠倒）虽然不越界，但宫约束整体错位，样例 1 与样例 2 都会被判成多解、输出 `0`。

## 扩展思考

若要列出全部解，把收线条件从「$\ge 2$」换成不设上限即可，骨架不动。阶数继续往上走，值得加的是约束传播（先把候选数为 $1$ 的格子批量填掉）与计数型剪枝，回溯的形状不变；数独之外的拉丁方、拼图填数，同样落在「位掩码表达约束 + MRV 选格」这一套框架里。
