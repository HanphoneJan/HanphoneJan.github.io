# P5567. 激活检查点放置

> 场次：2026年9月23日 · 来源：[CodeFun2000 P5567](https://codefun2000.com/p/P5567)

## 题目描述

在大模型训练中，前向传播会留下大量中间激活，反向传播时还要用到它们。当 GPU 显存吃紧时，激活重计算（Gradient Checkpointing）是一种常见的「用时间换空间」做法：只在若干「检查点」层保存激活，其余层在反向阶段再算一遍。本题要求：在给定显存预算下，求出最优的 Checkpoint 放置方案。

模型共有 $N$ 层（编号为 $1$ 到 $N$），按前向顺序依次执行。给定两个长度为 $N$ 的正整数数组：

- `forward_time[i]`（$0 \le i < N$）：第 $i+1$ 层前向传播的耗时；
- `memory[i]`（$0 \le i < N$）：在第 $i+1$ 层保存激活（打 Checkpoint）所需的额外显存。

固定边界：

- 第 $0$ 层（输入层）的激活常驻显存，不计入额外开销，它是天然的起始 Checkpoint；
- 第 $N$ 层是终点：不必在第 $N$ 层再存额外激活，也不占用 Checkpoint 显存。

操作：你可以在某些中间层 $c$（$1 \le c \le N-1$）打 Checkpoint。在第 $c$ 层打 Checkpoint 会占用 `memory[c-1]` 的显存（第 $c$ 层对应数组下标 $c-1$）。所有 Checkpoint 的显存占用之和不得超过 $MaxMem$。

重计算代价：
设两个相邻 Checkpoint 位置为 $c$ 与 $d$（$c < d$，中间没有别的 Checkpoint）。反向传播经过该区间时，需要从第 $c$ 层的激活出发，重新前向计算以恢复中间层激活。由于反向是逐层推进的，层 $d-1$ 只需重算一次（从 $c$ 前向到 $d-1$），层 $d-2$ 需要重算两次，以此类推。因此该区间的重计算代价为：

$$Cost(c,d) = \sum_{k=c+1}^{d-1} forward\_time[k-1] \times (d-k)$$

其中 $forward\_time[k-1]$ 是第 $k$ 层的前向耗时，$(d-k)$ 是该层被重复计算的次数。若 $d = c+1$（相邻 Checkpoint），代价为 $0$。

目标：在显存预算 $MaxMem$ 内选择 Checkpoint 放置方案，使整网总重计算代价最小。总代价等于所有相邻 Checkpoint 对之间的代价之和（隐含起点 $0$ 与终点 $N$）。

## 输入格式

输入格式如下：

1. `N MaxMem`
2. `f_1 f_2 ... f_N`
3. `m_1 m_2 ... m_N`

- 第 $1$ 行：两个非负整数 $N$ 与 $MaxMem$，分别表示模型层数与额外显存预算上限。
- 第 $2$ 行：$N$ 个空格分隔的正整数，表示每层前向传播耗时。
- 第 $3$ 行：$N$ 个空格分隔的正整数，表示在每层保存 Checkpoint 所需的额外显存。

保证：$1 \le N \le 100$，$0 \le MaxMem \le 1000$，$1 \le f_i,m_i \le 1000$。

## 输出格式

输出一行一个整数：最小总重计算代价。

## 示例

### 示例 1

**输入：**

```
5 3
5 10 5 10 20
1 2 1 3 1
```

**输出：**

```
15
```

**说明：**

可选的 Checkpoint 位置：层 $1,2,3,4$。始终存在隐式起点 $0$ 与终点 $5$。

| 方案 | Checkpoint 位置 | 显存消耗 | 区间划分 | 各区间代价 | 总代价 |
| ---- | --------------- | -------- | -------- | ---------- | ------ |
| A    | 无              | 0        | $(0,5)$  | $5\cdot4+10\cdot3+5\cdot2+10\cdot1=70$ | 70 |
| B    | $\{2\}$         | 2        | $(0,2),(2,5)$ | $5$，$5\cdot2+10\cdot1=20$ | 25 |
| C    | $\{1,3\}$       | 2        | $(0,1),(1,3),(3,5)$ | $0$，$10$，$10$ | 20 |
| D    | $\{2,3\}$       | 3        | $(0,2),(2,3),(3,5)$ | $5$，$0$，$10$ | 15 |

方案 D 显存消耗 $3 \le 3$，总代价 $15$ 最小。

$Cost(0,5)$ 细算：

- $k=1$：$forward\_time[0]\times(5-1)=5\times4=20$
- $k=2$：$forward\_time[1]\times(5-2)=10\times3=30$
- $k=3$：$forward\_time[2]\times(5-3)=5\times2=10$
- $k=4$：$forward\_time[3]\times(5-4)=10\times1=10$
  合计 $70$。注意第 $5$ 层（$k=5$）不在求和范围内（上界为 $d-1=4$）。

## 提示

提示
可建模为带容量约束的区间最短路 / 分段 DP。
先计算 $cost[c][d]$（$0 \le c < d \le N$），利用前缀和可在 $O(N^2)$ 内完成：

- 先算 $S[i]=\sum_{k=1}^{i}forward\_time[k-1]$（前缀和）
- $Cost(c,d)=\sum_{k=c+1}^{d-1}forward\_time[k-1]\cdot(d-k)$，可用递推在 $O(1)$ 得到每对。

再构建转移：对每个位置 $i$ 与已用显存 $w$，枚举上一个 Checkpoint 位置 $j$（$0 \le j < i$）：

$$dp[i][w]=\min_{j}\bigl(dp[j][w-memory[i-1]]+cost[j][i]\bigr)$$

其中 $dp[0][0]=0$（起点不耗显存），第 $N$ 层作为终点不消耗额外显存。

## 解题思路

### 先把图景压成「选切点」

$0\to1\to\cdots\to N$ 的一条链上，第 $0$ 层的激活常驻显存，是免费的起点切点；第 $N$ 层之后不再需要保存激活，是免费的终点切点；中间每层 $c$ 都可以花 `memory[c-1]` 的显存把它立成切点。一个方案就是在这条链上**挑几个切点**。相邻切点 $c<d$ 之间的段在反向传播时被重算：第 $d-1$ 层只需重算 1 次（从 $c$ 前向跑到 $d-1$），第 $d-2$ 层要再跑一次前向，算 2 次……于是

$$Cost(c,d)=\sum_{k=c+1}^{d-1} forward\_time[k-1]\times(d-k)$$

求和范围是**夹在中间的层**，两个端点的激活都是已存好的，不重算。

目标是在 $\sum memory\le MaxMem$ 下让各段代价之和最小，输出这个最小值。结构上的关键一句是：**段代价只由两个端点决定，与之前怎么切无关**——各段的代价彼此独立、可加、可拼，这正是「选切点」型 DP 的形状，切的缝天然落在切点上。

### 先想到的一维 DP 会被预算击穿

最容易想到的状态是一维的：`dp[i]` = 第 $i$ 层是切点时 $0\to i$ 的最小代价，转移枚举上一个切点 $j$。它的破绽在显存预算上：到过同一个位置 $i$ 的若干方案，代价小的那个可能恰好花掉了更多显存，让后面更长的段没有预算可花——只记代价不记花费，状态本身就不完备。所以状态必须同时记住两件事：

$$dp[i][w]=\text{第 } i \text{ 层是切点、已花 } w \text{ 显存时，}0\to i \text{ 的最小总代价}$$

$N\le100$、$MaxMem\le1000$，这张表 $100\times1001$ 格，每个 $(i,w)$ 枚举 $j$，转移总量约 $\frac{N^2}{2}\cdot MaxMem\approx5\times10^6$，Python 也轻松。数据范围把两条路都否定掉：子集枚举 $2^{N-1}$（$N=100$ 时 $2^{99}$）不用考虑，一维 DP 记不全，留下的就是这张二维表。

### 区间代价：把右端点拉长一圈

每次转移都要查 $Cost(j,i)$。当场按定义求和是 $O(N)$，整体会被拖慢一个 $N$ 的因子；先把所有 $(c,d)$ 的代价预处理成表，转移就变成查表 + $O(1)$。

递推的观察：把右端点从 $d-1$ 拉到 $d$，原区间内每一层的重算次数各 $+1$——这恰好等于 $c+1..d-1$ 层耗时之和；新进来的第 $d-1$ 层只算 1 次。合并成：

$$Cost(c,d)=Cost(c,d-1)+\bigl(prefix[d-1]-prefix[c]\bigr),\qquad prefix[t]=\sum_{k=1}^{t}forward\_time[k-1]$$

下标要对准：**第 $k$ 层的耗时存在数组下标 $k-1$**，所以「第 $c+1$ 层到第 $d-1$ 层」的耗时和是 $prefix[d-1]-prefix[c]$。相邻切点 $Cost(c,c+1)=0$，不用特判。

### 状态到代码的映射

- `dp[0][0]=0`，其余 $+\infty$：起点免费。
- dp 的行只到 $n-1$：终点 $N$ 不占显存也不付代价，最后一段用 $Cost(j,n)$ 在收尾循环里一次并入。
- `memory[i-1] > max_mem` 的层整行跳过——它注定当不了切点，这一行永远保持 $+\infty$。
- $w$ 是「恰好花费」语义，这样记表最省事；代价是收尾必须**在全部 $0\le w\le max\_mem$ 上取最小**（代码收尾的 `for w in range(max_mem + 1)`），只读 `dp[j][max_mem]` 会漏。

## 完整代码实现

```python
"""
P5567. 激活检查点放置 - 区间代价 + 分段动态规划

输入格式：
- 第 1 行：两个整数 N、MaxMem；
- 第 2 行：N 个正整数 forward_time；
- 第 3 行：N 个正整数 memory。

输出格式：
- 一行一个整数：最小总重计算代价。

时间复杂度：O(N^2 * MaxMem)
空间复杂度：O(N * MaxMem + N^2)
"""

import sys


def build_costs(forward_time):
    """预处理任意两个 Checkpoint 之间的重计算代价 cost[c][d]。"""
    n = len(forward_time)

    # prefix[t] = forward_time[0] + ... + forward_time[t-1]
    # 第 k 层的耗时是 forward_time[k-1]，所以第 c+1..d-1 层的耗时和是
    # prefix[d-1] - prefix[c]。
    prefix = [0] * (n + 1)
    for t in range(1, n + 1):
        prefix[t] = prefix[t - 1] + forward_time[t - 1]

    cost = [[0] * (n + 1) for _ in range(n)]

    # 把右端点从 d-1 拉到 d：中间每一层的系数都加 1，
    # 相当于把 c+1..d-1 的耗时各再算一次，正好是一段前缀和。
    for c in range(n):
        for d in range(c + 2, n + 1):
            cost[c][d] = cost[c][d - 1] + prefix[d - 1] - prefix[c]

    return cost


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    it = iter(data)
    n = int(next(it))
    max_mem = int(next(it))

    forward_time = [int(next(it)) for _ in range(n)]
    memory = [int(next(it)) for _ in range(n)]

    cost = build_costs(forward_time)

    INF = float("inf")

    # dp[i][w]：第 i 层作为最后一个 Checkpoint、已花费 w 显存时，
    # 从起点到第 i 层这一段的最小代价。
    dp = [[INF] * (max_mem + 1) for _ in range(n)]
    dp[0][0] = 0  # 起点免费

    for i in range(1, n):
        # 第 i 层打点的显存开销；它本身就超预算时，这一层不可能成为切点
        weight = memory[i - 1]
        if weight > max_mem:
            continue

        row = dp[i]
        for w in range(weight, max_mem + 1):
            best = INF
            # 枚举上一个切点 j，把 (j, i) 这一段的代价接上去
            for j in range(i):
                prev = dp[j][w - weight]
                if prev == INF:
                    continue
                candidate = prev + cost[j][i]
                if candidate < best:
                    best = candidate
            row[w] = best

    # 收尾：最后一段从切点 j 直达终点 n（终点不占显存）
    answer = INF
    for j in range(n):
        tail = cost[j][n]
        row = dp[j]
        for w in range(max_mem + 1):
            used = row[w]
            if used != INF and used + tail < answer:
                answer = used + tail

    print(answer)


if __name__ == "__main__":
    solve()
```

## 示例推演

输入 $N=5$、$MaxMem=3$，`forward_time=[5,10,5,10,20]`，`memory=[1,2,1,3,1]`。

**前缀和**：$prefix=[0,\ 5,\ 15,\ 20,\ 30,\ 50]$。

**区间代价表**（固定左端点，按递推从左往右填）：

| $c\backslash d$ | 1 | 2 | 3 | 4 | 5 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 0 | 0 | 5 | 20 | 40 | 70 |
| 1 | — | 0 | 10 | 25 | 50 |
| 2 | — | — | 0 | 5 | 20 |
| 3 | — | — | — | 0 | 10 |
| 4 | — | — | — | — | 0 |

抽查两个格子：$Cost(0,5)=Cost(0,4)+\bigl(prefix[4]-prefix[0]\bigr)=40+30=70$，与题面说明里逐项累计的 $20+30+10+10$ 一致；$Cost(2,5)=5+15=20$，展开核对 $5\times2+10\times1=20$ 也一致。

**DP 表**（$w$ 为恰好花费，$\infty$ 表示不可达）：

| $i\backslash w$ | 0 | 1 | 2 | 3 |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 0 | $\infty$ | $\infty$ | $\infty$ |
| 1 | $\infty$ | 0 | $\infty$ | $\infty$ |
| 2 | $\infty$ | $\infty$ | 5 | 0 |
| 3 | $\infty$ | 20 | 10 | 5 |
| 4 | $\infty$ | $\infty$ | $\infty$ | 40 |

填几格看看：$dp[2][3]=dp[1][1]+Cost(1,2)=0+0=0$（切点 $1$ 花 `memory[0]=1`，切点 $2$ 再花 `memory[1]=2`，合计 3）；$dp[3][2]=dp[1][1]+Cost(1,3)=10$，而 $dp[3][3]=dp[2][2]+Cost(2,3)=5+0=5$。同样到达层 $3$，花 3 的方案比花 2 的便宜 5——一维表每层只留一格，无论留下哪个，另一个方案连同它剩下的预算额度一起消失，这正是维度必须存在的原因。

**收尾**（终点 5 免费、不占显存，全部 $w$ 一起扫）：

| $j$ | 取格 | $dp[j][w]$ | $Cost(j,5)$ | 合计 |
| :--- | :--- | :--- | :--- | :--- |
| 0 | $w=0$ | 0 | 70 | 70 |
| 1 | $w=1$ | 0 | 50 | 50 |
| 2 | $w=2/3$ | 5 / 0 | 20 | 25 / 20 |
| 3 | $w=1/2/3$ | 20 / 10 / 5 | 10 | 30 / 20 / **15** |
| 4 | $w=3$ | 40 | 0 | 40 |

最小值 $15$ 来自 $j=3,w=3$。回溯来源：$dp[3][3]=dp[2][2]+Cost(2,3)$，$dp[2][2]=dp[0][0]+Cost(0,2)$，故切点为 $\{2,3\}$，方案 $0\to2\to3\to5$：显存 $memory[1]+memory[2]=2+1=3\le3$，代价 $Cost(0,2)+Cost(2,3)+Cost(3,5)=5+0+10=15$。输出 `15`。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| :--- | :--- | :--- | :--- |
| 枚举 Checkpoint 子集 | $O(2^{N-1}\cdot N)$ | $O(N)$ | $N=100$ 时 $2^{99}$，不可行 |
| 分段 DP，转移现场求段代价 | $O(N^3\cdot MaxMem)$ | $O(N\cdot MaxMem)$ | 正确，但每次转移多付一个 $O(N)$ |
| 段代价预处理 + 分段 DP（最优） | $O(N^2\cdot MaxMem)$ | $O(N\cdot MaxMem+N^2)$ | 转移查表 $O(1)$，约 $5\times10^6$ 次运算；本题采用 |

## 易错点总结

### 1. 「恰好 $w$」语义下，答案要扫全部预算

dp 表按「恰好花费 $w$」记录。收尾若只读 $dp[j][max\_mem]$，预算 10 而真正要用的方案只花 1 时，那一格可能整行是 $+\infty$，直接输出就错。代码收尾用 `for w in range(max_mem + 1)` 在全预算上取最小。

### 2. 层号与数组下标差一位

题面按 $1$ 起编号讲层，数组按 $0$ 起下标存：第 $k$ 层耗时是 `forward_time[k-1]`、第 $i$ 层打点扣 `memory[i-1]`。错一位时区间代价表整体算偏，输出变大变小但不报任何异常；样例 1 的 $Cost(0,5)=70$ 是现成的核对锚点。

### 3. 终点 $N$ 不占显存

dp 的行只到 $n-1$，最后一段由 $Cost(j,n)$ 收尾。若把第 $n$ 层也当普通层去扣 `memory[n-1]`，显存预算被无谓挤占——样例里 $MaxMem=3$，方案 $\{2,3\}$ 会当场失效，答案整体变大。

## 扩展思考

- 要输出方案本身：加一张 `pre[i][w]` 记录转移来源的 $j$，从收尾的最小值处倒推即可。
- 把「显存预算」换成「最多切 $k$ 刀」是同一族题，状态里的 $w$ 换成计数即可；P5568 的 NPU 均衡调度是它的另一支近亲——约束变成任务分组，判定从 DP 换成回溯搜索。
