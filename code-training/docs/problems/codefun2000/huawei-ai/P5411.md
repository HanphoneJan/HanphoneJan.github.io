# P5411. CDN 节点聚类选址与用户覆盖计算

> 场次：2026年9月9日 · 来源：[CodeFun2000 P5411](https://codefun2000.com/p/P5411)

## 题目描述

在内容运营平台中，CDN 分发服务器用于为用户提供就近的内容下载服务。现有 $p$ 座城市，每座城市具有二维坐标和用户数。平台计划建设 $q$ 台 CDN，以兼顾覆盖用户规模与空间距离，使全体用户的加权总距离尽可能小。请按照 k-means 聚类流程确定每台 CDN 的选址坐标及其覆盖用户数。

计算过程遵循以下规则：

- 初始时，地图上尚未部署任何 CDN；
- CDN 必须位于某一座城市的坐标上；
- 迭代开始时，将输入顺序中的前 $q$ 座城市作为初始 CDN 选址；
- 每一轮迭代中，先为每座城市分配距离最近的一台 CDN；若某座城市到多台 CDN 的距离相等，则将其分配给编号更靠前的那一台；
- 针对每台 CDN 当前覆盖的城市集合，重新选择一座集合内的城市作为新的 CDN 选址，使该集合内所有用户到该城市的加权距离总和最小；若有多座城市并列最优，则选择原输入中编号更靠前的一座；
- 当所有 CDN 所在城市不再变化时，停止迭代。

城市坐标为 $(x, y)$，CDN 坐标为 $(c_x, c_y)$。一名用户到某台 CDN 的距离定义为欧氏距离：

$$d = \sqrt{(x - c_x)^2 + (y - c_y)^2}$$

若第 $i$ 座城市的用户数为 $u_i$，其被分配到的 CDN 编号为 $z_i$，则该 CDN 坐标为 $(c_{x,z_i}, c_{y,z_i})$。全体用户的加权总距离为：

$$Total = \sum_{i=1}^{p} u_i \cdot \sqrt{(x_i - c_{x,z_i})^2 + (y_i - c_{y,z_i})^2}$$

每台 CDN 的覆盖用户数等于被分配至该 CDN 的所有城市的用户数之和。

约束条件：

- 城市数量 $p$ 为正整数，满足 $0 < p < 100$；
- 每座城市的横坐标、纵坐标和用户数均为浮点数，数值均大于 `0` 且小于 `100`；
- CDN 数量 $q$ 为正整数，满足 $0 < q < 100$ 且 $q \le p$。

## 输入格式

第一行包含一个正整数 $p$，表示城市数量。

接下来 $p$ 行，每行包含三个以英文逗号分隔的浮点数 $a,b,c$，依次表示该城市的横坐标、纵坐标和用户数，单位为万人。

最后一行包含一个正整数 $q$，表示允许建设的 CDN 数量。

## 输出格式

输出 $q$ 行，每行包含三个以英文逗号分隔的浮点数 $a,b,c$，依次表示一台 CDN 的横坐标、纵坐标及其覆盖用户数，单位为万人。所有浮点数均保留 `2` 位小数。

CDN 按横坐标 $a$ 升序输出；若横坐标相同，则按纵坐标 $b$ 升序输出。

## 示例

### 示例 1

**输入：**

```
4
1.00,1.00,10.00
2.00,1.00,1.00
5.00,5.00,1.00
6.00,5.00,10.00
2
```

**输出：**

```
1.00,1.00,11.00
6.00,5.00,11.00
```

**说明：**

按输入顺序将城市记为 `0`、`1`、`2`、`3`。初始时，前 `2` 座城市分别作为第 `1` 台和第 `2` 台 CDN 的选址，即 $(1.00,1.00)$ 与 $(2.00,1.00)$。

第一轮分配中，城市 `0` 到 $(1.00,1.00)$ 的距离为 $0$，分配给第 `1` 台 CDN；城市 `1` 到 $(2.00,1.00)$ 的距离为 $0$，分配给第 `2` 台 CDN。城市 `2` 到 $(1.00,1.00)$ 的距离约为 $5.66$，到 $(2.00,1.00)$ 的距离为 $5.00$，分配给第 `2` 台 CDN。城市 `3` 到 $(1.00,1.00)$ 的距离约为 $6.40$，到 $(2.00,1.00)$ 的距离约为 $5.66$，也分配给第 `2` 台 CDN。

因此第 `1` 台 CDN 的簇只包含城市 `0`；第 `2` 台 CDN 的簇包含城市 `1`、`2`、`3`。第一轮重新选址时，第 `1` 台簇内只有城市 `0`，仍选城市 `0`。第 `2` 台簇内以城市 `1`、`2`、`3` 分别作为候选，加权距离和约为 $61.57$、$15.00$、$6.66$，因此选择城市 `3`，坐标为 $(6.00,5.00)$。

第二轮分配中，城市 `0` 和城市 `1` 距离 $(1.00,1.00)$ 更近，分配给第 `1` 台 CDN；城市 `2` 和城市 `3` 距离 $(6.00,5.00)$ 更近，分配给第 `2` 台 CDN。第二轮重新选址时，第 `1` 台簇中城市 `0` 的加权距离和为 $1.00$，城市 `1` 为 $10.00$，仍选城市 `0`；第 `2` 台簇中城市 `2` 的加权距离和为 $10.00$，城市 `3` 为 $1.00$，仍选城市 `3`。选址不再变化，停止迭代。

最终第 `1` 台 CDN 位于 $(1.00,1.00)$，覆盖城市 `0` 和城市 `1`，用户数为 $10.00+1.00=11.00$；第 `2` 台 CDN 位于 $(6.00,5.00)$，覆盖城市 `2` 和城市 `3`，用户数为 $1.00+10.00=11.00$。按横坐标升序输出。

### 示例 2

**输入：**

```
1
5.50,6.25,7.75
1
```

**输出：**

```
5.50,6.25,7.75
```

**说明：**

只有 `1` 座城市和 `1` 台 CDN。初始 CDN 选址就是该城市 $(5.50,6.25)$。

该城市到 CDN 的距离为 $0$，加权距离和为 $7.75 \times 0 = 0$，因此选址不会发生变化。最终 CDN 坐标仍为 $(5.50,6.25)$，覆盖用户数为该城市的用户数 `7.75` 万人。

### 示例 3

**输入：**

```
3
1.00,1.00,2.00
1.00,3.00,4.00
4.00,2.00,6.00
3
```

**输出：**

```
1.00,1.00,2.00
1.00,3.00,4.00
4.00,2.00,6.00
```

**说明：**

CDN 数量与城市数量相同，共有 `3` 座城市和 `3` 台 CDN。初始时前 `3` 座城市各自作为一台 CDN 的选址。

每座城市到自身 CDN 的距离都是 $0$，到其他 CDN 的距离均大于 $0$，因此分配结果固定为每座城市归属自己的 CDN。每个簇只有一座城市，重新选择时选址保持不变。

最终按横坐标、纵坐标升序输出：$(1.00,1.00)$ 覆盖用户数 `2.00`，$(1.00,3.00)$ 覆盖用户数 `4.00`，$(4.00,2.00)$ 覆盖用户数 `6.00`。

## 解题思路

### 输出格式先把「输出是什么」钉死

答案按**坐标**排序输出，而不是按 CDN 编号：每行「横坐标,纵坐标,覆盖用户数」，全部保留两位小数。前两个数来自最终选址，第三个来自它对应的分配——这一层分清楚，实现才不会把覆盖数算在别的划分上。

迭代流程题面写死了四个要素，先钉住：初始选址是**输入顺序的前 $q$ 座城市**（这是一错全错的设定）；每轮先分配（每座城市去距离最近的 CDN，距离相等给编号更靠前的 CDN），再更新（每台 CDN 在自己的簇内挑一座城市，使簇内所有用户到它的**加权距离和**最小，并列给输入编号更靠前的城市）；所有选址不再变化即停止。CDN 只能落在城市的坐标上，所以「更新」不是求均值点、而是在簇内枚举候选——这正是 k-medoids 的形态。

### 数据范围免检，功夫全在判定细节上

$p<100$：一轮分配 $O(pq)$、更新最多 $O(p^2)$，几百轮也就是百万级运算，任何朴素实现都够快。所以这题的考察点不在加速，而在让每一步「更小 / 相等」的判定可靠：

- **选址用「城市编号」存**（代码的 `center[k]` 是下标，坐标随时查表）。收敛判定因此是最朴素的整数列表相等。若用坐标比较，两者这次恰好都取自同一张城市表，看似可行，但浮点相等判定本身脆弱：只要有人在中间算过一次均值或插值，$10^{-16}$ 量级的差会让循环永远停不下来。用编号存储把这个隐患连根拔掉。
- **分配比较平方距离**（`distance_sq`）：$d_1<d_2$ 与平方后的比较等价，省掉 $p\times q$ 次开方。
- **更新必须用真实欧氏距离**（`math.hypot`）：目标是加权 $d$ 之和，不是加权 $d^2$。开方是非线性的，拿平方距离当权重等于换了个评价目标，两个接近的候选之间就会选错。
- **平局规则写进比较条件**：分配时 `k` 从 $0$ 升序扫、比较只写「严格更近才换」（`d2 < best_d2 - 1e-9`），距离相等自然留给编号靠前的 CDN；更新时候选按城市编号升序扫、`cost < best_cost - 1e-6` 同理。
- 两处容差的分工：对称几何下数学相等的量经浮点会差 $10^{-13}$ 级，容差把这种伪差异抹掉，平局规则才真正生效；容差都远小于任何真实差距（分配比的是平方距离，量级 $10^4$；更新加权和也在 $10^4$ 量级），不会误伤。

### 空簇与收尾

簇可能为空：两台 CDN 迭代后落到同一座城市、或某台 CDN 的成员被编号更靠前的一台抢走。题目没有定义空簇的更新，「在簇内选一座城市」对空集无解，唯一自然的延伸是**保持原位**（代码 `if not members: continue`），也让迭代不至于崩溃。

收尾三件事：循环退出后**再分配一次**，用最终选址统计覆盖用户数（第二个 `assign_cities()` 调用），保证覆盖数与输出的坐标属于同一套划分；按 $(x,y)$ 升序排序行，两位小数格式化时防 `-0.00`；`1000` 轮的迭代上限只是兜底，正常十几轮就收敛。

## 完整代码实现

```python
"""
P5411. CDN 节点聚类选址与用户覆盖计算 - 按规则模拟 k-means
"""

import math
import sys


def format_number(value: float) -> str:
    """保留两位小数，并避免输出 -0.00。"""
    if abs(value) < 0.005:
        value = 0.0
    return f"{value:.2f}"


def solve():
    """读入城市与 CDN 数量，模拟 k-means 迭代后输出选址与覆盖用户数。"""
    # 输入是“逗号分隔的浮点数”，把逗号统一换成空格再切分，解析最简单
    tokens = sys.stdin.read().replace(",", " ").split()
    if not tokens:
        return

    p = int(tokens[0])
    pos = 1
    xs = [0.0] * p
    ys = [0.0] * p
    users = [0.0] * p
    for i in range(p):
        xs[i] = float(tokens[pos])
        ys[i] = float(tokens[pos + 1])
        users[i] = float(tokens[pos + 2])
        pos += 3
    q = int(tokens[pos])

    q = min(q, p)  # 题目保证 q <= p，这里兜一层避免越界

    # center[k] 是第 k 台 CDN 当前所在的城市编号。
    # 用编号而不是坐标，判“选址是否变化”时直接比较整数即可。
    center = list(range(q))

    def distance_sq(i: int, city: int) -> float:
        dx = xs[i] - xs[city]
        dy = ys[i] - ys[city]
        return dx * dx + dy * dy

    def assign_cities():
        """把每座城市分配给最近的 CDN，返回分配结果与每个簇的成员列表。"""
        assign = [0] * p
        clusters = [[] for _ in range(q)]
        for i in range(p):
            best = 0
            best_d2 = float("inf")
            for k in range(q):
                d2 = distance_sq(i, center[k])
                # 严格更近才换人 => 距离相等时保留编号更小的 CDN
                if d2 < best_d2 - 1e-9:
                    best_d2 = d2
                    best = k
            assign[i] = best
            clusters[best].append(i)
        return assign, clusters

    def update_centers(clusters):
        """在每台 CDN 的簇内重新选址，返回新的城市编号列表。"""
        new_center = center[:]
        for k in range(q):
            members = clusters[k]
            if not members:
                # 簇为空（例如两台 CDN 落在同一点），没有候选城市，保持原位
                continue
            best_city = members[0]
            best_cost = None
            for cand in members:
                cost = 0.0
                xc = xs[cand]
                yc = ys[cand]
                for j in members:
                    # 加权和必须用真实欧氏距离，不能用平方距离代替
                    dist = math.hypot(xs[j] - xc, ys[j] - yc)
                    cost += users[j] * dist
                # members 按输入编号升序，只有“明显更小”才换 => 平局留编号小的
                if best_cost is None or cost < best_cost - 1e-6:
                    best_cost = cost
                    best_city = cand
            new_center[k] = best_city
        return new_center

    # 迭代到选址不再变化为止。理论上一定收敛，这里给一个上限兜底。
    for _ in range(1000):
        assign, clusters = assign_cities()
        new_center = update_centers(clusters)
        if new_center == center:
            break
        center = new_center

    # 用最终选址再分配一次，保证“覆盖用户数”与输出的坐标是同一套分配
    assign, clusters = assign_cities()

    coverage = [0.0] * q
    for i in range(p):
        coverage[assign[i]] += users[i]

    # 按横坐标升序、横坐标相同按纵坐标升序输出
    rows = [(xs[center[k]], ys[center[k]], coverage[k]) for k in range(q)]
    rows.sort(key=lambda row: (row[0], row[1]))

    lines = [",".join(format_number(v) for v in row) for row in rows]
    sys.stdout.write("\n".join(lines) + ("\n" if lines else ""))


if __name__ == "__main__":
    solve()
```

## 示例推演

### 样例 1：两轮迭代看全流程

$p=4$、$q=2$。初始选址：第 1 台在城 0 $(1,1)$，第 2 台在城 1 $(2,1)$。

**第一轮分配**：城 0、城 1 到自己的 CDN 距离为 0；城 2 $(5,5)$ 到 $(1,1)$ 约 $5.66$、到 $(2,1)$ 为 $5.00$；城 3 $(6,5)$ 到 $(1,1)$ 约 $6.40$、到 $(2,1)$ 约 $5.66$，更近后者。两簇为 $\{0\}$ 与 $\{1,2,3\}$。

**第一轮更新**：CDN 1 的簇只有城 0，不动。CDN 2 对三个候选算加权距离和：

| 候选 | 加权距离和 |
| --- | --- |
| 城 1 $(2,1)$ | $1\times0+1\times5+10\times5.66\approx61.57$ |
| 城 2 $(5,5)$ | $1\times5+1\times0+10\times1.00=15.00$ |
| 城 3 $(6,5)$ | $1\times5.66+1\times1+10\times0=6.66$ |

选城 3，选址变为 $[0,3]$，继续迭代。

**第二轮**：分配后两簇变为 $\{0,1\}$ 与 $\{2,3\}$。重新选址：CDN 1 的候选城 0 加权和 $1.00$ 小于城 1 的 $10.00$，CDN 2 的候选城 3 加权和 $1.00$ 小于城 2 的 $10.00$，选址保持 $[0,3]$ 不变，停止。

覆盖用户数：CDN 1 覆盖城 0、1 共 $11.00$，CDN 2 覆盖城 2、3 共 $11.00$。按横坐标升序输出：

```text
1.00,1.00,11.00
6.00,5.00,11.00
```

### 样例 2 与样例 3：一轮收敛

样例 2（$p=q=1$）：唯一城市到初始 CDN 距离为 0，簇内只有自己，覆盖数 $7.75$。样例 3（$q=p$）：每座城市到别的 CDN 都更远，分配固定为一城一簇，覆盖数就是各城自己的用户数 $2,4,6$。这两类输入的共性是第一轮就收敛——检查的主要是输出排序与格式，别把简单情形写崩。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 以浮点坐标保存选址 | $O(K\cdot(pq+p^2))$ | $O(p+q)$ | 工作量相同；收敛判定与平局处理都要面对浮点相等 |
| 以城市编号保存选址（最优） | $O(K\cdot(pq+p^2))$ | $O(p+q)$ | 收敛比较是整数列表；实际数据十几轮内收敛 |

$K$ 为迭代轮数。$p<100$，单轮 $pq+p^2<2\times10^4$，$K$ 即使取到几百也没有压力。

## 易错点总结

### 1. 两处平局各自的方向

分配平局给**CDN 编号更小**的，更新平局给**输入编号更小**的城市——两处都靠「升序扫描 + 严格更小才替换」实现（`d2 < best_d2 - 1e-9`、`cost < best_cost - 1e-6`）。若在相等时也换人、或扫描方向反了，对称布局下就会选错一座城市，覆盖数跟着错。

### 2. 更新阶段用平方距离替代真实距离

`math.hypot` 那行去掉开方就是另一个题目：加权和的对象变成 $d^2$，会系统性放大远处城市的代价，评价目标与题面规定不符。接近的两个候选之间（尤其平局附近）会选出错误的新址，整个后续迭代都在错误的基础上进行。

### 3. 空簇没有候选

`if not members: continue`——两台 CDN 迭代后落同址、或成员被编号更靠前的一台抢走时，簇内一城都没有。不做这个分支就取 `members[0]` 越界直接崩溃。保持原位让这台 CDN 留待下一轮再争取成员。

## 扩展思考

- 更新步不是求均值而是簇内选城，这正是 k-medoids 与 k-means 的分界：均值点最小化的是**平方**距离和，还可能不落在任何城市上。
- k-means 类算法的答案依赖初始中心。题面把初始选址写死为前 $q$ 座城市，正是为了让收敛结果唯一、可判题。
- $p$ 到 $10^5$ 量级时，每轮 $p\times q$ 的分配需要用 KD 树一类的空间索引剪枝，更新步也和簇内增量维护有关。
