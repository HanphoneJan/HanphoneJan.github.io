# P5468. 流水线并行的最小峰值负载

> 场次：2026年9月18日 · 来源：[CodeFun2000 P5468](https://codefun2000.com/p/P5468)

## 题目描述

要把一个神经网络的 $N$ 个层切到 $K$ 块 GPU 上做流水线并行。切完后每一段叫做一个 Stage，训练时按 Stage 顺序接力计算。

一个 Stage 的负载等于它包含的各层前向传播时间之和。若 Stage $s$ 覆盖连续层 $l_1,\dots,l_t$，则

$$Load_s = f[l_1] + \cdots + f[l_t]$$

其中 $f[i]$ 是第 $i$ 层的前向时间。流水线由最慢的 Stage 卡住，因此要最小化所有 Stage 负载的最大值。

切分必须同时满足：

1. 每个 Stage 内的层编号连续
2. 每一层恰好属于一个 Stage
3. 每个 Stage 至少含一层

## 输入格式

第一行两个整数 $N$、$K$，依次为层数和 Stage 个数。

第二行 $N$ 个整数 $f[0]\ f[1]\ \dots\ f[N-1]$，表示各层前向时间（毫秒）。

## 输出格式

输出一行一个整数，即最小化后的最大 Stage 负载。

## 数据范围

- $1 \le K \le N \le 5000$
- $1 \le f[i] \le 1000$

## 示例

### 示例 1

**输入：**

```
7 3
4 6 3 8 2 5 4
```

**输出：**

```
11
```

**说明：**

| 方案 | Stage 0 | Stage 1 | Stage 2 | 最大负载 |
| :--- | :--- | :--- | :--- | :--- |
| 按层数尽量均分 | [4,6,3] | [8,2] | [5,4] | $\max(13,10,9)=13$ |
| 最优 | [4,6] | [3,8] | [2,5,4] | $\max(10,11,11)=11$ |

只有这一种划分能把峰值压到 $11$。

### 示例 2

**输入：**

```
4 2
2 8 3 5
```

**输出：**

```
10
```

**说明：**

四层耗时为 $[2,8,3,5]$，要切成 $2$ 个 Stage。

| 方案 | Stage 0 | Stage 1 | 负载 | 最大负载 |
| :--- | :--- | :--- | :--- | :--- |
| A | [2] | [8,3,5] | $2$ vs $16$ | $16$ |
| B | [2,8] | [3,5] | $10$ vs $8$ | $10$ |
| C | [2,8,3] | [5] | $13$ vs $5$ | $13$ |

最优为方案 B，峰值负载 $10$。

## 解题思路

### 判定标准先立起来：给定上限能不能切

要输出的是一行整数：切成的 $K$ 个 Stage 里，最大的那个 Stage 负载最小能压到多少。把它当整体来求很难，但回答一个简单得多的问题很容易——

> 给定上限 $cap$，能否把层切分，使每一段的负载都不超过 $cap$？

这个判定有一个关键性质：**单调**。若 $cap$ 下能切出来，同一套切法在更大的 $cap$ 下照样合法，所以「可行」的 $cap$ 构成一段后缀，它的左端点就是要求的最小峰值。「求最小值」于是变成「二分答案，每轮只做一次可行性判定」。

### 判定为什么是「贪心装到装不下」

固定 $cap$，先问一个更细的问题：每段都不超过 $cap$ 时，**最少**要切几段？从左往右贪心——能塞就塞，再塞一层就超上限时才切一刀（代码里 `current + f <= cap` 才继续装，否则 `segments += 1`）。贪心得到的就是最少段数：它的第一段一直装到装不下为止，覆盖的前缀不短于任何合法方案的第一段；第一段更长意味着第二段的起点更靠左，同样的道理推给第二段、第三段——逐段归纳，贪心在任意一段结束时覆盖的范围都不会落后于别的方案，用的段数便最少。

判定规则两条：

- 段数 $\le K$：可行。段数不够 $K$ 时，把任意一个含两层以上的段再切一刀即可；$K\le N$ 保证最终总能切到恰好 $K$ 段。
- 段数 $>K$：不可行，$cap$ 太小。

### 数据范围与阶梯：DP 为什么不够用

$N\le5000$。把 $N-1$ 个层间空隙里选 $K-1$ 个切点的所有方案枚举，量是 $\binom{N-1}{K-1}$，直接排除。顺着题目形状最先想到的正规解法是分段 DP：设 $dp[c][i]$ 为「前 $i$ 层切成 $c$ 段」的最小峰值，转移枚举最后一段的起点 $j$：

$$dp[c][i]=\min_{0\le j<i}\max\!\left(dp[c-1][j],\ \mathrm{sum}(f[j..i-1])\right)$$

它是正确的，但复杂度 $O(KN^2)$，$N=5000$ 时约 $6\times10^{10}$，超时。而它的转移反复在问「最后一段从哪切最好」，这件事正是上面的判定一趟扫描就能回答的。「对 $cap$ 二分」配「$O(N)$ 判定」，合计 $O(N\log\sum f)$：二分约 $\log_2(5\times10^6)\approx23$ 轮、每轮扫一遍 $N$ 层，约 $1.2\times10^5$ 次操作。数据范围把这最后一步的方向指得清清楚楚。

### 实现映射

- 二分区间取 $[\max f,\ \sum f]$：下界 $\max f$ 是因为一层不可拆，$cap$ 小于单层最大值时根本无解（这道防线只能由下界把守，原因见易错点 2）；上界取总和，全部层作一段一定可行。
- 判定条件写 `segments_needed(...) <= k`，不是 `== k`。
- 收敛写法 `high = mid`、`low = mid + 1`：`mid` 本身可能是答案，不可跳过它；判定失败时 `mid` 一定不是答案，才能放心 `+1`。区间缩到一点时 `low` 即为结果。

## 完整代码实现

```python
import sys


def segments_needed(loads, cap):
    """在每段负载不超过 cap 的前提下，返回最少需要切成多少段。"""
    segments = 1          # 至少有一段，第一段从第 0 层开始
    current = 0           # 当前这一段的负载
    for f in loads:
        if current + f <= cap:
            # 还装得下就继续装：尽量少切，才能判断 cap 是否足够大
            current += f
        else:
            # 装不下了，必须从当前层开始新的一段
            segments += 1
            current = f
    return segments


def min_peak_load(loads, k):
    """二分最小的可行上限 cap，使得数组能切成不超过 k 段连续子数组。"""
    # 下界取单层最大值：任何一层都无法被拆开，所以 cap 不可能小于它。
    # 上界取总和：整段作为一段时负载就是总和，一定可行。
    low = max(loads)
    high = sum(loads)

    while low < high:
        mid = (low + high) // 2
        # 段数 <= k 说明 mid 够用，答案在左半边（含 mid）。
        # 段数 > k 说明 mid 太小，答案一定在 mid 右侧。
        if segments_needed(loads, mid) <= k:
            high = mid
        else:
            low = mid + 1

    return low


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    n = int(data[0])
    k = int(data[1])
    # 后面正好是 n 个层耗时；用切片一次取出，避免逐行读取的解析开销。
    loads = [int(x) for x in data[2:2 + n]]

    print(min_peak_load(loads, k))


if __name__ == "__main__":
    solve()
```

## 示例推演

### 样例 1：五轮二分

$N=7$、$K=3$，$f=[4,6,3,8,2,5,4]$。初始 $low=\max f=8$，$high=\sum f=32$。

| 轮 | $low$ | $high$ | $mid$ | 贪心切分 | 段数 | 判定 | 更新 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 8 | 32 | 20 | [4,6,3] [8,2,5,4] | 2 | $\le3$ 可行 | $high=20$ |
| 2 | 8 | 20 | 14 | [4,6,3] [8,2] [5,4] | 3 | 可行 | $high=14$ |
| 3 | 8 | 14 | 11 | [4,6] [3,8] [2,5,4] | 3 | 可行 | $high=11$ |
| 4 | 8 | 11 | 9 | [4] [6,3] [8] [2,5] [4] | 5 | $>3$ 不可行 | $low=10$ |
| 5 | 10 | 11 | 10 | [4,6] [3] [8,2] [5,4] | 4 | 不可行 | $low=11$ |

第 5 轮后 $low=high=11$，输出 `11`。两处值得停下来看：

- 第 3 轮的切分正是题目说明里的方案 $[4,6]\,[3,8]\,[2,5,4]$，三段负载 $10,11,11$，峰值就是 $cap$ 本身——判定通过时二分并不知道这就是答案，只是继续向左收。
- 第 4 轮的贪心细走一遍（$cap=9$）：$4+6=10>9$ 切；$6+3=9\le9$ 装；$9+8=17>9$ 切；$8+2=10>9$ 切；$2+5=7\le9$ 装；$7+4=11>9$ 切。得 5 段，超过 $K=3$，故不可行。

### 样例 2：小到一轮半看清

$N=4$、$K=2$，$f=[2,8,3,5]$。$low=8$、$high=18$：$mid=13$ 时贪心得 $[2,8,3]\,[5]$ 两段，可行；$mid=10$ 时 $[2,8]\,[3,5]$ 两段，可行；$mid=9$ 时 $[2]\,[8]\,[3,5]$ 三段，不可行，$low=10$。区间闭合，输出 `10`，与说明里的方案 B 一致。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| :--- | :--- | :--- | :--- |
| 枚举全部切点 | $O\!\left(\binom{N-1}{K-1}\cdot N\right)$ | $O(K)$ | 方案数指数量级，不可行 |
| 分段 DP $dp[c][i]$ | $O(KN^2)$ | $O(N)$ | 正确，但 $N=5000$ 时约 $6\times10^{10}$ 次运算 |
| 二分答案 + 贪心判定（最优） | $O(N\log\sum f)$ | $O(N)$ | 约 $1.2\times10^5$ 次操作；本题采用 |

## 易错点总结

### 1. 判定写成「恰好 $K$ 段」

可行的条件是段数 $\le K$（代码 `if segments_needed(loads, mid) <= k`）。写成 `== K` 会把「贪心只用了 2 段而 $K=3$」的可行 $cap$ 判成不可行：样例 1 里每个足够大的 $cap$ 贪心都只给两段（$[4,6,3]\,[8,2,5,4]$ 之类），若从 $cap=20$ 起问起，四个探测点全部落空，二分一路推到上界，最后输出 $32$——全部层挂一段的负载，比正确答案 $11$ 大一倍还多。

### 2. 贪心不管单层超限，防线只在下界

`segments_needed` 遇到某一层本身比 $cap$ 还大时，`current + f > cap` 让它单独成段，然后若无其事地继续装下一段——段数看不出异常，判定照样报「可行」。也就是说「$cap<\max f$ 不可行」这件事贪心不会替你发现；把二分下界钉在 `low = max(loads)` 上（代码 `min_peak_load` 的第一行）是唯一的防线，删掉它非法 $cap$ 会静默通过。

## 扩展思考

- 与 P5568 的 NPU 均衡调度共用「二分答案 + 可行性判定」的骨架，差别在判定函数：本题的段必须连续，一趟贪心判完；那边任务可以任放，判定本身就得回溯。
- 要输出切分方案：拿二分收敛出的 `cap` 再跑一遍 `segments_needed` 并记录切点即可；贪心天然把前面的段装得尽量长。
- 血缘：与「分割数组的最大值」（LeetCode 410）是同一模型。
