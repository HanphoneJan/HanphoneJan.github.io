# P5346. 双配置训练任务的最优资源调度

> 场次：2026年9月4日 · 来源：[CodeFun2000 P5346](https://codefun2000.com/p/P5346)

## 题目描述

一个模型训练集群需要依次执行 $n$ 个任务。对于任意第 $i$ 个任务，调度系统已经给出两套候选配置，它们在计算资源占用和训练耗时上各有差异。

具体地，若第 $i$ 个任务采用配置 `1`，资源消耗为 $c_1$，训练耗时为 $t_1$；若采用配置 `2`，资源消耗为 $c_2$，训练耗时为 $t_2$。资源统一按照“CPU 核心数 + GPU 显存 GB”计量，集群可使用的总资源量为 $C$。

现在要为每个任务选定一套配置，且每个任务只能选择两套之一。所有任务资源消耗的总和不得超过 $C$。在这些合法选择中，目标是最小化所有任务的总训练耗时，并进一步确定最优方案实际消耗的资源量以及未被使用的剩余资源量。

如果多个合法方案具有相同的最小总训练耗时，则取其中实际资源消耗最少的一个作为最终方案。

约束条件：

- 任务数量 $n$ 在 `1` 到 `100` 之间。
- 总资源上限 $C$ 在 `1` 到 `1000` 之间。
- 每个任务的 $c_1$、$t_1$、$c_2$、$t_2$ 均为 `1` 到 `100` 之间的正整数。

## 输入格式

第一行给出两个整数 $n$ 和 $C$，依次代表任务数量和总资源上限。

接下来的 $n$ 行中，第 $i$ 行包含四个正整数 $c_1$、$t_1$、$c_2$、$t_2$，分别对应该任务配置 `1` 的资源消耗、配置 `1` 的训练耗时、配置 `2` 的资源消耗、配置 `2` 的训练耗时。

## 输出格式

输出共三个整数，用单个空格分隔，依次为：满足资源限制的最小总训练耗时；该最小耗时方案中实际使用的资源总量；以及 $C$ 减去该实际使用资源量后的剩余资源。

## 示例

### 示例 1

**输入：**

```
3 10
4 5 2 3
3 4 5 2
1 2 2 2
```

**输出：**

```
7 8 2
```

**说明：**

任务 `1` 选择配置 `2`，资源消耗为 $2$，耗时 $3$；任务 `2` 选择配置 `2`，资源消耗为 $5$，耗时 $2$；任务 `3` 选择配置 `1`，资源消耗为 $1$，耗时 $2$。

总资源消耗为 $2+5+1=8$，不超过 $C=10$；总耗时为 $3+2+2=7$。每个任务各自的最小耗时之和为 $3+2+2=7$，所以无法再降低总耗时。

任务 `3` 两种配置耗时相同，配置 `1` 的资源更少，因此选择配置 `1`。剩余资源为 $10-8=2$。

### 示例 2

**输入：**

```
1 1
1 5 2 3
```

**输出：**

```
5 1 0
```

**说明：**

总资源上限为 `1`。任务 `1` 的配置 `1` 资源消耗为 `1`，可以放入；配置 `2` 资源消耗为 `2`，超过上限，不可行。

因此唯一合法选择是配置 `1`，总耗时 `5`，实际消耗资源 `1`，剩余资源 $1-1=0$。

### 示例 3

**输入：**

```
2 5
3 4 2 6
2 5 4 1
```

**输出：**

```
9 5 0
```

**说明：**

所有不超过资源上限的选择中，总耗时最少的是：任务 `1` 选择配置 `1`，任务 `2` 选择配置 `1`。

该方案资源消耗为 $3+2=5$，总耗时为 $4+5=9$，刚好等于资源上限。

若任务 `1` 选择配置 `2`，任务 `2` 选择配置 `1`，则总耗时为 $6+5=11$，资源消耗为 $2+2=4$，虽然资源更少但耗时更大。

其他方案例如任务 `2` 选择配置 `2` 会超过资源上限。因此最优输出依次为 `9`、`5`、`0`。

### 示例 4

**输入：**

```
3 1000
10 20 5 25
3 15 4 15
6 7 2 12
```

**输出：**

```
42 19 981
```

**说明：**

资源上限 `1000` 很充足，可以在每个任务上独立选择耗时更小的配置。

任务 `1` 选择配置 `1`，耗时 `20`，资源 `10`。任务 `2` 两种配置耗时都为 `15`，选择资源更少的配置 `1`，资源 `3`。任务 `3` 选择配置 `1`，耗时 `7`，资源 `6`。

总耗时为 $20+15+7=42$，总资源消耗为 $10+3+6=19$，剩余资源为 $1000-19=981$。

## 解题思路

### 输出里有什么：两级目标决定状态要记住两件事

答案不是一个数，而是三个：最小总耗时、最优方案实际花费的资源、剩余的 $C$ 减去它。判定标准也有两级：资源总和 $\le C$ 的方案里先比总耗时，耗时打平时再比花费资源。输出的后两个数都指向那个并列胜出的方案——如果整个过程只保留「最小耗时」一个量，最后就不知道该输出多少资源。所以状态值里必须同时装下耗时与资源，并且最好让一次比较就完成两级判定，这正是下文编码要解决的问题。

### 关键观察：约束只有一维，数据范围也指向它

每个任务必须且只能从两套配置里选一套，全局约束只有资源 $\le C$ 一条——这是分组背包最简的形态（每组两件、必取一件），而且只有一个约束维度。数据范围把这条路走死了：逐任务枚举的方案数为 $2^n$，$n\le100$ 时完全不可行；而拿「已用资源」当状态下标的一维背包是 $O(nC)$，$n\le100$、$C\le1000$ 时约 $2\times10^5$ 次转移。资源是整数且上限很小，「按资源开表」因此是顺理成章的选法。

### 状态与转移：两级目标写进一个整数

$dp[r]$ 定义为：处理完某个前缀的任务、资源恰好用掉 $r$ 时的最小编码分数，其中

$$
\text{score} = \text{总耗时}\times\text{BIG} + \text{花费资源},\qquad \text{BIG}=C+1
$$

花费资源最多是 $C$，永远小于 `BIG`，于是分数的高位是耗时、低位是资源：分数最小等价于耗时最小；耗时打平时，两个分数之差就是资源之差。收尾对 $r=0,\dots,C$ 取 $\min(dp)$，再整除、取余反解出耗时与资源。与「dp 只记最小耗时、收尾把每个 $r$ 的 $(\text{耗时}, r)$ 当元组比较」相比，编码把两级判定融进了转移里的一次整数比较。

两条约定要落实在状态定义上：

- **「恰好用掉 $r$」而不是「不超过 $r$」**：配合「每轮新表的初值全部不可达、只有 $dp[0]=0$ 可达」，每个任务必选一套就不再需要任何特判——没有哪一轮可以原地保留。
- **`big` 必须取 $C+1$ 严格大于一切可能的花费**：取 $C$ 时花费恰好为 $C$ 的方案会「进位」到耗时位，反解出的耗时凭空多 1（示例 3 恰好用满资源，专门检验这一处）。

### 实现映射

转移只有一行：`candidate = base + time * big + cost`，耗时配 `big` 占高位、资源原样加占低位。每轮开新表 `next_dp`（代码里 `dp = next_dp` 那行）是关键：在原表上就地更新的话，同一任务的前一套配置刚写出的状态会被后一套再转移一次，等于这个任务被计入两遍；新表把「每任务恰好一次」变成结构保证。收尾在 $dp[0..C]$ 里挑最小分数（`None` 表示不可达，跳过），反解后打印三个数。

## 完整代码实现

```python
"""
P5346. 双配置训练任务的最优资源调度 - 带两个目标的一维 DP

输入格式：
- 第 1 行：两个整数 n、C；
- 接下来 n 行：每行四个正整数 c1、t1、c2、t2。

输出格式：
- 一行三个整数：最小总耗时、该方案实际消耗的资源、剩余资源。

时间复杂度：O(n * C * 2)
空间复杂度：O(C)
"""

import sys


def solve():
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    it = iter(data)
    n = int(next(it))
    capacity = int(next(it))

    # BIG 要比任何可能的资源消耗都大，这样 score 的高位是耗时、
    # 低位是资源，反解时整除和取余不会互相进位。
    big = capacity + 1

    # dp[r] = 恰好用掉 r 点资源时的最小编码分数，None 表示不可达
    dp = [None] * (capacity + 1)
    dp[0] = 0  # 零个任务、零资源

    for _ in range(n):
        c1 = int(next(it))
        t1 = int(next(it))
        c2 = int(next(it))
        t2 = int(next(it))

        # 用一张新表：第 i 个任务只能从“处理完前 i-1 个任务”的状态转移一次。
        # 若在原表上就地更新，同一任务的另一套配置可能被重复使用。
        next_dp = [None] * (capacity + 1)

        for used in range(capacity + 1):
            base = dp[used]
            if base is None:
                continue  # 这个资源量凑不出来

            # 每组恰好两个物品：配置 1 与配置 2，各试一次
            for cost, time in ((c1, t1), (c2, t2)):
                new_used = used + cost
                if new_used > capacity:
                    continue  # 超出资源上限

                # 耗时放高位、资源放低位：耗时优先，同耗时再比资源
                candidate = base + time * big + cost
                if next_dp[new_used] is None or candidate < next_dp[new_used]:
                    next_dp[new_used] = candidate

        dp = next_dp

    # 资源上限是“不超过 C”，所以在所有可达状态里挑分数最小的
    best = None
    for used in range(capacity + 1):
        if dp[used] is not None and (best is None or dp[used] < best):
            best = dp[used]

    if best is None:
        # 题目保证至少存在一种合法选择，这里只是防御性处理
        print(-1)
        return

    # 反解：score = 耗时 * big + 资源，且资源 <= C < big
    total_time = best // big
    total_cost = best % big
    print(total_time, total_cost, capacity - total_cost)


if __name__ == "__main__":
    solve()
```

## 示例推演

### 示例 1：把 $2^3$ 种选择全部列出来

$n=3$、$C=10$，任务配置为：任务 1 取 $(4,5)$ 或 $(2,3)$，任务 2 取 $(3,4)$ 或 $(5,2)$，任务 3 取 $(1,2)$ 或 $(2,2)$（括号内为 $(资源, 耗时)$）：

| 任务 1 | 任务 2 | 任务 3 | 总资源 | 总耗时 | 是否合法 |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 8 | 11 | 合法 |
| 1 | 1 | 2 | 9 | 11 | 合法 |
| 1 | 2 | 1 | 10 | 9 | 合法 |
| 1 | 2 | 2 | 11 | — | 超预算 |
| 2 | 1 | 1 | 6 | 9 | 合法 |
| 2 | 1 | 2 | 7 | 9 | 合法 |
| 2 | 2 | 1 | 8 | 7 | 合法 |
| 2 | 2 | 2 | 9 | 7 | 合法 |

最小耗时 $7$，两个方案并列：资源 $8$ 与 $9$。编码视角下（`big=11`）：$(2,2,1)$ 的分数是 $7\times11+8=85$，$(2,2,2)$ 是 $7\times11+9=86$，$85<86$ 一次比较完事——耗时相同，资源 $8$ 胜出。反解 $85\div11=7$、$85\bmod11=8$，剩余 $10-8=2$，输出 `7 8 2`。

### 其余三个样例各说明一件事

- **示例 2**（`5 1 0`）：配置 2 要 2 点资源而 $C=1$，装不进去。耗时更小的配置也有不可选的时候，资源约束先于一切。
- **示例 3**（`9 5 0`）：方案 (2,1) 耗时 11 资源 4，方案 (1,1) 耗时 9 资源 5。资源少但耗时大，此时正确的取舍仍是「先耗时」；该例同时把资源用满（$C=5$），是 `big` 取值的试金石（见易错点 3）。
- **示例 4**（`42 19 981`）：$C=1000$ 充裕，每个任务独立取耗时更小的配置。任务 2 两套配置耗时同为 15，按并列规则取资源少的配置 1（资源 3 而不是 4），否则输出的资源与剩余都会差 1。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 枚举每个任务的两次选择 | $O(2^n\cdot n)$ | $O(n)$ | $n=100$ 时方案数为天文数字，不可行 |
| 按资源 DP，末尾分开存 (耗时, 资源) 再比较 | $O(nC)$ | $O(C)$ | 正确；收尾多一遍扫描，两级比较写成元组 |
| 按资源 DP + 整数编码（最优） | $O(nC)$ | $O(C)$ | 两级目标并入一次比较，答案直接取 $\min(dp)$ |

$n\le100$、$C\le1000$，转移次数约 $2\times10^5$，Python 里毫秒级跑完。

## 易错点总结

### 1. 就地更新，同一任务被选两遍

转移必须写到新表 `next_dp` 上（`dp = next_dp`）。若在原表上就地更新，前一套配置刚写出的状态会被后一套配置从那里再转移一次，一个任务可贡献两份资源与耗时。错掉之后输出的三个数不属于任何「逐任务选择」的组合，比如样例 1 可能给出一个看起来更快的假耗时。

### 2. 两级目标的次序弄反

编码的位权是「耗时×`big` + 资源」：耗时是主目标。若改成资源优先（把 `big` 配给资源位，或收尾先比资源再比耗时），样例 3 会选资源 4 耗时 11 的方案，输出变成与题面相反的取舍。

### 3. `big` 写成 `capacity`

资源恰好用满 $C$ 的方案会进位：样例 3 的编码是 $9\times5+5=50$，若 `big=5` 反解得「耗时 10、资源 0」，两个数都错。`big = capacity + 1` 保的是「低位不溢出、高位不掺假」。

## 扩展思考

- 组内有 $k$ 套配置时，内层循环换成遍历 $k$ 个候选即可，复杂度 $O(nCk)$。
- 要输出「每个任务选了哪套」，再开一张 parent 表记录每个状态来自哪个 $(r,\text{配置})$，从 $\min(dp)$ 倒推。
- 若 $C$ 大到 $10^9$，按资源开表不可行：可以改成按耗时开表（$dp[t]$ 记最小资源），或给资源定价做 Lagrangian 松弛——精确解在一般情形下是 NP 难的。
