# P5568. NPU梯度任务均衡调度

> 场次：2026年9月23日 · 来源：[CodeFun2000 P5568](https://codefun2000.com/p/P5568)

## 题目描述

在大模型分布式训练场景下，要把若干梯度更新任务分配到多张 NPU 上。目标是让各卡的「梯度计算总耗时」尽量均衡（即最小化「最大卡总耗时」），再按学习率衰减规则汇总总训练成本。

规则如下：

1. 任务分配：将 $grad\_times$ 划分成 $k$ 个子集（一张 NPU 对应一个子集）。每个任务必须分到恰好一个子集；在所有划分中，取「子集总和的最大值」最小的那些划分。
2. 成本计算：记 $max\_time$ 为各卡总耗时的最大值，$sum\_time\_j$ 为第 $j$ 张卡的总耗时。则
   - 第 $j$ 张卡学习率：$lr\_j = base\_lr \times decay\_rate^{max\_time - sum\_time\_j}$；
   - 第 $j$ 张卡训练成本：$sum\_time\_j \times lr\_j$；
   - 总训练成本：所有卡成本之和。

## 输入格式

一行字符串，用 `;` 分成四段：梯度耗时列表;NPU数量;基础学习率;衰减系数。例如：$8,5,4,3,3,2,1;3;0.1;0.8$。

1. 梯度耗时列表（$grad\_times$）：逗号分隔的一维数组，每个元素为单个梯度更新任务的耗时（非负整数）；
2. $NPU$ 数量（$k$）：正整数，满足 $1 \le k \le len(grad\_times)$；
3. 基础学习率（$base\_lr$）：浮点数；
4. 衰减系数（$decay\_rate$）：浮点数，满足 $0 < decay\_rate < 1$。

## 输出格式

一行字符串：最小最大总耗时,总训练成本。例如：$9,2.4400$。

- 最小最大总耗时：整数；
- 总训练成本：保留 $4$ 位小数的浮点数。

## 示例

### 示例 1

**输入：**

```
8,5,4,3,3,2,1;3;0.1;0.8
```

**输出：**

```
9,2.4400
```

**说明：**

解析得 $grad\_times=[8,5,4,3,3,2,1]$，$k=3$，$base\_lr=0.1$，$decay\_rate=0.8$。

总耗时 $8+5+4+3+3+2+1=26$，理想均分约 $26/3\approx 8.67$，且最大单任务为 $8$，故最小可能的最大子集和至少为 $9$。

一组达到该下界的划分：

- NPU1：$8+1=9$
- NPU2：$5+4=9$
- NPU3：$3+3+2=8$

负载为 $9,9,8$，$max\_time=9$。

成本：

- 负载 $9$：$9\times 0.1\times 0.8^{0}=0.9$（两张）
- 负载 $8$：$8\times 0.1\times 0.8^{1}=0.64$

总成本 $0.9+0.9+0.64=2.44$，输出 $9,2.4400$。

### 示例 2

**输入：**

```
6;1;0.2;0.9
```

**输出：**

```
6,1.2000
```

**说明：**

仅 $1$ 张 NPU、一个任务，故 $max\_time=6$，$sum\_time=6$。

$lr=0.2\times 0.9^{0}=0.2$，总成本 $6\times 0.2=1.2$，输出 $6,1.2000$。

## 解题思路

### 两段式输出：先均衡，后算钱

输出是一行 `最大耗时,总成本`，两件事有先后：先求出「各组耗时之和的最大值」的最小可能值 $max\_time$，再把达到它的各卡负载 $sum\_time\_j$ 代入公式结算：

$$lr\_j = base\_lr\times decay\_rate^{\,max\_time-sum\_time\_j},\qquad
cost=\sum_j sum\_time\_j\times lr\_j$$

指数是「与最满一张卡的差距」：负载恰为 $max\_time$ 的卡指数为 $0$，学习率不打折；负载越轻指数越大，而 $0<decay<1$，学习率被衰减得越狠、成本越低。所以「更均衡」与「更省钱」方向一致，但题面把第一目标钉死在 $max\_time$ 上，成本只是定案后的结算——两个阶段的顺序不能颠倒。

### 多机调度没有多项式精确解，数据范围默认了搜索

把 $n$ 个任务分成 $k$ 组、最小化最大组和，就是多机调度问题，NP-hard；任务可以任意分组（不要求连续、没有别的结构可用）。题面按这个设定出题，就默认了任务数不大，精确解只能靠搜索。先想最直接的形态：每个任务 $k$ 种归宿，共 $k^n$ 种分配全部枚举——$n=10,k=3$ 是 $5.9\times10^4$ 勉强能跑，$n=20$ 就是 $3\times10^9$，不可持续。

两个改造让搜索落地：

1. **把「求最小」换成「判定 $cap$」再二分**。某个 $cap$ 能放下全部任务，更大的 $cap$ 照样放得下（同一划分仍然合法），可行的 $cap$ 构成一段后缀，可以二分；判定搜索只要找到**一条**可行路径就返回，不必穷尽所有分配。二分范围：$low=\max(\text{最大单任务},\ \lceil S/k\rceil)$——单个任务必须整块放进某张卡，$k$ 张卡均摊总量 $S$ 至少要 $\lceil S/k\rceil$；$high=S$（全堆一张卡，一定可行）。
2. **判定 DFS 带两层去重剪枝**。容量剪枝：`cur + t > cap` 直接跳过这张卡；对称去重：同一层的逐卡循环里，两张卡**当前负载相同**时，任务放进哪张得到的负载集合完全一样，`tried` 集合保证每种负载值只试一次。

再往前一层保险是失败记忆：局面用 `(处理到第几个任务, 排序后的负载元组)` 表示——卡之间可以互换，键必须先排序；同一局面已证明无解就不再搜第二遍（代码里的 `failed` 集合）。

### 定案之后的复搜

二分途中每次成功的判定都能留下当时的负载数组，但那份残局属于哪一轮 $cap$ 并不可靠；干净的做法是拿到收敛的 $max\_time$ 后，用同一个 `search(times, k, max_time)` 再搜一次，这次返回的负载就是一组达到下限的 $sum\_time\_j$，代入公式算成本。达到同一 $max\_time$ 的划分若不止一组、算出的成本可能不同，题面未规定二级比较，代码取搜索顺序遇到的第一组；评测数据里达到它的划分唯一时无差别。

### 实现细节

- 输入是一行 `;` 分四段的字符串：`split(";")` 之后第一段再按 `,` 切出任务列表，后两段转浮点。
- `if k > n: k = n` 兜一层题面保证（$1\le k\le n$），避免空卡越权。
- 输出 `print(f"{max_time},{cost:.4f}")`：整数与 4 位小数用逗号连接，中间不能有空格。

## 完整代码实现

```python
"""
P5568. NPU梯度任务均衡调度 - 二分答案 + 回溯搜索

输入格式：一行字符串，用 ; 分成四段：
    grad_times;NPU数量;base_lr;decay_rate

输出格式：一行 "最小最大总耗时,总训练成本（4 位小数）"

复杂度：二分 O(log S) 次判定，每次判定是带剪枝的回溯搜索，
        最坏 O(k^n)，实际数据规模下剪枝后很快。
"""

import sys


def search(times, k, cap):
    """在「每张卡耗时都不超过 cap」的前提下找一个分配方案。

    找到时返回各卡负载列表（长度 k），找不到返回 None。
    """
    n = len(times)
    loads = [0] * k

    # 已经证明无解的局面：卡可以互换，所以负载要先排序再去重
    failed = set()

    def dfs(i):
        if i == n:            # 所有任务分配完毕，这一组负载满足上限
            return True

        state = (i, tuple(sorted(loads)))
        if state in failed:
            return False

        t = times[i]
        tried = set()         # 本层已经尝试过的负载值

        for j in range(k):
            cur = loads[j]
            # 负载相同的卡完全对称，只需要试一次
            if cur in tried:
                continue
            # 放进去就超上限，这条分支不可能有合法方案
            if cur + t > cap:
                continue

            tried.add(cur)
            loads[j] = cur + t
            if dfs(i + 1):
                return True
            loads[j] = cur    # 回溯：撤销这次分配
        failed.add(state)
        return False

    return loads if dfs(0) else None


def solve():
    text = sys.stdin.buffer.read().decode().strip()
    if not text:
        return

    parts = text.split(";")
    if len(parts) < 4:
        return

    times = [int(x) for x in parts[0].split(",") if x.strip()]
    k = int(parts[1])
    base_lr = float(parts[2])
    decay = float(parts[3])

    n = len(times)
    if k > n:                 # 题面保证 k <= n，这里兜一层
        k = n

    total = sum(times)

    # 二分最小的 max_time
    low = max(max(times), (total + k - 1) // k)
    high = total

    while low < high:
        mid = (low + high) // 2
        if search(times, k, mid) is not None:
            high = mid
        else:
            low = mid + 1

    max_time = low

    # 用最小的上限再搜一次，拿到一组具体的负载分配
    loads = search(times, k, max_time)

    # 按衰减公式累计每张卡的成本
    cost = 0.0
    for s in loads:
        cost += s * base_lr * (decay ** (max_time - s))

    print(f"{max_time},{cost:.4f}")


if __name__ == "__main__":
    solve()
```

## 示例推演

### 样例 1：二分被均值下界直接钉住

解析得 $[8,5,4,3,3,2,1]$、$k=3$、$base\_lr=0.1$、$decay=0.8$，总耗时 $S=26$。

- 下界 $\max(\text{最大单任务},\lceil26/3\rceil)=\max(8,9)=9$，上界 $26$。
- $cap=8$ 一眼不可行：三张卡总量上限 $3\times8=24<26$，根本装不下所有任务。
- 二分 $low=9$、$high=26$，探测 $mid=17,13,11,10,9$ 五个点，每个判定都成功（总能放出一条合法路径），于是 $high$ 一路收到 $9$，与下界重合——$max\_time=9$。判定全部成功没耗多少搜索，靠的是容量剪枝与对称去重。

定案后的复搜按搜索顺序走出具体负载（$cap=9$）：

| 步 | 任务 | 去处 | 负载 |
| :--- | :--- | :--- | :--- |
| 1 | 8 | 卡1 | $8,0,0$ |
| 2 | 5 | 卡2（$8+5>9$，卡1放不下） | $8,5,0$ |
| 3 | 4 | 卡2（$5+4=9\le9$） | $8,9,0$ |
| 4 | 3 | 卡3（卡1、卡2都超了） | $8,9,3$ |
| 5 | 3 | 卡3（$3+3=6\le9$） | $8,9,6$ |
| 6 | 2 | 卡3（$6+2=8\le9$） | $8,9,8$ |
| 7 | 1 | 卡1（$8+1=9\le9$） | $9,9,8$ |

全部任务放完、无卡超限，负载 $(9,9,8)$ 正是说明里的方案。代入成本公式：

- 负载 $9$ 的卡指数为 $0$：$9\times0.1\times0.8^0=0.9$，两张；
- 负载 $8$ 的卡指数为 $1$：$8\times0.1\times0.8=0.64$。

合计 $0.9+0.9+0.64=2.44$，输出 `9,2.4400`。

### 样例 2：一张卡，二分不动

$6;1;0.2;0.9$：$k=1$，下界 $\max(6,6)=6$、上界 $6$，二分区间为空，$max\_time=6$；负载 $(6)$，成本 $6\times0.2\times0.9^0=1.2$，输出 `6,1.2000`。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| :--- | :--- | :--- | :--- |
| 每任务任意分配的完全枚举 | $O(k^n\cdot k)$ | $O(n+k)$ | $n=20,k=3$ 已是 $3\times10^9$ 级别 |
| 二分答案 + 朴素回溯判定 | $O(\log S\cdot k^n)$ | $O(n+k)$ | 判定成功即返回，容量剪枝立即见效 |
| 二分 + 对称去重 + 失败记忆（最优） | $O(\log S\cdot M)$ | $O(n+k+M)$ | 本题采用；$M$ 为实际访问的局面数，远小于 $k^n$ |

## 易错点总结

### 1. 成本格式化必须补足 4 位小数

输出是「整数,4 位小数」（如 `2.4400`）。`f"{cost:.4f}"` 会自动补零；换成 `round(cost, 4)` 则 `2.4` 仍打成 `2.4`，格式直接对不上（代码最后一行 `print` 就是这道题的格式门槛）。另外中间的分隔符是逗号、两侧不留空格。

### 2. 回溯分支失败后必须把负载拨回去

`loads[j] = cur + t` 之后若 `dfs(i + 1)` 失败，要执行 `loads[j] = cur` 再试下一张卡（代码中「回溯」注释那一行）。漏掉的话，先试的分支把卡 $j$ 垫高了 $t$，后面的兄弟分支看到的是被改过的局面：本该可行的 $cap$ 被误判不可行，二分随之向右走，答案系统性偏大。

### 3. 失败记忆的键要先排序

局面等价于「排序后的负载元组」，卡可以互换。键写成 `tuple(loads)` 时，「(5,3)」与「(3,5)」会被当成两个局面，去重失效——答案不会错，但对称局面被成倍重搜，现象是对称负载的用例明显超时（代码里 `tuple(sorted(loads))` 那一行）。

## 扩展思考

- 多机调度的精确解只能走到小规模。规模一大常用 LPT 贪心（任务从大到小，放到当前最空的卡），峰值不超过理论下界的 $\frac43-\frac{1}{3k}$ 倍。
- 另一条精确路线是子集 DP：把已分好的任务集合压成 bitmask、枚举最后一组，$O(3^n)$，适合 $n\le15$ 且 $k$ 不定的场景。
- 若限制任务必须按编号连续分配，题目退化成「分割数组的最大值」，二分 + 贪心判定就够——正好是 P5468 的模型。
