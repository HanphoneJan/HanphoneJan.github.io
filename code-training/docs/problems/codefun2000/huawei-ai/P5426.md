# P5426. 连续保留与深度量化

> 场次：2026年9月11日 · 来源：[CodeFun2000 P5426](https://codefun2000.com/p/P5426)

## 题目描述

端侧计算平台运行大模型时，需要在有限内存下做高性能推理，因此要对模型层做动态剪枝（Pruning）和量化（Quantization）。一层网络含 $N$ 个参数块，块 $i$ 有两个属性：

1. 重要度评分 $S_i$：该块对模型精度的贡献，分值越高越重要。
2. 内存占用 $M_i$：该块量化后的存储开销。

系统负载会动态变化。必须在总内存预算 $B$ 的约束下，选出一段连续的参数块加以保留（连续是为了保证访存局部性），使得保留段的重要度之和最大。

给定 $N$ 个参数块的属性以及当前内存预算 $B$，计算：

1. 在连续块总内存满足 $\sum M \le B$ 的前提下，能够得到的最大重要度之和。
2. 引入「位宽折损」：允许对当前选中连续段中最不重要的一个参数块做深度量化，其内存占用变为 $\lfloor M_i/2\rfloor$，重要度变为 $0$。若有多块重要度同为最小，则对其中内存占用最大的一块折损。此种机制下，最大重要度之和是多少？

## 输入格式

第一行两个正整数 $N$ 和 $B$，分别表示参数块数量与内存预算。

第二行 $N$ 个正整数，依次为各块重要度 $S_1, S_2, \ldots, S_N$。

第三行 $N$ 个正整数，依次为各块内存占用 $M_1, M_2, \ldots, M_N$。

数据范围：

$1\le N\le 10^5$

$1\le B\le 10^9$

$1\le S_i\le 10^4$，$1\le M_i\le 10^4$

## 输出格式

输出一行两个整数，以空格分隔：

第一个整数：常规连续剪枝下的最大重要度之和。

第二个整数：引入「位宽折损」后的最大重要度之和。

若没有任何合法连续段，对应值为 $0$。折损是可选项：一段已经满足 $\sum M \le B$ 的区间，也可以不折损。

## 示例

### 示例 1

**输入：**

```
4 13
80 15 80 15
6 3 6 3
```

**输出：**

```
110 160
```

**说明：**

1. 常规：保留 $[15,80,15]$，占用 $3+6+3=12\le 13$，重要度 $110$。另一段 $[80,15,80]$ 占用 $15>13$，不合法；$[80,15]$ 合法但重要度只有 $95$。
2. 折损：保留 $[80,15,80]$，对重要度为 $15$ 的块折损，占用变为 $6+\lfloor 3/2\rfloor+6=13\le 13$，重要度 $80+0+80=160$。

### 示例 2

**输入：**

```
5 12
8 16 24 32 40
5 6 7 4 3
```

**输出：**

```
72 72
```

**说明：**

1. 常规：保留最后两块 $[32,40]$，占用 $4+3=7\le 12$，重要度 $72$。$[24,32,40]$ 占用 $7+4+3=14>12$；$[24,32]$ 占用 $11$ 但重要度只有 $56$。
2. 折损：$[24,32,40]$ 中最不重要的是 $24$，占用变为 $\lfloor 7/2\rfloor+4+3=10\le 12$，重要度 $72$，不优于常规。$[16,24,32]$ 折损 $16$ 后占用 $\lfloor 6/2\rfloor+7+4=14>12$。

## 解题思路

### 输出两个数，先把折损的判定标准钉死

输出一行两个整数：常规剪枝的最大重要度之和，以及允许「位宽折损」后的最大重要度之和。第一问是熟悉的「资源受限的连续子数组」；第二问的全部新东西都在一条规则上，而且这条规则把「答案是唯一的」拉得很窄：

- 折损对象**不是挑出来的，是被区间确定的**——区间内 $(S_i,\,-M_i,\,i)$ 字典序最小的那块。键的后两位不是装饰：重要度并列时取内存大的（省得多），内存再并列取下标小的（否则同一区间会出现多个答案）；
- 折损后目标块的内存变 $\lfloor M_i/2\rfloor$，等价说法是**省下** $M_i-\lfloor M_i/2\rfloor=\lceil M_i/2\rceil$ 内存、**损失**恰好 $S_i$ 重要度；
- 折损是**可选**的——本来就放得下的区间不折，所以第二问的答案至少等于第一问。

于是第二问的判定可以写成一个统一的量：对区间 $[l,r]$，设其折损对象为 $t$，

$$Eff(l,r)=\sum_{k=l}^{r}M_k-\left\lceil M_t/2\right\rceil,\qquad V(l,r)=\sum_{k=l}^{r}S_k-S_t,$$

在所有 $Eff\le B$ 的区间上最大化 $V$。整个解法要回答两个问题：$Eff$ 有没有单调性（决定线性扫描活不活），以及 $t$ 能不能 $O(1)$ 拿到（决定扫描快不快）。

### 正数给了第一问单调性，也先否掉一整族解法

动手前先看量级是这道题给的第一个线索：$N\le10^5$，逐左端点扫右端点枚举全部区间是 $10^{10}$ 次操作，一条死路。真正可用的只有 $O(N)$ 的一次扫描，而能撑住它的单调性恰好写在数据范围里——$S_i,M_i\ge1$。

固定右端点 $r$：往左扩一格，重要度更高、内存更大。于是对固定 $r$，最靠左的合法左端点就是该右端点下的最优解（再往左内存爆掉，往右白丢收益）；且 $r$ 右移时这个左端点不会回退，因为内存和只增不减。这就是第一问的双指针，$O(N)$。循环体在代码里对应得很直接：窗口先吃进右端点，超预算时左端点一格一格移出，收完恰好停在最靠左的合法位置，非空窗口的 `window_score` 直接参与取最大——窗口内其余左端点不必枚举：再往左就超出预算，往右收益只会更小。

### 第二问：有效内存仍然单调，所以还是双指针

第一问的双指针能否直接搬进第二问？表面上有个障碍：窗口里多了一个「被折损的块」，它的身份还会随窗口移动而换人，需要的量从 $\sum M$ 换成 $Eff$。关键是这个量保住了单调性：

**引理**：设当前折损对象为 $o$，向区间加入一块 $j$，则 $Eff$ 严格增大。分两种情况：

- $j$ 不是新对象：省的仍是 $\lceil M_o/2\rceil$，总内存多了 $M_j$，$Eff$ 增加 $M_j>0$；
- $j$ 成为新对象：省的换成 $\lceil M_j/2\rceil$，$Eff$ 增加 $M_j+\lceil M_o/2\rceil-\lceil M_j/2\rceil=\lfloor M_j/2\rfloor+\lceil M_o/2\rceil>0$，两个加项都被 $M_i\ge1$ 撑住。

由此得到两个结论。其一，可行区间对收缩封闭——不可行的区间挖掉一块还是不可行，所以右端点右移时左端点不必回溯，双指针照旧成立。其二，$V$ 也关于扩张严格增大：对象不变时增加 $S_j$；换人时新对象是 $j$，$V_{\text{new}}-V_{\text{old}}=(\sum S+S_j-S_j)-(\sum S-S_o)=S_o>0$，旧对象的重要度回来了。于是第二问与第一问同构：对每个右端点，仍取最靠左的可行左端点。

### 滑动窗口最小值：$O(1)$ 问出折损对象

窗口的折损对象就是键 $(S_i,\,-M_i,\,i)$ 最小的元素——标准的「滑动窗口最小值」，单调队列的经典形态。新元素入队时把队尾所有键不小于它的元素弹掉：那些元素既比新元素差，又比新元素先离开窗口，再无登场机会。左端点右移时，仅当移出的正好是队首才出队。

完整代码的落点：`keys` 数组把折损规则一次性编成三元组；主循环的 `while min_queue:` 队首即折损对象，$Eff\le B$ 就停手记候选，否则右移左端点（引理保证不漏解）；窗口可能被收空（单块折损后仍超预算），候选只对非空队列计算；`best_discount` 取 `best_plain` 作初值，表达「不折也是一种选择」；最后 `print(best_plain, best_discount)` 一行输出两个数。

## 完整代码实现

```python
"""
P5426. 连续保留与深度量化 - 双指针 + 单调队列
"""

import sys
from collections import deque


def solve():
    """读入参数块信息，分别计算常规剪枝与允许折损后的最大重要度之和。"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    it = iter(data)
    n = int(next(it))
    budget = int(next(it))
    score = [int(next(it)) for _ in range(n)]
    memory = [int(next(it)) for _ in range(n)]

    # ---------- 第一问：滑动窗口求“内存和 <= B 的最大重要度和” ----------
    best_plain = 0
    left = 0
    window_memory = 0
    window_score = 0
    for right in range(n):
        window_memory += memory[right]
        window_score += score[right]

        # 收缩到内存不超预算为止；若单块就超预算，窗口会被收成空的
        while window_memory > budget and left <= right:
            window_memory -= memory[left]
            window_score -= score[left]
            left += 1

        # 窗口非空时，它就是“以 right 结尾的最优合法段”：
        # 所有重要度都是正的，再往左扩只会更赚，扩不动才是最优。
        if left <= right and window_score > best_plain:
            best_plain = window_score

    # ---------- 第二问：把“折损对象”也纳入滑动窗口 ----------
    # 折损对象的排序键：重要度最小，其次内存最大，最后下标最小（保证唯一）。
    keys = [(score[i], -memory[i], i) for i in range(n)]

    best_discount = best_plain  # 折损是可选项，至少不会比常规方案差
    left = 0
    window_memory = 0
    window_score = 0
    # 单调队列：队首是当前窗口内键最小的元素，也就是折损对象
    min_queue = deque()

    for right in range(n):
        window_memory += memory[right]
        window_score += score[right]

        # 新元素入队前，弹掉队尾键不小于它的元素：
        # 它们既比新元素“差”，又会比新元素先离开窗口，以后不可能再成为折损对象。
        key_right = keys[right]
        while min_queue and keys[min_queue[-1]] >= key_right:
            min_queue.pop()
        min_queue.append(right)

        while min_queue:
            target = min_queue[0]
            # 折损 target 之后，这段区间实际占用的内存
            effective = window_memory - (memory[target] + 1) // 2
            if effective <= budget:
                break
            # 仍然超预算，只能把左端点右移（Eff 关于扩张严格递增，不会漏解）
            window_memory -= memory[left]
            window_score -= score[left]
            if min_queue[0] == left:
                min_queue.popleft()
            left += 1

        if min_queue:
            # 窗口非空，且价值关于扩张严格递增，当前窗口就是最优段
            target = min_queue[0]
            candidate = window_score - score[target]
            if candidate > best_discount:
                best_discount = candidate

    print(best_plain, best_discount)


if __name__ == "__main__":
    solve()
```

## 示例推演

### 样例 1

$N=4$、$B=13$：重要度 $80,15,80,15$，内存 $6,3,6,3$。

**第一问**：

| 右端点 | 窗口 | 内存和 | 重要度和 | 说明 |
| ------ | ---- | ------ | -------- | ---- |
| 0 | $[0,0]$ | 6 | 80 | 合法 |
| 1 | $[0,1]$ | 9 | 95 | 合法 |
| 2 | $[1,2]$ | 9 | 95 | 内存 $15>13$，左端点右移一格 |
| 3 | $[1,3]$ | 12 | 110 | 合法，答案 $110$ |

**第二问**（折损对象取窗口内 $(S,-M,i)$ 最小者）：

| 右端点 | 窗口 | 折损对象 | 总内存 | 有效内存 | 候选 $V$ |
| ------ | ---- | -------- | ------ | -------- | -------- |
| 0 | $[0,0]$ | 块0（$S{=}80$） | 6 | $6-3=3$ | 0 |
| 1 | $[0,1]$ | 块1（$S{=}15$） | 9 | $9-2=7$ | 80 |
| 2 | $[0,2]$ | 块1（$S{=}15$） | 15 | $15-2=13\le13$ | $175-15=160$ |
| 3 | $[1,3]$ | 块1（$S{=}15$） | 12 | $12-2=10$ | $110-15=95$ |

$r=3$ 时窗口先试 $[0,3]$：内存 $18$、有效内存 $16>13$ 不合法，左端点右移到 $1$。最终 $\max(0,80,160,95)=160$，对应「保留 $[80,15,80]$、折损重要度 $15$ 那块」；输出 `110 160`。

### 样例 2

$N=5$、$B=12$：重要度 $8,16,24,32,40$，内存 $5,6,7,4,3$。

**第一问**：窗口依次为 $[0,0]\,(8)$、$[0,1]\,(24)$、$[2,2]\,(24)$、$[2,3]\,(56)$、$[3,4]\,(72)$——$r=2$ 时内存 $18>12$ 连撤两格，$r=3$、$r=4$ 各收一格。答案是块 $[32,40]$，得 $72$。

**第二问**：

| 右端点 | 窗口 | 折损对象 | 有效内存 | 候选 $V$ |
| ------ | ---- | -------- | -------- | -------- |
| 0 | $[0,0]$ | 块0 | $5-3=2$ | 0 |
| 1 | $[0,1]$ | 块0 | $11-3=8$ | 16 |
| 2 | $[1,2]$ | 块1 | $13-3=10$ | $40-16=24$ |
| 3 | $[2,3]$ | 块2 | $11-4=7$ | $56-24=32$ |
| 4 | $[2,4]$ | 块2 | $14-4=10\le12$ | $96-24=72$ |

最大值 $72$，与第一问持平。这组样例还演示了折损不总是赚：折损要整块丢掉重要度，只有省下的内存能换来更多块时才划算——$[24,32,40]$ 折掉 $24$ 后装下了，可收益仍是 $72$。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 枚举所有区间（增量维护折损对象） | $O(N^2)$ | $O(1)$ | $N=10^5$ 时约 $10^{10}$ 次操作，不可行 |
| 双指针 + 单调队列（最优） | $O(N)$ | $O(N)$ | 两问各扫一遍；键数组与队列合计 $O(N)$ |

$N=10^5$ 时两遍扫描共约 $2\times10^5$ 次循环，纯 Python 约 0.1 秒。

## 易错点总结

### 1. 折损省下的是 $\lceil M/2\rceil$，不是 $\lfloor M/2\rfloor$

`effective = window_memory - (memory[target] + 1) // 2`。折损后内存是 $\lfloor M_i/2\rfloor$，**省下的**是差值 $\lceil M_i/2\rceil$。写成 `memory[target] // 2` 会让有效内存整体偏大：样例 1 的 $[80,15,80]$ 段会从 $13$ 被算成 $14>13$，那个 $160$ 就地消失，第二问退成 $110$。

### 2. 出队只在「移出的正好是队首」时发生

`if min_queue[0] == left: min_queue.popleft()`。左端点右移时，队列里多数下标还留在窗口内：无条件 `popleft` 会误删仍然有效的候选折损对象；不加判断则队首停在已离开窗口的块上，`effective` 扣掉的是窗外那块的一半，候选值全是错的。窗口被收空（单块折损后仍放不下）时，也要先判非空再取队首。

### 3. 第二问的下限由第一问兜底

`best_discount = best_plain` 一行表达「折损可选」。候选只在折损后找时，退化的输入会露馅：$N=1,B=1$、$S=5$、$M=1$ 单块放得下，折损候选是 $5-5=0$，不给初值就输出 `5 0` 而不是 `5 5`（内嵌自测样例 3）。样例 2 的两个 $72$ 同样靠这一行成立。

## 扩展思考

- 允许折损 $k>1$ 块时，$Eff$ 的单调性不再成立（省内存的对象会随窗口多次换人），要换堆配合 DP 之类的结构。单调队列的适用范围正好是「窗口内特殊元素只有一个」的这一族问题。
- 折损后重要度减半而不是清零的情形也是同一条路：$V$ 被扣掉的部分仍只由折损对象决定，「$V$ 随扩张严格增加」与 $Eff$ 的单调性都保得住。引理真正依赖的只有两件事——被扣的量只与折损对象有关，以及 $M_i\ge1$。
- 与「子数组最大和，允许至多删掉一个元素」同源：先把「带一个特殊元素的量」证明成关于窗口扩张单调，再决定特殊元素用什么结构维护。
