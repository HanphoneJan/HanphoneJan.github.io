# P5947. 最优流水线并行切分

> 场次：2026年10月28日-AI方向 · 来源：[CodeFun2000 P5947](https://codefun2000.com/p/P5947)

## 题目描述

将一个 $N$ 层的深度神经网络按流水线并行部署到 $K$ 个 GPU 上。层必须按从前往后的顺序切成恰好 $K$ 段连续子序列，每段分给一个 GPU，且每段至少包含 $1$ 层。

第 $i$ 层的计算耗时为 $T_i$，该层输出激活对应的通信耗时为 $S_i$（层号从 $1$ 到 $N$）。一段若没有覆盖到第 $N$ 层，总耗时等于段内各层计算耗时之和，再加上该段最后一层的通信耗时；同一段内部的相邻层通信耗时为 $0$。覆盖到第 $N$ 层的那段没有后继层，通信耗时为 $0$，总耗时只计计算耗时。

请给出一种切分，使 $K$ 个阶段总耗时的最大值最小，并输出这个最小值。

## 输入格式

共三行。

第一行是长度为 $N$ 的整数序列 $T_1,T_2,\ldots,T_N$。

第二行是长度为 $N$ 的整数序列 $S_1,S_2,\ldots,S_N$，与第一行等长。

第三行是一个整数 $K$，表示 GPU 数量。

## 输出格式

输出一个整数，表示单个 GPU 最大总耗时的最小值。

## 数据范围

- $1 \le N \le 300$
- $1 \le K \le N$
- $0 \le T_i,S_i \le 10^9$

时间限制：C/C++ $1000$ ms，其他语言 $2000$ ms。
内存限制：C/C++ $512$ MB，其他语言 $1024$ MB。

## 示例

### 示例 1

**输入：**

```
3 8
6 5
1
```

**输出：**

```
11
```

**说明：**

只有 $1$ 个 GPU，两层必须放在同一阶段。计算耗时为 $3+8=11$。两层之间没有跨 GPU 的切分，通信耗时为 $0$，答案是 $11$。

### 示例 2

**输入：**

```
5 7 4 6 8
3 2 9 6 1
3
```

**输出：**

```
14
```

**说明：**

最优切分是 $[1,2]$、$[3]$、$[4,5]$：

- 第 $1$ 段计算耗时 $5+7=12$，通信耗时 $S_2=2$，总耗时 $14$
- 第 $2$ 段计算耗时 $4$，通信耗时 $S_3=9$，总耗时 $13$
- 第 $3$ 段计算耗时 $6+8=14$，已经覆盖最后一层，通信耗时 $0$，总耗时 $14$

单个 GPU 的最大总耗时为 $14$。

另一合法切分 $[1,2]$、$[3,4]$、$[5]$ 的三段耗时分别是 $14$、$16$、$8$，最大值 $16$，比 $14$ 更差。

## 解题思路

### 先看清楚要最小化的是什么

$N$ 层按原顺序切成恰好 $K$ 段，每段至少一层，段与段之间不能打乱顺序。每一段交给一张卡依次算完，整条流水线的速度由最慢的那张卡决定，所以要输出的是「$K$ 段耗时的最大值」的最小可能值。

麻烦在于：一段的耗时并不等于它包含的各层计算量之和。层与层之间只在**换卡**的时候才通信——同一张卡上相邻的两层直接把激活递过去，耗时是 $0$；只有这一段的最后一层要把结果交给下一张卡，才付一次通信。换句话说，每段结尾都要做一次「交接」，而交接的价钱挂在**段尾那一层的 $S$** 上。

这段交接是后面所有推导的起点：一段贵不贵，不只看它有多长，还要看它**结束在哪一层**。

### 一段的耗时 = 段内计算 + 一次交接

按上面的口径，段 $[l,r]$ 的代价是

$$
\mathrm{cost}(l,r)=\sum_{i=l}^{r}T_i+\begin{cases}S_r,& r<N\\ 0,& r=N\end{cases}
$$

最后一段之后没有下一张卡，不用交接，所以 $S_N$ 被免掉。这一条让「末尾那段」天然比同长度的段便宜，是全题唯一与直觉相反的地方，代码里用 `if i < n` 把守（见「易错点」第一条）。

段内的计算量交给前缀和，一段的代价就能 $O(1)$ 算出来：

```python
pref = [0] * (n + 1)               # pref[i] = T_1 + ... + T_i
for i in range(1, n + 1):
    pref[i] = pref[i - 1] + T[i - 1]

# cost(l, r) = pref[r] - pref[l - 1] + (S[r - 1] if r < n else 0)
```

这是后面能把 DP 压到 $O(KN^2)$ 而不是 $O(KN^3)$ 的前提：枚举最后一段的起点时，不用再把这段重新加一遍。

### 贪心为什么失效：交接费会自己变小

把通信项拿掉，这题就是「分割数组的最大值」：$T_i\ge0$，段越长越贵，于是可以二分答案，判定时从左往右能装就装、装不下再切，段数 $\le K$ 即可行。

多出来的 $S_r$ 把这一步的立足点抽掉了。从 $[l,r]$ 再往后并一层，代价的变化是

$$
T_{r+1}+S_{r+1}-S_r
$$

前一项是加进来的计算量，后一项是交接点搬家带来的差价。$S$ 陡降的时候，差价可以是负的——并得更多反而更便宜。取 $T=[0,0,0]$、$S=[100,0,0]$：$[1]$ 单独成段的代价是 $0+S_1=100$，把第二层并进来却变成 $0+0+S_2=0$。

于是「能装就装」这句话没有判据：第一层自己一段就已经超上限，而要不要再并一层，取决于下一层的 $S$ 会不会突然变小。贪心在第一步就走不下去。

这个输入可以直接贴进运行条（答案 $0$，切法是 $[1,2]$ 与 $[3]$）：

```
0 0 0
100 0 0
2
```

### 更隐蔽的一处：「最少段数」也不成立

既然不能贪心，那二分答案还能不能救？二分要回答的是一个判定问题：「给定上限 $X$，能不能切成恰好 $K$ 段、每段都不超过 $X$」。老老实实按段数做一次 DP 当然能回答，但那就等于把整道题又做了一遍；更省事的想法是只求「最少要切成几段」，再看这个数是否 $\le K$。这个松懈在这里是错的。

取 $T=[0,0]$、$S=[100,0]$、$K=2$：唯一合法的两段切法是 $[1]$、$[2]$，代价分别是 $100$ 和 $0$，答案是 $100$。而 $X=0$ 时，整体一段 $[1,2]$ 的代价是 $0+0=0$，最少段数 $1\le 2$，松懈后的判定报「可行」——二分最后就会输出 $0$。

根子还是交接费：把一段拆成两段并不免费，前半段要多付一次交接。所以「能切 $c$ 段」推不出「能切 $c+1$ 段」，段数与可行性之间没有单调关系，夹逼失效。

同样的输入，答案是 $100$：

```
0 0
100 0
2
```

### 二分答案本身还活着，但绕一圈不省事

说清楚这一点，免得留下「这题不能二分」的错印象。把段代价写成

$$
\mathrm{cost}(l,r)=A[r]-\mathrm{pref}[l-1],\qquad A[r]=\mathrm{pref}[r]+S_r\ (r<N),\quad A[N]=\mathrm{pref}[N]
$$

固定 $X$ 后，「从 $p$ 走到 $i$」合法当且仅当 $\mathrm{pref}[p]\ge A[i]-X$。$\mathrm{pref}$ 非降，所以合法的 $p$ 恰好是一段后缀：每层做一次前缀计数，就能 $O(1)$ 判断每个 $i$ 上一步有没有可落脚的点，一次判定 $O(KN)$，配上 $O(\log V)$ 轮二分是 $O(KN\log V)$。

这条路是通的，但和 $O(KN^2)$ 的 DP 同量级（$N=300$ 时两者实测都在 $0.3$ 秒上下），代码还更长，所以本题不走。

顺手把它收成一句能带走的判据：**段代价能写成 $A[r]-\mathrm{pref}[l-1]$ 的形式时，看 $A$ 是否单调**。$A$ 单调（纯前缀和）→ 贪心判定成立；$A$ 不单调（本题 $A[r]=\mathrm{pref}[r]+S_r$）→ 判定只能自己做 DP。

### 把「最慢的那段」存进 DP 的值里

切法是一串切点，天然适合按段数分层：先决定第一段切到哪、第二段切到哪……于是设

> $dp[k][i]$：前 $i$ 层切成**恰好** $k$ 段时，这 $k$ 段耗时的最大值最小能到多少。

最后一段是 $[j+1,i]$，它前面是「前 $j$ 层切 $k-1$ 段」的子问题：

$$
dp[k][i]=\min_{k-1\le j<i}\max\bigl(dp[k-1][j],\ \mathrm{cost}(j+1,i)\bigr)
$$

这个转移能用，靠的是「最大值」这个聚合量的性质：**最后一段的耗时与前面怎么切无关**，所以整体的最大值必然等于「前 $k-1$ 段的最大值」与「最后一段」两者的较大者。状态里如果存的是总耗时，这条就不成立了——总耗时拆成两半再取大没有意义。

$j$ 从 $k-1$ 起，是因为前 $k-1$ 段每段至少一层，至少要占掉 $k-1$ 层；$i$ 从 $k$ 起同理。边界是 $dp[0][0]=0$，其余 $dp[0][i>0]=\infty$。

```python
INF = float("inf")
prev = [INF] * (n + 1)
prev[0] = 0                                  # 0 层切 0 段
for k in range(1, K + 1):
    cur = [INF] * (n + 1)                    # i < k 的格子必须保持不可达
    for i in range(k, n + 1):
        head = pref[i] + (S[i - 1] if i < n else 0)   # cost(j+1, i) 里只跟 i 有关的那一半
        best = INF
        for j in range(k - 1, i):
            best = min(best, max(prev[j], head - pref[j]))
        cur[i] = best
    prev = cur
print(prev[n])
```

`head - pref[j]` 就是 $\mathrm{cost}(j+1,i)$：把只跟 $i$ 有关的一半提到内层循环外面算一次，$4.5\times10^6$ 次转移下能省掉一半加减法。

### 这套循环实际跑多少次

内层循环的次数是

$$
\sum_{k=1}^{K}\sum_{i=k}^{N}(i-k+1)=\sum_{d=1}^{N}\frac{d(d+1)}{2}=\frac{N(N+1)(N+2)}{6}
$$

$N=300$ 时约 $4.5\times10^6$ 次转移。只保留上一层的 $dp$ 一行，空间是 $O(N)$；答案落在最后一行第 $N$ 格。

## 完整代码实现

```python
import sys

INF = float("inf")


def solve():
    # 输入固定三行：T 序列、S 序列、K
    lines = [ln for ln in sys.stdin.buffer.read().splitlines() if ln.strip()]
    if not lines:
        return
    T = list(map(int, lines[0].split()))
    S = list(map(int, lines[1].split()))
    K = int(lines[2].split()[0])
    n = len(T)

    # pref[i] = T_1 + ... + T_i，段 [l, r] 的计算耗时是 pref[r] - pref[l - 1]
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + T[i - 1]

    # prev[i]：前 i 层恰好切成 k-1 段时的最小最大耗时
    prev = [INF] * (n + 1)
    prev[0] = 0                      # 0 层切 0 段，只有这一格可达
    for k in range(1, K + 1):
        cur = [INF] * (n + 1)        # 每轮新建：i < k 必须保持不可达
        for i in range(k, n + 1):
            # cost(j+1, i) = head - pref[j]，head 只跟 i 有关
            head = pref[i] + (S[i - 1] if i < n else 0)
            best = INF
            for j in range(k - 1, i):
                best = min(best, max(prev[j], head - pref[j]))
            cur[i] = best
        prev = cur

    print(prev[n])


if __name__ == "__main__":
    solve()
```

## 示例推演

### 示例 1：末尾那段为什么不用交接

$N=2$、$T=[3,8]$、$S=[6,5]$、$K=1$。只有一种切法 $[1,2]$，它盖住了最后一层，按定义不用交接：$\mathrm{cost}(1,2)=\mathrm{pref}[2]-\mathrm{pref}[0]=11$。

式子里 $r=N$ 那一支把 $S_2=5$ 跳过了。写成「段尾一律加 $S_r$」的话这里会变成 $16$，比答案整整多出一次交接。

### 示例 2：三层表逐格填

$T=[5,7,4,6,8]$、$S=[3,2,9,6,1]$、$K=3$，前缀和 $\mathrm{pref}=[0,5,12,16,22,30]$。

**第一层**（$k=1$，只剩一整段 $[1,i]$）：

| $i$ | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 段 | $[1]$ | $[1,2]$ | $[1,3]$ | $[1,4]$ | $[1,5]$ |
| 计算 | 5 | 12 | 16 | 22 | 30 |
| 交接 | $+3$ | $+2$ | $+9$ | $+6$ | 末段，$+0$ |
| $dp[1][i]$ | 8 | 14 | 25 | 28 | **30** |

**第二层**（$k=2$，$i$ 从 2 起）：

| $i$ | $j=1$ | $j=2$ | $j=3$ | $j=4$ | $dp[2][i]$ |
| --- | --- | --- | --- | --- | --- |
| 2 | $\max(8,\ \mathrm{cost}(2,2)=9)=9$ | — | — | — | 9 |
| 3 | $\max(8,\ \mathrm{cost}(2,3)=20)=20$ | $\max(14,\ 13)=14$ | — | — | 14 |
| 4 | $\max(8,\ 23)=23$ | $\max(14,\ 16)=16$ | $\max(25,\ 12)=25$ | — | 16 |
| 5 | $\max(8,\ 25)=25$ | $\max(14,\ 18)=18$ | $\max(25,\ 14)=25$ | $\max(28,\ 8)=28$ | 18 |

拿 $dp[2][4]=16$ 念一遍：$j=2$ 对应 $[1,2]$ 与 $[3,4]$，前两段的最大值是 $dp[1][2]=14$，最后一段 $\mathrm{cost}(3,4)=4+6+S_4=16$，取大得 $16$；另外两个 $j$ 给的是 $23$ 和 $25$，都更差。

**第三层**（$k=3$，只剩 $i=5$）：

| $j$ | 前两段最优 $dp[2][j]$ | 最后一段 | 取大 | 对应切分 |
| --- | --- | --- | --- | --- |
| 2 | 9（$[1]$、$[2]$） | $\mathrm{cost}(3,5)=4+6+8=18$ | 18 | $[1],[2],[3,4,5]$ |
| 3 | 14（$[1,2]$、$[3]$） | $\mathrm{cost}(4,5)=6+8=14$ | **14** | $[1,2],[3],[4,5]$ |
| 4 | 16（$[1,2]$、$[3,4]$） | $\mathrm{cost}(5,5)=8$ | 16 | $[1,2],[3,4],[5]$ |

最小值 $14$，与题面说明一致。这张表顺带解释了说明里那句「另一合法切分最大值 $16$」：它就是 $j=4$ 那一行，被 $j=3$ 压住。$j=2$ 给出 $18$，代价是把后三层捆在一起——$[3,4,5]$ 光计算就要 $18$。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 枚举全部切点 | $O\!\left(\binom{N-1}{K-1}\cdot N\right)$ | $O(N)$ | $K$ 居中时方案数是天文数字，$N=300$ 完全不可算 |
| 二分答案 + 可达性判定 | $O(KN\log V)$ | $O(N)$ | 判定得是「恰好 $K$ 步可达」，每次 $O(KN)$；可行，但不比下一行快 |
| 分层 DP + 前缀和（最优） | $O(K\cdot N^2)$ | $O(N)$ | 转移总数 $\frac{N(N+1)(N+2)}{6}\approx 4.5\times10^6$，纯 Python 约 $0.3$ 秒 |

「分层 DP + 前缀和」的转移数在 $K=N$ 时取到上界：此时每个 $k$ 的内层循环都要从 $k$ 跑到 $N$，三段求和正好凑成 $\frac{N(N+1)(N+2)}{6}$。空间只需前缀和、上一层与当前层各一行，$O(N)$；把整张 $dp[k][i]$ 都留下会变成 $O(KN)$，而本题只问 $dp[K][N]$，没有回溯切分的需求，所以不必留。

## 易错点总结

### 1. 末段也加了交接费

代码里 `if i < n` 就是「盖住第 $N$ 层的段没有后继」这条规则。把它改成无条件 `+ S[i - 1]`，样例 1 会输出 $16$（$11+S_2=11+5$），样例 2 会输出 $15$——末段 $[4,5]$ 的 $14$ 被抬到 $15$，成了新的最大值，正好压过原来那个 $14$。

### 2. 滚动数组被复用成了同一个对象

为了省一次分配写 `cur = prev` 不行。$i$ 从小到大推进，内层读到的 `prev[j]` 已经是**本轮**的 $dp[k][j]$，等于允许在同一层里继续切，段数上限被打穿。样例 2 会输出 $13$——那是拆成五段 $[1],[2],[3],[4],[5]$ 时的最大值（$8,9,13,12,8$）。它比正确答案小，看上去还挺像回事，最难发现。每轮 `cur = [INF] * (n + 1)` 不能省，它同时保证了 $i<k$ 的格子（$i$ 层切 $k$ 段，根本不存在）不可达。

## 扩展思考

- **改成「至多 $K$ 段」就是另一道题。** 上面 $T=[0,0]$、$S=[100,0]$ 那个例子，恰好 $2$ 段的答案是 $100$，允许只用 $1$ 段时是 $0$。「恰好」这两个字不是措辞：合并一段能免掉一次交接，所以切得越多不一定越好。
- 若 $S$ 恒为 $0$，模型退化成「分割数组的最大值」，贪心判定重新成立，二分答案可以做到 $O(N\log\sum T)$（见 P5468）。
