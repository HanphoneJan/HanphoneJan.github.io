# P5947. 最优流水线并行切分

> 场次：2026年10月28日-AI方向 · 来源：[CodeFun2000 P5947](https://codefun2000.com/p/P5947)

## 题目描述

将一个 $N$ 层的深度神经网络按流水线并行部署到 $K$ 个 GPU 上。层必须按从前往后的顺序切成恰好 $K$ 段连续子序列，每段分给一个 GPU，且每段至少包含 $1$ 层。

第 $i$ 层的计算耗时为 $T_i$，该层输出激活对应的通信耗时为 $S_i$（层号从 $1$ 到 $N$）。一段若没有覆盖到第 $N$ 层，总耗时等于段内各层计算耗时之和，再加上该段最后一层的通信耗时；同一段内部的相邻层通信耗时为 $0$。覆盖到第 $N$ 层的那段没有后继层，通信耗时为 $0$，总耗时只计计算耗时。

请给出一种切分，使 $K$ 个阶段总耗时的最大值最小，并输出这个最小值。

## 输入格式

共三行。

第一行是长度为 $N$ 的整数序列 $T_1,T_2,\ldots,T_N$。

第二行是长度为 $N$ 的整数序列 $S_1,S_2,\ldots,S_N$，与第一行等长。

第三行是一个整数 $K$，表示 GPU 数量。

## 输出格式

输出一个整数，表示单个 GPU 最大总耗时的最小值。

## 数据范围

- $1 \le N \le 300$
- $1 \le K \le N$
- $0 \le T_i,S_i \le 10^9$

时间限制：C/C++ $1000$ ms，其他语言 $2000$ ms。

内存限制：C/C++ $512$ MB，其他语言 $1024$ MB。

## 示例

### 示例 1

**输入：**

```
3 8
6 5
1
```

**输出：**

```
11
```

**说明：**

只有 $1$ 个 GPU，两层必须放在同一阶段。计算耗时为 $3+8=11$。两层之间没有跨 GPU 的切分，通信耗时为 $0$，答案是 $11$。

### 示例 2

**输入：**

```
5 7 4 6 8
3 2 9 6 1
3
```

**输出：**

```
14
```

**说明：**

最优切分是 $[1,2]$、$[3]$、$[4,5]$：

- 第 $1$ 段计算耗时 $5+7=12$，通信耗时 $S_2=2$，总耗时 $14$
- 第 $2$ 段计算耗时 $4$，通信耗时 $S_3=9$，总耗时 $13$
- 第 $3$ 段计算耗时 $6+8=14$，已经覆盖最后一层，通信耗时 $0$，总耗时 $14$

单个 GPU 的最大总耗时为 $14$。

另一合法切分 $[1,2]$、$[3,4]$、$[5]$ 的三段耗时分别是 $14$、$16$、$8$，最大值 $16$，比 $14$ 更差。

## 解题思路

### 一段的耗时只由首尾两个层号决定

段内相邻层的通信是 $0$，整段只在"交给下一段"时付一次通信，而那次的通信耗时是**段尾那一层**的 $S$；覆盖到第 $N$ 层的段没有后继，连这一次也免掉。所以段 $[l,r]$ 的耗时是

$$
\mathrm{cost}(l,r)=\sum_{i=l}^{r}T_i+\begin{cases}S_r,& r<N\\ 0,& r=N\end{cases}
$$

前缀和让"段内计算耗时"变成一次减法，整段耗时 $O(1)$ 可算——这是后面 DP 能落在 $O(KN^2)$ 而不是 $O(KN^3)$ 的前提。

```python
pref = [0] * (n + 1)               # pref[i] = T_1 + ... + T_i
for i in range(1, n + 1):
    pref[i] = pref[i - 1] + T[i - 1]

# cost(l, r) = pref[r] - pref[l-1] + (S[r-1] if r < n else 0)
```

### 为什么这题不能二分答案配贪心

同一模型去掉通信项之后，标准解法是"二分答案 + 从左往右贪心装"：$T_i\ge0$ 时一段的成本是纯前缀和，延长只会更贵，"装到装不下为止"得到的段数最少，段数 $\le K$ 即判定可行。本题多出来的 $S_r$ 项把这条链条的两环都打断了。

**第一环：段成本对"往后延长"不再单调。** 从 $[l,r]$ 延长到 $[l,r+1]$，成本变化是 $T_{r+1}+S_{r+1}-S_r$，$S$ 骤降时这个量可以是负的。取 $T=[0,0,0]$、$S=[100,0,0]$：$[1]$ 的成本是 $0+100=100$，$[1,2]$ 的成本却是 $0+0+S_2=0$——装得更多反而更便宜。于是"装到装不下为止"这一步没有落脚点：层 $1$ 单独成段已经超上限，而"要不要再装一层"没有单调的判据可依；正确答案是 $0$（切成 $[1,2]$ 与 $[3]$）。

**第二环：可行的段数不是一个区间。** 二分答案还必须能回答"恰好 $K$ 段、每段不超过 $X$ 可行吗"。若偷懒改成"最少段数 $\le K$ 即可行"，取 $T=[0,0]$、$S=[100,0]$、$K=2$：唯一合法的两段切法是 $[1]$、$[2]$，成本 $100$ 与 $0$，答案 $100$；而 $X=0$ 时整体一段 $[1,2]$ 的成本是 $0$，最少段数 $1\le 2$，判定会报"可行"。原因正是切分不单调：把一段拆成两段，前半段要多付一次 $S$，成本可能从 $0$ 跳到 $100$（反之合并也可能把两段各自合法的方案抬过上限），所以"能切 $c$ 段"推不出"能切 $c\pm1$ 段"，夹逼失效。

数据范围也印证了这一点：同模型的 P5468 允许 $N\le5000$、用 $O(N\log\sum T)$ 通过；本题 $N$ 被压到 $300$，正好是 $O(KN^2)$ 的规模。剩下的正路只有按段数分层做 minimax 动态规划。

### 状态：把"最大段耗时"装进 DP 的值里

设 $dp[k][i]$ 为**前 $i$ 层切成恰好 $k$ 段**时，"$k$ 段耗时的最大值"的最小可能值。转移枚举最后一段的起点：

$$
dp[k][i]=\min_{k-1\le j<i}\max\bigl(dp[k-1][j],\ \mathrm{cost}(j+1,i)\bigr)
$$

$j$ 从 $k-1$ 起，是因为前 $k-1$ 段每段至少一层，至少要占掉 $k-1$ 层；$i$ 从 $k$ 起同理。边界 $dp[0][0]=0$，其余 $dp[0][i>0]=\infty$。

这个式子能成立，靠的是"最大值"这个聚合量的一个性质：**最后一段的耗时与前面怎么切无关**，所以整体最大值一定是"前 $k-1$ 段的最大值"与"最后一段耗时"两者取大。状态里存的若是总耗时就不成立了，因为总耗时不能这样拆开再取大。

```python
INF = float("inf")
prev = [INF] * (n + 1)
prev[0] = 0                                  # 0 层切 0 段
for k in range(1, K + 1):
    cur = [INF] * (n + 1)                    # i < k 的格子必须保持不可达
    for i in range(k, n + 1):
        head = pref[i] + (S[i - 1] if i < n else 0)   # cost(j+1, i) = head - pref[j]
        best = INF
        for j in range(k - 1, i):
            tail = head - pref[j]
            v = prev[j] if prev[j] > tail else tail
            if v < best:
                best = v
        cur[i] = best
    prev = cur
print(prev[n])
```

`head - pref[j]` 这个写法不是炫技：$\mathrm{cost}(j+1,i)$ 里随 $j$ 变化的只有 $-\mathrm{pref}[j]$，把 $i$ 那一半提到内层循环外面算一次，省掉每次转移的一次加法和一次减法。

### 转移总数与滚动数组

内层循环的次数是

$$
\sum_{k=1}^{K}\sum_{i=k}^{N}(i-k+1)=\sum_{d=1}^{N}\frac{d(d+1)}{2}=\frac{N(N+1)(N+2)}{6}
$$

$N=300$ 时约 $4.5\times10^6$ 次转移，纯 Python 约 $0.3$ 秒。只留上一层的 $dp$ 一行，空间是 $O(N)$；答案在最后一层的第 $N$ 格。

## 完整代码实现

```python
import sys

INF = float("inf")


def solve():
    # 输入固定三行：T 序列、S 序列、K
    lines = [ln for ln in sys.stdin.buffer.read().splitlines() if ln.strip()]
    if not lines:
        return
    T = list(map(int, lines[0].split()))
    S = list(map(int, lines[1].split()))
    K = int(lines[2].split()[0])
    n = len(T)

    # pref[i] = T_1 + ... + T_i，段 [l, r] 的计算耗时是 pref[r] - pref[l-1]
    pref = [0] * (n + 1)
    for i in range(1, n + 1):
        pref[i] = pref[i - 1] + T[i - 1]

    # prev[i]：前 i 层恰好切成 k-1 段时的最小最大耗时
    prev = [INF] * (n + 1)
    prev[0] = 0                      # 0 层切 0 段，只有这一格可达
    for k in range(1, K + 1):
        cur = [INF] * (n + 1)        # 每轮新建：i < k 必须保持不可达
        for i in range(k, n + 1):
            # cost(j+1, i) = pref[i] - pref[j] + (S_i if i < n else 0)
            head = pref[i] + (S[i - 1] if i < n else 0)
            best = INF
            for j in range(k - 1, i):
                tail = head - pref[j]
                v = prev[j] if prev[j] > tail else tail
                if v < best:
                    best = v
            cur[i] = best
        prev = cur

    print(prev[n])


if __name__ == "__main__":
    solve()
```

## 示例推演

### 样例 1：一段的通信为什么是 0

$N=2$、$T=[3,8]$、$S=[6,5]$、$K=1$。只有一种切分 $[1,2]$，它覆盖了第 $N$ 层，按定义通信耗时为 $0$，只算 $3+8=11$。

$\mathrm{cost}(1,2)=\mathrm{pref}[2]-\mathrm{pref}[0]=11$；式子里 $r=N$ 那一支把 $S_2=5$ 免掉了。若图省事写成"段尾一律加 $S_r$"，答案会变成 $16$——整道题唯一一处与直觉相反的设定就在这里：**最后一段反而更便宜**。

### 样例 2：三层 DP 表逐格填

$T=[5,7,4,6,8]$、$S=[3,2,9,6,1]$、$K=3$，前缀和 $\mathrm{pref}=[0,5,12,16,22,30]$。

**第一层**（$k=1$，只有一整段 $[1,i]$）：

| $i$ | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 段 | $[1]$ | $[1,2]$ | $[1,3]$ | $[1,4]$ | $[1,5]$ |
| 计算 | 5 | 12 | 16 | 22 | 30 |
| 加 $S_i$ | $+3$ | $+2$ | $+9$ | $+6$ | 末段，$+0$ |
| $dp[1][i]$ | 8 | 14 | 25 | 28 | **30** |

**第二层**（$k=2$，$i$ 从 2 起）：

| $i$ | $j=1$ | $j=2$ | $j=3$ | $j=4$ | $dp[2][i]$ |
| --- | --- | --- | --- | --- | --- |
| 2 | $\max(8,\ \mathrm{cost}(2,2)=9)=9$ | — | — | — | 9 |
| 3 | $\max(8,\ \mathrm{cost}(2,3)=20)=20$ | $\max(14,\ 13)=14$ | — | — | 14 |
| 4 | $\max(8,\ 23)=23$ | $\max(14,\ 16)=16$ | $\max(25,\ 12)=25$ | — | 16 |
| 5 | $\max(8,\ 25)=25$ | $\max(14,\ 18)=18$ | $\max(25,\ 14)=25$ | $\max(28,\ 8)=28$ | 18 |

以 $dp[2][4]=16$ 为例读一遍：$j=2$ 对应切分 $[1,2]$ 与 $[3,4]$，前两段的最大值是 $dp[1][2]=14$，最后一段 $\mathrm{cost}(3,4)=4+6+S_4=16$，取大得 $16$；另外两个 $j$ 给出 $23$ 与 $25$，都更差，所以留 $16$。

**第三层**（$k=3$，只剩 $i=5$）：

| $j$ | 前两段最优 $dp[2][j]$ | 最后一段 | 取大 | 对应切分 |
| --- | --- | --- | --- | --- |
| 2 | 9（$[1]$、$[2]$） | $\mathrm{cost}(3,5)=4+6+8=18$ | 18 | $[1],[2],[3,4,5]$ |
| 3 | 14（$[1,2]$、$[3]$） | $\mathrm{cost}(4,5)=6+8=14$ | **14** | $[1,2],[3],[4,5]$ |
| 4 | 16（$[1,2]$、$[3,4]$） | $\mathrm{cost}(5,5)=8$ | 16 | $[1,2],[3,4],[5]$ |

最小值 $14$，与题面说明一致。这张表还顺带解释了说明里那句"另一合法切分最大值 $16$"：它就是 $j=4$ 那一行，被 $j=3$ 压住。$j=2$ 那行给出 $18$，是"把后三层捆在一起"的代价——$[3,4,5]$ 的计算耗时 $18$ 本身就是瓶颈。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 枚举全部切点 | $O\!\left(\binom{N-1}{K-1}\cdot N\right)$ | $O(N)$ | $K$ 居中时方案数是天文数字，$N=300$ 完全不可算 |
| 分层 DP + 前缀和（最优） | $O(K\cdot N^2)$ | $O(N)$ | 转移总数 $\frac{N(N+1)(N+2)}{6}\approx 4.5\times10^6$，纯 Python 约 $0.3$ 秒 |

第二行的时间界在 $K=N$ 时取到：此时每一层都要单独成段，$dp$ 表几乎填满。空间只需前缀和、上一层与当前层各一行，$O(N)$；若把整张 $dp[k][i]$ 都留下，空间会变成 $O(KN)$，而本题只问 $dp[K][N]$，没有回溯切分的需求，所以不需要。

## 易错点总结

### 1. 末段也加了通信耗时

`head = pref[i] + (S[i - 1] if i < n else 0)` 里的 `if i < n` 是"覆盖第 $N$ 层的段没有后继"这条规则。去掉它、改成无条件 `+ S[i - 1]`，样例 1 会输出 $16$（$11+S_2=11+5$），样例 2 会输出 $15$（末段 $[4,5]$ 的 $14$ 被抬到 $15$，成为新的最大值）。

### 2. 滚动数组被复用成了同一个对象

`cur = prev`（或者两个名字换来换去地原地更新）时，$i$ 从小到大推进，内层读到的 `prev[j]` 已经是**本轮**的 $dp[k][j]$，等于允许在同一层里继续切，段数上限被打穿。样例 2 会输出 $13$——那是五段 $[1],[2],[3],[4],[5]$ 的最大值（$8,9,13,12,8$），比正确答案 $14$ 小，看上去还挺合理，不容易发现。每轮 `cur = [INF] * (n + 1)` 是必须的，同时这也保证了 $i<k$ 的格子（$i$ 层切 $k$ 段，根本不存在）保持不可达。
