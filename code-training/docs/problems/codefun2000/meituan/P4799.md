# P4799. 晶石净化

> 场次：2026年4月18日-开发岗 · 来源：[CodeFun2000 P4799](https://codefun2000.com/p/P4799)

## 题目描述

在一间能量实验室中，从左到右依次摆放着 $n$ 个晶石，每个晶石拥有一个正整数的能量值。研究员将进行 $m$ 轮净化操作，每轮操作规则如下：在当前尚未被净化的晶石中，选择能量值最小的一个将其净化移除；如果同时存在多个能量值同为最小的晶石，则移除其中最靠左（即出现最早）的那一个。请你计算出所有净化操作完成后，剩余晶石的能量值序列（保留原始顺序）。

约束：
- 测试数据组数 $T$ 不超过 `2*10^5`。
- 每组数据中，晶石数量 $n$ 不超过 `2*10^5`，净化轮数 $m$ 满足 $0 \le m < n$。
- 每个晶石的能量值均为 $1$ 到 $n$ 之间的整数。
- 所有测试数据中 $n$ 的总和不超过 `4*10^5`。

## 输入格式

第一行包含一个整数 $T$，表示测试数据的组数。接下来每组数据包含两行：第一行有两个整数 $n$ 和 $m$，分别表示晶石数量和净化轮数；第二行有 $n$ 个整数，依次给出从左到右每个晶石的能量值。

## 输出格式

对于每组测试数据，在一行内输出剩余晶石的能量值，整数之间用空格分隔。

## 示例

### 示例 1

**输入：**

```
1
5 3
2 3 2 1 2
```

**输出：**

```
3 2
```

**说明：**

初始晶石能量值为 $[2, 3, 2, 1, 2]$，共 $n=`5`$ 个晶石，需要进行 $m=`3`$ 轮净化。

第 `1` 轮：当前序列中最小能量值为 `1`，仅有位置 `4` 的晶石为 `1`，将其净化移除，剩余序列为 $[2, 3, 2, 2]$。

第 `2` 轮：最小能量值为 `2`，存在多个（原位置 `1`、`3`、`5`），移除最靠左的 `2`（原位置 `1`），剩余序列为 $[3, 2, 2]$。

第 `3` 轮：最小能量值仍为 `2`，移除剩余中最靠左的 `2`（原位置 `3`），最终剩余晶石为 $[3, 2]$，按原顺序输出 `3 2`。

### 示例 2

**输入：**

```
1
3 0
5 3 7
```

**输出：**

```
5 3 7
```

**说明：**

净化轮数 $m=`0`$，表示不进行任何净化操作。剩余晶石即为初始序列 $[5, 3, 7]$，按原顺序输出 `5 3 7`。

### 示例 3

**输入：**

```
1
4 3
4 4 4 4
```

**输出：**

```
4
```

**说明：**

初始晶石能量值全为 `4`，共 $n=`4`$ 个，净化 $m=`3`$ 轮。每轮当前序列的最小值均为 `4`，根据规则移除最靠左的一个。

第 `1` 轮：移除位置 `1` 的 `4`，剩余 $3$ 个 `4`。
第 `2` 轮：移除剩余中最靠左的 `4`（原位置 `2`），剩余 $2$ 个 `4`。
第 `3` 轮：再移除剩余中最靠左的 `4`（原位置 `3`），最终只剩位置 `4` 的晶石，输出 `4`。

## 解题思路

### 「按轮删最小」的次序可以预先算死

每轮操作是「删当前最小值，平局取最左」。把全体晶石按（能量值，下标）排序：序数第 $r$ 小的那颗若还活着，任何一颗序数更靠前的（能量更小，或能量相同但更靠左）只要活着就必然在更早的轮次先被删掉——所以第 $r$ 轮删掉的**恰好是**排序后第 $r$ 个，与「当时还剩什么」无关。$m$ 轮操作于是等价于：删掉这个顺序的前 $m$ 个，剩下的按原始位置输出。一次 $O(n \log n)$ 的排序替代了 $m$ 轮模拟。

注意到这个等价还自带一个边界：题面约束 $0 \le m < n$，因此任何输入至少留下一颗晶石，输出不会为空。

### 数据范围与实现的对应

所有组的 $n$ 总和不超过 $4 \times 10^5$，$T$ 至多 $2 \times 10^5$：逐轮用堆模拟每轮 $O(\log n)$、总 $O(m \log n)$，最坏 $m = n-1$ 时也稳，但「排序一次」的实现更短且同样 $O(n \log n)$。实现映射：

- 排序键直接用 `key=lambda i: (vals[i], i)`——元组第一分量管能量值，第二分量管平局时的下标（更小即更靠左）；
- 排序后的切片 `order[:m]` 就是全部被删的下标集合，用一个集合排除；
- 输出严格按原始下标顺序扫一遍生成，不做二次排序。

多组数据的输入/输出都用整块读写：先把全部 token 一次读进内存，再 `"\n".join` 输出，避免每组数据的读写开销。

## 完整代码实现

```python
"""
P4799. 晶石净化 - 按（能量值, 下标）排序 + 标记删除（模拟）

题意：n 个晶石排成一行，进行 m 轮净化。每轮移除当前剩余晶石中能量值最小的
一个；能量值相同则移除最靠左的。最后按原始顺序输出剩余序列。

关键观察：m 轮删的永远是「当前最小、平局取最左」，而这个选择与删除发生的
次序无关——第 r 轮移除的必定是全体晶石按（能量值, 下标）排序后的第 r 个。
理由：按这个序比较，序数在前的晶石若还在（它本来就比本轮候选更小/更靠左），
就必然先于本轮候选被选中；所以整个 m 轮操作正好删掉排序后的前 m 个。
于是不用逐轮模拟，一次排序 + 标记即可，剩余的按原始顺序输出。

输入格式：
- 第 1 行：测试组数 T；
- 每组两行：第一行 n 和 m（0 <= m < n），第二行 n 个能量值。

输出格式：
- 每组一行，剩余晶石的能量值，空格分隔。

时间复杂度：O(n log n)（所有组的 n 总和不超过 4*10^5）
空间复杂度：O(n)
"""

# https://codefun2000.com/p/P4799
import sys

# @sample-start
"""
样例 1:
1
5 3
2 3 2 1 2
->
3 2
"""
# @sample-end

# @sample-start
"""
样例 2:
1
3 0
5 3 7
->
5 3 7
"""
# @sample-end

# @sample-start
"""
样例 3:
1
4 3
4 4 4 4
->
4
"""
# @sample-end


def solve():
    """按（能量值, 下标）排序删除前 m 个，输出剩余序列。"""
    data = sys.stdin.buffer.read().split()
    pos = 1
    t = int(data[0])
    out = []
    for _ in range(t):
        n = int(data[pos])
        m = int(data[pos + 1])
        pos += 2
        vals = [int(x) for x in data[pos:pos + n]]
        pos += n

        # 排序键 (能量值, 下标) 同时表达了两条规则：
        # 能量值小者优先；能量值相同时下标小（更靠左）者优先。
        # 排序后的前 m 个正是 m 轮净化会依次移除的晶石。
        order = sorted(range(n), key=lambda i: (vals[i], i))
        removed = set(order[:m])

        out.append(" ".join(str(vals[i]) for i in range(n) if i not in removed))
    sys.stdout.write("\n".join(out) + "\n")


def run_tests():
    """运行嵌入的官方样例与自加的边界/变形用例。"""
    import io
    import random

    def run_once(inp):
        old = sys.stdin, sys.stdout
        sys.stdin = io.TextIOWrapper(io.BytesIO(inp.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            return sys.stdout.getvalue().rstrip("\n")
        finally:
            sys.stdin, sys.stdout = old

    def brute(vals, m):
        """参照实现：用逐轮堆模拟还原规则本身，验证排序等价性。"""
        import heapq
        hp = [(v, i) for i, v in enumerate(vals)]
        heapq.heapify(hp)
        alive = [True] * len(vals)
        for _ in range(m):
            v, i = heapq.heappop(hp)
            while not alive[i]:
                v, i = heapq.heappop(hp)
            alive[i] = False
        return [v for i, v in enumerate(vals) if alive[i]]

    cases = [
        # 官方样例 1：平局时移除最靠左的 2
        ("1\n5 3\n2 3 2 1 2\n", "3 2"),
        # 官方样例 2：m=0 不删任何晶石
        ("1\n3 0\n5 3 7\n", "5 3 7"),
        # 官方样例 3：全相等时逐个移除最左边
        ("1\n4 3\n4 4 4 4\n", "4"),
        # 边界：m = n-1 只剩最大值（平局时剩最靠右的最大值）
        ("1\n4 3\n2 9 9 1\n", "9"),
        # 已升序排列：每轮删的都是最左边的（最小的）
        ("1\n5 2\n1 2 3 4 5\n", "3 4 5"),
        # 已降序排列：删的是能量值全局最小的若干个
        ("1\n5 2\n5 4 3 2 1\n", "5 4 3"),
        # 最小值分散在两端：平局取左，第二轮仍在左端
        ("1\n4 2\n1 3 3 1\n", "3 3"),
        # 多组数据混排
        ("2\n3 1\n7 7 7\n5 4\n1 2 2 3 3\n", "7 7\n3"),
    ]

    for i, (inp, expected) in enumerate(cases, 1):
        got = run_once(inp)
        status = "✓" if got == expected else "✗"
        print(f"样例 {i}: 期望={expected!r}, 实际={got!r} {status}")

    # 随机对拍：与逐轮堆模拟比较
    rng = random.Random(20260418)
    ok = True
    for trial in range(300):
        n = rng.randint(1, 18)
        m = rng.randint(0, n - 1)
        vals = [rng.randint(1, n) for _ in range(n)]
        inp = "1\n%d %d\n%s\n" % (n, m, " ".join(map(str, vals)))
        got = run_once(inp)
        want = " ".join(map(str, brute(vals, m)))
        if got != want:
            ok = False
            print(f"对拍失败: vals={vals}, m={m}, 期望={want}, 实际={got}")
    print("随机对拍:", "全部通过" if ok else "存在失败")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()
```

## 示例推演

样例 1：$[2, 3, 2, 1, 2]$，$m=3$。排序键（值，下标，下标从 0 计）：

$$(1,3)\ <\ (2,0)\ <\ (2,2)\ <\ (2,4)\ <\ (3,1)$$

前 3 个是被删下标 $\{3, 0, 2\}$，剩余下标 1（值 3）与 4（值 2），按原始顺序输出 `3 2`。与逐轮走一遍对照：第 1 轮删值 1（位置 3），第 2 轮在三个 2 里删最左的位置 0，第 3 轮删剩下最左的 2（位置 2）——三次删除的结果与切片完全一致。

样例 3：$[4,4,4,4]$，$m=3$。四个键 $(4,0),(4,1),(4,2),(4,3)$ 全由平局键决胜负，删掉前 3 个，只剩位置 3 输出 `4`。

另一组演示易踩的两个地方。输出顺序：样例 1 删完剩下位置 1（值 3）和位置 4（值 2），原始序输出 `3 2`；若把剩余值再按能量从小到大排一遍就会给出 `2 3`，一步露馅。平局方向：$[3, 9, 3]$ 配 $m=1$，按（值，下标）删 $(3,0)$，剩余 $[9,3]$ 输出 `9 3`；平局键若反接（下标大者优先）会先删 $(3,2)$，剩余 $[3,9]$ 输出 `3 9`——序列整体错位。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 逐轮最小值扫描 | $O(n \cdot m)$ | $O(1)$ | 空间最省；$m$ 接近 $n$ 时最坏 $O(n^2)$ |
| 逐轮堆模拟 | $O((n + m) \log n)$ | $O(n)$ | 直接按规则还原，正确但常数大 |
| 一次排序 + 标记删除（最优） | $O(n \log n)$ | $O(n)$ | 前 $m$ 个（按值 + 下标）即被删者，剩余按原序输出，本题采用 |

所有组 $n$ 总和 $4 \times 10^5$，排序总耗时在 $10^7$ 比较以内。

---

## 易错点总结

### 1. 剩余序列必须按原始顺序输出，不能按排序后的顺序

「删除集合」可以从排序键里一块拿到，但留下来的是**原序列**的相对位置。把剩余值再按能量从小到大输出（即直接输出 `sorted` 的后 $n-m$ 个值），样例 1 会给出 `2 3` 而不是 `3 2`——位置 1 的 3 排在位置 4 的 2 前面这件事只靠原始顺序保证。

### 2. 平局键的方向反了删错人

排序键写成 `(vals[i], -i)` 或对下标降序时，能量相同的晶石会先删靠右的。在左右同值的构造（如 $[1, 3, 3, 1]$、$m=2$）里输出恰好还是 `3 3` 看不出差别，而 $[2, 3, 2, 1, 2]$ 这类删中间与删末端会改变答案的输入（正确 `3 2`，反接后删掉位置 4 的 2 得 `3 3`）才能定位。

## 扩展思考

- $m$ 接近 $n$ 时本题等价于「保留排序后靠后的 $n-m$ 个」，这与 Top-K 问题同构；若 $n$ 极大而 $m$ 很小，把排序换成堆（只维护 $m$ 个最劣者）能把内存常数压下来。
- 「删除次序与剩余状态无关」是这个等价成立的根基。一旦规则改为「删除后重排」（如每次删后把最右一颗挪到队首），次序就会和剩余状态纠缠，只能老老实实逐轮模拟。
