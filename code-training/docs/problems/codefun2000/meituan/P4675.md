# P4675. 符石共鸣的最大能量

> 场次：2026年3月28日-开发岗 · 来源：[CodeFun2000 P4675](https://codefun2000.com/p/P4675)

## 题目描述

在一片古老的遗迹中，你发现了一排符石，从左到右编号为 $1$ 到 $n$。第 $i$ 块符石蕴含的能量值为 $v_i$（可能为正、负或零）。你可以从中挑选任意数量的符石（可以不选，也可以全部选择），并保持原有的相对顺序将这些符石拼接成一个新的序列。该序列将产生共鸣效应：序列中的第 $1$ 个符石贡献 $+v$，第 $2$ 个贡献 $-v$，第 $3$ 个贡献 $+v$，依此类推，符号正负交替。

若你选择了 $k$ 块符石，其能量依次为 $s_1, s_2, \ldots, s_k$，则共鸣总能量为
$$E = s_1 - s_2 + s_3 - s_4 + \cdots + (-1)^{k-1}s_k.$$
特别地，若不选任何符石，总能量视为 $0$。

你需要计算在该规则下所能获得的最大总能量。

**约束条件**
- 单组数据中符石个数 $n$ 满足 $1 \le n \le 2 \times 10^5$。
- 所有测试数据中 $n$ 的总和不超过 $5 \times 10^5$。
- 每个能量值 $v_i$ 满足 $|v_i| \le 10^6$。

## 输入格式

第一行输入一个整数 $T$（$1 \le T \le 2 \times 10^5$），表示测试数据组数。
对于每组测试数据：
第一行输入一个整数 $n$（$1 \le n \le 2 \times 10^5$），表示该组符石的数量；
第二行输入 $n$ 个整数 $v_1, v_2, \ldots, v_n$（$|v_i| \le 10^6$），表示从左到右每块符石的能量值。
所有测试数据的 $n$ 之和不超过 $5 \times 10^5$。

## 输出格式

对于每组测试数据，输出一行一个整数，代表可以得到的最大共鸣总能量。

## 示例

### 示例 1

**输入：**

```
1
1
100
```

**输出：**

```
100
```

**说明：**

仅有一块符石，能量为 `100`。可选的方案有两种：
1. 不选任何符石，共鸣总能量为 `0`；
2. 选择该符石，序列为 `[100]`，共鸣能量为 $+100$。
显然最大总能量为 `100`。此样例测试了 $n=1$ 的边界情况。

### 示例 2

**输入：**

```
1
4
-3 -1 -4 -2
```

**输出：**

```
3
```

**说明：**

四块符石能量全为负，分别为 `-3`、`-1`、`-4`、`-2`。

最优方案是选择第 `2` 块和第 `3` 块符石，子序列为 `[-1, -4]`。
共鸣总能量计算：$E = s_1 - s_2 = (-1) - (-4) = 3$。

其他可能的选择：只选一块最多为 `-1`；选两块若取 `-3` 和 `-4` 得 $(-3)-(-4)=1$；选三块或四块均小于 `3`。因此最大总能量为 `3`。此样例说明全负数组可通过合理选择获得正值。

### 示例 3

**输入：**

```
1
5
5 -3 4 -2 6
```

**输出：**

```
20
```

**说明：**

五块符石能量依次为 `5`、`-3`、`4`、`-2`、`6`。

最优方案是选择全部五块符石，子序列为原序列本身。
其共鸣总能量为：
$$E = 5 - (-3) + 4 - (-2) + 6 = 5 + 3 + 4 + 2 + 6 = 20$$

若尝试丢弃某些符石，例如丢弃 `-3` 和 `-2`，子序列为 `[5, 4, 6]`，能量为 $5 - 4 + 6 = 7$，比 `20` 小。全选时所有负数恰好位于减数位置，使它们变为正贡献，因此总能量达到最大 `20`。

## 解题思路

### 符号只由"已被选的个数"决定

判定标准写得很干净：选出的子序列 $s_1, s_2, \ldots, s_m$ 的共鸣值为 $s_1 - s_2 + s_3 - \cdots$，符号在第几位就取什么号，与符石本身的能量正负无关。特别地，什么都不选时规定为 $0$——这一条在样例 2 全负的数组里非常关键：最优解是 $(-1) - (-4) = 3$，靠"减一个负数"把负符石变成正贡献。

从左到右处理符石时，一个"已搭好的部分序列"按已选个数只有两种后继形态：

- 已选偶数个（含空序列，值 $0$）：下一个填入的贡献 $+v$，记这个最优值为 $f$；
- 已选奇数个：下一个填入的贡献 $-v$，记为 $g$。

新符石 $x$ 只能挂在某个已有序列的尾部，两种转移同时发生：

$$f \leftarrow \max(f,\; g - x), \qquad g \leftarrow \max(g,\; f + x)$$

两条都必须用**更新前**的旧值（$x$ 向奇长度序列借负号、向偶长度序列借正号是同一时刻的两个分支），$f$ 初值 $0$ 把"不选任何符石"并入比较，$g$ 初值 $-\infty$ 表示奇长度序列不能凭空存在。答案取 $\max(f, g)$。

### 为什么是 DP 而不是按数值排序的贪心

这个结构像"把正的放正号位、负的放负号位"就能解决，但符号位由**保序的选取顺序**决定，无法重排：样例 3 里 $5, -3, 4, -2, 6$ 全选得 $20$，而丢掉两个负数反而只剩 $7$。数据范围 $n \le 2\times10^5$、$\sum n \le 5\times10^5$，线性两状态 DP 恰好是下限级别的复杂度，直接一遍扫描完成。

实现上把两状态压进两个标量（`best_resonance` 的 `f, g`），用 Python 的元组同时赋值保证两条转移共享旧值（`f, g = max(f, g - x), max(g, f + x)`），空序列的关注点全在初值上。

## 完整代码实现

```python
"""
P4675. 符石共鸣的最大能量 - 线性 DP（交替符号子序列）

题面要点：从符石序列 v_1..v_n 里挑一个子序列保序拼接，共鸣值为
E = s_1 − s_2 + s_3 − …（首位 +，正负交替）。可以一个都不选（E = 0）。
求 E 的最大值。

输入：第一行 T；每组第一行 n，第二行 n 个能量值（可能为负）。
输出：每组一行最大共鸣值。

核心思路：
1. 把「选好的序列」按已选个数分类只有两种状态——
   f：已选偶数个（含空序列，值 0），下一个填入的符石贡献 +v；
   g：已选奇数个，下一个填入的符石贡献 −v。
2. 从左到右扫，新符石 v 只能接到某个已有序列的尾部：
   f = max(f, g − v)   # 接到奇长度序列后面，该位取负
   g = max(g, f + v)   # 接到偶长度序列后面，该位取正
   两条转移同时用更新前的旧值（元组同时赋值）。
   f 初值 0 兜底了「不选任何符石」；g 初值 −inf（奇长度序列必须非空）。
3. 答案 = max(f, g)。

时间复杂度：O(Σn)
空间复杂度：O(1)（每组）
"""

# https://codefun2000.com/p/P4675
import sys

# @sample-start
"""
样例输入 1:
1
1
100

样例输出 1:
100
"""
# @sample-end

# @sample-start
"""
样例输入 2:
1
4
-3 -1 -4 -2

样例输出 2:
3
"""
# @sample-end

# @sample-start
"""
样例输入 3:
1
5
5 -3 4 -2 6

样例输出 3:
20
"""
# @sample-end

NEG_INF = -(1 << 60)


def best_resonance(values):
    """返回该组符石的交替符号子序列最大共鸣值（含空序列的 0）。"""
    f, g = 0, NEG_INF   # f: 偶长度(下一位 +v)；g: 奇长度(下一位 −v)
    for x in values:
        # 两条转移同时使用旧值：x 挂在奇长度后面取负，挂在偶长度后面取正
        f, g = max(f, g - x), max(g, f + x)
    return max(f, g)


def solve():
    data = sys.stdin.buffer.read().split()
    pos = 0
    t = int(data[pos])
    pos += 1
    out = []
    for _ in range(t):
        n = int(data[pos])
        pos += 1
        values = [int(x) for x in data[pos:pos + n]]
        pos += n
        out.append(str(best_resonance(values)))
    sys.stdout.write("\n".join(out) + "\n")


def run_tests():
    """官方样例 + 边界/变形用例 + 随机暴力对拍。"""
    import io

    test_cases = [
        # 官方样例 1：n = 1，选它就是 100
        (
            "1\n1\n100\n",
            "100",
        ),
        # 官方样例 2：全负数组，选 [-1, -4] 得 (-1) - (-4) = 3
        (
            "1\n4\n-3 -1 -4 -2\n",
            "3",
        ),
        # 官方样例 3：全选，负数恰好都落在减数位
        (
            "1\n5\n5 -3 4 -2 6\n",
            "20",
        ),
        # 全正数组也会丢弃部分正数让前面的正数站到减数位：[10,1,10] -> 10-1+10=19
        (
            "1\n3\n10 1 10\n",
            "19",
        ),
        # 全负且两个：取差值
        (
            "1\n2\n-5 -9\n",
            "4",
        ),
        # 全是 0：最大值 0（空序列也算）
        (
            "1\n3\n0 0 0\n",
            "0",
        ),
        # 两个零夹一大数
        (
            "1\n3\n0 7 0\n",
            "7",
        ),
        # 多组数据串一起
        (
            "2\n1\n-4\n1\n2\n",
            "0\n2",
        ),
    ]

    for i, (inp, expected) in enumerate(test_cases, 1):
        old_stdin, old_stdout = sys.stdin, sys.stdout
        sys.stdin = io.TextIOWrapper(io.BytesIO(inp.encode("utf-8")))
        sys.stdout = io.StringIO()
        try:
            solve()
            output = sys.stdout.getvalue().strip()
        finally:
            sys.stdin, sys.stdout = old_stdin, old_stdout

        status = "✓" if output == expected else "✗"
        print(f"样例 {i}: 期望={expected}, 实际={output} {status}")

    # 随机暴力对拍：小 n 枚举全部子序列逐个算共鸣值
    import random

    rng = random.Random(20260411)
    ok = True
    for case in range(500):
        n = rng.randint(1, 10)
        values = [rng.randint(-6, 6) for _ in range(n)]
        brute = 0
        for mask in range(1, 1 << n):
            seq = [values[k] for k in range(n) if mask >> k & 1]
            total = 0
            for idx, s in enumerate(seq, 1):
                total += s if idx % 2 == 1 else -s
            brute = max(brute, total)
        got = best_resonance(values)
        if got != brute:
            ok = False
            print(f"对拍失败: values={values} DP={got} 暴力={brute}")
            break
    print(f"随机暴力对拍 500 组: {'✓' if ok else '✗'}")


if __name__ == "__main__":
    if len(sys.argv) > 1 and sys.argv[1] == "--test":
        run_tests()
    else:
        solve()

```

## 示例推演

以样例 2 的全负数组 $-3, -1, -4, -2$ 走一遍（$f$ 含空序列的 $0$，$g$ 从 $-\infty$ 起步）：

| 处理完 | $f$（下一位收 $+v$） | $g$（下一位收 $-v$） | 对应代表序列 |
| ------ | ---- | ---- | ---- |
| $-3$ | $0$ | $-3$ | $[-3]$ |
| $-1$ | $0$ | $-1$ | $[-1]$（单选比 $[-3,-1]$ 的 $-2$ 好） |
| $-4$ | $3$ | $-1$ | $[-1,-4] = (-1) - (-4)$ |
| $-2$ | $3$ | $1$ | $[-1,-4,-2] = -1+4-2$ |

答案 $\max(3, 1) = 3$，与官方说明一致。line-tracking 一遍可见 $f$ 何时翻正：第三块符石进来时 $g - (-4) = -1 + 4 = 3$ 压过了 $0$——"负符石落在奇长度序列后面取负"正是全负数组里唯一的翻正通道。

样例 3 的 $5, -3, 4, -2, 6$ 全选，正位 $5+4+6 = 15$、负位 $-3-2$ 取负后 $+5$，共 $20$；而丢掉两个负数变成 $5 - 4 + 6 = 7$。第三步 $g$ 涨到 $12$（对应 $5,-3,4,-2$ 之后只欠一个取负的位）——其后 $6$ 挂上去的分支 $g = 12$ 的序列取负得 $20$，比任何"丢负符石"的方案都大。

## 易错点总结

### 1. 两条转移必须共享旧值

更新 $f$ 之后紧接着用新 $f$ 去更新 $g$（或反过来），等于让同一块符石在一个"时刻"里既当正号位又当负号位。`f, g = max(f, g - x), max(g, f + x)` 的元组同时赋值是整份实现的关键一行；拆成两条顺序语句后，"先更新 $f$" 的写法会多出一条同符石双使用的转移路径，小样例多次全负数据即可见结果偏大。

### 2. $g$ 的初值用 $0$ 而不是 $-\infty$

$g$ 表示"已选奇数个"的最优值，$0$ 属于空序列（偶数个），不是它的合法状态。初值写成 $0$ 时，单符石 $-2$ 的一组会算出 $2$：`max(f, g - x)` 里 $g$ 的 $0$ 先被借走了一个本不存在的"负号位"，$0 + 2 = 2$ 反而成了答案，而正确答案是"不选"的 $0$。`NEG_INF = -(1 << 60)` 压住这个凭空的分支。

### 3. 答案漏掉 $g$

奇长度序列（第一位取 $+$）的候选答案全在 $g$ 里；若只返回 $f$，样例 3 的全选方案是奇长度，输出会错成 $14$ 而不是 $20$。`return max(f, g)` 的两边都要在。

## 扩展思考

- "保序子序列 + 符号由位数决定"的状态设计通用于一类交替和问题：每多一种符号轮换周期，状态数就多一份，但扫描一遍、共享旧值同步推进的骨架不变。
- 与最长交替子序列（奇偶翻转型）对比：那里状态记录的是"上一位符号"，本题记录的是"已选个数奇偶"，本质都是把决策的历史压成一个指示位。
