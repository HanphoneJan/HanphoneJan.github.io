# BISHI76. 迷宫寻路

## 题目描述

旺仔哥哥被困在一个 n 行 m 列的矩形迷宫里。每个格子要么是空地（`.`），
要么是墙（`#`）。他只能从一个空地移动到其上下左右相邻的空地。
已知起点为左上角 (1, 1)，终点为右下角 (n, m)。请判断他是否能到达终点。

## 输入格式

第一行输入两个正整数 n、m。
接下来的 n 行，每行输入一个长为 m 的、仅包含字符 `.` 与 `#` 的字符串，
描述整个迷宫。保证起点和终点均为空地。

## 输出格式

若旺仔哥哥可以走到终点，则输出单词 `Yes`；否则输出 `No`。

## 示例

### 示例 1

**输入：**
```
3 5
.##.#
.#...
...#.
```

**输出：**
```
Yes
```

**说明：**
存在一条只经过 `.` 的路径从 (1,1) 到 (3,5)，例如
(1,1)→(2,1)→(3,1)→(3,2)→(3,3)→(2,3)→(1,3)→(1,4)→(1,5)→(2,5)→(3,5)。

## 解题思路

### 第一步：理解问题本质

把每个 `.` 当成图上的一个点，两个上下左右相邻的空地之间有一条边。
问题就是：图中起点和终点是否连通？这是一次标准的**图遍历**。

### 第二步：暴力 DFS（可能爆栈）

从起点出发递归搜索：

```python
def dfs(x, y):
    # 三个出口缺一不可：出界、撞墙、走回已访问的格子
    if 越界 or 是墙 or 已访问:
        return
    # 先标记再递归：若先递归后标记，相邻格子会互相回访形成死循环
    mark(x, y)
    dfs(x + 1, y); dfs(x - 1, y); dfs(x, y + 1); dfs(x, y - 1)
```

思路没问题，但递归深度可能达到 n×m（最坏上百万），
Python 默认递归限制会直接 `RecursionError`。
即使提高上限，栈空间也可能不够。

### 第三步：BFS（推荐）

用队列代替递归，一层一层往外扩散，天然不会爆栈：

1. 把起点入队并标记已访问；
2. 每次取出队首，向四个方向找**没访问过的空地**，标记后入队；
3. 一旦访问到终点就输出 `Yes`；
4. 队列空了还没到终点，输出 `No`。

BFS 还能顺带得到「最短步数」，是多源网格题的首选写法。

## 完整代码实现

```python
import sys
from collections import deque


def solve() -> None:
    """从左上角 BFS，判断能否到达右下角"""
    data = sys.stdin.read().split()
    if not data:
        return
    n = int(data[0])
    m = int(data[1])
    grid = data[2:2 + n]

    if grid[0][0] == '#' or grid[n - 1][m - 1] == '#':
        sys.stdout.write("No\n")
        return

    seen = [[False] * m for _ in range(n)]
    seen[0][0] = True
    queue = deque([(0, 0)])
    while queue:
        x, y = queue.popleft()
        if x == n - 1 and y == m - 1:
            sys.stdout.write("Yes\n")
            return
        for dx, dy in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nx, ny = x + dx, y + dy
            if 0 <= nx < n and 0 <= ny < m and not seen[nx][ny] and grid[nx][ny] == '.':
                seen[nx][ny] = True
                queue.append((nx, ny))
    sys.stdout.write("No\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

迷宫如下（`.` 可走，`#` 是墙），坐标按 1 起写：

```
. # # . #
. # . . .
. . . # .
```

BFS 从 (1,1) 出发，队列按先进先出推进（每次出队后列出新入队的格子）：

| 出队 | 新入队 | 队列剩余 |
|------|--------|----------|
| (1,1) | (2,1) | (2,1) |
| (2,1) | (3,1) | (3,1) |
| (3,1) | (3,2) | (3,2) |
| (3,2) | (3,3) | (3,3) |
| (3,3) | (2,3) | (2,3) |
| (2,3) | (2,4) | (2,4) |
| (2,4) | (1,4)、(2,5) | (1,4)、(2,5) |
| (1,4) | 无（上方是墙、右侧是墙） | (2,5) |
| (2,5) | (3,5) | (3,5) |
| (3,5) | 出队即终点 → `Yes` | 空 |

这条链其实就是题目说明里那条路：每一步都只有一个新格子可入队，所以队列始终只有一个元素。若是开阔地形，同一层会一次压进好几个格子，出队顺序才是「按距离一圈圈」的。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 递归 DFS | O(n*m) | O(n*m) | 可能爆栈 |
| 迭代 DFS | O(n*m) | O(n*m) | 安全 |
| BFS（最优） | O(n*m) | O(n*m) | 每格只入队一次，还能求最短路 |

## 易错点总结

### 1. 标记写成「出队时」而不是「入队时」

`seen[nx][ny] = True` 必须在 `queue.append` 之前完成。只在 `popleft()` 之后才标记，同一个空格会被它的每个邻居各入队一次，而每份副本出队时又各自向外扩一圈——入队次数随地图边长指数增长。全空地 $n\times n$ 实测入队次数：$n=2$ 是 $5$、$n=3$ 是 $19$、$n=4$ 是 $69$、$n=5$ 是 $251$、$n=6$ 是 $923$（每加一行约乘 $3.7$），正确写法恒为 $n^2$；20×20 就足以让程序挂住。

### 2. 终点判断放在出队时，却忘了起点可能就是终点

`if x == n - 1 and y == n - 1` 在循环开头判断，起点入队后立刻出队，`n = m = 1` 也能正确输出 `Yes`。若把它挪到「入队时判断」并只对邻居生效，起点自身永远不会被检查，1×1 的迷宫会输出 `No`。
