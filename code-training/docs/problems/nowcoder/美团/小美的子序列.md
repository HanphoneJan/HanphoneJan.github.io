# 小美的子序列

> 美团 2023-09-02 笔试编程题（每题 20 分）

## 题目描述

小美在 n 行 m 列的本子上写了许多字母，她会在每一行中找出一个字母，
然后按行序组成一个字符串。小美想知道，组成的字符串中是否存在至少一个
包含 `meituan` 子序列的字符串。

## 输入格式

第一行两个整数 n、m（1 ≤ n, m ≤ 1000）。
接下来 n 行，每行一个长度为 m 的字符串，表示小美写下的字母。

## 输出格式

若存在至少一个字符串包含 `meituan` 子序列，则输出 `YES`，否则输出 `NO`。

## 示例

### 示例 1

**输入：**
```
3 3
abc
def
ghi
```

**输出：**
```
NO
```

**说明：**
三行里都找不到 `m`，凑不出 `meituan`，输出 NO。

### 示例 2

**输入：**
```
8 2
nm
ex
it
td
ul
qu
ac
nt
```

**输出：**
```
YES
```

**说明：**
依次从第 1~5、7、8 行取出 `m e i t u a n`，组成的字符串里含有
`meituan` 子序列。

---

## 解题思路

### 把「组字符串」翻译成「按行各取一个字符」

每行只能出一个字母，组出来的字符串顺序就是行的顺序。要问「是否存在包含 `meituan` 子序列的字符串」，
等价于：

> 能否在第 1、2、…、n 行里按行号递增的顺序挑出 7 行，使它们各自含有的某个字符依次是
> `m e i t u a n`？

子序列不要求连续，只要顺序对。所以每行的任务只有一个：**它能不能提供「现在缺的那个字母」**。

### 唯一需要记住的状态：目标前缀匹配到第几位

令 `idx` 表示

> 扫过前 t 行之后，用这 t 行（每行最多取一个字符）最多能拼出的 `meituan` 前缀长度。

`idx` 是唯一需要的状态：后面所有选择只跟「还差哪几个字母」有关，跟前面具体用了哪些行无关。
转移就两种：

- 第 t+1 行里有 `TARGET[idx]` → 补上这一位，`idx += 1`；
- 没有 → 这行对答案没用，`idx` 不动。

```python
idx = 0
for row in rows:
    if idx < len(TARGET) and TARGET[idx] in row:
        idx += 1
```

### 为什么这个贪心不会漏解

把「`idx` 就是最大值」当成不变量，对行数归纳：

- **归纳假设**：扫完前 t 行时 `idx` 等于「用前 t 行最多能拼出的前缀长度」。
- **扫第 t+1 行**：任何用前 t+1 行拼出的前缀，要么**不用**这一行（长度不超过旧 `idx`），
  要么**用了**这一行 —— 用了它就必须把它当作第 `idx+1` 个字符，即要求
  `TARGET[idx] in row`。于是新的上界恰好是「含 `TARGET[idx]` 就 +1，否则不变」，与代码一致。

直观说法是：**当前缺的字母越早补齐，后面剩下的行越多**；故意等一行只会让可用行变少，
不可能变多。这与「判断字符串 a 是不是 b 的子序列」是同一套贪心。

复杂度是每行做一次 `in` 判断，O(n·m)。

## 完整代码实现

页面上的「跑样例」与逐帧可视化跑的就是这一块：

```python
import sys

TARGET = "meituan"


def solve() -> None:
    """每行匹配一个目标字符，能匹配完就 YES"""
    data = sys.stdin.read().split()
    if not data:
        return
    n = int(data[0])
    rows = data[2:2 + n]   # 第 2 个整数是列数 m，逐行匹配时用不到

    idx = 0
    for row in rows:
        if idx < len(TARGET) and TARGET[idx] in row:
            idx += 1
    sys.stdout.write("YES\n" if idx == len(TARGET) else "NO\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

示例 1：`n = 3`、`m = 3`，三行分别是 `abc`、`def`、`ghi`。目标第一位是 `m`：

| 行 | 内容 | 需要匹配 | 是否命中 | idx |
|----|------|----------|----------|-----|
| 1 | abc | m | 否 | 0 |
| 2 | def | m | 否 | 0 |
| 3 | ghi | m | 否 | 0 |

扫完 `idx = 0 ≠ 7`，输出 `NO`。第一位就断了，后面几位根本轮不到。

示例 2：`n = 8`、`m = 2`，逐行匹配 `meituan`：

| 行 | 内容 | 需要匹配 | 是否命中 | idx |
|----|------|----------|----------|-----|
| 1 | nm | m | 是（第 2 个字符） | 1 |
| 2 | ex | e | 是 | 2 |
| 3 | it | i | 是 | 3 |
| 4 | td | t | 是 | 4 |
| 5 | ul | u | 是 | 5 |
| 6 | qu | a | 否（只有 q、u） | 5 |
| 7 | ac | a | 是 | 6 |
| 8 | nt | n | 是 | 7 |

`idx` 到达 7（`len("meituan")`），输出 `YES`。第 6 行是唯一被跳过的一行 ——
它既不含当时缺的 `a`，也不影响后面的匹配，跳过它不损失任何东西。
注意第 1 行 `nm` 里的 `m` 在第 2 个位置，仍然可以取：这一行只贡献一个字符，取哪一个由我们挑。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 暴力枚举每行的取法 | O(mⁿ) | O(n) | 每行 m 种选法、共 n 行，行数一多就完全不可行 |
| 逐行贪心（最优） | O(n·m) | O(1) | 每行一次 `in` 判断，只维护一个指针 |

---

## 易错点总结

1. **不判 `idx < len(TARGET)` 就取 `TARGET[idx]`**：7 个字母匹配完之后，下一行会去取
   `TARGET[7]`，抛 `IndexError: string index out of range`。示例 2 恰好在第 8 行匹配完就结束，
   看不出这个问题；输入只要多一行（哪怕只有一个字母）程序就崩。
2. **在同一行里连续匹配多个字母**：把 `if` 写成 `while idx < len(TARGET) and TARGET[idx] in row: idx += 1`，
   就变成了「一行可以出任意多个字符」。输入 6 行 `me / i / t / u / a / n` 会被判成 `YES`
   （第 1 行一口气吃掉 `m`、`e`），可 6 行最多只能出 6 个字符，正确答案是 `NO`。

---

## 扩展思考

- 若每行可以任取多个字符（等价于把矩阵按行优先展平成一个长串），问题退化成「长串里是否存在
  `meituan` 子序列」，仍是同一个指针一路扫过去，复杂度 O(n·m)。
- 若目标串很长、矩阵很大，可以把每行先转成 `set(row)`，把 `in` 判断从 O(m) 降到期望 O(1)，
  但建集合本身也是 O(m)，只有对同一行反复查询时才划算。
