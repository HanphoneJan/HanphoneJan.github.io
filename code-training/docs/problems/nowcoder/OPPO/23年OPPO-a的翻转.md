# 23年OPPO-a的翻转

> OPPO 笔试真题 · 2023 秋招 · 研发岗
>
> 判题请到[牛客原题](https://www.nowcoder.com/practice/dcce2d0cc8f740c29e0885df96c9d625)提交。

## 题目描述

数字$a$翻转数位得到数字$b$，计算$a+b$。

## 输入格式

一个正整数$a\;(1\leqslant a \leqslant 10^9)$。保证$a$在十进制下每一位都非$0$。

## 输出格式

一个正整数表示答案。

## 示例

### 示例 1

**输入：**

```text
12
```

**输出：**

```text
33
```

**说明：**

正整数$a=12$，翻转得到$b=21$，$a+b=33$。

### 示例 2

**输入：**

```text
23
```

**输出：**

```text
55
```

## 解题思路

### 把题意翻译成一个算式

「翻转数位」是把十进制的写法倒过来读，不是按位取反、也不是二进制翻转：`12345` 翻成 `54321`。
所以整道题就是读入 `a`、算出 `b = reverse(a)`、输出 `a + b`，没有任何选择余地。

### 怎么把数位倒过来

两种写法算的是同一个东西。

**数学写法**：反复取个位，接到 `b` 的末尾。

```python
b, t = 0, a
while t:
    b = b * 10 + t % 10
    t //= 10
```

`t % 10` 拿到当前最低位；`b * 10` 把已经拼好的部分整体左移一位、腾出个位，两者相加就把这一位接在了末尾。
循环用替身 `t` 而不是直接改 `a`，因为下面还要用原始的 `a` 求和。

**字符串写法**：十进制写法就是数位序列，倒序之后按十进制读回来即可。

```python
b = int(str(a)[::-1])
```

两者为什么等价：数学写法第 k 轮取到的是 `a` 从低位起的第 k 位，接到结果末尾后，
结果里就是「低位在前」的序列 —— 恰好是写法倒过来。`d` 位的 `a` 循环 `d` 次，两种写法都只做 `d` 次数位操作。

倒过来之后会不会出现前导零？题面保证 `a` 的每一位都非 0，所以倒过来后首位（原来的末位）也非 0，
`b` 的位数与 `a` 相同，两种写法不会丢位。即使允许出现 0（比如 `a = 120`），
数学写法得到 21、`int("021")` 也得到 21，答案 `120 + 21 = 141` 仍然一致。

### 相加与范围

```python
sys.stdout.write(str(a + b) + "\n")
```

`a ≤ 10^9` 且每位非 0，所以 `a`、`b` 都最多 9 位，`a + b < 2 × 10^9`，32 位有符号整数装得下。
Python 的整数不会溢出；换成 C++ / Java 时用 `long long` / `long` 更稳妥。

## 完整代码实现

字符串反转的版本（页面上的「跑样例」与逐帧可视化跑的就是它）：

```python
import sys


def solve() -> None:
    """把 a 的数位翻转得到 b，输出 a + b"""
    data = sys.stdin.read().split()
    if not data:
        return
    a = int(data[0])
    # 数位翻转：字符串反转后转回整数
    b = int(str(a)[::-1])
    sys.stdout.write(str(a + b) + "\n")


if __name__ == "__main__":
    solve()
```

数学取余的版本，不依赖 `str`，可以直接搬到 C++ / Java：

```python
import sys


def solve() -> None:
    """数学写法：逐位取余拼出翻转数，再与原数相加"""
    data = sys.stdin.read().split()
    if not data:
        return
    a = int(data[0])

    b, t = 0, a          # t 是替身，a 要留着求和
    while t:
        b = b * 10 + t % 10
        t //= 10

    sys.stdout.write(str(a + b) + "\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

示例 1，`a = 12`，先走字符串写法：

| 步骤 | 值 |
|------|----|
| 读入 `a` | `12` |
| `str(a)` | `"12"` |
| `str(a)[::-1]` | `"21"` |
| `int(...)` 得到 `b` | `21` |
| `a + b` | `33` |

数学写法跑同一组数据，逐轮看 `b` 与 `t`：

| 轮次 | 处理前 `t` | `t % 10` | 处理前 `b` | `b = b * 10 + 个位` | `t // 10` |
|------|-----------|----------|-----------|---------------------|-----------|
| 1 | 12 | 2 | 0 | 2 | 1 |
| 2 | 1 | 1 | 2 | 21 | 0（循环结束） |

两轮之后 `b = 21`，`a + b = 12 + 21 = 33`，与字符串写法一致。

示例 2，`a = 23`：翻转得 `32`，`23 + 32 = 55`。

再看两种规模：

- `a = 9`（一位数）：翻转还是 `9`，输出 `18`，循环只跑一轮；
- `a = 12345`：翻转得 `54321`，`12345 + 54321 = 66666`；`b` 依次是 5 → 54 → 543 → 5432 → 54321。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 字符串反转 | O(d) | O(d) | `str` 与 `int` 各建一份长度为 d 的临时对象 |
| 数学取余（最优） | O(d) | O(1) | 只多一个累加变量，且可直接搬到 C++ / Java |

> `d` 是 `a` 的位数。`a ≤ 10^9` 时 `d ≤ 9`，两种写法在这道题上都瞬间完成。

---

## 易错点总结

1. **数学写法直接改 `a`，求和时原数已经没了**：把循环写成 `while a: b = b * 10 + a % 10; a //= 10`，
   循环结束时 `a == 0`，最后 `a + b` 拿到的只是翻转数。样例 1 会输出 `21` 而不是 `33`。
   用替身变量（`t = a`）或先存一份原值即可。

2. **`str(a)[::-1]` 忘了 `int()`**：`a + str(a)[::-1]` 直接抛 `TypeError`（`int` 与 `str` 相加）；
   写成 `str(a) + str(a)[::-1]` 不报错，但输出的是拼接结果 `1221`，而不是 `33`。

## 扩展思考

- 允许含 0 时，`int` 会吃掉前导零：`120 → 21`，`120 + 21 = 141` 仍然正确；只有要求「保留前导零输出」时才需要另行处理。
- 把「十进制翻转」换成「二进制翻转并去掉前导 0」，就是[小O的数位翻转](小O的数位翻转.md) 里的操作。
- 回文数判断是同一个动作：翻转后与自己比较是否相等。
