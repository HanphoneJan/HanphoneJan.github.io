# 小欧的选数乘积

> OPPO 笔试真题 · 2023 秋招 · 算法岗
>
> 判题请到[牛客原题](https://www.nowcoder.com/practice/a94f523ebe424d0481533dc9e6138724)提交。

## 题目描述

小欧拿到了两个正整数$x$和$y$，她想进行一些操作使得$x$不小于$y$，操作方式是：选择$a$数组中的一个元素$a_i$，将$x$乘以$a_i$，并删掉$a$数组中所有的$a_i$。

小欧想知道，自己最少进行多少次操作，可以使得$x$不小于$y$？

## 输入格式

第一行输入两个正整数$x$和$y$，用空格隔开。

第二行输入一个正整数$n$，代表数组大小。

第三行输入$n$个正整数$a_i$，代表数组的元素。

$1\leq x,y,a_i \leq 10^{9}$

$1\leq n \leq 10^5$

## 输出格式

如果小欧无法在有限的操作下使得$x$不小于$y$，则输出-1。

否则输出一个整数，代表小欧的操作次数。

## 示例

### 示例 1

**输入：**

```text
3 40
4
2 3 4 4
```

**输出：**

```text
3
```

**说明：**

第一次操作，小欧选择数字3，$x$变成9，此时数组为[2,4,4]

第二次操作，小欧选择数字4，$x$变成36，此时数组为[2]

第三次操作，小欧选择数字2，$x$变成72，此时数组为空。三次操作后$x$不小于$y$

操作的方式不是唯一的，但可以证明操作的最小次数为3。

### 示例 2

**输入：**

```text
2 5
5
2 2 2 2 2
```

**输出：**

```text
-1
```

**说明：**

当小欧选择2后，$x$变成4，但此时数组为空。因此无法继续操作，$x$永远不可能不小于$y$。

### 示例 3

**输入：**

```text
5 5
5
2 2 2 2 2
```

**输出：**

```text
0
```

**说明：**

小欧不需要任何操作。

## 解题思路

### 选一次就把同值的全删掉：能用的只有「不同的值」

操作是「乘上 $a_i$，再删掉数组里**所有**等于 $a_i$ 的元素」。所以选过 $v$ 之后
$v$ 就从数组里消失了，第二次不可能再选它 —— **每种不同的值最多用一次**。
重复元素唯一的用处是「证明 $v$ 存在」，它们不会让乘积多乘一次。

去重并降序就是这个意思：

```python
values = sorted({int(v) for v in data[3:3 + n]}, reverse=True)
```

`set` 吃掉重复，`reverse=True` 让后面的循环从最大的值开始乘。

### 最少次数只由「取几个」决定，不取决于「取哪几个」

题目问的是最小操作次数 $k$，判定标准是「乘完之后 $x$ 是否 $\ge y$」。这里有一条
可以直接证明的结论：

> 固定操作次数 $k$，从不同值里挑 $k$ 个，乘积最大的挑法一定是**最大的 $k$ 个**。

原因是乘积对每个因子都单调：把其中任何一个换成更小的值，乘积只会变小或不变。
于是「存在一种 $k$ 次操作能达标」等价于「最大的 $k$ 个不同值乘起来达标」。

又因为所有 $a_i \ge 1$，乘积随 $k$ 单调不减 —— 能达标的 $k$ 构成一段后缀，
**最小的那个就是第一次达标的时刻**。所以按降序累乘，第一次 $x \ge y$ 就停：

```python
ops = 0
for v in values:              # 从大到小
    if v == 1:                # 后面全是 1 了，乘上去不会有任何变化
        break
    x *= v
    ops += 1
    if x >= y:
        sys.stdout.write(str(ops) + "\n")
        return
```

`if x >= y` 写在**乘完立刻检查**的位置，有两个作用：一是它就是答案的判定；
二是让 $x$ 始终小于 $y \le 10^9$，再乘一个 $a_i$ 最多到 $10^{18}$，不会滚成
几十万位的天文数字。

### 三种出口：0、某个 $k$、$-1$

- **一开始就 $x \ge y$**：答案是 0，循环前就要返回，不能让循环跑出 1；
- **乘到某个 $k$ 达标**：这个 $k$ 就是最小次数；
- **乘完了仍不到 $y$**：输出 $-1$。这一支同时覆盖两种无解：所有不同值全是 1
  （`break` 后落到这里），以及值的个数不够、乘积不够大。

### 为什么不需要「枚举挑哪几个」

子集枚举看起来像通往答案的路，但上一条结论已经把「挑哪几个」压成了
「挑几个」：固定 $k$ 时最优选法唯一确定（最大的 $k$ 个）。搜索空间从
$2^{n}$ 个子集塌缩成一维的 $k$，剩下的工作只是排序加一遍前缀乘积。

## 完整代码实现

```python
import sys


def solve() -> None:
    """不同值降序去重后依次相乘，乘到不小于 y 为止"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    x = int(data[0])
    y = int(data[1])
    n = int(data[2])

    if x >= y:
        sys.stdout.write("0\n")
        return

    # 同一个值只能选一次，先把重复的合并掉，再从大到小用
    values = sorted({int(v) for v in data[3:3 + n]}, reverse=True)

    ops = 0
    for v in values:
        if v == 1:
            # 后面全是 1 了，乘上去没有任何效果
            break
        x *= v
        ops += 1
        if x >= y:
            sys.stdout.write(str(ops) + "\n")
            return

    sys.stdout.write("-1\n")


if __name__ == "__main__":
    solve()
```

排序的一种替代写法：不开排序、每次线性扫一遍剩下的值取最大。时间变成
$O(n^2)$，$n = 10^5$ 时过不了，但它能说明「降序」不是排序 API 的细节，
而是贪心本身的要求：

```python
import sys


def solve() -> None:
    """不排序：每轮线性找当前最大值，选出后从候选里删掉"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    x, y, n = int(data[0]), int(data[1]), int(data[2])
    if x >= y:
        sys.stdout.write("0\n")
        return

    rest = {int(v) for v in data[3:3 + n]}
    ops = 0
    while rest:
        v = max(rest)          # 每轮花 O(n) 找最大
        rest.discard(v)
        if v == 1:
            break
        x *= v
        ops += 1
        if x >= y:
            sys.stdout.write(str(ops) + "\n")
            return

    sys.stdout.write("-1\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

### 示例 1：`x = 3, y = 40, a = [2, 3, 4, 4]`

去重后不同值是 $\{2, 3, 4\}$（两个 4 只算一个），降序排好：$4, 3, 2$。

| 第几次 | 选的值 | $x$ 变化 | $x \ge 40$？ |
| --- | --- | --- | --- |
| 1 | 4 | 3 → 12 | 否 |
| 2 | 3 | 12 → 36 | 否 |
| 3 | 2 | 36 → 72 | **是** |

输出 3。注意 $12 < 40$ 时还不能停：$k = 1, 2$ 时「最大的 $k$ 个」的乘积都不够，
说明别的选法（比如先乘 2）只会更差。

题面的说明是先选 3 再选 4 再选 2，顺序不同、次数一样 —— 固定个数的乘积与
相乘顺序无关，降序只是让达标来得最早。

### 示例 2：`x = 2, y = 5, a = [2, 2, 2, 2, 2]`

不同值只有 $\{2\}$。乘一次得到 $x = 4$，仍未到 5；此时 2 已经从数组里全部
删掉（本来就是同一个值），没有下一个可乘的数，循环退出，输出 $-1$。

这也说明「$n = 5$」容易被误读成「能乘 5 次」：真正能乘的次数是不同值的个数。

### 示例 3：`x = 5, y = 5, a = [2, 2, 2, 2, 2]`

一开始 $x \ge y$，在循环之前就返回 0。

### 补充例子：`x = 6, y = 100, a = [2, 3, 5]`

| 第几次 | 选的值 | $x$ 变化 | $x \ge 100$？ |
| --- | --- | --- | --- |
| 1 | 5 | 6 → 30 | 否 |
| 2 | 3 | 30 → 90 | 否 |
| 3 | 2 | 90 → 180 | **是** |

输出 3。如果按输入顺序 $2, 3, 5$ 乘，$x$ 走 $12 \to 36 \to 180$，同样在第三次
达标，看不出差别；但把数组换成 `x = 2, y = 5, a = [2, 3]` 就能看出先后顺序的
影响：先乘 3 一次就够（$6 \ge 5$），先乘 2 则要两次。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 不排序，每轮线性找最大值 | $O(n^2)$ | $O(n)$ | 贪心正确，但每轮多花一遍扫描；$n = 10^5$ 时约 $10^{10}$ 次比较 |
| 去重 + 降序排序 + 逐个乘（最优） | $O(n \log n)$ | $O(n)$ | 主要开销在排序，乘的次数不超过不同值的个数 |

## 易错点总结

1. **没有去重**：把数组原样降序排（`sorted(...)` 少了 `set`），示例 1 会变成
   $3 \to 12 \to 48$，两次就达标，输出 2 而正确答案是 3。选一次 4 就把两个 4
   一起删掉了。
2. **排序方向写反**：升序（或干脆按输入顺序）累乘，输入 `x = 2, y = 5, a = [2, 3]`
   时先乘 2 得到 4、还差一点，再乘 3 才达标，输出 2；正确答案是 1（直接乘 3）。
   降序保证「第 $k$ 次检查时手里的乘积已经是 $k$ 次操作能取得的最大值」。

## 扩展思考

- **如果每次只删掉选中的那一个元素**（而不是所有相同值）：不同值可以重复使用，
  答案就变成「取最大的若干个（允许重复）」，可以直接排序取前缀。
- **如果 $a_i$ 可以是 0 或负数**：乘 0 会让 $x$ 永远停在 0，负数还会让符号翻转，
  单调性失效，贪心不再成立，需要按正负分开讨论。
- **如果要求恰好 $k$ 次操作**（不能提前停）：那就变成「挑 $k$ 个使乘积最大」的
  问题，本题的排序结论仍然有用，但要补上「乘积不够也得凑满 $k$ 次」的收尾判断。
