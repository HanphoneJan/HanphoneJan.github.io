# 小欧喝水

> OPPO 笔试真题 · 2024 秋招 · 后端岗 · [牛客原题](https://www.nowcoder.com/practice/b5c4d567ca6a450eae7bee2852078b10)

## 题目描述

小欧拿了 `n` 个杯子排成一排，其中有 `k` 个杯子装满了水，剩余的 `n-k` 个杯子为空。小欧每回合的操作如下：

1. 随机选择一个杯子。
2. 杯子是空的，回合直接结束。
3. 杯子是满的。如果小欧上一回合喝过了水，则回合结束；否则将喝完这杯水，回合结束。

小欧想知道，她喝完所有水的回合数期望是多少？

## 输入格式

两个正整数 `n`、`k`，用空格隔开。

`1 <= k <= n <= 10^6`

## 输出格式

一个浮点数，代表期望的回合数。与正确答案的误差不超过 `10^-6` 即认为正确。

## 示例

### 示例 1

**输入：**

```
1 1
```

**输出：**

```
1.000000000
```

**说明：** 只有一杯水，第一回合就可以喝完。

### 示例 2

**输入：**

```
2 1
```

**输出：**

```
2.000000000
```

**说明：** 有 50% 的概率 1 回合喝完，25% 的概率需要 2 回合，12.5% 的概率需要 3 回合……分布是 `P(T = m) = (1/2)^m`，期望 `Σ m/2^m = 2`。

### 示例 3

**输入：**

```
2 2
```

**输出：**

```
4.000000000
```

**说明：** 第一回合必然喝掉一杯；第二回合是冷却，无论选到什么都不喝；从第三回合起每回合有 1/2 的概率选中剩下那杯。总回合数 `2 + 2 = 4`。

## 解题思路

杯子之间只有「满 / 空」的区别，具体是哪几个杯子满了并不重要。所以状态只要两个数：还剩几杯水 `f`，以及上一回合有没有喝过水。喝一杯水之后必然跟着一个「冷却回合」，正是这多出来的 1 回合让答案从 `n·H_k` 变成 `n·H_k + k - 1`。

### 只剩两个状态

设 `E(f)`：还剩 `f` 杯水、且**上一回合没喝过水**时，喝完剩下所有水还需要的期望回合数。

上一回合喝过水时，这一回合无论选到什么都喝不到（选到空杯没得喝，选到满杯也被冷却挡住），但它**只消耗 1 回合**，下一回合标记就恢复成「没喝过」。所以冷却的代价是固定的 1 回合，不需要单独定义一个状态。

### 写方程、解出递推

`f >= 2` 时，这一回合：

- 以 `f/n` 的概率选中满杯 → 喝掉一杯，接着花 1 个冷却回合，再面对 `f-1` 杯；
- 以 `(n-f)/n` 的概率选中空杯 → 什么都没发生，仍是 `f` 杯。

$$
E(f) = 1 + \frac{f}{n}\bigl(1 + E(f-1)\bigr) + \frac{n-f}{n}E(f)
$$

把右边的 `(n-f)/n·E(f)` 移到左边，剩下 `f/n·E(f)`，两边除以 `f/n`：

$$
E(f) = \frac{n}{f} + 1 + E(f-1)
$$

也就是说，多一杯水，期望就多 `n/f + 1` 回合：`n/f` 是「在所有 `n` 个杯子里等这一个杯子被选中」的几何期望，`+1` 是喝完之后的那次冷却。

### 最后一杯不需要冷却

`f = 1` 时没有下一杯要喝，喝完就结束，所以

$$
E(1) = n
$$

（每回合有 `1/n` 的概率选中它，几何分布的期望是 `n`。）递推从 `f = 2` 开始用，边界单独给。

代码就只有两行：

```python
harmonic = fsum(1.0 / i for i in range(1, k + 1))
ans = n * harmonic + (k - 1)
```

### 推演：示例 3

`n = 2, k = 2`。

| 回合 | 剩余杯数 | 发生了什么 | 累计回合 |
| --- | --- | --- | --- |
| 1 | 2 | 两杯都是满的，必选中满杯，且上一回合没喝过 → 喝掉一杯 | 1 |
| 2 | 1 | 上一回合喝过水 → 冷却，选到满杯也不喝 | 2 |
| 3 起 | 1 | 每回合 `1/2` 概率选中它，期望还要 `E(1) = 2` 回合 | 2 + 2 = 4 |

公式代进去：`2 × H_2 + (2 - 1) = 2 × 1.5 + 1 = 4`。

## 完整代码实现

```python
import sys
from math import fsum


def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    n = int(data[0])
    k = int(data[1])

    # E(k) = n * H_k + (k - 1)，H_k 是调和数 1 + 1/2 + ... + 1/k
    harmonic = fsum(1.0 / i for i in range(1, k + 1))
    ans = n * harmonic + (k - 1)
    sys.stdout.write(f"{ans:.9f}\n")


if __name__ == "__main__":
    solve()
```

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 按状态解方程，逐个存 `E(1..k)` | O(k) | O(k) | 每一步都依赖 `E(f-1)`，但可以只留一个变量 |
| 调和数累加（最优） | O(k) | O(1) | 一个累加器走完，`k = 10^6` 也只要几十毫秒 |

## 易错点总结

### 1. 漏掉冷却回合

喝完一杯之后的那一回合是白白消耗的。把递推里的 `+1` 去掉（认为喝完立刻可以继续喝），`n = 2, k = 2` 会算成 `2 × H_2 = 3`，而正确答案是 4。示例 3 的说明里那句「第二回合无论是否选到有水的杯子都不会喝水」就是这一回合。

### 2. `E(1)` 也算上冷却

`f = 1` 时喝完就结束了，没有下一杯，`E(1) = n`；写成 `n + 1` 会把 `n = 1, k = 1` 算成 2（正确 1）。递推里那个 `+1` 只属于「喝完还有下一杯」的情形，所以累加的是 `k - 1` 次而不是 `k` 次。

## 扩展思考

- 去掉冷却规则后，期望退化成经典的「集齐 `k` 个指定杯子」：`E = n·H_k`。本题多的正好是 `k - 1` 个冷却回合。
- `k` 再大（比如 `10^9`）时不能再循环，用 `H_k ≈ ln k + γ + 1/(2k)` 估算；本题 `k <= 10^6`，直接累加更稳。
