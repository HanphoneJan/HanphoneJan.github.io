# 小O的整数操作

> OPPO 笔试真题 · 2024 秋招 · AI/算法岗
>
> 判题请到[牛客原题](https://www.nowcoder.com/practice/52e3cbb106d54366a3f5fefac03d169f)提交。

## 题目描述

小O有一个整数 $n$，她每次可以进行以下操作之一：

1. 将 $n$ 减去 $1$；

2. 将 $n$ 除以 $k$（当 $n$ 可以被 $k$ 整除时）。

小O想知道，将 $n$ 变成 $m$ 至少需要多少次操作。

## 输入格式

在一行上输入三个整数 $n,m$ 和 $k\ ( 1 \leq m \leq n \leq 10^9;\ 1 \leq k \leq 10^9 )$ 表示初始数字、目标数字和 可以除的数字。

## 输出格式

在一行上输出一个正整数，表示将 $n$ 变成 $m$ 至少需要多少次操作。

## 示例

### 示例 1

**输入：**

```text
10 4 2
```

**输出：**

```text
2
```

**说明：**

先将 10 除以 2 得到 5，再将 5 减去 1 得到 4，共需要 2 次操作。

---

## 解题思路

### 两种操作都让 $n$ 变小，路径形状是固定的

- $n \to n - 1$；
- $n \to n/k$（要求整除）。

两者都只会让数变小，而目标 $m \le n$。所以整个过程是一条一路向下的路径，
每个时刻只需要决定「这一步减 1 还是除以 $k$」—— 一旦决定在哪些位置除，
整条路径就确定了。不需要搜索状态空间，需要的是「在哪除」的正确判据。

### 为什么「能除就除」是对的：一次交换论证

比较两种花法。假设当前数记作 $N$：

- 在**除法之前**把商降低 1：要减 $k$ 步，因为 $(N-k)/k = N/k - 1$；
- 在**除法之后**把结果降低 1：只要减 1 步。

也就是说，除之前做的每一次多余减法，效果都要被除以 $k$，是笔亏本买卖。
把那些减法挪到除之后再补，结果一样，步数不增。所以最优路径里，除法之前的
减法只做**必须做的事**：把 $N$ 补成 $k$ 的整数倍。

这条论证就是贪心的全部依据 —— **能除就除**。

### 除法有两个前提，缺一个就只能减

1. **必须整除**：$n \bmod k = r \ne 0$ 时先减 $r$ 步。少了除不了，多了白费，
   恰好 $r$ 步；
2. **除完不能低于 $m$**：只有 $n/k \ge m$ 才除。操作只能让数变小，一旦越过 $m$
   就再也回不来了，这时只能老老实实减 $n - m$ 步。

两条都检查完，循环就变成下面这样：

```python
ans = 0
while n > m:
    if n % k == 0:
        if n // k >= m:        # 除完不会越过 m，除是划算的
            n //= k
            ans += 1
        else:                  # 除完就比 m 小了，只能减
            ans += n - m
            break
    else:
        r = n % k              # 先减到最近的 k 的倍数
        if n - r >= m:
            n -= r
            ans += r
        else:                  # 减不到下一个倍数，直接减到 m
            ans += n - m
            break
```

两个 `else` 分支里的 `ans += n - m; break` 是同一个意思：**走不动了，剩下的
距离只能用减法一次走完**。它们同时保证循环一定会结束 —— 每一轮要么把 $n$ 变小
至少一倍，要么直接退出。

### $k = 1$ 必须先挡掉

$k = 1$ 时「除以 1」原地踏步，而 `n % 1 == 0` 恒成立，上面的循环会永远停在同一
个数上。这种输入下除法毫无意义，答案就是全用减法：

```python
if k == 1:
    sys.stdout.write(str(n - m) + "\n")
    return
```

### 为什么循环只有 $O(\log n)$ 轮

每一轮成功除一次，$n$ 就变成 $n/k \le n/2$（因为 $k \ge 2$），所以最多约
$\log_2 n$ 次除法；每两次除法之间最多做一次「补成倍数」的批量减法。$n \le 10^9$
时循环不超过三十来轮。

## 完整代码实现

```python
import sys


def solve() -> None:
    """贪心地「能除就除，除不动就先补到能除」"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    n, m, k = int(data[0]), int(data[1]), int(data[2])

    if k == 1:                     # 除法原地踏步，只剩减法
        sys.stdout.write(str(n - m) + "\n")
        return

    ans = 0
    while n > m:
        if n % k == 0:
            if n // k >= m:        # 除完不会越过 m，除是划算的
                n //= k
                ans += 1
            else:                  # 除完就比 m 小了，只能减
                ans += n - m
                break
        else:
            r = n % k              # 先减到最近的 k 的倍数
            if n - r >= m:
                n -= r
                ans += r
            else:                  # 减不到下一个倍数，直接减到 m
                ans += n - m
                break

    sys.stdout.write(str(ans) + "\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

以示例 `n = 10, m = 4, k = 2` 为例：

| 步骤 | 当前 $n$ | 判断 | 动作 | 累计操作 |
| ---- | -------- | ---- | ---- | -------- |
| 1 | 10 | $10 \bmod 2 = 0$ 且 $10/2 = 5 \ge 4$ | 除以 2，$n = 5$ | 1 |
| 2 | 5 | $5 \bmod 2 = 1$，凑整减 1 后 $4 \ge 4$ | 减 1，$n = 4$ | 2 |
| 3 | 4 | $n = m$，循环结束 | — | 2 |

答案 2。全程用减法要 $10 - 4 = 6$ 次，除法省下了 4 次。

再看 `n = 7, m = 3, k = 2`（除不尽的情形）：

| 步骤 | 当前 $n$ | 判断 | 动作 | 累计操作 |
| ---- | -------- | ---- | ---- | -------- |
| 1 | 7 | $7 \bmod 2 = 1$，$7 - 1 = 6 \ge 3$ | 减 1，$n = 6$ | 1 |
| 2 | 6 | $6 \bmod 2 = 0$，$6/2 = 3 \ge 3$ | 除以 2，$n = 3$ | 2 |

答案 2。第一步只减 1 就够了：7 是奇数，减 1 就凑成 2 的倍数（$6 = 2 \times 3$）。
多减的那些步在除法面前只值 $1/k$，纯属浪费 —— 这正是上面那条交换论证在具体
数字上的样子。

最后看一个「除过头」的例子 `n = 10, m = 6, k = 2`：

| 步骤 | 当前 $n$ | 判断 | 动作 | 累计操作 |
| ---- | -------- | ---- | ---- | -------- |
| 1 | 10 | $10 \bmod 2 = 0$，但 $10/2 = 5 < 6$ | 不除，直接减 $10-6 = 4$ 次 | 4 |

只要除就会掉到 5，低于目标且无法回升，所以答案是 4。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 全程一步步减 1 | $O(n-m)$ | $O(1)$ | $n \le 10^9$ 时最多 $10^9$ 轮，必然超时 |
| 贪心「能除就除」（最优） | $O(\log_k n)$ | $O(1)$ | 每除一次 $n$ 至少减半，循环不超过约 30 轮 |

## 易错点总结

1. **不判整除就直接 `n //= k`**：输入 `7 3 2` 时 $7//2 = 3$，一步「到位」，输出 1；
   但 7 不能被 2 整除，这一步是非法的，正确答案是 2（先减 1 到 6，再除以 2）。
   判据是 `if n % k == 0` 这一行。
2. **除之前不检查 `n // k >= m`**：输入 `10 6 2` 时先除得到 5，比目标还小，
   输出 1 而正确答案是 4。越过 $m$ 之后没有任何操作能让数变大，只能整段用减法。
3. **忘了特判 $k = 1$**：`n % 1 == 0` 恒成立、`n //= 1` 不改值，循环 `while n > m`
   永远不退出，程序卡死（页面上表现为一直跑不出结果）。

## 扩展思考

- 如果操作换成「$+1$ 和 $/k$」，方向就反过来了：应当从 $m$ 出发考虑「乘 $k$ 还是
  $+1$」，这是另一道经典题。一旦允许「变大」的操作，本文的交换论证（把减法挪到
  除法之后只会更省）就不再成立，得回到最短路 / BFS 的思路。
- 用 $k$ 进制看：一次「减到最近的倍数」正好把最低一位清零，代价是该位数字；
  一次除法就是右移一位。所以 $m = 1$ 时的总操作数是「$(\text{位数} - 1)$ 次除法
  + 各位数字（最高位除外）之和次减法」。$10$ 在二进制下是 `1010`，位数 4，
  非最高位数字和为 1，合计 $(4-1) + 1 = 4$ 步 —— 与逐步模拟一致。
