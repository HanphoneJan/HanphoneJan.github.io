# 小欧的数组修改

> OPPO 笔试真题 · 2023 秋招 · 移动端岗
>
> 判题请到[牛客原题](https://www.nowcoder.com/practice/9d57195bcec9415e9d12db846545ee0f)提交。

## 题目描述

小欧拿到了一个数组，她可以修改其中任意一个元素的值（也可以不修改），使得出现次数最多的那个元素次数尽可能多。你能求出这个最多的出现次数吗？

## 输入格式

第一行输入一个正整数$n$，代表数组的大小。

第二行输入$n$个正整数$a_i$，代表数组的各个元素。

$1\leq n,a_i \leq 10^5$

## 输出格式

一个正整数，代表小欧操作后出现最多的元素次数。

## 示例

### 示例 1

**输入：**

```text
3
1 2 3
```

**输出：**

```text
2
```

**说明：**

将1修改为3，数组变成[3,2,3]，3出现了2次。修改方式并不是唯一的。

### 示例 2

**输入：**

```text
1
4
```

**输出：**

```text
1
```

**说明：**

由于只有一个数，所以无论是否进行修改，它都只出现了1次。

## 解题思路

### 只能动一个位置，答案只有两种形状

题目允许「修改一个元素」或「不修改」。所以最终数组与原数组最多差一个位置，
答案也只可能来自两种操作：什么都不做，或者把某个下标的值换成另一个值。

### 上界：最多 $c+1$

设当前出现次数最多的值出现了 $c$ 次。把下标 $i$ 的值从 $p$ 改成 $q$：

- 值 $q$ 的频次至多 $+1$（若 $q \ne p$）；
- 值 $p$ 的频次 $-1$，其它值的频次不变。

所以任何一次修改之后，最大频次都不超过 $c+1$ —— 一个位置只能给某个计数
贡献一次增量。这是答案的上界。

### 上界什么时候取不到：整个数组都是同一个值

- **$c < n$**：等众数的位置只有 $c$ 个，而数组有 $n$ 个位置，所以一定存在一个
  值**不等于**众数的位置。把它改成众数的值，众数的频次从 $c$ 变成 $c+1$，
  上界取到。
- **$c = n$**：所有位置都是众数。改任何一个都会让它的频次掉到 $n-1$（其它值
  只变成 1），所以最优是**不修改**，答案 $n$。

两种情况合起来正好是

$$
\min(n,\ c+1)
$$

$c = n$ 时 $\min(n, n+1) = n$，$c < n$ 时 $\min(n, c+1) = c+1$。一个式子覆盖
两种情形，代码里不需要额外分支。

### 一遍扫描求 $c$

用一个哈希表边读边计数，同时维护当前的最大频次：

```python
cnt = {}
best = 0
for token in data[1:1 + n]:
    v = int(token)
    c = cnt.get(v, 0) + 1
    cnt[v] = c
    if c > best:
        best = c
```

`best` 必须在**循环内**跟着更新（或者最后取 `max(cnt.values())`）：它是「到目前为止
出现过的最大频次」，不是最后一个元素的出现次数。

## 完整代码实现

```python
import sys


def solve():
    """统计每个值出现的次数，取最大值后加一（不超过 n）"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    n = int(data[0])
    best = 0
    cnt = {}
    for token in data[1:1 + n]:
        v = int(token)
        c = cnt.get(v, 0) + 1
        cnt[v] = c
        if c > best:
            best = c
    sys.stdout.write(str(min(n, best + 1)) + "\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

**示例 1**：`n = 3`，数组是 `1 2 3`。

| 值 | 出现次数 |
| --- | --- |
| 1 | 1 |
| 2 | 1 |
| 3 | 1 |

最大频次 $c = 1$，答案 $= \min(3,\ 1+1) = 2$。

构造：把第一个位置的 `1` 改成 `3`，数组变成 `[3, 2, 3]`，`3` 出现 2 次。
改成 `1` 也行（`[1, 1, 3]`），方案不唯一，最大值唯一。

**示例 2**：`n = 1`，数组是 `4`。

最大频次 $c = 1 = n$，答案 $= \min(1,\ 2) = 1$。只有一个位置，改与不改都只有
一个数，取不到 $c+1$ —— 这正是 `min(n, ...)` 起作用的地方。

### 补充：两个方向各看一个

- $n = 4$，数组 `7 7 7 7`：$c = 4 = n$，答案 $\min(4, 5) = 4$。把某个 7 改掉会让
  7 只剩 3 个，保持不动才是最优。
- $n = 3$，数组 `2 2 3`：$c = 2$，答案 $\min(3, 3) = 3$。把 `3` 改成 `2` 得到
  `[2, 2, 2]`，上界 $c+1$ 与 $n$ 同时到顶。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 枚举「改哪个位置 × 改成什么值」并重数频次 | $O(n^3)$ | $O(n)$ | 每种情况都要重新统计一遍频次，$n = 10^5$ 时不可行 |
| 哈希表一遍计数 + 上界（最优） | $O(n)$ | $O(n)$ | 扫一遍求出 $c$，答案直接是 $\min(n, c+1)$ |

---

## 易错点总结

1. **不取 `min(n, ...)`**：直接输出 `best + 1`，示例 2（$n = 1$）会输出 2 而不是 1；
   更常见的表现是全相同的数组（$n = 4$、四个都是 7）输出 5。代码里对应
   `min(n, best + 1)` 这一处。
2. **计数写成 `cnt[v] += 1`**：键不存在时直接 `KeyError`，示例 1 在读到第一个数
   `1` 时就崩。必须用 `cnt.get(v, 0) + 1` 或 `collections.Counter`。

---

## 扩展思考

- 若允许最多修改 $k$ 个元素，答案变成 $\min(n, c+k)$：每改一个位置最多给众数
  贡献一次增量。
- 若还要输出方案，需要额外记下「出现次数最多的值」和「任意一个不属于它的下标」，
  改完再输出整个数组即可。
