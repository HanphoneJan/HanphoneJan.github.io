# 小欧的字符串构造

> OPPO 笔试真题 · [牛客原题](https://www.nowcoder.com/practice/3cf0c0aa163a44aba2ee1f7062cb8a12)

## 题目描述

小欧有一个字符串 `s`，她想构造一个长度为 `k` 的字符串 `t`，使得 `s + t` 或 `t + s` 拼成的字符串是回文串。

如果可以构造，则输出 `t`；若无法构造，请输出 `-1`。

## 输入格式

第一行输入一个长度不超过 `10^5` 的字符串 `s`。

第二行输入一个整数 `k`（`1 <= k <= 10^5`）。

## 输出格式

输出一个字符串表示答案；无法构造时输出 `-1`。

## 示例

### 示例 1

**输入：**

```
abc
3
```

**输出：**

```
cba
```

**说明：** 拼成 `abccba` 或 `cbaabc` 都是回文。

## 解题思路

`t` 的自由度完全由 `k` 和 `n = len(s)` 的大小关系决定。`k >= n` 时 `t` 可以比 `s` 长，可以用 `s + rev(s)` 这个「天生回文」的骨架把 `t` 填满；`k < n` 时 `t` 短于 `s`，它的每一位都被对面的字符镜像锁死，只剩「中间那一截是不是回文」需要验。

### `k >= n`：用 `s + rev(s)` 的骨架

记住一个基本事实：**`s + rev(s)` 一定是回文**。长度为 `2n`，第 `i` 位是 `s[i]`，对称位 `2n-1-i` 落在 `rev(s)` 里，也正好是 `s[i]`。

于是把 `t` 写成 `u + rev(s)`，其中 `len(u) = k - n`：

```
s + t = s + u + rev(s)
```

它的反转是 `s + rev(u) + rev(s)`。两式对比：只要 `u` 自己是回文，整个串就是回文。取全 `'a'` 的 `u` 永远满足条件，所以 `k >= n` 时一定有解：

```python
t = 'a' * (k - n) + s[::-1]
```

`k == n` 时 `u` 是空串，`t` 就是 `rev(s)`。

### `k < n`：`t` 被镜像锁死

此时 `t` 比 `s` 短，两条拼接路线各给出一个候选：

- **`s + t`**：回文要求最后 `k` 位与前 `k` 位镜像，而最后 `k` 位正是 `t` 倒过来，所以 `t = rev(s[:k])`。定下 `t` 后，首尾各消耗 `k` 位，中间剩下的 `s[k:]` 必须自己回文；
- **`t + s`**：同理 `t = rev(s[n-k:])`，并要求剩下的 `s[:n-k]` 回文。

```python
t = s[:k][::-1]
if s[k:] == s[k:][::-1]:
    return t
t = s[n-k:][::-1]
if s[:n-k] == s[:n-k][::-1]:
    return t
return '-1'
```

两条都过不了就输出 `-1`。注意「剩下的段是回文」这一条不能省：`t` 只对齐了首尾的 `k` 位，中间那截没人管。

### 推演：示例 1 与一个无解例子

示例 1：`s = "abc"`、`k = 3`，`k >= n`，`t = 'a' * 0 + rev("abc") = "cba"`。`s + t = "abccba"` 是回文。

再看 `s = "abc"`、`k = 1`（`k < n`）：

| 路线 | 候选 `t` | 剩余段 | 剩下的段是回文？ |
| --- | --- | --- | --- |
| `s + t` | `rev("a") = "a"` | `s[1:] = "bc"` | 否 |
| `t + s` | `rev("c") = "c"` | `s[:2] = "ab"` | 否 |

两条都失败，输出 `-1`。`s + t = "abca"` 确实不是回文——以为「`t` 只要镜像前 `k` 位」就够了，就会在这里错过中间那截。

## 完整代码实现

```python
import sys


def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    s = data[0].decode()
    k = int(data[1])
    n = len(s)

    if k >= n:
        # s + (u + rev(s)) 回文，只要 u 自己是回文；全 'a' 一定满足
        sys.stdout.write('a' * (k - n) + s[::-1])
        return

    # k < n：两条路线各锁死一个候选，再验中间剩下的段
    t = s[:k][::-1]
    if s[k:] == s[k:][::-1]:
        sys.stdout.write(t)
        return

    t = s[n - k:][::-1]
    if s[:n - k] == s[:n - k][::-1]:
        sys.stdout.write(t)
        return

    sys.stdout.write('-1')


if __name__ == "__main__":
    solve()
```

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 枚举所有长度为 `k` 的 `t` | O(26^k) | O(k) | `k` 到 10^5，完全不可行 |
| 按 `k` 与 `n` 分类构造（最优） | O(n + k) | O(n + k) | 切片、反转、回文比较都是一次线性扫描 |

## 易错点总结

### 1. `k >= n` 时直接输出 `rev(s)`

`rev(s)` 的长度是 `n`，而题目要求 `t` 的长度恰好是 `k`。`s = "abc"`、`k = 5` 时只输出 `"cba"`（长度 3），正确答案是 `"aacba"`——多出来的 `k - n` 位要补在 `rev(s)` 前面，且补的那段自身得是回文。

### 2. `k < n` 时只对齐首尾，不检查中间

`s = "abc"`、`k = 1` 时按 `t = rev(s[:1]) = "a"` 直接输出，拼出来 `"abca"` 不是回文。中间剩下的 `s[k:]`（这里是 `"bc"`）必须自己回文，否则这条路根本不成立，要换 `t + s` 那条再试。

## 扩展思考

- `k == n` 是第一条路线的边界：`u` 为空，答案是 `rev(s)`，此时 `s + rev(s)` 恰好是回文。
- 若题目要求「`s + t` 和 `t + s` 同时是回文」，`k >= n` 的构造就不再总是成立，需要 `u` 取成 `s` 与 `rev(s)` 都能接受的形状。
