# 小欧逛商店

> OPPO 笔试真题 · 2024 秋招 · 算法岗
>
> 判题请到[牛客原题](https://www.nowcoder.com/practice/919086dc716a466ba8284d5c749e8c15)提交。

## 题目描述

小欧准备去商店买东西，商店中有$n$个物品从左向右摆成一排，第$i$个物品的体积为$a_i$，价值为$b_i$。小欧有一个容量为$x$的背包，她每次看到能装进背包里的物品都会装进去，如果装不进去就跳过这个物品。

小欧想知道，她总共能买多少价值的物品？

## 输入格式

第一行输入两个正整数$n,x$，代表物品数量和背包容量。

接下来的$n$行，每行输入两个正整数$a_i$和$b_i$，代表每个物品的体积和价值。

$1\leq n \leq 10^5$

$1\leq a_i,b_i,x \leq 10^9$

## 输出格式

一个整数，代表总价值之和。

## 示例

### 示例 1

**输入：**

```text
3 5
4 3
2 5
1 3
```

**输出：**

```text
6
```

**说明：**

先买第一个物品，价值为 3。

遇到第二个物品时，此时剩余容量为 1，无法购买。

然后买第三个物品，价值为 3。

## 解题思路

### 题目没有留出选择：规则本身决定了答案

题面把挑选过程写死了：从左往右看，**能装就装**，装不下就跳过，跳过的不再回头。
所以读者要算的不是「怎么挑最优」，而是「按这条规则走完，总价值是多少」。
既然没有决策点，就不存在「这个贪心会不会不是最优」的问题 —— 把这个过程照抄成一次遍历即可。

### 为什么 0-1 背包和排序都不适用

0-1 背包解的是「容量有限时任意挑选、总价值最大」，它允许为了后面的物品而放弃当前能装的物品；
本题规则不允许。两者是**不同的问题**，不是同一问题的粗糙版本：样例里价值 5 的物品背包能挑中，而题目规则只能跳过。

数据范围也在指向一遍扫描：`x ≤ 10^9`，按容量开 DP 表根本开不出来；`n ≤ 10^5`，预期是 O(n)。
笔试里这种「规则已经写死 + 巨大容量」的组合，通常是让你别套模板，直接模拟。

### 一遍扫描只需要两个变量

`rest` 是剩余容量，`total` 是已买的价值：

```python
rest, total = x, 0
for a, b in items:
    if a <= rest:      # 恰好等于剩余容量也装得下
        rest -= a
        total += b
```

三处细节都要对上题面：

- 判定用 `<=`。体积恰好等于剩余容量时是装得下的，用 `<` 会漏掉这一类；
- `rest -= a` 只写在 `if` 里面。跳过的物品不占容量，`rest` 保持不变；
- 顺序就是输入顺序。一旦排序，「谁先来」就变了，答案也随之改变。

### 总和的范围

`b_i ≤ 10^9`、最多 `10^5` 件，总价值最大 `10^14`，超过 32 位整数。Python 不受影响；
换 C++ 时 `total` 要用 `long long`。

## 完整代码实现

一次读完所有 token 再迭代的版本（页面上的「跑样例」与逐帧可视化跑的就是它）：

```python
import sys


def solve() -> None:
    """按顺序模拟：装得下就装"""
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    it = iter(data)
    n = int(next(it))
    rest = int(next(it))          # 剩余容量
    total = 0                     # 已买物品的总价值
    for _ in range(n):
        volume = int(next(it))
        value = int(next(it))
        if volume <= rest:        # 等于剩余容量也算装得下
            rest -= volume
            total += value
    sys.stdout.write(str(total) + "\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

输入 `n = 3, x = 5`，物品依次是 `(4, 3)`、`(2, 5)`、`(1, 3)`：

| 顺序 | 体积 | 价值 | 处理前 `rest` | 判定 | 处理后 `rest` | `total` |
|------|------|------|---------------|------|---------------|---------|
| 1 | 4 | 3 | 5 | `4 <= 5`，装 | 1 | 3 |
| 2 | 2 | 5 | 1 | `2 > 1`，跳过 | 1 | 3 |
| 3 | 1 | 3 | 1 | `1 <= 1`，装 | 0 | 6 |

输出 `6`。第 2 件物品价值最高，但它来的时候只剩 1 的容量，只能跳过。

换个挑法就能看出规则的分量：若按价值从大到小排序再装 `(2, 5)`、`(4, 3)`、`(1, 3)`，
会装下 `(2, 5)` 与 `(1, 3)`，总价值 `5 + 3 = 8`；用 0-1 背包求最优也是 `8`。
而题目规则给出 `6`。`8` 不是「更优的同一个答案」，它是**另一个问题的答案**。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 0-1 背包（按容量 DP） | O(n·x) | O(x) | 解的是「任意挑选」；`x ≤ 10^9` 时表开不出来 |
| 顺序模拟（最优） | O(n) | O(1) | 只留 `rest` 与 `total`，边读边处理 |

## 易错点总结

1. **判定写成 `volume < rest`**：体积恰好等于剩余容量时是装得下的。样例第 3 件 `(1, 3)` 来的时候
   `rest` 正好是 1，会被跳过，输出 `3` 而不是 `6`。

2. **先把物品收进列表再排序**：加一行 `items.sort(key=lambda t: -t[1])` 就改变了装填顺序。
   样例会得到 `8`（先装 `(2, 5)` 再装 `(1, 3)`），而正确答案是 `6`。题面规定的顺序就是输入顺序，
   一旦排序，「谁先来」这个信息就丢了。

## 扩展思考

- 允许任意挑选时就是 0-1 背包；按体积从小到大贪心能装下最多**件数**，但不保证总价值最大。
- 把「装不下就跳过」改成「装不下就结束购物」，答案变成某个前缀上的模拟，循环里加一个 `break` 即可。
- 这类题在笔试里很常见：先找有没有决策点。没有决策点就照着规则模拟，不要急着往背包、排序上靠。
