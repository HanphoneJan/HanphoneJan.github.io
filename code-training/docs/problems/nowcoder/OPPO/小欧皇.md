# 小欧皇

> OPPO 笔试真题 · 2024 秋招 · 算法岗
>
> 判题请到[牛客原题](https://www.nowcoder.com/practice/6afe13c512d44b30b03933471d259ba4)提交。

## 题目描述

小欧正在扮演一个中世纪的皇帝。地图上有 $n$ 个城市，其中有 $m$ 条道路，每条道路连接了两个城市。

小欧占领了其中一些城市。如果两个城市可以通过若干条道路互相到达，且这些道路经过的城市都是小欧占领的，那么这两个城市之间就可以通过经商获得收益 $1$。请注意，每两个城市之间的收益只会被计算一次。

现在，小欧准备占领一个未被占领的城市，使得总收益最大化。你能帮帮她吗？

## 输入格式

第一行输入两个正整数 $n,m \left( 1 \leqq n,m \leqq 10^5\right)$，代表城市数量和道路数量。

第二行输入一个长度为 $n$ 的 01 串。第 $i$ 个字符为 '0' 代表小欧未占领该城市，'1' 代表小欧已经占领了该城市。

接下来的 $m$ 行，每行输入两个正整数 $u,v \left(1 \leqq u,v \leqq n,  u \neq v\right)$，代表城市 $u$ 和城市 $v$ 有一条道路连接。

## 输出格式

输出一行两个空格隔开的整数，第一个整数代表占领的城市编号，第二个整数代表占领后的收益。

请保证收益的最大化。如果有多种方案收益最大，小欧会优先占领编号最小的城市。

## 示例

### 示例 1

**输入：**

```text
5 5
01010
1 2
1 3
1 4
4 5
1 5
```

**输出：**

```text
1 3
```

**说明：**

占领 1 号城市后，总收益为 3。

1 号城市和 2 号城市经商，1 号城市和 4 号城市经商，2 号城市和 4 号城市经商。

## 解题思路

### 收益就是「已占领城市之间」的两两配对

只保留**两端都被占领**的道路，剩下的图会分成若干个连通块。块内任意两个城市
都能通过这些道路互相到达（路上的城市当然都是占领的），跨块的两个城市则走不通。
「每两个城市之间的收益只算一次」说明一对城市最多贡献 1，于是总收益是块内配对数
之和：

$$
base = \sum_{\text{块}} \binom{s}{2}, \qquad \binom{s}{2} = \frac{s(s-1)}{2}
$$

用组合数而不是 $s(s-1)$，是因为 $(u,v)$ 与 $(v,u)$ 是同一对；只按块求和而不是
全图求和，是因为跨块的点不连通。

### 并查集只合并两端都被占领的边

```python
for u, v in edges:
    graph[u].append(v)
    graph[v].append(u)
    if occupied[u] and occupied[v]:         # 只有两端都被占领才连通
        dsu.union(u, v)
```

这一步把「已占领城市之间的可达性」原样搬进并查集：每个集合恰好是一个连通块，
`dsu.size[根]` 就是 $s$。

关键点是它**只建一次**。枚举候选城市时，占领状态其实没有改变 —— 我们只是
「假设」多占领一个城市再回头撤销，所以原图的连通块结构始终相同，所有候选城市
共用同一个并查集。这正是整题能做到 $O((n+m)\,\alpha(n))$ 的原因：不是对每个
候选城市重跑一遍连通块。

### 当前收益 `base`：每个块算一次

```python
base = 0
for i in range(n):
    if occupied[i] and dsu.find(i) == i:    # 只认根，一个块算一次
        s = dsu.size[i]
        base += s * (s - 1) // 2
```

`dsu.find(i) == i` 是在判断「$i$ 是不是根」。少了这一条，块里每个城市都会把
整块的 $\binom{s}{2}$ 加一遍，收益会被放大 $s$ 倍。

### 占领 $u$ 之后：只有贴着 $u$ 的块被并成一块

设 $u$ 直接相连的、已被占领的块大小是 $s_1, \dots, s_d$（同一个块只算一次）。
占领 $u$ 之后，这些块加上 $u$ 自己合成一个大小为

$$
S = 1 + s_1 + \cdots + s_d
$$

的大块，其余块一动不动。所以

$$
total(u) = base - \sum_{j=1}^{d}\binom{s_j}{2} + \binom{S}{2}
$$

减号那一项不能省：被并的块内部原来那些配对**现在仍然存在**（它们在大块里依然
互相可达），新大块的 $\binom{S}{2}$ 里已经把它们又数了一遍，不先扣掉就重复计数。
没贴到 $u$ 的块，块内配对和跨块不连通的事实都没变，不用动。

这里有一个必须守住的不变式：**`base` 始终是「当前占领状态」下的收益，我们只在
算式里做加减，从不真的把 $u$ 并进 `dsu`。** 所以每个候选城市都从同一个 `base`
出发，互不污染；算完一个 `total(u)`，并查集和 `base` 都还是原样。

### 相邻块要去重，并列要取最小编号

```python
roots = set()
for v in graph[u]:
    if occupied[v]:
        roots.add(dsu.find(v))
```

`roots` 必须是 `set` 而不是 `list`：$u$ 可能通过好几条边连到**同一个**块
（例如块 $\{2,3\}$ 里的 2 和 3 都与 $u$ 相邻），这时这个块只能算一次。用
`list` 会把同一个 $s$ 加两遍，$S$ 偏大。

```python
if total > best_total:                  # 严格大于
    best_total = total
    best_city = u
```

`u` 是**从小到大**枚举的，所以「第一次出现当前最大值」的城市一定是同分里编号
最小的那个。写成 `>=` 会让后面同分的城市覆盖它。

### 并查集的两个优化

```python
def find(self, x: int) -> int:
    root = x
    while self.parent[root] != root:
        root = self.parent[root]
    while self.parent[x] != root:          # 路径压缩
        self.parent[x], x = root, self.parent[x]
    return root
```

路径压缩把查找过的点直接挂到根上；`union` 里按集合大小合并，把小树接到大树下面。
两者合起来让每次操作的均摊代价是 $\alpha(n)$。完整类见下面的代码。

## 完整代码实现

```python
import sys


class DSU:
    """路径压缩 + 按大小合并的并查集"""

    def __init__(self, n: int) -> None:
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x: int) -> int:
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:          # 路径压缩
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a: int, b: int) -> None:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]


def solve() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    n = int(data[0])
    m = int(data[1])
    occupied = [c == 49 for c in data[2]]       # 49 是字符 '1' 的字节值

    edges = []
    pos = 3
    for _ in range(m):
        u = int(data[pos]) - 1
        v = int(data[pos + 1]) - 1
        pos += 2
        edges.append((u, v))

    graph = [[] for _ in range(n)]
    dsu = DSU(n)
    for u, v in edges:
        graph[u].append(v)
        graph[v].append(u)
        if occupied[u] and occupied[v]:         # 只有两端都被占领才连通
            dsu.union(u, v)

    # 当前收益：每个已占领连通块贡献 C(s, 2)
    base = 0
    for i in range(n):
        if occupied[i] and dsu.find(i) == i:
            s = dsu.size[i]
            base += s * (s - 1) // 2

    best_city = -1
    best_total = -1
    for u in range(n):
        if occupied[u]:
            continue
        roots = set()
        for v in graph[u]:
            if occupied[v]:
                roots.add(dsu.find(v))
        joined = 1
        lost = 0
        for r in roots:
            s = dsu.size[r]
            joined += s
            lost += s * (s - 1) // 2
        total = base + joined * (joined - 1) // 2 - lost
        if total > best_total:                  # 严格大于，天然保留最小编号
            best_total = total
            best_city = u

    if best_city == -1:                         # 题目保证至少有一个未占领城市
        best_city, best_total = 0, base
    sys.stdout.write(f"{best_city + 1} {best_total}\n")


if __name__ == "__main__":
    solve()
```

## 示例推演

输入中 `01010` 表示只有 2 号、4 号城市已被占领，道路是
`1-2`、`1-3`、`1-4`、`4-5`、`1-5`。

先看当前图：2 号、4 号之间没有直连（它们只通过未占领的 1 号相通），所以各自
成块，大小都是 1：

$$
base = \binom{1}{2} + \binom{1}{2} = 0 + 0 = 0
$$

逐个尝试未占领的城市：

| 占领 | 相邻的已占领块 | $S$ | 扣掉的 $\sum\binom{s_j}{2}$ | $\binom{S}{2}$ | 总收益 |
| ---- | -------------- | --- | --- | --- | ------ |
| 1 | $\{2\}$、$\{4\}$ | $1+1+1=3$ | 0 + 0 = 0 | 3 | 3 |
| 3 | 无（只连着 1 号，1 号未占领） | 1 | 0 | 0 | 0 |
| 5 | $\{4\}$ | $1+1=2$ | 0 | 1 | 1 |

最大是 3，对应 1 号城市。占领后 $\{1,2,4\}$ 三城两两可经商，恰好 3 对，与题面
说明一致。输出 `1 3`。

### 补充例子：扣减项真的会起作用

```
4 2
0110
2 3
1 2
```

2 号与 3 号已占领且直连，成块 $\{2,3\}$，$base = \binom{2}{2} = 1$。

- 占领 1 号：它连着 2 号，所在块大小 $s = 2$。$S = 1 + 2 = 3$，
  新块贡献 $\binom{3}{2} = 3$，扣掉旧块的 $\binom{2}{2} = 1$，
  总收益 $1 + 3 - 1 = 3$。占领后 $\{1,2,3\}$ 三城全连通，确实是 3 对。
- 占领 4 号：没有边，$S = 1$，总收益仍是 1。

输出 `1 3`。若漏掉扣减项（`lost`），这里会算成 $1 + 3 = 4$，比真实收益多算的
正是块 $\{2,3\}$ 内部那一对。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| ---- | ---------- | ---------- | ---- |
| 每个候选城市重新 DFS 一遍求连通块 | $O(n(n+m))$ | $O(n+m)$ | 思路直白，但 $n,m \le 10^5$ 时不可行 |
| 并查集 + 一次枚举（最优） | $O((n+m)\,\alpha(n))$ | $O(n+m)$ | 并查集只建一次，每个点、每条边只处理常数次 |

## 易错点总结

1. **相邻块没去重**：`roots` 写成 `list`（`roots.append(dsu.find(v))`），同一个块
   有几条边连到 $u$ 就被加几次。把补充例子再加一条边 `1 3`，块 $\{2,3\}$ 会
   被加两次，$S$ 从 3 变成 5，收益从 3 变成 9。
2. **忘记减掉被并块的原贡献**：`total = base + joined * (joined - 1) // 2`，少了
   `- lost`。补充例子的输出会变成 `1 4` 而不是 `1 3`，而且被并的块越大偏得越多
   （块内每一对都被重复计了一次）。
3. **并列时写成 `>=`**：输入 `4 2 / 0100 / 1 2 / 3 2` 时，占领 1 号与 3 号的收益
   都是 1，正确答案是 `1 1`；用 `>=` 会被 3 号覆盖，输出 `3 1`。

## 扩展思考

- 并查集只支持合并、不支持拆分，所以「加一个点、合并若干块」这类题特别适合它。
  如果改成「删掉一个已占领的城市」，删点会让块裂开，通常要离线倒序处理：
  把删除看成倒着加，问题重新变回合并。
- 如果允许占领**两个**城市，两个新城市可能连到同一个块、也可能通过彼此连通，
  收益要按「它们是否相邻」分两种情形算，枚举量升到 $O(n^2)$ 级别，需要对块的
  收益排序后再挑。
