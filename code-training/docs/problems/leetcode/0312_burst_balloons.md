# 312. 戳气球

## 题目描述

有 `n` 个气球，编号为 `0` 到 `n-1`，每个气球上都标有一个数字，这些数字存在数组 `nums` 中。

现在要求你戳破所有的气球。戳破第 `i` 个气球，可以获得 `nums[i - 1] * nums[i] * nums[i + 1]` 枚硬币。这里 `nums[-1]` 和 `nums[n]` 都视为 `1`。

求所能获得硬币的最大数量。

## 示例

**示例 1：**
```
输入：nums = [3,1,5,8]
输出：167
解释：
nums = [3,1,5,8] -> [3,5,8] -> [3,8] -> [8] -> []
coins =  3*1*5    +   3*5*8   +  1*3*8  + 1*8*1 = 15 + 120 + 24 + 8 = 167
```

**示例 2：**
```
输入：nums = [1,5]
输出：10
```

## 解题思路

### 先看输出：每次收益都取决于「当时」的邻居

戳破一个气球的收益是「它自己 × 左边邻居 × 右边邻居」。戳掉之后，它的左右两个气球**变成了邻居** —— 一次选择会改写后面所有气球的邻居关系。

所以「现在戳哪个最划算」这种局部判断没有意义：一个数字大的气球现在戳能拿高分，但把它留作邻居，可能让后面两次收益都更大。真正的状态是「还剩下哪些气球」，最坏 `2^n` 种；直接枚举戳破顺序则是 `n!` 种。题目 `n ≤ 300`，这两条路都走不通。

### 关键转换：固定「区间里最后一个被戳破的是谁」

正着走不通，就把某一次选择钉死。取任意一段**开区间** `(i, j)`（`i`、`j` 是两个还不戳的边界），假设这段里**最后**被戳破的气球是 `k`：

- `k` 被戳破的那一刻，`(i, k)` 和 `(k, j)` 里的气球已经全没了，所以 `k` 的邻居**只能**是 `i` 和 `j`，收益固定为 `nums[i] * nums[k] * nums[j]`；
- `(i, k)` 里的气球怎么戳，和 `(k, j)` 里的完全无关 —— 它们各自被自己的边界夹着，谁也不会跑到对面去。

这两句话把「顺序」这个全局难题拆成了两个互不影响的子问题，并且 `k` 的收益与「之前怎么戳」无关。于是：

```text
dp[i][j] = max over k in (i, j) of  dp[i][k] + dp[k][j] + nums[i] * nums[k] * nums[j]
```

「最后被戳」是这条式子成立的全部理由：只有它才保证 `i`、`j` 在 `k` 被戳时**还在**，收益里的两个因子才是这两个数。

数组两端补上值为 `1` 的虚拟气球，是为了让「第一个」和「最后一个」真实气球也有确定的边界，递推里不必特判越界。

### 方法一：记忆化递归

把上面的定义直接写成函数。`dfs(i, j)` 返回把 `(i, j)` 里的气球全部戳破能拿到的最大收益；区间里已经没有气球时（`i + 1 >= j`）返回 0。

```python
from functools import cache

class Solution:
    def maxCoins(self, nums: list[int]) -> int:
        a = [1, *nums, 1]

        @cache
        def dfs(i: int, j: int) -> int:
            if i + 1 >= j:          # 开区间里已经没有气球
                return 0
            return max(
                dfs(i, k) + dfs(k, j) + a[i] * a[k] * a[j]
                for k in range(i + 1, j)
            )

        return dfs(0, len(a) - 1)
```

`dfs(0, len(a) - 1)` 的两个边界正好是两个虚拟气球，整个数组就是最大的那个开区间。状态 `(i, j)` 只有 `O(n^2)` 个，每个枚举 `O(n)` 个 `k`，所以时间是 `O(n^3)`；递归深度是区间嵌套的层数，最多 `n`。

记忆化的好处是只算真正被用到的状态，而且写起来和「最后一个是谁」这句话逐字对应。代价是函数调用与缓存查找的常数开销，以及长数组时的栈深。

### 方法二：区间 DP（按长度递推）

把递归翻过来求值。观察转移式：`dp[i][j]` 只用 `dp[i][k]` 和 `dp[k][j]`，而这两个区间都比 `(i, j)` **短**。所以只要按区间长度从小到大填，每个格子在用到时都已经算好。

```python
class Solution:
    def maxCoins(self, nums: list[int]) -> int:
        a = [1, *nums, 1]
        n = len(a)
        dp = [[0] * n for _ in range(n)]

        for span in range(2, n):              # span = j - i
            for i in range(n - span):
                j = i + span
                dp[i][j] = max(
                    dp[i][k] + dp[k][j] + a[i] * a[k] * a[j]
                    for k in range(i + 1, j)
                )

        return dp[0][n - 1]
```

`span` 从 2 开始：`span = 1` 的区间里没有任何整数 `k`，`dp` 就应该是 0。`span` 一直取到 `n - 1`，对应「两个虚拟气球夹着全部真实气球」这个最终答案。

注意内层 `k` 的范围是 `range(i + 1, j)`，不含两端：`i`、`j` 是边界，不是要戳的气球。

### 两种写法怎么选

| | 记忆化递归 | 区间 DP |
|---|---|---|
| 与推理的贴合度 | 与「最后一个是谁」逐字对应 | 需要先想清楚填表顺序 |
| 常数 | 函数调用 + 缓存查找 | 纯数组读写，更快 |
| 空间 | `O(n^2)` 缓存 + `O(n)` 栈 | `O(n^2)` 表 |
| 适合 | 先写对、验证转移式 | 提交版、想压常数 |

两者是**同一套递推的两种求值顺序**，不存在「更聪明的算法」。先写记忆化确认转移式，再改成按长度递推，是区间 DP 最稳的路径；反过来先背递推式，循环顺序一写错就会静默算错（见「易错点」）。

## 完整代码实现

下面是基准实现（页面上的逐帧可视化回放的也是这一段）：与上文「方法二」同一条转移，把 `max` 写成显式的两参数循环。

```python
from typing import List


class Solution:
    """
    戳气球 - 区间动态规划

    dp[i][j] 表示戳破 (i,j) 开区间内所有气球能获得的最大硬币数
    在数组两端添加虚拟气球1，简化边界处理

    时间复杂度：O(n^3)
    空间复杂度：O(n^2)
    """

    def maxCoins(self, nums: List[int]) -> int:
        # 在数组两端添加虚拟气球1
        nums = [1] + nums + [1]
        n = len(nums)

        # dp[i][j] 表示戳破 (i,j) 开区间内所有气球能获得的最大硬币数
        dp = [[0] * n for _ in range(n)]

        # 按区间长度从小到大枚举（长度至少为2才有中间元素）
        for length in range(2, n):
            for i in range(n - length):
                j = i + length
                # 枚举 (i,j) 区间内最后一个被戳破的气球 k
                for k in range(i + 1, j):
                    dp[i][j] = max(
                        dp[i][j],
                        dp[i][k] + dp[k][j] + nums[i] * nums[k] * nums[j]
                    )

        return dp[0][n - 1]
```

## 示例推演

以 `nums = [3, 1, 5, 8]` 为例，补上虚拟气球后 `a = [1, 3, 1, 5, 8, 1]`（下标 0~5），`dp` 是一张 6×6 的表。

按区间长度 `span = j - i` 从 2 填到 5，每个格子展开所有 `k` 的候选值（`dp[i][k]`、`dp[k][j]` 取前面已经填好的格子）：

| 区间 `(i, j)` | `span` | 各 `k` 的候选值 | `dp[i][j]` | 最后戳的 `k` |
|---|---|---|---|---|
| (0,2) | 2 | k=1: `0 + 0 + 1×3×1 = 3` | 3 | 1 |
| (1,3) | 2 | k=2: `0 + 0 + 3×1×5 = 15` | 15 | 2 |
| (2,4) | 2 | k=3: `0 + 0 + 1×5×8 = 40` | 40 | 3 |
| (3,5) | 2 | k=4: `0 + 0 + 5×8×1 = 40` | 40 | 4 |
| (0,3) | 3 | k=1: `0 + 15 + 1×3×5 = 30`；k=2: `3 + 0 + 1×1×5 = 8` | 30 | 1 |
| (1,4) | 3 | k=2: `0 + 40 + 3×1×8 = 64`；k=3: `15 + 0 + 3×5×8 = 135` | 135 | 3 |
| (2,5) | 3 | k=3: `0 + 40 + 1×5×1 = 45`；k=4: `40 + 0 + 1×8×1 = 48` | 48 | 4 |
| (0,4) | 4 | k=1: `0 + 135 + 1×3×8 = 159`；k=2: `3 + 40 + 1×1×8 = 51`；k=3: `30 + 0 + 1×5×8 = 70` | 159 | 1 |
| (1,5) | 4 | k=2: `0 + 48 + 3×1×1 = 51`；k=3: `15 + 40 + 3×5×1 = 70`；k=4: `135 + 0 + 3×8×1 = 159` | 159 | 4 |
| (0,5) | 5 | k=1: `0 + 159 + 1×3×1 = 162`；k=2: `3 + 48 + 1×1×1 = 52`；k=3: `30 + 40 + 1×5×1 = 75`；k=4: `159 + 0 + 1×8×1 = 167` | **167** | 4 |

最终 `dp[0][5] = 167`，对应「最后戳下标 4 的 `8`」。

把「最后戳」这条链顺着拆开，还能还原出具体顺序：

- 全局最后是 `8`（`k = 4`），它左边是 `dp[0][4] = 159`、右边是空区间；
- `dp[0][4]` 的最后是 `3`（`k = 1`），左边空、右边是 `dp[1][4] = 135`；
- `dp[1][4]` 的最后是 `5`（`k = 3`），右边是 `dp[3][4] = 0`、左边是 `dp[1][3] = 15`；
- `dp[1][3]` 的最后是 `1`（`k = 2`）。

所以顺序是 `1 → 5 → 3 → 8`，收益依次为 `3×1×5 = 15`、`3×5×8 = 120`、`1×3×8 = 24`、`1×8×1 = 8`，合计 `167` —— 与题面解释里的 `15 + 120 + 24 + 8` 完全一致。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 枚举戳破顺序 | O(n!) | O(n) | 每种顺序都要重算一遍邻居 |
| 记忆化递归 | O(n^3) | O(n^2) | 状态 O(n^2) 个、每个枚举 O(n) 个 k，递归栈另算 O(n) |
| 区间 DP（最优） | O(n^3) | O(n^2) | 同上，但没有递归开销 |

> `n` 是补完虚拟气球之后的长度（原长 + 2），只差常数。

## 易错点总结

1. **按 `i`、`j` 递增填表，而不是按区间长度**：写成 `for i in range(n): for j in range(i + 2, n)` 时，`dp[k][j]`（`k > i` 的行）还没算，恒为 0，转移退化成「只算右边空区间」。示例 1 会返回 `63` 而不是 `167`。
2. **`n` 在补虚拟气球之前取**：`n = len(nums)` 写在 `nums = [1] + nums + [1]` 之前，区间枚举就少掉最长的那几段，示例 1 返回 `30`、`nums = [1,5]` 返回 `0`。
3. **记忆化边界写成 `i == j`**：`i + 1 == j`（区间里只剩一个空档）时 `range(i + 1, j)` 是空的，`max()` 直接抛 `ValueError: max() arg is an empty sequence`。边界必须是 `i + 1 >= j`。

## 扩展思考

- **同一形状的题**：1000 题「合并石头」把「最后一个被戳」换成「最后一次合并」，转移式一样，只是代价是整段石子之和（要前缀和）。看到「最后一次操作把区间分成两半」就该想到区间 DP。
- **为什么不用「第一个戳谁」做状态**：那样必须记住「当前还剩哪些气球」，状态数是指数的；「最后一个」只依赖两个边界，才把状态压到 `O(n^2)`。这是区间 DP 里最值得记住的一次视角翻转。
