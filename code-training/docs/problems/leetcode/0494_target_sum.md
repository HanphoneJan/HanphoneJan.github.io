# 494. 目标和

## 题目描述

给你一个非负整数数组 `nums` 和一个整数 `target` 。

向数组中的每个整数前添加 `'+'` 或 `'-'` ，然后串联起所有整数，可以构造一个 **表达式** ：

例如，`nums = [2, 1]` ，可以在 `2` 之前添加 `'+'` ，在 `1` 之前添加 `'-'` ，然后串联起来得到表达式 `+2-1` 。

返回可以通过上述方法构造的、运算结果等于 `target` 的不同 **表达式** 的数目。

## 示例

**示例 1：**
```
输入：nums = [1,1,1,1,1], target = 3
输出：5
解释：
-1+1+1+1+1 = 3
+1-1+1+1+1 = 3
+1+1-1+1+1 = 3
+1+1+1-1+1 = 3
+1+1+1+1-1 = 3
```

**示例 2：**
```
输入：nums = [1], target = 1
输出：1
```

## 解题思路

### 符号选择与下标子集是一一对应的

给每个 `nums[i]` 挑一个符号，等价于先把一批下标放进「正号组」，其余进「负号组」。设两组的和分别是 `P`、`N`：

```text
P - N = target
P + N = sum(nums)
```

两式相加得 `P = (sum(nums) + target) / 2`。于是**表达式的个数 = 下标子集里和为 `P` 的子集个数**：每个子集对应一种「哪些位置带正号」的选法，反过来也一样。这一步把「挑符号」换成了「挑子集和」，问题才落到背包上。

`P` 有两条硬性要求，不满足直接返回 0：

- `P` 必须是非负整数 —— `sum(nums) + target` 为奇数时 `P` 是小数；
- `|target|` 不能超过 `sum(nums)`，否则连「全部同号」都凑不出来。

还有一步常被跳过：把子集换成它的补集，和就从 `P` 变成 `N = sum(nums) - P`，而「和为 `P` 的子集」与「和为 `N` 的子集」通过取补集一一对应，个数相同。所以背包容量可以取两者中较小的那个，即 `(sum(nums) - |target|) / 2`。完整代码里的 `m` 就是这个数，**不是 `P`**：示例 1 里 `P = 4`、`N = 1`，代码的容量是 1。`target` 为负时 `P`、`N` 互换，`abs(target)` 让同一个式子继续成立。

也就是说，代码注释里那句「使和为 `P` 的方案数」是对的，只是它实际跑的容量是 `N` —— 两个数算出来的答案一样，取小的那个更省时间和空间。

### 方法一：枚举 2^n 种符号组合

`n ≤ 20`，`2^20 ≈ 10^6`，直接枚举是能过的最小改动：

```python
from typing import List

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        n = len(nums)

        def dfs(i: int, rest: int) -> int:
            if i == n:
                return int(rest == 0)      # 用完所有数且正好凑齐，才算一种
            return dfs(i + 1, rest - nums[i]) + dfs(i + 1, rest + nums[i])

        return dfs(0, target)
```

`rest` 是「还需要凑出的值」，每层分正负两支、两种选择的答案相加，就是枚举本身。好处是不需要任何转换，`target` 为负也照跑；代价是 `n` 每加一，调用次数翻倍，而数据范围一旦变大就不成立了。

### 方法二：记忆化（把 `rest` 一起当状态）

枚举慢在重复：走到第 `i` 个数时，`rest` 只取决于前 `i` 个数的符号和。不同的符号组合只要和相同，后面的分支就完全一样。加一行 `@cache` 即可：

```python
from functools import cache
from typing import List

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        n = len(nums)

        @cache
        def dfs(i: int, rest: int) -> int:
            if i == n:
                return int(rest == 0)
            return dfs(i + 1, rest - nums[i]) + dfs(i + 1, rest + nums[i])

        return dfs(0, target)
```

状态数上界是 `n × (2 × sum(nums) + 1)`，实际可达的远少于这个数。空间就是缓存条目数，递归深度只有 `n`。它比「先做数学转换再背包」更容易写对：不需要考虑奇偶、越界这些前提，`target` 是正是负都不影响。

### 方法三：0/1 背包计数

`f[c]` = 用已经处理过的那些数，凑出和 `c` 的**下标子集个数**。初始化 `f[0] = 1`（空集），其余为 0；每读一个 `x`，把容量从大到小更新 `f[c] += f[c - x]`。

三处细节都能对应到代码：

- **倒序**：`f[c - x]` 必须是「加入 `x` 之前」的方案数。正序时 `f[c - x]` 可能刚被同一个 `x` 更新过，等于允许 `x` 被用第二次，数量会明显偏大。
- **加法而不是取较大值**：这是计数题。每个旧的 `f[c - x]` 方案后面接上 `x`，都是一个全新的、和为 `c` 的方案，所以要累加。
- **`f[0] = 1`**：什么都不选也算一种方案。漏掉它，整张表永远是 0。

`x = 0` 不用特判：`range(m, -1, -1)` 会更新到 `c = 0`，`f[0] += f[0]` 正好让方案数翻倍 —— 一个 0 既可以放正号组也可以放负号组，本来就是两种表达式。最后返回 `f[m]`。

```python
from typing import List

class Solution:
    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        s = sum(nums) - abs(target)
        if s < 0 or s % 2:                  # |target| 超过总和，或 P 不是整数
            return 0

        m = s // 2                          # 容量取 P、N 中较小的那个
        f = [1] + [0] * m                   # f[c] = 和为 c 的下标子集数

        for x in nums:
            for c in range(m, x - 1, -1):   # 倒序：每个下标只用一次
                f[c] += f[c - x]

        return f[m]
```

## 完整代码实现

```python
from typing import List


class Solution:
    """
    目标和 - 0/1背包问题

    正号部分和 P = (target + sum(nums)) / 2
    问题转化为：从nums中选若干个数，使和为P的方案数

    时间复杂度：O(n * m)
    空间复杂度：O(m)
    """

    def findTargetSumWays(self, nums: List[int], target: int) -> int:
        s = sum(nums) - abs(target)
        if s < 0 or s % 2:
            return 0

        m = s // 2  # 背包容量
        f = [1] + [0] * m  # f[c]表示凑出和c的方案数

        for x in nums:
            # 倒序遍历，避免重复计算（0/1背包）
            for c in range(m, x - 1, -1):
                f[c] += f[c - x]

        return f[m]
```

## 示例推演

以 `nums = [1,1,1,1,1]`、`target = 3` 为例。

先算容量：`sum = 5`，`P = (5 + 3) / 2 = 4`，`N = 5 - 4 = 1`，取较小的 `m = 1`（代码里 `s = 5 - 3 = 2`，`m = s // 2 = 1`）。所以它数的是「和为 1 的子集」。

`f = [1, 0]`，逐个数更新（`x = 1` 时只更新 `c = 1`）：

| 处理到 | `x` | `f[0]` | `f[1]` | 说明 |
|---|---|---|---|---|
| 初始 | — | 1 | 0 | 空集凑出 0 |
| 第 1 个 1 | 1 | 1 | 1 | `f[1] += f[0]` |
| 第 2 个 1 | 1 | 1 | 2 | `f[1] += f[0]` |
| 第 3 个 1 | 1 | 1 | 3 | 同上 |
| 第 4 个 1 | 1 | 1 | 4 | 同上 |
| 第 5 个 1 | 1 | 1 | 5 | 同上 |

`f[1] = 5`：五个下标各自单独成集，正好对应「哪一个数带负号」的五种选法，与示例列出的五个表达式一一对应。

再看一组容量更大的：`nums = [1,2,3]`、`target = 0`。`sum = 6`，`P = N = 3`，`m = 3`，`f = [1,0,0,0]`。

| 处理到 | `x` | 更新 | `f` |
|---|---|---|---|
| 初始 | — | — | `[1,0,0,0]` |
| 1 | 1 | `f[1] += f[0]` | `[1,1,0,0]` |
| 2 | 2 | `f[3] += f[1]`、`f[2] += f[0]` | `[1,1,1,1]` |
| 3 | 3 | `f[3] += f[0]` | `[1,1,1,2]` |

`f[3] = 2`，两个子集是 `{3}` 与 `{1,2}`，对应 `-1-2+3 = 0` 和 `+1+2-3 = 0` 两种表达式。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 枚举符号 | O(2^n) | O(n) | n ≤ 20 时约 10^6 次调用，能过 |
| 记忆化搜索 | O(n * R) | O(n * R) | R 为可达的和的个数，缓存 `(i, rest)` |
| 0/1 背包一维（最优） | O(n * m) | O(m) | m = (sum − \|target\|) / 2，不超过 sum / 2 |

> `n = len(nums)`；`sum ≤ 20000` 时 `m ≤ 10000`。

## 易错点总结

1. **漏掉 `if s < 0` 这一步**：`s = sum(nums) - abs(target)` 为负时 `m = s // 2 < 0`，`[1] + [0] * m` 仍然是 `[1]`，`return f[m]` 读到的是 `f[-1]`（Python 的负下标回绕到最后一个元素）→ 返回 1。`nums = [1]`、`target = 3` 会给出 1 而不是 0，没有任何报错。
2. **内层循环写成正序 `for c in range(x, m + 1)`**：同一个数被反复使用。`nums = [1,2,3]`、`target = 0` 会返回 3（多算了 `1+1+1`），正确是 2。
3. **容量下界写成 `range(m, x, -1)`**（少了那个 `-1`）：容量恰好等于 `x` 的那一格永远不会被更新。`nums = [1,3]`、`target = 2` 时 `m = 1`、`x = 1`，循环一次都不执行，返回 0，正确是 1（`3 - 1 = 2`）。

## 扩展思考

- **和 416 的区别只在「状态存什么」**：416 分割等和子集只问「能不能凑出」，`f` 是布尔数组，转移用 `or`；这里问「有几种凑法」，同一个 `f[c]` 换成计数、转移换成加法。1049 最后一块石头的重量 II 同理，只是最后多一步取绝对值。
- **零元素会让答案翻倍**：`nums` 里每个 0 都让最终答案乘 2，背包里的 `f[0] += f[0]` 自动完成了这件事；如果先手动把 0 过滤掉再去重，就会少算这一倍。
