# 0056. 合并区间

## 题目描述

以数组 `intervals` 表示若干个区间的集合，其中单个区间为 `intervals[i] = [starti, endi]` 。请你合并所有重叠的区间，并返回一个不重叠的区间数组，该数组需恰好覆盖输入中的所有区间。

## 示例

**示例 1：**
```
输入：intervals = [[1,3],[2,6],[8,10],[15,18]]
输出：[[1,6],[8,10],[15,18]]
解释：区间 [1,3] 和 [2,6] 重叠, 将它们合并为 [1,6]。
```

**示例 2：**
```
输入：intervals = [[1,4],[4,5]]
输出：[[1,5]]
解释：区间 [1,4] 和 [4,5] 可被视为重叠区间。
```

---

## 解题思路

### 输出是什么，以及「重叠」到底怎么判

输出是一组互不重叠、按左端点升序排列的区间，合起来恰好覆盖输入覆盖过的所有点。所以判据不是「有没有公共部分」这么宽松：题目把**端点相接**也算重叠，`[1,4]` 与 `[4,5]` 必须合并成 `[1,5]`。这一条直接决定了代码里比较用的是 `<=` 而不是 `<`。

### 为什么必须先按左端点排序

按左端点排好之后，两个区间 `[a,b]`、`[c,d]`（`a ≤ c`）重叠当且仅当 `c ≤ b`——一句话就能判。

不排序的话，一个新区间可能同时与已合并结果里的好几个重叠，也可能「插」在它们中间。按输入顺序处理 `[[1,2],[4,5],[0,3]]`：先收下 `[1,2]`，`[4,5]` 不重叠就追加，轮到 `[0,3]` 时只和最后一个 `[4,5]` 比（`0 ≤ 5`），合并成 `[0,5]`，结果 `[[1,2],[0,5]]`——两个区间自己还重叠着，根本不是合法答案（正确答案是 `[[0,5]]`）。

排序之后还有一条传递性，它才是「每轮只跟最后一个合并区间比」的依据：已合并的区间按左端点升序且互不重叠，所以若 `curr[0] > merged[-1][1]`，那么更早的那些区间的右端点都小于 `merged[-1]` 的左端点，更不可能碰到 `curr`。于是 `merged[-1]` 一行就够了，不需要回头检查前面。

排序还顺带解决了一件事：`curr[0] ≥ prev[0]` 恒成立，所以合并后的左端点不必修改，只需处理右端点。

### 排序后线性扫描

```python
from typing import List

class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        intervals.sort(key=lambda x: x[0])          # 按左端点排序，可能重叠的区间必然相邻
        merged = []
        for a, b in intervals:
            # 只和最后一个合并区间比：排序保证 curr 碰不到更早的区间
            if merged and a <= merged[-1][1]:
                merged[-1][1] = max(merged[-1][1], b)   # 右端点取较大者
            else:
                merged.append([a, b])
        return merged
```

三行各自对应一个决策：

- `intervals.sort(key=lambda x: x[0])`——只按左端点排，右端点不参与比较。这里是就地排序：`intervals` 是入参，排完之后调用方手里的顺序也变了；如果函数要保留原数组，就得换成 `intervals = sorted(intervals, key=...)`，多付一份 `O(n)` 副本。
- `if merged and a <= merged[-1][1]`——`merged` 的真值判断同时兜住了空输入和第一个区间，所以不需要额外写 `n <= 1` 的特判；`<=` 而不是 `<` 就是上面那条「端点相接算重叠」。
- `merged[-1][1] = max(merged[-1][1], b)`——不能写成 `= b`。`[1,5]` 与 `[2,3]` 合并时 `b = 3` 比现有右端点 5 小，直接覆盖会把区间截短成 `[1,3]`。

### 方法二：数端点，而不是比区间

同一件事可以换个视角：每个区间拆成两个事件，`(a, +1)` 表示进入、`(b, -1)` 表示离开，按坐标排序后扫描，深度从 0 变 1 的地方是某个合并区间的起点，从 1 回到 0 的地方是终点。

```python
class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        events = []
        for a, b in intervals:
            events.append((a, 1))
            events.append((b, -1))
        # 同一坐标上先处理 +1 再处理 -1：这样 [1,4] 与 [4,5] 在 4 处是「交接」而不是「断开」
        events.sort(key=lambda e: (e[0], -e[1]))

        res, depth, start = [], 0, 0
        for x, d in events:
            if depth == 0:
                start = x
            depth += d
            if depth == 0:
                res.append([start, x])
        return res
```

两种写法的复杂度一样（都是排序主导的 `O(n log n)`），差别在常量和用途：

- 事件版要排 `2n` 个元素、维护 `depth` 和 `start`，常数更大，输出还得自己拼 `[start, x]`；
- 但它是扫描线的通用形态——`depth` 的历史最大值就是「同一时刻最多几个区间重叠」（253 会议室 II 要的正是这个数），排序 + 合并的那一版给不出这个信息。

所以合并区间本身用第一种更直接；需要「重叠层数」时才值得掏事件版。另外要注意 `-e[1]` 这个 tie-break 不能省：按 `(x, e[1])` 排会让 `-1` 排在 `+1` 前面，`[1,4]` 与 `[4,5]` 被切成两个区间。

## 完整代码实现

下面这份与上面同构，差别只有两处：`merged` 直接用 `intervals[0]` 起步、空输入和单区间靠 `n <= 1` 提前返回。由于它之后用 `prev[1] = max(...)` 改的就是那个列表对象，入参里的第一个区间也会被改写——本题不要求保留入参，所以没有影响。

```python
from typing import List

class Solution:
    def merge(self, intervals: List[List[int]]) -> List[List[int]]:
        """
        合并区间 - 贪心算法

        核心思想：按左端点排序，维护当前合并区间
        """
        # 按左端点排序（关键步骤）
        intervals.sort(key=lambda x: x[0])
        n = len(intervals)

        if n <= 1:
            return intervals

        merged = [intervals[0]]  # 初始化 merged 为第一个区间

        for curr in intervals[1:]:
            prev = merged[-1]  # 上一个合并后的区间

            # 检查是否重叠：当前区间的左端点 <= 上一个区间的右端点
            if curr[0] <= prev[1]:
                # 重叠，合并区间：更新右端点为两者的最大值
                prev[1] = max(prev[1], curr[1])
            else:
                # 不重叠，添加新区间
                merged.append(curr)

        return merged
```

## 示例推演

**`intervals = [[1,3],[2,6],[8,10],[15,18]]`**，排序后顺序不变。

`merged` 初始为 `[[1,3]]`。

| 轮次 | `curr` | `prev` | `curr[0] <= prev[1]` | 操作 | `merged` |
|---|---|---|---|---|---|
| 1 | `[2,6]` | `[1,3]` | `2 <= 3` 成立 | `prev[1] = max(3, 6) = 6` | `[[1,6]]` |
| 2 | `[8,10]` | `[1,6]` | `8 <= 6` 不成立 | 追加 | `[[1,6],[8,10]]` |
| 3 | `[15,18]` | `[8,10]` | `15 <= 10` 不成立 | 追加 | `[[1,6],[8,10],[15,18]]` |

返回 `[[1,6],[8,10],[15,18]]`。

**`intervals = [[1,4],[4,5]]`**：`merged = [[1,4]]`，`curr = [4,5]` 时 `4 <= 4` 成立（等号是关键），合并成 `[1, max(4,5)] = [1,5]`。

**`intervals = [[1,5],[2,3]]`**：`curr = [2,3]` 与 `[1,5]` 重叠，`max(5, 3) = 5`，结果仍是 `[1,5]`——后一个区间更短，但它不能把 `[1,5]` 的右端点截短。

**空输入 `[]`**：`n = 0`，`if n <= 1` 直接返回 `intervals`，也就是 `[]`；单区间 `[[5,9]]` 走同一个分支原样返回。

事件扫描在同一组样例上的过程（`[1,3],[2,6],[8,10],[15,18]`）：

| 事件 | `depth` 变化 | 动作 |
|---|---|---|
| `(1, +1)` | 0 → 1 | `start = 1` |
| `(2, +1)` | 1 → 2 | 无 |
| `(3, -1)` | 2 → 1 | 无 |
| `(6, -1)` | 1 → 0 | 收一个区间 `[1,6]` |
| `(8, +1)` | 0 → 1 | `start = 8` |
| `(10, -1)` | 1 → 0 | 收 `[8,10]` |
| `(15, +1)` | 0 → 1 | `start = 15` |
| `(18, -1)` | 1 → 0 | 收 `[15,18]` |

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 排序 + 线性扫描（最优） | O(n log n) | O(n) | 排序主导扫描；只跟最后一个合并区间比较 |
| 端点事件扫描 | O(n log n) | O(n) | 要排 `2n` 个事件，但能顺带算出最大重叠层数 |

## 易错点总结

1. **重叠判断写成 `curr[0] < prev[1]`**：`[1,4]` 与 `[4,5]` 判成不重叠，返回两个区间 `[[1,4],[4,5]]` 而不是一个 `[[1,5]]`。端点相接在本题算重叠，必须用 `<=`。
2. **右端点写成 `prev[1] = curr[1]`**：`[1,5]` 与 `[2,3]` 会合并成 `[1,3]`，覆盖范围变小；这类「后一个区间被前一个包含」的输入在示例里没有，容易漏测。
3. **排序键写成 `key=lambda x: x[1]`（按右端点）**：上面的传递性立刻失效。`[[2,3],[1,5]]` 排完是 `[[2,3],[1,5]]`，合并成 `[2,5]`——左端点 1 被丢掉，正确答案是 `[[1,5]]`。
