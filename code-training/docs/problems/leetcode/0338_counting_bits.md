# 338. 比特位计数

## 题目描述

给定整数 `n`，返回长度为 `n + 1` 的数组 `ans`，其中 `ans[i]` 是 `i` 的二进制表示里 `1` 的个数（`0 ≤ i ≤ n`）。

## 示例

### 示例 1

**输入：** n = 2
**输出：** [0,1,1]
**解释：** `0 = 0`、`1 = 1`、`2 = 10`。

### 示例 2

**输入：** n = 5
**输出：** [0,1,1,2,1,2]
**解释：** `0..5` 的二进制分别是 `0`、`1`、`10`、`11`、`100`、`101`。

## 解题思路

### 路线：每个 i 都能从更小的数「借」答案

单独数一个数要 `O(log n)`，n 个数就是 `O(n log n)`。要降到 `O(n)`，就不能每个数都从头数，而要找一条把 `bits[i]` 接到某个更小下标上的关系。

三种关系都能成立，区别只在「从 i 里拿掉哪一位」：

- 拿掉最低位：`bits[i >> 1]` 已经算过，再把被拿掉的 `i & 1` 加回来；
- 拿掉最低的那个 `1`：`i & (i - 1)` 一定更小；
- 拿掉最高位：`i - highBit` 落在 `[0, highBit)` 里，也一定更小。

三条都是「大下标依赖小下标」，所以按 `i` 从小到大填一遍即可。

### 手法一：右移一位，再补最低位

`i >> 1` 是 `i` 去掉最低位，二进制里剩下的 `1` 的个数不变；被拿掉的那一位如果是 `1`，就再补一个：

$$
\text{bits}[i] = \text{bits}[i \gg 1] + (i \mathbin{\&} 1)
$$

```python
bits = [0] * (n + 1)
for i in range(1, n + 1):
    bits[i] = bits[i >> 1] + (i & 1)
```

`i >> 1 < i` 对一切 `i ≥ 1` 成立，所以循环从小到大时，右边那格一定已经填好。偶数的 `i & 1` 是 0，奇数是 1；这一行同时覆盖了「偶数与 i/2 相同」「奇数比 i-1 多一个 1」两条规律。

### 手法二：清除最低位的 1

`i & (i - 1)` 把 `i` 最低位的那个 `1` 抹掉，所以它比 `i` 少一个 `1`：

$$
\text{bits}[i] = \text{bits}[i \mathbin{\&} (i - 1)] + 1
$$

```python
bits = [0] * (n + 1)
for i in range(1, n + 1):
    bits[i] = bits[i & (i - 1)] + 1
```

这个写法的好处是不用判断奇偶，坏处是它**必须从 `i = 1` 开始**：`i = 0` 时 `0 & -1` 还是 0，会把 `bits[0]` 写成 1，后面整串跟着错。

### 手法三：按最高有效位分组

设 `highBit` 是不超过 `i` 的最大 2 的幂。`i` 与 `i - highBit` 只差最高位那一个 `1`：

$$
\text{bits}[i] = \text{bits}[i - \text{highBit}] + 1
$$

```python
bits = [0] * (n + 1)
high = 0
for i in range(1, n + 1):
    if i & (i - 1) == 0:      # i 是 2 的幂
        high = i
    bits[i] = bits[i - high] + 1
```

`i & (i - 1) == 0` 是「i 只有一位 1」的判据，所以每跨过一个 2 的幂就更新 `high`。`i - high` 落在 `[0, high)`，属于已经填过的区间。

### 推演：`n = 5`

| `i` | 二进制 | `i >> 1` | `i & 1` | `bits[i >> 1]` | `bits[i]` |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | — | — | — | 0 |
| 1 | 1 | 0 | 1 | 0 | 1 |
| 2 | 10 | 1 | 0 | 1 | 1 |
| 3 | 11 | 1 | 1 | 1 | 2 |
| 4 | 100 | 2 | 0 | 1 | 1 |
| 5 | 101 | 2 | 1 | 1 | 2 |

结果 `[0,1,1,2,1,2]`。换成手法二看 `i=3`：`3 & 2 = 2`，`bits[2] + 1 = 2`；手法三看 `i=5`：`high=4`，`bits[1] + 1 = 2`，三条路殊途同归。

## 完整代码实现

```python
from typing import List


class Solution:
    def countBits(self, n: int) -> List[int]:
        bits = [0] * (n + 1)
        for i in range(1, n + 1):
            # 去掉最低位后 1 的个数不变，再把被去掉的那一位补回来
            bits[i] = bits[i >> 1] + (i & 1)
        return bits
```

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 每个数逐位统计 | O(n log n) | O(1) | 每个 `i` 都要扫过它的全部二进制位 |
| 右移递推（最优） | O(n) | O(1) | 每个 `i` 一次查表加一次位与；空间不计返回数组 |
| 清除最低位 / 最高位递推 | O(n) | O(1) | 同样是每个 `i` 常数次位运算 |

空间里的 `O(1)` 都不计长度为 `n + 1` 的返回数组，那是题目要求的输出本身。

## 易错点总结

### 1. 清除最低位的版本从 `i = 0` 开始循环

`for i in range(n + 1)` 会让 `i = 0` 执行 `bits[0] = bits[0 & -1] + 1 = 1`，把起点的 0 写成 1。`n = 1` 的输出从 `[0,1]` 变成 `[1,2]`，后面每个数都跟着多 1。这个版本必须写 `range(1, n + 1)`。

### 2. 最高位版本忘了在 2 的幂处更新 `high`

`if i & (i - 1) == 0: high = i` 这一行漏掉后，`high` 会一直是 0，`bits[i - high]` 就是 `bits[i]` 自己——读到的还是当前格里的初始 0，于是每个 `i` 都只得到 1。`n = 2` 时结果 `[0,1,1]` 恰好与正确答案相同，看不出来；`n = 5` 才暴露：得到 `[0,1,1,1,1,1]`，而正确答案是 `[0,1,1,2,1,2]`。

### 3. 右移版本把 `(i & 1)` 写成固定的 `1`

`bits[i] = bits[i >> 1] + 1` 让每个 `i ≥ 1` 都多算一个 1。`n = 2` 得 `[0,1,2]`，而 `2 = 10` 只有 1 个 1。偶数的最低位是 0，这一项必须是 `i & 1` 而不是常量。

## 扩展思考

- **数单个数的 1**：191 题。`while x: x &= x - 1; cnt += 1` 的循环次数等于 1 的个数，比逐位右移更快。
- **两数二进制不同的位数**：461 题。先异或，再对结果做本题的计数。
- **n 很大时**：`bits` 数组本身要 `O(n)` 内存，若只查询个别数，直接 `int.bit_count()`（Python 3.10+）即可，不必整表预处理。
