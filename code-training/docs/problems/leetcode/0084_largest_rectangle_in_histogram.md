# 84. 柱状图中最大的矩形

## 题目描述

给定 n 个非负整数，用来表示柱状图中各个柱子的高度。每个柱子彼此相邻，且宽度为 1 。

求在该柱状图中，能够勾勒出来的矩形的最大面积。

## 示例

**示例 1：**
```
输入：heights = [2,1,5,6,2,3]
输出：10
解释：最大的矩形为图中红色区域，面积为 10
```

**示例 2：**
```
输入：heights = [2,4]
输出：4
```

## 解题思路

### 换一个枚举对象：不枚举区间，枚举「最矮的那根柱子」

矩形由高和左右边界决定，但这两样都不自由 —— 只要知道矩形里最矮的柱子是谁，它们同时确定：

- 高不会超过区间内最矮的柱子；把上边缘抬到那根柱子的顶部，面积只增不减。所以**最优矩形的上边缘一定贴着某根柱子的顶部**，高度就是某个 `heights[i]`。
- 高度锁定成 `heights[i]` 之后，左右各只能扩到「第一根比它矮的柱子」为止，再往外一步就撑不住了。

于是每个下标 `i` 恰好对应一个候选答案：

```text
以 i 为最矮柱：  heights[i] × (右边第一个更矮的下标 - 左边第一个更矮的下标 - 1)
```

枚举 `i` 只有 `n` 个候选，剩下的事就是「对每个 `i` 求左右第一个更矮的位置」，也就是**下一个更小元素**。

对照暴力：枚举所有区间是 `O(n²)` 个，每个区间还要扫一遍才知道最矮柱是谁，`O(n³)`（预处理区间最小值表能降到 `O(n²)`，但那张表本身要 `O(n²)` 空间）。**换掉枚举对象，复杂度就从平方掉到线性** —— 这是本题的核心，后面两种写法只是「怎么求这两个边界」的不同做法。

### 单调栈：弹出栈顶的那一刻，左右边界同时到手

维护一个装**下标**的栈，栈内柱子高度单调不降。扫描到 `i` 时：

- 若 `heights[i]` 比栈顶矮，那栈顶柱子的**右边界就是 `i`** —— 它是右边第一根比栈顶矮的柱子；
- 把它弹掉之后，新的栈顶就是它**左边第一根更矮的柱子** —— 比它矮的一直留在栈里没被动过，比它高的早被弹走了。

所以同一个 `while` 迭代里，两个边界都拿到了。每根柱子进栈一次、出栈一次，总代价 `O(n)`。

实现上有两处便利处理：

1. **首尾各加一个高度 0 的哨兵**。首哨兵让「弹到栈空」不可能发生，结算时 `stack[-1]` 永远存在，宽度公式不必特判；尾哨兵负责在扫描结束时把栈里剩下的柱子全部结算 —— 没有它，那些一路递增的柱子直到循环结束都没算过面积。
2. **弹出条件用 `>`，不用 `>=`**。等高的柱子不弹，一起留在栈里：弹出右边那根等高柱时，栈顶是它的等高兄弟，算出的宽度偏小；最后弹出最左边那根时，栈顶才是严格更矮的柱子，宽度才完整。等高柱的矩形范围一模一样，只要有一根算到完整宽度，`max` 就不会漏答案。

```python
from typing import List

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        heights = [0] + heights + [0]        # 首尾哨兵
        stack = []                            # 下标栈，栈内高度单调不降
        max_area = 0

        for i in range(len(heights)):
            # 当前柱子比栈顶矮 -> 栈顶柱子的右边界确定
            while stack and heights[stack[-1]] > heights[i]:
                h = heights[stack.pop()]      # 被弹出的这根就是「最矮柱」
                width = i - stack[-1] - 1     # 栈顶已是左边第一个更矮的
                max_area = max(max_area, h * width)
            stack.append(i)

        return max_area
```

对着上面的分析读代码里的三处：`heights[stack.pop()]` 是「枚举最矮柱」，`i` 是右边界，`stack[-1]` 是左边界，`width` 就是两者之间的柱数。

### 换成两个数组：左右各扫一遍，把边界存起来

如果「弹出的一瞬间同时算两个边界」不好在脑子里跟踪，可以拆成两个直白的 pass：从左往右求 `left[i]`，从右往左求 `right[i]`，最后统一算面积。栈的作用完全一样，只是不急着结算。

```python
from typing import List

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        n = len(heights)

        left = [-1] * n                  # 左边第一个更矮的下标，没有则 -1
        stack = []
        for i in range(n):
            while stack and heights[stack[-1]] >= heights[i]:
                stack.pop()              # 弹走不比自己矮的，留下来的才是边界
            left[i] = stack[-1] if stack else -1
            stack.append(i)

        right = [n] * n                  # 右边第一个更矮的下标，没有则 n
        stack = []
        for i in range(n - 1, -1, -1):
            while stack and heights[stack[-1]] >= heights[i]:
                stack.pop()
            right[i] = stack[-1] if stack else n
            stack.append(i)

        return max(heights[i] * (right[i] - left[i] - 1) for i in range(n))
```

同样是 `O(n)`，但多一个长度为 `n` 的 `right` 数组、多一趟循环。换来的是**每个下标的含义写在数组名里**，不用在脑子里维护「弹完之后栈里还剩什么」。调试和讲给别人听时省力得多。注意这里弹出条件改成了 `>=`：留下严格更矮的元素，边界语义才和 `left`/`right` 这两个名字对得上；等高的柱子每一根都能自己算到完整宽度，结论不变。

### 换成分治：以区间最矮柱为界

还有一个完全不靠栈的角度。对区间 `[lo, hi]`，答案只可能是三者之一：

- 跨过区间最矮柱 `m` 的矩形：高 `heights[m]`、宽覆盖整个区间；
- 完全落在 `[lo, m-1]` 里；
- 完全落在 `[m+1, hi]` 里。

递归取三者最大值即可，不需要任何额外数据结构。

```python
from typing import List

class Solution:
    def largestRectangleArea(self, heights: List[int]) -> int:
        def solve(lo: int, hi: int) -> int:
            if lo > hi:
                return 0
            m = min(range(lo, hi + 1), key=lambda k: heights[k])
            return max(
                heights[m] * (hi - lo + 1),   # 跨过最矮柱
                solve(lo, m - 1),             # 只在左边
                solve(m + 1, hi),             # 只在右边
            )

        return solve(0, len(heights) - 1)
```

思路最干净，代价全在「每次都要在区间里线性找最小值」：随机数据接近 `O(n log n)`，但**输入递增时最矮柱总在最左端**，递归退化成 `n` 层、每层扫一遍，直接变 `O(n²)`，而且 `n = 10^5` 时递归深度也撑不住。适合当思路对照，不适合提交。

### 三种写法怎么选

| 写法 | 时间 | 额外空间 | 什么时候用 |
|---|---|---|---|
| 单调栈（一次扫描） | O(n) | O(n) | 默认提交版本，栈里最多 `n` 个下标 |
| 左右各扫一遍 | O(n) | O(n) | 需要把边界数组留给别的逻辑，或想先读懂再背 |
| 分治 | 平均 O(n log n)，最坏 O(n²) | O(n) 递归栈 | 只作为思路对照 |

## 完整代码实现

```python
from typing import List

class Solution:
    """
    柱状图中最大的矩形 - 单调栈

    核心思想：
    对于每个柱子 heights[i]，如果能快速知道左侧第一个比它矮的位置 left[i]
    和右侧第一个比它矮的位置 right[i]，那么以 heights[i] 为高的最大矩形宽度
    就是 right[i] - left[i] - 1。

    单调栈的作用：
    维护一个单调递增的栈，栈中存储柱子的索引。
    当遇到比栈顶矮的柱子时，栈顶柱子的右边界就确定了。

    哨兵技巧：
    在数组首尾添加高度为0的哨兵，确保所有柱子都能被处理，且栈永不为空。

    与接雨水的区别：
    - 接雨水找两边第一个比它高的，用递减栈
    - 最大矩形找两边第一个比它矮的，用递增栈

    时间复杂度：O(n)
    空间复杂度：O(n)
    """

    def largestRectangleArea(self, heights: List[int]) -> int:
        # 首尾加哨兵0，确保所有柱子都能被处理，且栈永不为空
        heights = [0] + heights + [0]
        stack = []
        max_area = 0

        for i in range(len(heights)):
            # 当前柱子比栈顶矮，栈顶柱子的右边界确定
            while stack and heights[stack[-1]] > heights[i]:
                h = heights[stack.pop()]  # 栈顶柱子的高度
                # 此时栈顶是左边第一个小于h的柱子索引
                width = i - stack[-1] - 1
                max_area = max(max_area, h * width)
            stack.append(i)

        return max_area
```

## 示例推演

以 `heights = [2,1,5,6,2,3]` 为例。加上首尾哨兵后，数组变成下标 `0..7` 的 `[0,2,1,5,6,2,3,0]`（原来的 `heights[i]` 现在在 `i+1` 的位置）。

逐轮看栈的变化与结算：

| `i` | `heights[i]` | 动作 | 弹栈结算 | 栈（下标） | `max_area` |
|---|---|---|---|---|---|
| 0 | 0 | 栈空，直接入栈 | — | `[0]` | 0 |
| 1 | 2 | 比栈顶高，入栈 | — | `[0,1]` | 0 |
| 2 | 1 | 弹出 1 | `h=2`，宽 `2-0-1=1`，面积 2 | `[0,2]` | 2 |
| 3 | 5 | 入栈 | — | `[0,2,3]` | 2 |
| 4 | 6 | 入栈 | — | `[0,2,3,4]` | 2 |
| 5 | 2 | 弹出 4、3 | `h=6`，宽 `5-3-1=1`，面积 6；`h=5`，宽 `5-2-1=2`，面积 10 | `[0,2,5]` | 10 |
| 6 | 3 | 入栈 | — | `[0,2,5,6]` | 10 |
| 7 | 0 | 弹出 6、5、2 | `h=3`，宽 `7-5-1=1`，面积 3；`h=2`，宽 `7-2-1=4`，面积 8；`h=1`，宽 `7-0-1=6`，面积 6 | `[0,7]` | 10 |

答案是 10，出现在 `i = 5` 这一轮：弹出下标 3（高 5）时，右边界是下标 5（高 2，第一根比 5 矮的），左边界是弹完之后露出的栈顶下标 2（高 1），宽度 `5-2-1 = 2` 对应原数组的下标 3、4 两根柱子 —— 就是 `5` 和 `6` 这两根，`5 × 2 = 10`。

再看两个边界情况：

- `heights = [2,4]`：一直递增，两根柱子都不会在中途被弹，直到尾哨兵（下标 3）才依次结算。高 4 宽 1 得 4，高 2 宽 2 得 4，答案 4 —— 正是示例 2。
- `heights = [2,2]`：加哨兵后 `[0,2,2,0]`。`i=2` 时栈顶等高不满足 `>`，不弹；`i=3`（尾哨兵）才弹出下标 2，此时栈顶是下标 1（等高），宽度只有 1；再弹出下标 1，栈顶是下标 0（严格更矮），宽度 `3-0-1=2`，面积 4。等高柱里只有最左边那根算到完整宽度，答案不受影响。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 枚举区间（暴力） | O(n³) | O(1) | 每个区间再扫一遍求最矮柱；预处理最小值表可降到 O(n²)，但要 O(n²) 空间 |
| 单调栈（最优） | O(n) | O(n) | 每根柱子进栈、出栈各一次 |
| 左右各扫一遍 | O(n) | O(n) | 同样是单调栈，多一趟循环与一个边界数组 |
| 分治 | 平均 O(n log n)，最坏 O(n²) | O(n) | 输入递增时最矮柱总在最左端，退化成链 |

> `n = len(heights)`。

## 易错点总结

1. **`width` 必须在 `pop()` 之后算**：先取 `width = i - stack[-1] - 1` 再 `stack.pop()`，`stack[-1]` 还是被弹的那根柱子自己，宽度恒偏小；`[2,1,5,6,2,3]` 会返回 5 而不是 10。
2. **首哨兵不能省**：只写 `heights + [0]` 时，扫到下标 1（高度 1）就要弹出高度 2 的柱子，弹出后栈空，`stack[-1]` 直接抛 `IndexError: list index out of range`。
3. **宽度公式的 `- 1` 少写一位**：写成 `h * (i - stack[-1])`，每根柱子的跨度都被多算一格，示例 1 返回 15 而不是 10。
