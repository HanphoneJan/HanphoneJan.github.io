# 947. 移除最多的同行或同列石头

## 题目描述

`n` 块石头放置在二维平面中的一些整数坐标点上。每个坐标点上最多只能有一块石头。

如果一块石头的 **同行或者同列** 上有其他石头存在，那么就可以移除这块石头。

给你一个长度为 `n` 的数组 `stones`，其中 `stones[i] = [x_i, y_i]` 表示第 `i` 块石头的位置，返回 **最多** 可以移除的石头个数。

**示例 1：**

```
输入：stones = [[0,0],[0,1],[1,0],[1,2],[2,1],[2,2]]
输出：5
解释：一种移除 5 块石头的方法如下所示：
1. 移除石头 [2,2]，因为它和 [2,1] 同列
2. 移除石头 [2,1]，因为它和 [0,1] 同行
3. 移除石头 [1,2]，因为它和 [1,0] 同列
4. 移除石头 [1,0]，因为它和 [0,0] 同行
5. 移除石头 [0,1]，因为它和 [0,0] 同列
剩下的石头是 [0,0]。
```

**示例 2：**

```
输入：stones = [[0,0],[0,2],[1,1],[2,0],[2,2]]
输出：3
解释：移除 [2,2]、[2,0] 和 [0,2] 这三块石头之后，剩下两块石头 [0,0] 和 [1,1]。
```

**提示：**

- `1 <= stones.length <= 1000`
- `0 <= x_i, y_i <= 10^4`
- `stones` 中每个点都不相同

## 解题思路

### 判定标准：能删几块，取决于「石头之间怎么连」

「同行或同列还有别的石头」这句话等价于：这块石头在下面这张图里有邻居 ——

- 顶点是一块块石头；
- 两块石头同行或同列，就连一条边。

一块石头能删，当且仅当它当前还有邻居。于是问题变成：在这张图上，最多能按顺序删掉多少个顶点，且每次删的顶点都还有邻居。

**关键结论：一个含 `k` 块石头的连通分量，最多删掉 `k-1` 块。**

- 至少留下 1 块：删到只剩 1 块时，它没有任何邻居，删不动了，所以不可能删掉全部 `k` 块。
- 恰好能删 `k-1` 块：取这个分量的一棵生成树，反复删掉树上的叶子。叶子在树里只有一个邻居，也就是它在原图里至少有一个邻居，删它合法；删掉之后剩下的树仍然连通，可以接着删。一路删到只剩 1 个节点，共删 `k-1` 次。

于是答案就是 `n - 连通分量个数`。剩下的工作只有一件：数分量。

### 为什么把「行」和「列」也当成顶点

按石头直接建图，要判断「任意两块石头是否同行同列」，最坏是 `O(n²)` 对。但这张图有个特殊结构：两块石头同行，是因为它们共享同一个**行号**；同列是因为共享同一个**列号**。

把行号、列号也提升成顶点，石头就变成一条边：

> 石头 `[x, y]` 就是一条连接「行 `x`」与「列 `y`」的无向边。

这个二分图（左边一排是行，右边一排是列）完整保留了石头的连通性：两块石头同行，它们的边共用同一个行顶点，于是连通；同列同理。石头的连通分量与行/列顶点的连通分量一一对应，所以数行/列图的连通块，就是在数石头的连通块。

### 方法一：石头当顶点，用哈希表把同行、同列的石头串起来

如果坚持按石头建图，也不必真的连出 `O(n²)` 条边：同一行的石头两两相连等于一张团，而团里的连通性用一条链就能表达 —— 让这一行里每块石头都连到这一行的**第一块**石头即可。

```python
from typing import List

class Solution:
    def removeStones(self, stones: List[List[int]]) -> int:
        n = len(stones)
        adj = [[] for _ in range(n)]
        first_in_row, first_in_col = {}, {}

        for i, (x, y) in enumerate(stones):
            if x in first_in_row:                  # 同行：连到这一行第一块
                j = first_in_row[x]
                adj[i].append(j)
                adj[j].append(i)
            else:
                first_in_row[x] = i
            if y in first_in_col:                  # 同列：连到这一列第一块
                j = first_in_col[y]
                adj[i].append(j)
                adj[j].append(i)
            else:
                first_in_col[y] = i

        comp, seen = 0, [False] * n
        for s in range(n):
            if seen[s]:
                continue
            comp += 1
            seen[s] = True
            stack = [s]
            while stack:
                u = stack.pop()
                for v in adj[u]:
                    if not seen[v]:
                        seen[v] = True
                        stack.append(v)
        return n - comp
```

边数是 `O(n)`：每块石头最多产生两条边（一条通向行首、一条通向列首）。这份代码的好处是**分量里的石头看得见** —— 如果题目改成「输出每个分量最终保留哪块」，在 DFS 里顺手记一下就行。

### 方法二：行/列当顶点，一次并查集

按上一节的结构，每块石头就是一次 `merge(行 x, 列 y)`。全部处理完之后，同一个分量里的行与列都挂在同一个根上，答案仍是 `n - 分量数`，只是分量数改成「这些石头落在几个不同的根上」。

```python
from typing import List

class Solution:
    def removeStones(self, stones: List[List[int]]) -> int:
        OFFSET = 10005                        # 列节点平移到行节点之后
        fa = list(range(2 * OFFSET))

        def find(x: int) -> int:
            while fa[x] != x:
                fa[x] = fa[fa[x]]
                x = fa[x]
            return x

        for x, y in stones:
            rx, ry = find(x), find(y + OFFSET)
            if rx != ry:
                fa[ry] = rx

        roots = {find(x) for x, _ in stones}
        return len(stones) - len(roots)
```

`OFFSET` 的作用是**把列号与行号放进互不重叠的两段下标**：行用 `0 … 10000`，列用 `10005 … 20005`。不加偏移，行 `3` 与列 `3` 就是同一个并查集节点，两块毫不相干的石头会被并到一起（见「易错点」第 1 条）。

`roots` 只收集行节点就够：每块石头都把它的行与列并到了一起，取任意一侧都能代表整个分量。

两种写法复杂度同阶（都是 `O(n)` 级别），选择看需要什么：

| 关注点 | 石头建图 + DFS | 行列并查集 |
|---|---|---|
| 额外结构 | 邻接表 `O(n)` 条边，加一个 `seen` | 一个 `2 × OFFSET` 的 `fa` 数组 |
| 能否取出分量成员 | 能，DFS 里直接记录 | 能，但要再遍历一次全部节点 |
| 坐标范围很大时 | 无影响，哈希表存 | 数组开不下，得先做坐标离散化 |

本题坐标上限 `10^4` 是给定的，所以「开一个 20010 的数组」是安全的；如果坐标到了 `10^9`（同类题里很常见的设定），行列并查集就得先压缩坐标，那一步会让它比 DFS 版更啰嗦。

## 完整代码实现

下面这段是本题的基准实现（页面上的「跑样例」与逐帧可视化回放的也是它），也就是方法二的提交形态：并查集抽成独立的类，按大小合并。

```python
from typing import List

class UnionFind:
    def __init__(self, n):
        self.fa = list(range(n))
        self.size = [1] * n

    def find(self, x):
        if self.fa[x] != x:
            self.fa[x] = self.find(self.fa[x])
        return self.fa[x]

    def merge(self, x, y):
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False
        if self.size[rx] < self.size[ry]:
            rx, ry = ry, rx
        self.fa[ry] = rx
        self.size[rx] += self.size[ry]
        return True


class Solution:
    def removeStones(self, stones: List[List[int]]) -> int:
        n = len(stones)
        offset = 10005
        uf = UnionFind(10005 * 2)
        for x, y in stones:
            uf.merge(x, y + offset)
        roots = set()
        for x, y in stones:
            roots.add(uf.find(x))
        return n - len(roots)
```

`UnionFind(10005 * 2)` 这个上界刚好盖住 `y + 10005` 的最大值 `20005`。统计分量时收集的是「每块石头的行节点所在的根」，因为石头的行与列已经被并到一起，收集一侧即可。

## 示例推演

### 示例 1：`stones = [[0,0],[0,1],[1,0],[1,2],[2,1],[2,2]]`

记列 `y` 的节点为 `y + 10005`：列 0 是 `10005`，列 1 是 `10006`，列 2 是 `10007`。

| 石头 | `merge` | 结果 |
|---|---|---|
| `[0,0]` | `merge(0, 10005)` | 行 0 与列 0 成一组 |
| `[0,1]` | `merge(0, 10006)` | 列 1 并进行 0 那一组 |
| `[1,0]` | `merge(1, 10005)` | 行 1 并进同一组 |
| `[1,2]` | `merge(1, 10007)` | 列 2 并进同一组 |
| `[2,1]` | `merge(2, 10006)` | 行 2 并进同一组 |
| `[2,2]` | `merge(2, 10007)` | 两端已经同根，什么都不做 |

六块石头的行节点全部落在同一个根上，`len(roots) = 1`，答案 `6 - 1 = 5`。

这 5 次删除对应示例给出的顺序：`[2,2]` 与 `[2,1]` 共享 `x = 2`，`[2,1]` 与 `[0,1]` 共享 `y = 1`，`[1,2]` 与 `[1,0]` 共享 `x = 1`，`[1,0]` 与 `[0,0]` 共享 `y = 0`，`[0,1]` 与 `[0,0]` 共享 `x = 0`，最后剩下 `[0,0]`。**每一步删掉的石头在剩下的图里都还有邻居**，这正是连通分量能一路削到只剩 1 块的原因。

### 示例 2：`stones = [[0,0],[0,2],[1,1],[2,0],[2,2]]`

| 石头 | `merge` | 分量 |
|---|---|---|
| `[0,0]` | `merge(0, 10005)` | `{行0, 列0}` |
| `[0,2]` | `merge(0, 10007)` | `{行0, 列0, 列2}` |
| `[1,1]` | `merge(1, 10006)` | 与第一组无关，另开一组 `{行1, 列1}` |
| `[2,0]` | `merge(2, 10005)` | 行 2 并进第一组 |
| `[2,2]` | `merge(2, 10007)` | 两端同组，无变化 |

两个分量：`{行0, 行2, 列0, 列2}` 与 `{行1, 列1}`。`len(roots) = 2`，答案 `5 - 2 = 3`。

第一组里有 4 块石头（`[0,0]`、`[0,2]`、`[2,0]`、`[2,2]`），能删 3 块；第二组只有 `[1,1]` 一块，删不掉。合计 `3 + 0 = 3`，与输出一致。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 石头建图 + DFS | O(n) | O(n) | 邻接表最多 `2n` 条边，`seen` 长度 `n` |
| 行列并查集（最优） | O(n·α(2·10^4)) | O(10^4) | 坐标上限固定，数组即可；大坐标要离散化 |

## 易错点总结

1. **列号不偏移，或偏移量不大于最大行号**：直接写 `merge(x, y)` 时，`stones = [[0,5],[5,0]]` 会把行 5 与列 0 当成同一个节点 —— 两块的坐标是 `(0,5)` 与 `(5,0)`，既不同行也不同列，正确答案是 `0`（一块都删不掉），代码会给出 `1`。偏移取 `10000` 同样出事：行号上限就是 `10000`，`[10000,3]` 的行节点与 `[5,0]` 的列节点都落在 `10000` 上，两块无关的石头被并到一起，`[[10000,3],[5,0]]` 返回 `1`，正确是 `0`。
2. **只按行合并，漏掉列**：方法一里把 `first_in_col` 那半个循环删掉，示例 2 只剩「行 0 内的两块」「行 2 内的两块」两条链，分量数变成 3，答案 `5 - 3 = 2`，而正确值是 `3`。列方向的边不是可选的补充，它是连通性的另一半。

## 扩展思考

「把两个维度都提升成节点」这套做法在 721 题（账户合并）里是同一个形状：名字是行、邮箱是列，`merge(名字, 邮箱)` 之后同一个人的所有邮箱自然落进一组。判据也一样 —— 当连通关系来自「共享某个属性值」而不是「元素之间直接给出」时，把属性值本身变成节点，边数就从平方级降到线性。
