# 0055. 跳跃游戏

## 题目描述

给你一个非负整数数组 `nums` ，你最初位于数组的 **第一个下标** 。数组中的每个元素代表你在该位置可以跳跃的最大长度。

判断你是否能够到达最后一个下标。

## 示例

**示例 1：**
```
输入：nums = [2,3,1,1,4]
输出：true
解释：可以先跳 1 步，从下标 0 到达下标 1，然后再从下标 1 跳 3 步到达最后一个下标。
```

**示例 2：**
```
输入：nums = [3,2,1,0,4]
输出：false
解释：无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ，所以永远不可能到达最后一个下标。
```

---

## 解题思路

### 要回答的是什么：可达性，不是步数

输出只有一个布尔值。这决定了三件事：不用记录「怎么跳过来的」，不求最少步数（那是 45 题），也不必真的把每一种跳法走一遍。只要能证明「存在一条路径」，答案就是 `true`。

`nums[i]` 是**最大**跳跃长度，意味着可以少跳 —— 落点不必正好是 `i + nums[i]`。

### 关键观察：能到达 `i`，就意味着 `0..i` 全部可达

这条性质是整题的地基。设从某个位置能落到 `i`，那么同一段飞行途中经过的每个格子也都能落上去（少跳几步就行）。于是**可达位置永远是一段从 0 开始的连续区间 `[0, R]`**，不会出现「中间断了但后面到了」的情况。

区间怎么往前推？站在区间里的任一位置 `i`，它最多把右端点顶到 `i + nums[i]`；取所有 `i` 里的最大值，就是新区间：

```text
R = max(R, i + nums[i])     # 只要 i 落在 [0, R] 里
```

这条式子就是贪心的全部内容。它成立靠的正是上面那条前缀性质 —— 只要 `i <= R`，`i` 一定可达，不需要再确认「真的有一条路走过来」。

### 方法一：按定义做 DP（O(n²)，先把问题写对）

把每一种跳法都走一遍的朴素 DFS 会反复回到同一批位置，代价是指数级的；而「位置 `i` 是否可达」一旦算出来就不会再变，完全可以先存成一张表。这是最贴定义的写法：对每个 `i` 回头找「谁跳得过来」。

```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        n = len(nums)
        dp = [False] * n
        dp[0] = True
        for i in range(1, n):
            for j in range(i):                     # 找一个能跳到 i 的落脚点
                if dp[j] and j + nums[j] >= i:
                    dp[i] = True
                    break
        return dp[n - 1]
```

`dp[i]` 的定义没有问题，问题在内层：对每个 `i` 都从 0 重新扫一遍 `j`，`O(n²)`，`n = 10^4` 就是千万级操作。而这里需要的信息其实只有一个数 —— 「`j <= reach` 的那些 `j` 里 `j + nums[j]` 的最大值」，同一批数被反复比较。

### 方法二：贪心，把内层循环压成一个最大值

由前缀性质，`j < i` 且 `dp[j]` 为真，等价于 `j <= R`。那就边走边维护这个最大值，内层循环消失：

```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        n = len(nums)
        reach = 0                                  # 目前能到达的最右下标
        for i in range(n):
            if i > reach:                          # 连 i 都到不了，后面更到不了
                return False
            reach = max(reach, i + nums[i])
            if reach >= n - 1:                     # 已经能落到终点
                return True
        return True
```

两个判断的**顺序**是这份代码唯一的技巧：

- `if i > reach` 必须在更新**之前**。它意味着 `[0, reach]` 这一段已经检查完了，而 `i` 及它后面的位置都不可达 —— `nums[i]` 再大也用不上，因为根本跳不到 `i`；
- `reach >= n - 1` 只是提前收工，删掉它循环照样正确，最后的 `return True` 兜住。

`[3,2,1,0,4]` 就是靠第一条判断出局的：`reach` 一路停在 3，`i` 走到 4 时 `4 > 3`，当场返回 `false`。

### 方法三：反向贪心（从终点倒推「必须够得着哪里」）

同一件事还可以反着讲：从右往左扫，维护一个「目前必须能从左边够到的位置」`last`，初值是终点。若 `i` 能一步跳到 `last`（`i + nums[i] >= last`），那么「必须够到 `last`」这件事就可以前移成「必须够到 `i`」。

```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        last = len(nums) - 1                       # 还需要有人能落到这里
        for i in range(len(nums) - 2, -1, -1):
            if i + nums[i] >= last:
                last = i                           # 目标前移
        return last == 0
```

扫完若 `last` 被一路推到 0，说明从起点出发能接上这条链；若停在某个 `last > 0`，就是起点够不着。

两种贪心是同一个事实的两种叙述：正向问「最远能到哪」，反向问「最远的要求能退到哪」。差别在写法 —— 反向版只有一个 `if`、没有提前退出，也完全不用操心「`i` 是否可达」（`last` 的语义本身保证了这一点）；正向版能在中途收工，`[2,3,1,1,4]` 在 `i = 1` 就返回了。

### 三种写法怎么选

| 写法 | 时间 | 空间 | 适用 |
|---|---|---|---|
| DP | O(n²) | O(n) | 讲清「可达」的定义；出现「最少步数」「限定步数」时要改状态 |
| 正向贪心 | O(n) | O(1) | 默认写法，能提前退出 |
| 反向贪心 | O(n) | O(1) | 少写一个分支；也适合回答「哪些位置能到终点」 |

## 完整代码实现

下面这段是本题的基准实现（页面上的「跑样例」与逐帧可视化回放的也是这一段）：维护最远可达位置，先判可达性再扩展，能到终点就提前返回。

```python
from typing import List

class Solution:
    def canJump(self, nums: List[int]) -> bool:
        """
        跳跃游戏 - 贪心算法

        核心思想：维护能到达的最远位置
        """
        n = len(nums)
        if n <= 1:
            return True

        max_reach = 0  # 能到达的最远位置

        for i in range(n):
            # 如果当前位置超过了最远可达位置，无法继续前进
            if i > max_reach:
                return False

            # 更新最远可达位置
            max_reach = max(max_reach, i + nums[i])

            # 提前退出：已经可以到达终点
            if max_reach >= n - 1:
                return True

        return True
```

## 示例推演

**示例 1**：`nums = [2,3,1,1,4]`，`n = 5`，终点下标 4，`max_reach` 从 0 开始。

| i | `nums[i]` | `i > max_reach`？ | `i + nums[i]` | `max_reach` | 是否能到终点 |
|---|---|---|---|---|---|
| 0 | 2 | `0 > 0` 否 | 2 | 2 | `2 >= 4` 否 |
| 1 | 3 | `1 > 2` 否 | 4 | 4 | `4 >= 4` **是，返回 true** |

`i = 0` 时 `max_reach = 0`，`0 > 0` 不成立，说明起点自己总是可达的；`i = 1` 之所以能扩展，是因为 `1 <= 2`（下标 1 落在 `[0,2]` 里）。

**示例 2**：`nums = [3,2,1,0,4]`，`n = 5`。

| i | `nums[i]` | `i > max_reach`？ | `i + nums[i]` | `max_reach` | 是否能到终点 |
|---|---|---|---|---|---|
| 0 | 3 | `0 > 0` 否 | 3 | 3 | `3 >= 4` 否 |
| 1 | 2 | `1 > 3` 否 | 3 | 3 | 否 |
| 2 | 1 | `2 > 3` 否 | 3 | 3 | 否 |
| 3 | 0 | `3 > 3` 否 | 3 | 3 | 否 |
| 4 | 4 | `4 > 3` **是** | —（还没轮到扩展） | — | **返回 false** |

`i = 4` 这一行说明了判断顺序为什么不能换：`nums[4] = 4` 能把 `max_reach` 顶到 8，但下标 4 根本到不了，这个 4 毫无意义。

同一组输入用反向贪心：`last = 4`，`i = 3` 时 `3 + 0 = 3 < 4`，不够；`i = 2` 时 `2 + 1 = 3 < 4`，不够；`i = 1` 时 `1 + 2 = 3 < 4`，不够；`i = 0` 时 `0 + 3 = 3 < 4`，不够。扫完 `last` 仍是 4，`last == 0` 不成立，返回 `false`。示例 1 则相反：`i = 3` 时 `3 + 1 = 4 >= 4`，`last` 变 3；`i = 2` 时 `2 + 1 >= 3`，`last` 变 2；`i = 1` 时 `1 + 3 >= 2`，`last` 变 1；`i = 0` 时 `0 + 2 >= 1`，`last` 变 0，返回 `true`。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 无记忆化 DFS | O(k^n) | O(n) | 每个位置展开最多 `k = max(nums)` 条分支，同一位置被反复走到 |
| DP | O(n²) | O(n) | 每个 `i` 都回扫一遍 `j` |
| 反向贪心 | O(n) | O(1) | 目标从终点往前移，只看会不会被够到 |
| 正向贪心（最优） | O(n) | O(1) | 维护最远可达，能到终点就提前退出 |

## 易错点总结

1. **两个判断写反顺序（先扩展、后判 `i > max_reach`）**：不可达的位置也参与扩展。`nums = [0,1]` 时 `i = 1` 先把 `max_reach` 顶到 2，于是返回 `true`，而正确答案是 `false`。
2. **扩展写成 `max_reach = i + nums[i]`（漏掉 `max`）**：之前更远的落脚点被丢掉。`nums = [3,0,0,1,0]` 在 `i = 1` 处把 `max_reach` 从 3 改成 1，接着 `i = 2` 就判成不可达，返回 `false`，而正确答案是 `true`（0 → 3 → 4）。
3. **判可达写成 `if i >= max_reach`（`>` 写成 `>=`）**：起点自己就被当成越界 —— `i = 0` 时 `0 >= 0` 成立，函数立刻返回 `false`，连示例 1 都过不了。

## 扩展思考

### 1. 要最少步数就是 45 题

45 题的贪心单位从「位置」变成「层」：在「当前这一步能到达的整段区间」里找出下一步能顶到的最远边界，走完一层步数加 1。本题的 `reach >= n - 1` 一成立就能收工，45 题不能 —— 更早到达并不等于步数更少。

### 2. 如果只能跳到 `i ± nums[i]`（1306 题）

那就不是「任意不超过 `nums[i]` 的落点」了，「可达位置是一段连续前缀」这条性质直接消失（可能跳到身后，也可能跳过中间），只能老老实实 BFS/DFS 在图上搜。判据只有一条：落点是不是一个连续区间。
