# 990. 等式方程的可满足性

## 题目描述

给定一个由表示变量之间关系的字符串方程组成的数组，每个字符串方程 `equations[i]` 的长度为 `4`，并采用两种不同的形式之一：`"a==b"` 或 `"a!=b"`。在这里，`a` 和 `b` 是小写字母（不一定不同），表示单字母变量名。

只有当可以将整数分配给变量名，以便满足所有给定的方程时才返回 `true`，否则返回 `false`。

**示例 1：**

```
输入：["a==b","b!=c","c==a"]
输出：false
```

**示例 2：**

```
输入：["a==b","b==c","c==a"]
输出：true
```

**示例 3：**

```
输入：["a==b","b!=a"]
输出：false
```

**提示：**

- `1 <= equations.length <= 500`
- `equations[i].length == 4`
- `equations[i][0]` 是小写字母
- `equations[i][1]` 要么是 `'='` 要么是 `'!'`
- `equations[i][2]` 要么是 `'='` 要么是 `'!'`
- `equations[i][3]` 是小写字母

## 解题思路

### 判定标准：26 个字母的「分组」问题

方程只有 `a==b` 与 `a!=b` 两种形式，`a`、`b` 都是单个小写字母，所以这道题的全部对象就是 26 个字母。

`==` 满足自反、对称、传递：`a==a` 恒成立，`a==b` 可以换序，`a==b` 与 `b==c` 能推出 `a==c`。三条合起来说的是同一件事 —— **`==` 把所有字母划分成若干个等价类，同一类里的字母必须取同一个整数**。

`!=` 的语义只有一半：它不要求两端取某两个特定的值，只**禁止**两端落进同一个等价类。

于是判定标准可以写得很干净：

> 按全部 `==` 把 26 个字母分组；如果没有任何一条 `!=` 的两端落在同一组里，返回 `true`，否则返回 `false`。

### 关键观察：为什么「先合并全部等式，再检查不等式」一定够

两个方向都要说清，否则读者会怀疑「会不会有需要回头拆开某个等式的情况」。

- **必要性**：假设存在一组可行的整数赋值。`==` 两端取值相同，说明「值相同」这个关系本身就已经把每条 `==` 的两端放在一起，它给出的分组一定满足全部等式约束；而并查集分出的组，是把这些约束**全部**合并后的结果，只会比它更细（并查集的每一组都落在某个「值相同」的组里）。既然 `!=` 两端取值不同，它们就不可能同组。所以并查集里一旦出现「`!=` 两端同根」，就不存在可行赋值。
- **充分性**：反过来，如果所有 `!=` 两端都不同组，就给每个组分配一个互不相同的整数 —— 第 1 组全填 0，第 2 组全填 1，以此类推。同组内的 `==` 全成立，不同组之间的 `!=` 也全成立，这本身就是一组可行解。

充分性这一半是本题的题眼：**`!=` 只「禁止」，不「要求」**。它没有规定两个变量必须取哪两个不同的值，所以只要给不同组不同的数，所有不等式同时被满足，没有任何需要协调的冲突。因此既不需要回溯，也不需要「先满足不等式再回头修正」。

对比 **886 题（可能的二分法）** 就明白了：那题的边要求两端**必须异色**，颜色只有两种，一条链上颜色被迫交替，才需要染色加冲突检测（本质是判二分图）。本题的约束是「必须同色」（`==`），颜色数量不限，冲突只可能出现在 `!=` 这一侧。**同色约束可以无脑合并，异色约束才会逼出搜索。**

### 方法一：传递闭包（26 个变量时最直白的写法）

把「必须相等」记成一张 26 × 26 的布尔表。先按 `==` 标格子，跑一遍 Floyd 求出传递闭包，再逐条检查 `!=`：

```python
from typing import List

class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        eq = [[False] * 26 for _ in range(26)]
        for i in range(26):
            eq[i][i] = True                      # 自反：字母与自己同组
        for e in equations:
            if e[1] == '=':
                x, y = ord(e[0]) - 97, ord(e[3]) - 97
                eq[x][y] = eq[y][x] = True
        for k in range(26):                      # Floyd：允许借 k 中转一次
            for i in range(26):
                if eq[i][k]:
                    for j in range(26):
                        if eq[k][j]:
                            eq[i][j] = True
        for e in equations:
            if e[1] == '!':
                x, y = ord(e[0]) - 97, ord(e[3]) - 97
                if eq[x][y]:
                    return False
        return True
```

`eq[x][y]` 的真值就是「x 与 y 是否被强制相等」。26³ ≈ 1.8 万次内层判断，远在时限之内，所以这是能通过的实现，不是凑数的暴力。

它的代价不在时间，而在**结构假设**：表的大小是「字母表大小」的平方。变量一旦换成任意字符串（力扣另一批题正是如此），这张 26 × 26 的表立刻失去意义。

### 方法二：并查集（只关心「和谁一组」，不关心表长什么样）

并查集维护的东西正好是等价类：每个元素一个集合，`merge` 把两个集合并起来，`find` 回答「你属于哪个集合」。它的规模只取决于「有多少个不同元素」，不取决于元素长什么样。

- 26 个字母各建一个集合；
- 第一遍只看 `==`，把两端并起来；
- 第二遍只看 `!=`，两端同根就是矛盾。

```python
from typing import List

class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        fa = list(range(26))

        def find(x: int) -> int:
            while fa[x] != x:              # 路径减半：边走边把链压短
                fa[x] = fa[fa[x]]
                x = fa[x]
            return x

        for e in equations:                # 第一遍：只并等式
            if e[1] == '=':
                rx, ry = find(ord(e[0]) - 97), find(ord(e[3]) - 97)
                fa[ry] = rx
        for e in equations:                # 第二遍：只查不等式
            if e[1] == '!' and find(ord(e[0]) - 97) == find(ord(e[3]) - 97):
                return False
        return True
```

两遍循环不是书写习惯，而是算法本身：第一遍跑完，`fa` 才等于「全部 `==` 的传递闭包」，第二遍才有东西可查。压成一遍（边扫边判断）会在 `["a==b","b!=c","c==a"]` 上给出错误答案 —— 检查 `b!=c` 时 `c==a` 还没被读到，详见「易错点」第 1 条。

这里没有按秩合并，只有路径减半，复杂度仍然是「近似常数」：26 个节点的树最多几层，`α(26)` 在人眼可见的范围内就是 1 到 2 次跳转。

### 方法三：在等式图上跑 DFS，把每个连通块编上号

换一种容器来装同一件事：把每个字母看成点，每条 `==` 看成一条无向边。等式关系的传递性在这个图里的名字就叫「连通」—— `a` 连 `b`、`b` 连 `c`，三者自然在同一个连通块。

1. 按 `==` 建邻接表；
2. 对每个尚未访问的字母跑一次 DFS，把整块标上同一个编号 `comp[i]`；
3. 逐条检查 `!=`，两端编号相同即矛盾。

```python
from typing import List

class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        adj = [[] for _ in range(26)]
        for e in equations:
            if e[1] == '=':
                x, y = ord(e[0]) - 97, ord(e[3]) - 97
                adj[x].append(y)
                adj[y].append(x)

        comp = [-1] * 26                       # -1 表示还没编号
        for s in range(26):
            if comp[s] != -1:
                continue
            comp[s] = s
            stack = [s]
            while stack:                       # 用显式栈，省掉递归深度的心算
                u = stack.pop()
                for v in adj[u]:
                    if comp[v] == -1:
                        comp[v] = s
                        stack.append(v)

        for e in equations:
            if e[1] == '!' and comp[ord(e[0]) - 97] == comp[ord(e[3]) - 97]:
                return False
        return True
```

`comp[i]` 就是「颜色」：同一连通块同色，不同块异色。这是一次「颜色数量不限、边要求同色」的染色，所以一遍 DFS 就染完，没有选择也没有回溯。

三种写法对比：

| 写法 | 什么时候合适 | 主要代价 |
|---|---|---|
| 传递闭包 | 变量集合固定且很小，想要一张完整的「谁和谁相等」表 | 26³ 的常数与 676 个格子，规模稍微一变就失效 |
| 并查集 | 默认写法：只问「是否同类」，不关心同类里还有谁 | 需要两遍扫描，且顺序不能颠倒 |
| 等式图 DFS | 需要真的取出「每一组有谁」，或者题目要求输出分组 | 要建邻接表，多一份与 `==` 条数同阶的边 |

本题只问「有没有矛盾」，不需要知道每组的具体成员，并查集最短。DFS 版的价值在于它把「等价类等于连通块」摆到明面上：读到 `a==b`、`b==c` 时，读者能直接看见 `a` 与 `c` 被一条路径连起来；并查集则把这条路径藏进了 `fa` 数组。

## 完整代码实现

下面这段是本题的基准实现（页面上的「跑样例」与逐帧可视化回放的也是它）：把并查集抽成独立的类，`Solution` 只负责两遍扫描。方法二的紧凑写法与它等价，提交时任选一个。

```python
from typing import List

class UnionFind:
    def __init__(self, n: int = 26):
        self.fa = list(range(n))
        self.size = [1] * n

    def find(self, x: int) -> int:
        if self.fa[x] != x:
            self.fa[x] = self.find(self.fa[x])
        return self.fa[x]

    def merge(self, x: int, y: int) -> bool:
        rx, ry = self.find(x), self.find(y)
        if rx == ry:
            return False
        if self.size[rx] < self.size[ry]:
            rx, ry = ry, rx
        self.fa[ry] = rx
        self.size[rx] += self.size[ry]
        return True


class Solution:
    def equationsPossible(self, equations: List[str]) -> bool:
        uf = UnionFind(26)
        for e in equations:
            if e[1] == '=':
                x = ord(e[0]) - ord('a')
                y = ord(e[3]) - ord('a')
                uf.merge(x, y)
        for e in equations:
            if e[1] == '!':
                x = ord(e[0]) - ord('a')
                y = ord(e[3]) - ord('a')
                if uf.find(x) == uf.find(y):
                    return False
        return True
```

`UnionFind.merge` 返回一个 `bool`，表示这次合并是否真的把两个不同的集合并到了一起。本题用不到这个返回值（`a==a` 这种自合并会被直接跳过），保留它是为了让这个类在别的题里可以直接复用。

## 示例推演

### 示例 1：`["a==b","b!=c","c==a"]` → `false`

把并查集简写成只画用到的 `a`、`b`、`c`（下标 0、1、2），其余 23 个字母始终各自成组，不参与判断。

**第一遍，只看 `==`：**

| 方程 | 动作 | `find(a), find(b), find(c)` |
|---|---|---|
| `a==b` | `find(a)=0`、`find(b)=1`，令 `fa[1] = 0` | 0, 0, 2 |
| `b!=c` | 跳过 | 0, 0, 2 |
| `c==a` | `find(c)=2`、`find(a)=0`，令 `fa[2] = 0` | 0, 0, 0 |

第一遍结束时 `{a, b, c}` 已经是一组。

**第二遍，只看 `!=`：**

| 方程 | 判断 | 结果 |
|---|---|---|
| `b!=c` | `find(b) = 0`，`find(c) = 0`，同根 | 返回 `false` |

如果把两遍合成一遍（读到哪条就处理哪条），顺序会变成：`a==b` 合并 → 读到 `b!=c` 时 `c` 还是独立的根 2，判定通过 → `c==a` 再把 `c` 并进来。此时已经没有第二次机会发现 `b` 与 `c` 同组，程序返回 `true`。**这就是顺序必须拆成两遍的原因。**

### 示例 2：`["a==b","b==c","c==a"]` → `true`

第一遍把三条等式全部处理：`a==b` 后 `fa[1]=0`；`b==c` 时 `find(b)=0`、`find(c)=2`，令 `fa[2]=0`；`c==a` 时两端已经同根，什么都不做。三个字母同组。

第二遍没有 `!=` 可查，返回 `true`。

### 示例 3：`["a==b","b!=a"]` → `false`

第一遍只有 `a==b`，`fa[1]=0`。第二遍读 `b!=a`：`find(b)=0`、`find(a)=0`，同根，返回 `false`。

### 一个「可满足」的对照：`["a!=b"]` → `true`

第一遍没有等式，`a`、`b` 分别是以自己为根的独立集合。第二遍 `find(a)=0`、`find(b)=1`，不同组，检查通过，返回 `true`。赋值时让 `a = 0`、`b = 1` 即可 —— 这正是充分性证明里「给每组分配不同整数」的具体做法。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 传递闭包（Floyd） | O(n + 26³) | O(26²) | 26³ ≈ 1.8 万次内层判断，常数上完全够用 |
| 等式图 DFS | O(n + 26) | O(n + 26) | 邻接表里放每条 `==` 的两个方向 |
| 并查集（最优） | O(n·α(26)) ≈ O(n) | O(26) | 两遍扫描，α 增长极慢 |

> `n = len(equations)`。26 是常量，三种写法对 `n` 都是线性的，差别在常数与适用范围。

## 易错点总结

1. **把合并与检查挤进同一个循环**：写成 `for e in equations: if e[1] == '=': 合并 else: 检查`。示例 1 里 `b!=c` 出现在 `c==a` 之前，检查时 `c` 还是独立的根 2，于是判定通过，最终返回 `true`，而正确答案是 `false`。必须写成两个独立的 `for`。
2. **运算符取错下标**：`e[1]` 才是 `=` 或 `!`，`e[2]` 是第二个符号。`"a!=b"` 的 `e[2]` 恰好是 `'='`，写成 `if e[2] == '='` 会把不等式当成等式合并 —— `["a!=b"]` 本应返回 `true`（两者取不同的值即可），这时会返回 `false`。
3. **检查不等式时比较父节点而不是根**：`if fa[x] == fa[y]` 只在两个字母恰好都直接挂在根上时才成立。`["a==b","c==d","b==c","a!=d"]` 合并后 `fa = [0, 0, 0, 2]`：`fa[d] = fa[3] = 2`，`fa[a] = 0`，两者不等，于是返回 `true`；而 `find(d) = find(a) = 0`，正确答案是 `false`。

## 扩展思考

如果约束从「相等」变成「相差多少」（`a 除以 b 等于 k`，如 399 题除法求值），普通并查集就不够了：它记不住两组之间的倍数关系。那类题要用**带权并查集**，在 `find` 时顺带把「自己到根的倍数」累乘起来，`merge` 时按倍数差决定挂哪一边。思路仍然是「先合并同类，再验证矛盾」，只是每组多了一个可运算的状态。
