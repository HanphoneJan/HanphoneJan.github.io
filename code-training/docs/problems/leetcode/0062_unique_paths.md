# 0062. 不同路径

## 题目描述

一个机器人位于一个 `m x n` 网格的左上角 （起始点在下图中标记为 "Start" ）。

机器人每次只能向下或者向右移动一步。机器人试图达到网格的右下角（在下图中标记为 "Finish" ）。

问总共有多少条不同的路径？

## 示例

**示例 1：**
```
输入：m = 3, n = 7
输出：28
```

**示例 2：**
```
输入：m = 3, n = 2
输出：3
解释：
从左上角开始，总共有 3 条路径可以到达右下角。
1. 向右 -> 向下 -> 向下
2. 向下 -> 向下 -> 向右
3. 向下 -> 向右 -> 向下
```

**示例 3：**
```
输入：m = 7, n = 3
输出：28
```

## 解题思路

### 要数的是条数，而每条路径的步数组成是固定的

从 `(0,0)` 到 `(m-1,n-1)`，不管怎么绕，都必须恰好走 `m-1` 步向下、`n-1` 步向右，总步数 `m+n-2`。也就是说**所有路径的长度相同、用掉的动作也相同**，区别只在顺序。

这一条把题目分成两条互不相干的路：

- **组合**：顺序问题 → 从 `m+n-2` 个位置里挑 `n-1` 个放「右」，其余放「下」；
- **DP**：拆「最后一步从哪来」→ 到达 `(i,j)` 的路径 = 从上方来的 + 从左方来的。

两条都要会。组合数一行就出答案，但它依赖「每条路径都是同一种动作的排列」这个前提；一旦网格里出现障碍（63 题），路径长度和动作集合都不再固定，组合公式立刻失效。DP 慢一些，却能直接吞下障碍、代价、方向限制这些变体。

### 方法一：组合数，一步到位

答案就是「`m+n-2` 个位置选 `n-1` 个」：

```text
C(m+n-2, n-1) = (m+n-2)! / ((n-1)! (m-1)!)
```

```python
from math import comb

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        return comb(m + n - 2, n - 1)
```

`math.comb` 是标准库函数，不用自己写阶乘再相除。取 `n-1` 还是 `m-1` 都行（`C(a,b) = C(a,a-b)`），写成 `comb(m+n-2, min(m,n)-1)` 时乘除次数最少。

局限有两个：一是结果是大整数，`m = n = 100` 时数值有 59 位，Python 会自动扩展位数，换到定长整数的语言里就得换成 `long long` 并小心溢出（`C(34,17) = 2333606220` 已经超过 32 位 `int` 上限）；二是它**只适用于「无障碍、只问条数」**的情形。

### 方法二：二维 DP，把「最后一步」拆开

定义 `dp[i][j]` = 从起点走到 `(i,j)` 的路径条数。走到 `(i,j)` 的最后一步只有两种可能：从 `(i-1,j)` 下来，或从 `(i,j-1)` 过来。这两个来源的路径集合不相交（最后一步方向不同），可以直接相加：

```text
dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

边界是「只有一条路」的那些格子：第一行只能一路向右（`dp[0][j] = 1`），第一列只能一路向下（`dp[i][0] = 1`）。

```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        dp = [[0] * n for _ in range(m)]
        for i in range(m):
            dp[i][0] = 1
        for j in range(n):
            dp[0][j] = 1
        for i in range(1, m):
            for j in range(1, n):
                dp[i][j] = dp[i - 1][j] + dp[i][j - 1]
        return dp[m - 1][n - 1]
```

填表顺序必须「从上到下、从左到右」：算 `dp[i][j]` 时，上面一格和左边一格都得是已经算好的值。

同一个转移也可以写成记忆化递归（`dfs(i, j)` 返回 `dfs(i-1,j) + dfs(i,j-1)`，`i == 0 or j == 0` 时返回 1），求值方向相反，状态与答案完全一样。

### 方法三：一维滚动，只留一行

`dp[i][j]` 只用到上一行的同一列和本行的左边一格，整张表可以压成一行 `f`：

```python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        f = [1] * n                          # 第一行全是 1
        for _ in range(1, m):
            for j in range(1, n):            # j 从 1 开始：第 0 列恒为 1
                f[j] += f[j - 1]             # 旧 f[j] 是上面一格，f[j-1] 是本行左格
        return f[n - 1]
```

`f[j] += f[j-1]` 一行干了两件事：`f[j]` 在覆盖前是 `dp[i-1][j]`，`f[j-1]` 已经是本行刚算出的 `dp[i][j-1]`，相加正是转移式。

这个「就地覆盖」安全的前提是内层**从左往右**：右边的格子还没被本行写过（保持上一行的值），左边的已经写完了（是这一行的值）。反过来写就变成拿上一行的左格去加，含义全错。

### 三种写法怎么选

| 写法 | 时间 | 空间 | 什么时候用 |
|---|---|---|---|
| 组合数 | O(min(m,n)) | O(1) | 无障碍、只问条数，一行解决 |
| 一维 DP | O(m×n) | O(n) | 需要转移关系（加障碍、加代价） |
| 二维 DP | O(m×n) | O(m×n) | 第一次理解转移，或需要回看整张表 |

组合数在这题是压倒性的：`m = n = 100` 时 DP 是一万次加法，`comb` 只有几十次乘除。但「更快的写法」不等于「更通用的写法」—— 63 题只要在网格里放一个障碍，组合数就得整个换掉，而 DP 只多一个 `if`。

## 完整代码实现

下面这段是本题的基准实现（页面上的「跑样例」与逐帧可视化回放的也是这一段），三个方法按「组合数 → 一维 DP → 二维 DP」排列，判题时任选一个提交。

```python
from math import comb

class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        """
        不同路径 - 组合数学解法（最优）

        核心思想：从 m+n-2 步中选择 n-1 步向右
        """
        # 选择 n-1 个位置放"右"，其余放"下"
        return comb(m + n - 2, n - 1)

    def uniquePathsByDP(self, m: int, n: int) -> int:
        """
        动态规划解法 - 空间优化版
        """
        # dp[j] 表示当前行第 j 列的路径数
        dp = [1] * n  # 初始化第一行，所有位置的路径数都是 1

        for i in range(1, m):  # 从第二行开始遍历
            for j in range(1, n):  # 从第二列开始
                # dp[j] 存储的是上一行的值（dp[i-1][j]）
                # dp[j-1] 存储的是当前行的值（dp[i][j-1]）
                dp[j] += dp[j - 1]

        return dp[n - 1]

    def uniquePathsBy2D(self, m: int, n: int) -> int:
        """
        标准二维DP写法，更容易理解
        """
        # dp[i][j] = 到达 (i,j) 的路径数
        dp = [[0] * n for _ in range(m)]

        # 初始化边界
        for i in range(m):
            dp[i][0] = 1
        for j in range(n):
            dp[0][j] = 1

        # 填充DP表
        for i in range(1, m):
            for j in range(1, n):
                dp[i][j] = dp[i-1][j] + dp[i][j-1]

        return dp[m-1][n-1]
```

## 示例推演

以示例 1 的 `m = 3, n = 7` 为例，要走 `m-1 = 2` 步向下、`n-1 = 6` 步向右，共 8 步。

**组合数**：从 8 个位置里挑 2 个放「下」（等价于挑 6 个放「右」）：

```text
C(8, 2) = 8 × 7 / 2 = 28
```

**二维 DP**：第 0 行与第 0 列全是 1（只有一条路），其余格子等于「上面 + 左边」。

| `dp` | j=0 | j=1 | j=2 | j=3 | j=4 | j=5 | j=6 |
|---|---|---|---|---|---|---|---|
| i=0 | 1 | 1 | 1 | 1 | 1 | 1 | 1 |
| i=1 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| i=2 | 1 | 3 | 6 | 10 | 15 | 21 | **28** |

挑几格看加法：

- `dp[1][1] = dp[0][1] + dp[1][0] = 1 + 1 = 2`：到 `(1,1)` 可以「右→下」或「下→右」；
- `dp[1][6] = dp[0][6] + dp[1][5] = 1 + 6 = 7`：从上方 `(0,6)` 下来 1 条，从左边 `(1,5)` 过来 6 条；
- `dp[2][2] = dp[1][2] + dp[2][1] = 3 + 3 = 6`；
- `dp[2][6] = dp[1][6] + dp[2][5] = 7 + 21 = 28`，与组合数一致。

**一维 DP**：`f` 初值是 `[1,1,1,1,1,1,1]`（第一行），每处理一行就原地覆盖：

```text
i = 1：j 从 1 走到 6 → [1, 2, 3, 4, 5, 6, 7]
i = 2：j 从 1 走到 6 → [1, 3, 6, 10, 15, 21, 28]
```

`f[6] = 28`。示例 2（`m = 3, n = 2`）用组合数是 `C(3,1) = 3`，DP 表填出来是 `[[1,1],[1,2],[1,3]]`，右下角同样是 3。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 组合数（最优） | O(min(m,n)) | O(1) | 只数乘法次数，大整数的位运算另计 |
| 一维 DP | O(m×n) | O(n) | 滚动一行，每个格子一次加法 |
| 二维 DP | O(m×n) | O(m×n) | 整张表，每个格子一次加法 |

## 易错点总结

1. **组合数的参数写成 `comb(m + n, n - 1)`（漏了 `- 2`）**：`m + n - 2` 是**边数**，起点那一格不算。`m = 3, n = 2` 时正确是 `comb(3, 1) = 3`，写成 `comb(5, 1) = 5`。
2. **一维 DP 的内层写成 `for j in range(n)`**：`j = 0` 时执行的是 `f[0] += f[-1]`，Python 的负下标**静默回绕**到 `f[n-1]` 取值，不报错。`m = 3, n = 7` 会返回 43 而不是 28。
3. **一维 DP 的初值写成 `f = [0] * n`**：第一行丢掉了「只有一条路」这个初值，整行累加链断掉，`m = 3, n = 7` 直接返回 0。

## 扩展思考

### 1. 有障碍就是 63 题

转移只多一个判断：障碍格 `dp = 0`。

```python
from typing import List

class Solution:
    def uniquePathsWithObstacles(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        dp = [[0] * n for _ in range(m)]
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 1:              # 障碍格，没有路径能落在上面
                    dp[i][j] = 0
                elif i == 0 and j == 0:
                    dp[i][j] = 1
                else:
                    up = dp[i-1][j] if i > 0 else 0
                    left = dp[i][j-1] if j > 0 else 0
                    dp[i][j] = up + left
        return dp[m-1][n-1]
```

这时组合数公式不再成立：路径长度随障碍位置变化，「8 步里选 2 步」这种描述无从下手。

### 2. 要输出所有路径就是回溯

把每条路径具体写出来，就得 DFS + 回溯，每条路径 `O(m+n)`，总代价是指数级的 —— 与「只数条数」是两个问题。判据：输出是数字还是路径列表。
