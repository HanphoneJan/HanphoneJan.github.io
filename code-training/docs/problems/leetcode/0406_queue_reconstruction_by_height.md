# 406. 根据身高重建队列

## 题目描述

假设有打乱顺序的一群人站成一个队列，数组 `people` 表示队列中一些人的属性（不一定按顺序）。每个 `people[i] = [hi, ki]` 表示第 `i` 个人的身高为 `hi`，前面 **正好** 有 `ki` 个身高大于或等于 `hi` 的人。

请你重新构造并返回输入数组 `people` 所表示的队列。

## 示例

**示例 1：**
```
输入：people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]
输出：[[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]
```

**示例 2：**
```
输入：people = [[6,0],[5,0],[4,0],[3,2],[2,2],[1,4]]
输出：[[4,0],[5,0],[2,2],[3,2],[1,4],[6,0]]
```

---

## 解题思路

### 一个人的 `k` 只由「比他高或一样高的人」决定

`[h, k]` 的完整意思是：最终队列里，他前面身高 `>= h` 的人**正好** `k` 个。比他矮的人站他前面多少个都不影响这个计数。

这句话把问题切成了两半：先决定**按什么顺序放人**，再决定**每个人放到哪个位置**。麻烦在于位置不是独立的 —— 往中间插一个人，后面所有人的下标都会右移。

### 先放高的：位置直接就是插入下标

如果按身高从高到低处理，轮到某人时，**已经放进队列的人身高全都 `>= h`**。这时把他插到下标 `k`（0 起），他前面恰好有 `k` 个人，而且这 `k` 个人全都 `>= h` —— 要求当场满足。

之后再放进来的人都比他矮，插到他前面也不会被计入他的 `k`。所以一次放对之后，这个位置不会再被后来的操作破坏。

这就是贪心的全部内容：**用排序顺序把「后面的人会影响我」这件事消掉**，插完就不用回头改。剩下的唯一自由就是「插到第几个位置」，而 `k` 正好就是答案。

```python
class Solution:
    def reconstructQueue(self, people: List[List[int]]) -> List[List[int]]:
        people.sort(key=lambda p: (-p[0], p[1]))   # 身高降序，同身高 k 升序
        ans = []
        for h, k in people:
            ans.insert(k, [h, k])                  # 前面 k 个都比自己高
        return ans
```

`ans.insert(k, x)` 与基准实现里的 `ans[k:k] = [x]` 完全等价，选一个顺手的即可。

### 同身高的人：`k` 必须升序

身高相同的人彼此也计数（`>=` 包含等于），所以同身高组内部不能随便排。

同身高的人 `k` 必然互不相同：如果两个人身高都是 `h`、`k` 也相同，那他们要求「前面正好 `k` 个 `>= h` 的人」，可两人其中一个必然排在另一个后面，多出来的那个就满足不了。所以组内按 `k` 升序排，就是按「要求前面有几个」从小到大排。

升序还有个直接后果：组内每个人被插入的下标严格递增（`k` 就是下标），而同一身高组在排序里是连续的一段，组内几次插入之间不会夹进更矮的人。所以后插的人一定落在前一个人右边，前面那些人的位置一动都不动 —— 「前面正好 `k` 个」这个计数不会被后来的同身高者改坏。

### 另一个方向：从矮到高，给高个子留空位

把顺序反过来，思路也跟着变：处理某人时，已放好的都是**更矮**的人，他们以后都不会被计入 `k`。真正要数的是**还没放的高个子**。

于是换个说法：把这个人放在「左边恰好还剩 `k` 个空位」的位置上。那 `k` 个空位最终都会被 `>= h` 的人占掉（后面放进来的人身高只增不减），他前面就正好有 `k` 个不低于他的人；已经坐在他左边的矮个子一个都不算。

同身高的人在这个方向里要 `k` **降序**：`k` 大的占更靠右的位置，`k` 小的人后面再补到它左边，正好凑满它的计数。

「找第 `k+1` 个空位」是这版的全部工作量。直接扫一遍是 `O(n)`，用树状数组记「每个位置还空着」，就能 `O(log n)` 用倍增找到它：

```python
from typing import List

class Solution:
    def reconstructQueue(self, people: List[List[int]]) -> List[List[int]]:
        n = len(people)
        people.sort(key=lambda p: (p[0], -p[1]))   # 身高升序，同身高 k 降序

        # 树状数组维护「哪些位置还空着」；全 1 数组的 BIT 恰好是 tree[i] = lowbit(i)
        tree = [0] + [i & -i for i in range(1, n + 1)]

        def kth(k: int) -> int:
            """第 k 个空位的位置（1 起）。"""
            pos, step = 0, 1 << (n.bit_length() - 1)
            while step:
                nxt = pos + step
                if nxt <= n and tree[nxt] < k:
                    pos = nxt
                    k -= tree[nxt]
                step >>= 1
            return pos + 1

        def occupy(i: int) -> None:
            while i <= n:
                tree[i] -= 1
                i += i & -i

        ans = [None] * n
        for h, k in people:
            pos = kth(k + 1)        # 左边留出 k 个空位给更高的人
            ans[pos - 1] = [h, k]
            occupy(pos)
        return ans
```

### 两种写法怎么选

| | 先高后低 + 插入 | 先低后高 + 数空位（树状数组） |
|---|---|---|
| 排序关键字 | `(-h, k)` | `(h, -k)` |
| 每个人做多少事 | 在列表中间插入，搬移 `O(n)` 个元素 | 找第 `k+1` 个空位 `O(log n)`，占位 `O(log n)` |
| 总量 | `O(n log n + n²)` | `O(n log n)` |
| 代码量 | 5 行 | 30 行，还要维护一棵树状数组 |

本题 `n ≤ 2000`，插入法最多搬移两百万个元素，完全够快；它还有个额外好处：**正确性几乎不用解释**，「插到下标 `k`」就是 `k` 的字面意思。树状数组版真正的用武之地是 `n` 到十万级的时候。

## 完整代码实现

```python
from typing import List


class Solution:
    """
    根据身高重建队列 - 贪心算法

    按身高降序，身高相同按 k 升序
    依次插入到结果列表的第 k 个位置

    时间复杂度：O(n log n)
    空间复杂度：O(n)
    """

    def reconstructQueue(self, people: List[List[int]]) -> List[List[int]]:
        # 按身高降序，身高相同则按前面人数升序
        people.sort(key=lambda x: (-x[0], x[1]))
        ans = list()
        for person in people:
            # 将当前人插入到 ans[person[1]] 位置
            ans[person[1]:person[1]] = [person]
        return ans
```

## 示例推演

以示例 1 的 `people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]` 为例。

**第一步排序**（身高降序，同身高 `k` 升序）：

| 原顺序 | 身高 | `k` | 排序后位置 |
|---|---|---|---|
| `[7,0]` | 7 | 0 | 1 |
| `[7,1]` | 7 | 1 | 2 |
| `[6,1]` | 6 | 1 | 3 |
| `[5,0]` | 5 | 0 | 4 |
| `[5,2]` | 5 | 2 | 5 |
| `[4,4]` | 4 | 4 | 6 |

排序结果：`[7,0], [7,1], [6,1], [5,0], [5,2], [4,4]`。

**第二步逐个插入**（`ans.insert(k, 人)`），每一步旁边写出「插进去之后他前面有几个 `>=` 他的人」：

| 步骤 | 当前人 | 插入下标 `k` | 插入后的队列 | 他前面 `>=` 他身高的人数 |
|---|---|---|---|---|
| 1 | `[7,0]` | 0 | `[[7,0]]` | 0 ✔ |
| 2 | `[7,1]` | 1 | `[[7,0],[7,1]]` | 1（`7`）✔ |
| 3 | `[6,1]` | 1 | `[[7,0],[6,1],[7,1]]` | 1（`7`）✔ |
| 4 | `[5,0]` | 0 | `[[5,0],[7,0],[6,1],[7,1]]` | 0 ✔ |
| 5 | `[5,2]` | 2 | `[[5,0],[7,0],[5,2],[6,1],[7,1]]` | 2（`5`、`7`）✔ |
| 6 | `[4,4]` | 4 | `[[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]` | 4（`5`、`7`、`5`、`6`）✔ |

最终结果 `[[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]`，与示例一致。

第 5 步值得停一下：`[5,2]` 插到下标 2 时，前面的 `[5,0]` 身高也是 5，`>= 5` 成立，所以它被算进了那 2 个人里。这就是「`>=` 包含等于」在起作用。

**示例 2 换个验证角度**：`[[6,0],[5,0],[4,0],[3,2],[2,2],[1,4]]` 的身高两两不同，排序后正好是原顺序。依次插入的结果是：

| 步骤 | 当前人 | 下标 | 队列 |
|---|---|---|---|
| 1 | `[6,0]` | 0 | `[[6,0]]` |
| 2 | `[5,0]` | 0 | `[[5,0],[6,0]]` |
| 3 | `[4,0]` | 0 | `[[4,0],[5,0],[6,0]]` |
| 4 | `[3,2]` | 2 | `[[4,0],[5,0],[3,2],[6,0]]` |
| 5 | `[2,2]` | 2 | `[[4,0],[5,0],[2,2],[3,2],[6,0]]` |
| 6 | `[1,4]` | 4 | `[[4,0],[5,0],[2,2],[3,2],[1,4],[6,0]]` |

结果与示例 2 相同。这组数据身高全不相同，所以第二个排序关键字完全不起作用 —— 它检验的是插入位置，不检验并列规则。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 排序 + 逐个插入（基准实现） | O(n log n + n²) | O(n) | 每次 `insert` 要搬移 O(n) 个元素，`n ≤ 2000` |
| 排序 + 树状数组找空位（最优） | O(n log n) | O(n) | 排序 O(n log n)，之后 n 次「找空位」各 O(log n) |

> 插入法的 `O(n²)` 来自 Python 列表的中间插入（底层要整体右移），排序那部分仍是 `O(n log n)`。题目给出 `n ≤ 2000`，两种写法都远低于时限。

## 易错点总结

1. **排序方向写成升序**：`people.sort(key=lambda x: (x[0], x[1]))`。插入时前面的人身高都 `<= h`，`k` 的语义完全对不上。示例 1 会得到 `[[7,0],[7,1],[5,0],[6,1],[4,4],[5,2]]`，其中 `[5,0]` 前面站着 `[7,0]` 和 `[7,1]` 两个更高的人，而它的 `k` 是 0。
2. **同身高的第二关键字写成 `-x[1]`（`k` 降序）**：`people.sort(key=lambda x: (-x[0], -x[1]))`。示例 1 排序后变成 `[7,1], [7,0], [6,1], [5,2], [5,0], [4,4]`，插到 `[5,2]` 时那 2 个 `>= 5` 的人还没凑齐，最终得到 `[[5,0],[7,0],[6,1],[5,2],[4,4],[7,1]]`（和答案差在中间两位）。只有两个同身高的人时这种排法可能碰巧插对，所以要自己造一组三个同身高的数据（如 `[[7,0],[7,1],[7,2]]`，会得到 `[[7,0],[7,2],[7,1]]`）来验。
