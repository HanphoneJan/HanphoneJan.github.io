# 239. 滑动窗口最大值

## 题目描述

给你一个整数数组 `nums`，有一个大小为 `k` 的滑动窗口从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 `k` 个数字。滑动窗口每次只向右移动一位。

返回滑动窗口中的最大值。

**提示：**

- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`
- `1 <= k <= nums.length`

## 示例

### 示例 1

**输入：** nums = [1,3,-1,-3,5,3,6,7], k = 3

**输出：** [3,3,5,5,6,7]

**解释：**

```
滑动窗口的位置                最大值
[1  3  -1] -3  5  3  6  7       3
 1 [3  -1  -3] 5  3  6  7       3
 1  3 [-1  -3  5] 3  6  7       5
 1  3  -1 [-3  5  3] 6  7       5
 1  3  -1  -3 [5  3  6] 7       6
 1  3  -1  -3  5 [3  6  7]      7
```

### 示例 2

**输入：** nums = [1], k = 1

**输出：** [1]

## 解题思路

每个窗口都重新扫一遍是 O(nk)，而窗口每次只移动一格：进去一个数、出去一个数。能不能只维护「还有机会成为最大值的那些下标」？能——用一个队列，队列里的值从队首到队尾递减，队首永远是当前窗口的最大值。每个下标最多进队一次、出队一次，总代价 O(n)。

### 队列里存的是下标

只存值的话，窗口右移时没法知道「队首那个最大值是不是已经滑出去了」。存下标就能同时回答两件事：值是多少（`nums[q[0]]`），还在不在窗口里（`q[0] >= i - k + 1`）。

### 三步：进、出、记

**① 进队并维护单调性**：新来的 `x` 若比队尾的元素还大（或相等），队尾那个元素就永远当不成最大值了——它比 `x` 先出窗口，值又更小，所以直接从队尾弹掉，直到队尾比 `x` 大为止。

**② 弹出滑出窗口的队首**：窗口左端点是 `left = i - k + 1`，队首下标若小于 `left`，它已经不在这格窗口里了，从队首弹掉。窗口每轮只右移一格，所以最多只有一个下标过期，这里写 `if` 就够了。

**③ 记录答案**：`left >= 0` 时窗口才装满 `k` 个元素，此时 `nums[q[0]]` 就是这一格窗口的最大值。

```python
for i, x in enumerate(nums):
    while q and nums[q[-1]] <= x:   # ① 新人更强，老人让位
        q.pop()
    q.append(i)
    left = i - k + 1
    if q[0] < left:                 # ② 队首滑出窗口
        q.popleft()
    if left >= 0:                   # ③ 窗口满了才记答案
        ans.append(nums[q[0]])
```

### 为什么队首一定是最大值

队列里的下标是按时间顺序排列的，值是递减的。任何不在队列里的下标，只有两种命运：被后面某个更大的值顶掉了（那它不可能是最大值），或者已经滑出窗口（那它不算数）。所以「当前窗口的最大值」只可能在队列里，而队列递减，队首即答案。

### 推演：示例 1

`k = 3`，窗口左端点 `left = i - 2`。

| `i` | `nums[i]` | ① 进队后（下标） | `left` | ② 是否弹队首 | ③ 答案 |
| --- | --- | --- | --- | --- | --- |
| 0 | 1 | [0] | −2 | 否 | — |
| 1 | 3 | [1] | −1 | 否 | — |
| 2 | −1 | [1, 2] | 0 | 否 | 3 |
| 3 | −3 | [1, 2, 3] | 1 | 否 | 3 |
| 4 | 5 | [4] | 2 | 否 | 5 |
| 5 | 3 | [4, 5] | 3 | 否 | 5 |
| 6 | 6 | [6] | 4 | 否 | 6 |
| 7 | 7 | [7] | 5 | 否 | 7 |

第 1 步：`3` 进队时把下标 0（值 1）弹掉——窗口右移后 1 不可能再是最大值。第 4 步：`5` 一次弹掉 3、2、1 三个下标，队列只剩它自己。整个过程中队首都没有过期，所以「② 是否弹队首」这一列全是「否」；换一组 `[9,8,7,6], k = 2` 就能看到过期：`i = 2` 时队首下标 0 已滑出，弹出后答案才是 8。

## 完整代码实现

```python
from collections import deque
from typing import List


class Solution:
    def maxSlidingWindow(self, nums: List[int], k: int) -> List[int]:
        ans = []
        q = deque()                     # 存下标，值从队首到队尾递减
        for i, x in enumerate(nums):
            # ① 进队：队尾比新值小的都当不成最大值了
            while q and nums[q[-1]] <= x:
                q.pop()
            q.append(i)
            # ② 出队：队首滑出窗口
            left = i - k + 1
            if q[0] < left:
                q.popleft()
            # ③ 记住：窗口装满 k 个元素后，队首就是最大值
            if left >= 0:
                ans.append(nums[q[0]])
        return ans
```

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 每个窗口重新扫 k 个元素 | O(nk) | O(1) | k 接近 n 时退化成 O(n²) |
| 大根堆存 `(-值, 下标)` | O(n log n) | O(n) | 每轮入堆一次，惰性删除过期堆顶 |
| 单调队列（最优） | O(n) | O(k) | 每个下标最多进队一次、出队一次，队列长度不超过窗口大小 |

## 易错点总结

### 1. 只维护单调性，不弹滑出窗口的队首

删掉 `if q[0] < left: q.popleft()` 后，队首可能是早就出窗的最大值。示例 1 恰好看不出来（那个 3 后来被 5 顶掉了），换 `[9,8,7,6], k = 2` 立刻暴露：输出 `[9,9,9]`，正确答案是 `[9,8,7]`。

### 2. 出队条件差一格

`q[0] < left` 写成 `q[0] < left - 1`，过期一格的下标会多留一轮。同样用 `[9,8,7,6], k = 2`：`i = 2` 时队首是下标 0（值 9），本该弹出却留着，输出 `[9,9,8]`。判断依据是「下标小于窗口左端点」，而左端点是 `i - k + 1`，不是 `i - k`。

## 扩展思考

- 把「弹队尾」的比较从 `<=` 改成 `<`，等值元素会留在队列里。答案不变（等值元素谁当队首都对），只是队列更长；`<=` 更省空间。
- 同一套「右边入、左边出、队首取答案」的骨架，把「最大」换成「最小」就是滑动窗口最小值；把队列换成「前缀和 + 单调队列」可以求长度受限的最大子段和。
