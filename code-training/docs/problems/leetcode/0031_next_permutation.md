# 31. 下一个排列

## 题目描述

整数数组的**下一个排列**是指其整数的下一个字典序更大的排列。更正式地，如果数组的所有排列根据其字典顺序从小到大排列在一个容器中，那么数组的下一个排列就是在这个有序容器中排在它后面的那个排列。如果不存在下一个更大的排列，那么这个数组必须重排为字典序最小的排列（即，其元素按升序排列）。

- 必须**原地**修改，只允许使用额外常数空间。

**提示：**

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 100`

## 示例

### 示例 1

**输入：** nums = [1,2,3]

**输出：** [1,3,2]

### 示例 2

**输入：** nums = [3,2,1]

**输出：** [1,2,3]

### 示例 3

**输入：** nums = [1,1,5]

**输出：** [1,5,1]

## 解题思路

求「下一个排列」和求「下一个整数」是同一件事：尽量只改动**最靠右**的一位。扫描从右往左找「还能变大」的位置 `i`，把它换成右边比它大的数中最小的那个，再把 `i` 右边重排成升序——此时右边一定是降序，所以「重排成升序」就是一次反转。

### 第一步：找最靠右的下降点

从右往左找第一个 `nums[i] < nums[i+1]` 的位置。它右边是一段**降序**（否则更靠右的位置就该被选中），所以 `i` 就是把前缀压到极限的位置：只有换掉 `nums[i]`，排列才会变大，而且变大幅度最小。

```python
i = n - 2
while i >= 0 and nums[i] >= nums[i + 1]:
    i -= 1
```

找不到（`i == -1`）说明整个数组降序，它已经是字典序最大的排列，下一个排列要回到最小的那个：直接把整个数组反转。

### 第二步：换一个「刚好大一点」的数

`i` 右边是降序的，所以从右往左数，第一个大于 `nums[i]` 的数就是右边**最小**的那个大于它的数。换它，才保证是「下一个」而不是跳过去。

```python
j = n - 1
while nums[j] <= nums[i]:
    j -= 1
nums[i], nums[j] = nums[j], nums[i]
```

### 第三步：把后缀变成最小

换完之后，`i` 右边仍然是降序（被换过来的数刚好卡在正确的位置），而降序数组反一下就是升序，也就是这一段的字典序最小值。

```python
l, r = i + 1, n - 1
while l < r:
    nums[l], nums[r] = nums[r], nums[l]
    l += 1
    r -= 1
```

`i == -1` 时 `l = 0`，同一段代码正好把整个数组反转，所以「整体降序」这个边界不需要单独写分支。

### 推演：`[1,3,5,4,2]`

| 步骤 | 操作 | 数组 |
| --- | --- | --- |
| 初始 | — | [1,3,5,4,2] |
| ① 找下降点 | `3 < 5`，`i = 1` | [1,3,5,4,2] |
| ② 找替换数 | 从右往左第一个 `> 3` 的是 4，`j = 3` | [1,4,5,3,2] |
| ③ 反转 `i+1` 之后 | 反转 `[5,3,2]` | [1,4,2,3,5] |

再走一遍示例 2：`[3,2,1]` 全程降序，`i = -1`；跳过第二步，第三步从 `0` 开始反转，得到 `[1,2,3]`。

## 完整代码实现

```python
from typing import List


class Solution:
    def nextPermutation(self, nums: List[int]) -> None:
        """
        Do not return anything, modify nums in-place instead.
        """
        n = len(nums)

        # ① 最靠右的下降点：它右边全是降序
        i = n - 2
        while i >= 0 and nums[i] >= nums[i + 1]:
            i -= 1

        # ② 右边第一个大于 nums[i] 的数（因为右边降序，从右往左第一个就是最小的那个）
        if i >= 0:
            j = n - 1
            while nums[j] <= nums[i]:
                j -= 1
            nums[i], nums[j] = nums[j], nums[i]

        # ③ 反转后缀：降序反一下就是升序；i == -1 时正好反转整个数组
        left, right = i + 1, n - 1
        while left < right:
            nums[left], nums[right] = nums[right], nums[left]
            left += 1
            right -= 1
```

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
| --- | --- | --- | --- |
| 生成全部排列再取下一个 | O(n!) | O(n!) | 枚举量随 n 爆炸 |
| 三步扫描（最优） | O(n) | O(1) | 三次线性扫描，原地交换与反转 |

## 易错点总结

### 1. 下降点找反了

`while i >= 0 and nums[i] >= nums[i + 1]` 写成 `nums[i] < nums[i + 1]`，找的就成了「上升点」，示例 1 的 `[1,2,3]` 会一路退到 `i = -1`，输出 `[3,2,1]`（正确答案 `[1,3,2]`）。判据是「左边比右边小」，也就是从右往左第一次不再降序的位置。

### 2. 替换数从左往右找

`j` 从 `i + 1` 往右找第一个大于 `nums[i]` 的数，取到的是右边**最大**的那个。`[1,3,5,4,2]` 会得到 `[1,5,2,4,3]`，而正确答案是 `[1,4,2,3,5]`——把「刚好大一点」换成了「大很多」，跳过了好几个排列。后缀是降序，所以必须从右往左找。

## 扩展思考

- 求「上一个排列」时把三处比较全部取反（找 `nums[i] > nums[i+1]`、找第一个小于 `nums[i]` 的数、后缀改成降序），扫描方向不变。
- 若数组里有重复元素，这套三步法依然正确：`nums[i] >= nums[i+1]` 里的等号保证不会把相等的元素当成下降点。
