# 0124. 二叉树中的最大路径和

## 题目描述

二叉树中的 **路径** 被定义为一条节点序列，序列中每对相邻节点之间都存在一条边。同一个节点在一条路径序列中 **至多出现一次**。该路径 **至少包含一个** 节点，且不一定经过根节点。

**路径和** 是路径中各节点值的总和。

给你一个二叉树的根节点 `root`，返回其 **最大路径和**。

## 示例

**示例 1：**
```
输入：root = [1,2,3]
输出：6
解释：最优路径是 2 -> 1 -> 3 ，路径和为 2 + 1 + 3 = 6
```

**示例 2：**
```
输入：root = [-10,9,20,null,null,15,7]
输出：42
解释：最优路径是 15 -> 20 -> 7 ，路径和为 15 + 20 + 7 = 42
```

## 解题思路

### 路径长什么样：每条路径有唯一的「最高点」

路径在这个题里是一条不重复经过节点的简单路径。在树上，这样一条路径必有一个**最高点** —— 离根最近的那个节点。从这个最高点往下，路径最多分出两条「腿」：一条进左子树、一条进右子树；每条腿都是一路向下、不再分叉的链。

这句话把问题拆成两层，而且两层的要求不一样：

- **对外**（返回给父节点）：腿只能有**一条**。父节点只有一个接口接孩子，接不了两条；
- **对内**（更新答案）：以当前节点为最高点时才可以把两条腿都接上，此时路径是「左腿 + 当前节点 + 右腿」。

把这两件事混在一起写，就是这题最常见的错：返回完整路径和，祖先把它当成一条腿，同一批节点被算了两遍。

每个节点都当一次最高点，取最大值，就覆盖了所有可能的路径 —— 包括整条路径都在某棵子树里、完全不经过根的那种。

对比一下最直接的想法：枚举两个端点再求它们之间的路径和。树上有 `O(n²)` 对节点，每一对还要先求 LCA 才知道路径经过哪些节点，而本做法每个节点只处理一次。

### 关键观察：负数的子树不如不接

一条腿往下延伸，每多接一个节点就多一段和。如果某棵子树能提供的最大下行链是负的，接上只会让和小下去，那就不接，贡献记 0。

「不接」不等于路径可以为空：最高点自己的值永远被计入，所以每条路径至少有一个节点，这正是题目要求的。这也是为什么答案要能是负数 —— 全负的树上，答案是最接近 0 的那个单节点。

### 方法一：后序 DFS + 全局最大值（返回一条腿，答案另存）

自底向上。先拿到左右子树各自能提供的最大下行链（负数截成 0），在当前节点处做两件事：

```text
经过当前节点的完整路径 = 左链 + 当前值 + 右链      → 更新全局答案
返回给父节点的链       = 当前值 + max(左链, 右链)   → 只能挑一条
```

```python
from typing import Optional

class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        best = root.val                     # 至少要有一个节点，先拿根节点的值兜底

        def gain(node: Optional[TreeNode]) -> int:
            nonlocal best
            if node is None:
                return 0                    # 空子树贡献 0，等于「不接」
            left = max(gain(node.left), 0)
            right = max(gain(node.right), 0)
            best = max(best, left + right + node.val)   # 以它为最高点
            return node.val + max(left, right)          # 只能给父节点一条腿

        gain(root)
        return best
```

三个细节都在代码里：

- `best` 用 `root.val` 起手，不是 0。全负的树上答案是最接近 0 的负数，用 0 会把「一条路径都不选」当成合法答案；
- `gain(None)` 返回 0，一箭双雕：既表示「这条腿不接」，又让叶子节点的 `left + right + node.val` 自然退化成它自己的值；
- `return node.val + max(left, right)` 是唯一往上传的东西。注意它**不是** `left + right + node.val` —— 那正是「返回完整路径和」的错法。

先递归再处理自己，天然就是后序：父节点用到的两个数，是子节点算完才拿到的。

### 方法二：不用全局变量，返回 (下行链, 子树内最优)

`nonlocal` 是这份代码唯一的状态出口，读的人必须在脑子里跟踪「`best` 在递归途中被改过几次」。把它换成返回值，函数就成了纯函数：每棵子树返回两个数 —— **给父节点用的下行链** 和 **这棵子树内部的答案**。

```python
from typing import Optional

class Solution:
    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        def dfs(node: Optional[TreeNode]) -> tuple:
            if node is None:
                return 0, float('-inf')     # 空树里一条路径都没有
            l_down, l_best = dfs(node.left)
            r_down, r_best = dfs(node.right)

            down = node.val + max(l_down, r_down, 0)          # 给父节点：挑一条腿或不挑
            through = node.val + max(l_down, 0) + max(r_down, 0)  # 以它为最高点
            return down, max(through, l_best, r_best)

        return dfs(root)[1]
```

`down` 里的 `max(l_down, r_down, 0)` 是「两条腿挑一条，或者一条都不挑」；`through` 里两项各自 `max(..., 0)`，是「左腿接不接」和「右腿接不接」两个独立决定。`float('-inf')` 让「子树里没有路径」这个初值不会污染 `max`（用 0 的话，全负子树会被算成 0）。

两种写法遍历次数、复杂度完全一样，差别在代码形状：

- 全局变量版更短，但 `best` 的生命周期横跨整个递归，调试时没法把某棵子树的答案单独拿出来看；
- 元组版是纯函数，任意子树都能单独调用验证 —— `dfs(node)` 直接回答「这棵子树里的最大路径和是多少」，也天然适配不允许闭包 / 全局状态的场景。

### 两种写法怎么选

| 写法 | 时间 | 空间 | 什么时候用 |
|---|---|---|---|
| 全局变量 + 返回单值 | O(n) | O(h) | 面试默认写法，代码最短 |
| 返回二元组 | O(n) | O(h) | 想把递归调成纯函数、方便单测或并行 |

没有更快的算法：答案依赖每个节点的值，至少得把整棵树读一遍。所以「更好的写法」指的是**更好读、更好验证**，不是更小的复杂度。

## 完整代码实现

下面这段是本题的基准实现（页面上的「跑样例」与逐帧可视化回放的也是这一段）：`findPath` 返回以当前节点为端点的最大链式路径和，全局 `res` 记录完整路径的最大值。

```python
from typing import Optional

class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right

class Solution:
    """
    124. 二叉树中的最大路径和 - 深度优先搜索（后序遍历）

    核心思想：
    同时维护两个值：
    1. 以当前节点为端点的最大链式路径和（返回给父节点）
    2. 经过当前节点的完整路径和（更新全局最大值）

    时间复杂度：O(n)
    空间复杂度：O(h)，h 为树高
    """

    def maxPathSum(self, root: Optional[TreeNode]) -> int:
        if not root:
            return 0

        res = root.val

        def findPath(root: TreeNode) -> int:
            nonlocal res
            if not root:
                return 0

            left_s = max(findPath(root.left), 0)
            right_s = max(findPath(root.right), 0)

            ans = left_s + right_s + root.val
            res = max(ans, res)

            return max(left_s, right_s) + root.val

        findPath(root)
        return res
```

## 示例推演

以示例 2 的 `root = [-10, 9, 20, null, null, 15, 7]` 为例：

```text
         -10
        /    \
       9      20
             /  \
            15   7
```

`res` 从根节点的 `-10` 起手。后序访问顺序是 9 → 15 → 7 → 20 → -10：

| 顺序 | 节点 | 左收益 | 右收益 | 经过它的完整路径 | `res` | 返回给父节点的链 |
|---|---|---|---|---|---|---|
| 1 | 9 | 0 | 0 | 0 + 0 + 9 = 9 | max(-10, 9) = 9 | max(0, 0) + 9 = 9 |
| 2 | 15 | 0 | 0 | 0 + 0 + 15 = 15 | max(9, 15) = 15 | max(0, 0) + 15 = 15 |
| 3 | 7 | 0 | 0 | 0 + 0 + 7 = 7 | 15 | max(0, 0) + 7 = 7 |
| 4 | 20 | 15 | 7 | 15 + 20 + 7 = **42** | 42 | max(15, 7) + 20 = 35 |
| 5 | -10 | 9 | 35 | 9 + (-10) + 35 = 34 | 42 | max(9, 35) + (-10) = 25 |

节点 20 那一行是全场最高点：左右两条腿都能接上，得到 42。节点 -10 那一行虽然返回 25，但「以 -10 为最高点」的完整路径只有 34，比 42 小，所以 `res` 不再变。

示例 1 的 `root = [1,2,3]` 更短：节点 2 返回 2、节点 3 返回 3，到根节点时 `2 + 1 + 3 = 6`，返回 `max(2,3) + 1 = 4`，答案 6。

再看一个负数被截断的例子：`root = [-1, 10, null, -100]`（根 -1，左孩子 10，10 的左孩子 -100）。节点 -100 返回 -100，到节点 10 时 `max(-100, 0) = 0`，于是 `10 + 0 + 0 = 10`，`res` 变成 10；再往上的 -1 得到 `10 - 1 = 9`，`res` 保持 10。答案 10，路径就是单节点 `10`。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 枚举所有节点对 | O(n²) | O(h) | 每对还要先求 LCA 再累加，实际不可用 |
| 后序 DFS + 全局最大值（最优） | O(n) | O(h) | 每个节点访问一次，只返回一条腿 |
| 后序 DFS 返回二元组 | O(n) | O(h) | 纯函数版，同样是每个节点一次 |

> `h` 是树高。递归栈在链状树上会变成 `O(n)`。

## 易错点总结

1. **子树收益漏掉 `max(..., 0)`**：`left_s = findPath(root.left)` 少了外层 `max`，负的子树被算进路径。`root = [-1, 10, null, -100]` 会得到 9 而不是 10 —— 节点 10 被强行接上了 -100。
2. **递归返回 `left_s + right_s + root.val`（完整路径和）**：父节点把它当成一条腿，再加自己的另一条腿，路径分叉两次。`root = [1,2,3,4,5]` 会在根处算出 `11 + 1 + 3 = 15`，而正确答案是 `4 + 2 + 5 = 11`。
3. **`res` 初始化成 0**：全负的树会返回 0，而正确答案是最大的那个负数。`root = [-3]` 应返回 -3，`root = [-3, -1, -2]` 应返回 -1。

## 扩展思考

### 1. 543 题（二叉树的直径）：同一个形状，换单位

把「和最大」换成「边数最多」，递归返回的东西从「最大下行和」变成「最大下行深度」，答案更新成 `left_depth + right_depth`。两题骨架完全一样：**对外只能给一条腿，对内可以两条都算**。

### 2. 687 题（最长同值路径）：多一个合并条件

同样返回单边长度，但只有「子节点与本节点值相同」时那条腿才接得上。判断放在 `max(..., 0)` 的位置上：值不同就贡献 0。这类「树形 DP」题的共同点是状态定义在「往下走的一条链」上，答案在「某个节点处两条链合流」时更新。
