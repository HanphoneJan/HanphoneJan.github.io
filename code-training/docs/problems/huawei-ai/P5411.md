# P5411. CDN 节点聚类选址与用户覆盖计算

> 场次：2026年9月9日 · 来源：[CodeFun2000 P5411](https://codefun2000.com/p/P5411)

## 题目描述

在内容运营平台中，CDN 分发服务器用于为用户提供就近的内容下载服务。现有 $p$ 座城市，每座城市具有二维坐标和用户数。平台计划建设 $q$ 台 CDN，以兼顾覆盖用户规模与空间距离，使全体用户的加权总距离尽可能小。请按照 k-means 聚类流程确定每台 CDN 的选址坐标及其覆盖用户数。

计算过程遵循以下规则：

- 初始时，地图上尚未部署任何 CDN；
- CDN 必须位于某一座城市的坐标上；
- 迭代开始时，将输入顺序中的前 $q$ 座城市作为初始 CDN 选址；
- 每一轮迭代中，先为每座城市分配距离最近的一台 CDN；若某座城市到多台 CDN 的距离相等，则将其分配给编号更靠前的那一台；
- 针对每台 CDN 当前覆盖的城市集合，重新选择一座集合内的城市作为新的 CDN 选址，使该集合内所有用户到该城市的加权距离总和最小；若有多座城市并列最优，则选择原输入中编号更靠前的一座；
- 当所有 CDN 所在城市不再变化时，停止迭代。

城市坐标为 $(x, y)$，CDN 坐标为 $(c_x, c_y)$。一名用户到某台 CDN 的距离定义为欧氏距离：

$$d = \sqrt{(x - c_x)^2 + (y - c_y)^2}$$

若第 $i$ 座城市的用户数为 $u_i$，其被分配到的 CDN 编号为 $z_i$，则该 CDN 坐标为 $(c_{x,z_i}, c_{y,z_i})$。全体用户的加权总距离为：

$$Total = \sum_{i=1}^{p} u_i \cdot \sqrt{(x_i - c_{x,z_i})^2 + (y_i - c_{y,z_i})^2}$$

每台 CDN 的覆盖用户数等于被分配至该 CDN 的所有城市的用户数之和。

约束条件：

- 城市数量 $p$ 为正整数，满足 $0 < p < 100$；
- 每座城市的横坐标、纵坐标和用户数均为浮点数，数值均大于 `0` 且小于 `100`；
- CDN 数量 $q$ 为正整数，满足 $0 < q < 100$ 且 $q \le p$。

## 输入格式

第一行包含一个正整数 $p$，表示城市数量。

接下来 $p$ 行，每行包含三个以英文逗号分隔的浮点数 $a,b,c$，依次表示该城市的横坐标、纵坐标和用户数，单位为万人。

最后一行包含一个正整数 $q$，表示允许建设的 CDN 数量。

## 输出格式

输出 $q$ 行，每行包含三个以英文逗号分隔的浮点数 $a,b,c$，依次表示一台 CDN 的横坐标、纵坐标及其覆盖用户数，单位为万人。所有浮点数均保留 `2` 位小数。

CDN 按横坐标 $a$ 升序输出；若横坐标相同，则按纵坐标 $b$ 升序输出。

## 示例

### 示例 1

**输入：**

```
4
1.00,1.00,10.00
2.00,1.00,1.00
5.00,5.00,1.00
6.00,5.00,10.00
2
```

**输出：**

```
1.00,1.00,11.00
6.00,5.00,11.00
```

**说明：**

按输入顺序将城市记为 `0`、`1`、`2`、`3`。初始时，前 `2` 座城市分别作为第 `1` 台和第 `2` 台 CDN 的选址，即 $(1.00,1.00)$ 与 $(2.00,1.00)$。

第一轮分配中，城市 `0` 到 $(1.00,1.00)$ 的距离为 $0$，分配给第 `1` 台 CDN；城市 `1` 到 $(2.00,1.00)$ 的距离为 $0$，分配给第 `2` 台 CDN。城市 `2` 到 $(1.00,1.00)$ 的距离约为 $5.66$，到 $(2.00,1.00)$ 的距离为 $5.00$，分配给第 `2` 台 CDN。城市 `3` 到 $(1.00,1.00)$ 的距离约为 $6.40$，到 $(2.00,1.00)$ 的距离约为 $5.66$，也分配给第 `2` 台 CDN。

因此第 `1` 台 CDN 的簇只包含城市 `0`；第 `2` 台 CDN 的簇包含城市 `1`、`2`、`3`。第一轮重新选址时，第 `1` 台簇内只有城市 `0`，仍选城市 `0`。第 `2` 台簇内以城市 `1`、`2`、`3` 分别作为候选，加权距离和约为 $61.57$、$15.00$、$6.66$，因此选择城市 `3`，坐标为 $(6.00,5.00)$。

第二轮分配中，城市 `0` 和城市 `1` 距离 $(1.00,1.00)$ 更近，分配给第 `1` 台 CDN；城市 `2` 和城市 `3` 距离 $(6.00,5.00)$ 更近，分配给第 `2` 台 CDN。第二轮重新选址时，第 `1` 台簇中城市 `0` 的加权距离和为 $1.00$，城市 `1` 为 $10.00$，仍选城市 `0`；第 `2` 台簇中城市 `2` 的加权距离和为 $10.00$，城市 `3` 为 $1.00$，仍选城市 `3`。选址不再变化，停止迭代。

最终第 `1` 台 CDN 位于 $(1.00,1.00)$，覆盖城市 `0` 和城市 `1`，用户数为 $10.00+1.00=11.00$；第 `2` 台 CDN 位于 $(6.00,5.00)$，覆盖城市 `2` 和城市 `3`，用户数为 $1.00+10.00=11.00$。按横坐标升序输出。

### 示例 2

**输入：**

```
1
5.50,6.25,7.75
1
```

**输出：**

```
5.50,6.25,7.75
```

**说明：**

只有 `1` 座城市和 `1` 台 CDN。初始 CDN 选址就是该城市 $(5.50,6.25)$。

该城市到 CDN 的距离为 $0$，加权距离和为 $7.75 \times 0 = 0$，因此选址不会发生变化。最终 CDN 坐标仍为 $(5.50,6.25)$，覆盖用户数为该城市的用户数 `7.75` 万人。

### 示例 3

**输入：**

```
3
1.00,1.00,2.00
1.00,3.00,4.00
4.00,2.00,6.00
3
```

**输出：**

```
1.00,1.00,2.00
1.00,3.00,4.00
4.00,2.00,6.00
```

**说明：**

CDN 数量与城市数量相同，共有 `3` 座城市和 `3` 台 CDN。初始时前 `3` 座城市各自作为一台 CDN 的选址。

每座城市到自身 CDN 的距离都是 $0$，到其他 CDN 的距离均大于 $0$，因此分配结果固定为每座城市归属自己的 CDN。每个簇只有一座城市，重新选择时选址保持不变。

最终按横坐标、纵坐标升序输出：$(1.00,1.00)$ 覆盖用户数 `2.00`，$(1.00,3.00)$ 覆盖用户数 `4.00`，$(4.00,2.00)$ 覆盖用户数 `6.00`。
