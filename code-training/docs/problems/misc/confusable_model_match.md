# 芯片型号模糊匹配

> 芯片贸易业务面试手撕题 · 核心代码模式

## 题目描述

客户在 QQ 上发来的询盘里，型号是手打的，最常见的手误是把数字打成形近字母：`O` 和 `0`、`I` 和 `1`、`S` 和 `5` 混着打。给一个询盘型号和一个标准型号库，找出库里与它最接近的型号。

距离规则：

- 比较时**大小写不敏感**；
- 易混字符互相替换代价为 **0.5**（`O`/`0`、`I`/`1`、`S`/`5`，两个方向都算）；
- 其它字符的替换、插入、删除代价都是 **1**；
- 距离**超过**阈值的型号不算匹配。

返回最小距离，以及所有达到最小距离的型号；并列时按它们在库里的原顺序返回。没有任何型号的距离不超过阈值时，返回 `(None, [])`。

## 输入格式

- `query`：询盘里的型号；
- `library`：标准型号列表；
- `threshold`：距离阈值。代价以 0.5 为粒度，阈值不是 0.5 的整数倍时向下取整（`1.9` 按 `1.5` 处理）。

## 输出格式

- `(距离, 型号列表)`；
- 无匹配时 `(None, [])`。

## 示例

### 示例 1

**输入：** `query = "STM32F1O3C8T6", library = ["STM32F103C8T6", "STM32F103CBT6", "STM32F101C8T6", "STM32F103RCT6"], threshold = 2`

**输出：** `[0.5, ["STM32F103C8T6"]]`

**说明：** 询盘第 8 位是字母 `O`，标准型号对应位置是数字 `0`，易混替换只花 0.5。另外三个候选分别是 1.5、1.5、2.5，最大的那个超过阈值。

### 示例 2

**输入：** `query = "stm32f103c8t6", library = ["STM32F103C8T5", "STM32F103C8T7"], threshold = 2`

**输出：** `[1.0, ["STM32F103C8T5", "STM32F103C8T7"]]`

**说明：** 询盘全小写，库里是混合大小写，比较前会统一转小写，所以大小写不算差异。两个候选各差一位数字（`5`/`6`、`7`/`6`），都是普通替换，距离并列，按库中顺序一起返回。

### 示例 3

**输入：** `query = "STM32F1O3C8T6", library = ["ATMEGA328P", "STM32F103RCT6"], threshold = 2`

**输出：** `[null, []]`

**说明：** `ATMEGA328P` 与询盘长度差 4，插删代价已经超过阈值；`STM32F103RCT6` 的距离是 2.5。库里没有匹配项，返回 `(None, [])`，页面上按 JSON 显示成 `[null, []]`。

## 解题思路

### 这题要走哪条路

拆成两层：**一对字符串怎么量差距**，和**整个型号库怎么挑出最像的**。

第一层是加权编辑距离。普通编辑距离把每次替换都记 1，这里要把「像手误」的替换降到 0.5。第二层是扫库：每个型号算一次距离，只留距离最小的一批，超过阈值的直接丢。

### 为什么普通编辑距离不够

普通编辑距离能看出「差了几处」，看不出「差的是不是手误」。举个例子：询盘是 `STM32F103C8T6`，库里同时有

- `STM32F1O3C8T6` —— 把数字 `0` 打成了字母 `O`；
- `STM32F103C8T5` —— 最后一位数字打错了。

普通编辑距离下两者都是 1，并列返回，业务还得自己挑。把易混替换降到 0.5 之后，前者是 0.5、后者是 1，答案唯一：`STM32F1O3C8T6`。

所以 0.5 的作用不只是「放宽阈值内能进几个」，而是**给候选排序**：手误比真错更像。

### 代价只有三档，全部乘 2 存成整数

| 操作 | 代价 | 乘 2 后 |
|------|------|---------|
| 字符相同 | 0 | 0 |
| 易混替换（`o`/`0`、`i`/`1`、`s`/`5`） | 0.5 | 1 |
| 其它替换 | 1 | 2 |
| 插入 / 删除 | 1 | 2 |

乘 2 之后，阈值也乘 2，最后把结果除以 2 返回。这样 DP 里所有加法、最小值、与阈值的比较都发生在整数上，并列判断是精确的 `==`。

### 一对型号：加权编辑距离

设 `a` 是询盘（转小写），`b` 是型号（转小写），`dp[i][j]` 表示「把 `a` 的前 `i` 个字符变成 `b` 的前 `j` 个字符」的最小代价。最后一位只有三种处理方式：

- 删掉 `a[i-1]`：剩下 `dp[i-1][j]`，代价 1；
- 在末尾插入 `b[j-1]`：剩下 `dp[i][j-1]`，代价 1；
- 把 `a[i-1]` 替换成 `b[j-1]`：剩下 `dp[i-1][j-1]`，代价 0、0.5 或 1。

三种都要算，取最小：

```python
def _distance_x2(a: str, b: str) -> int:
    n, m = len(a), len(b)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        dp[i][0] = 2 * i                 # 删掉 a 的全部字符
    for j in range(1, m + 1):
        dp[0][j] = 2 * j                 # 插入 b 的全部字符
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            dp[i][j] = min(
                dp[i - 1][j] + 2,                                    # 删
                dp[i][j - 1] + 2,                                    # 插
                dp[i - 1][j - 1] + _sub_cost(a[i - 1], b[j - 1]),    # 替换 / 相同
            )
    return dp[n][m]
```

`_sub_cost` 就是上面的代价表：相同返回 0，易混对返回 1，其它返回 2。

边界 `dp[i][0]` 和 `dp[0][j]` 是「从空串插入 / 删到空串」，各自要 `i`、`j` 次操作，乘 2 就是 `2i`、`2j`。

### 扫库时的剪枝

型号库可能很大，但真正接近的候选很少，有两个地方可以不进 DP：

**长度差距**：每次插入或删除最多改变长度差 1，代价至少 1。所以 `|len(a) - len(b)| × 2 > limit` 的型号一定超阈值，连表都不用开。

**前缀代价**：所有代价非负，`dp[i][j]` 只会越加越大。某一格算出来已经超过 `limit`，从它往后的路径不可能再降回阈值内，这一格可以直接丢弃。

有了这两条，真正算 DP 的只有长度接近的少数型号。

### 并列与空结果

扫库时维护两个变量：`best` 是最小距离，`hits` 是所有达到最小距离的型号。

- `d < best`：找到了更近的，替换 `best`，`hits` 清空后只放当前型号；
- `d == best`：并列，直接追加；
- `d > limit`：超过阈值，丢弃。

题目说的是「距离**超过**阈值不算匹配」，所以判断用 `>` 而不是 `>=`：距离正好等于阈值的候选仍然要留下。示例 2 的 1.0 就是「不超过 2」的正常匹配。

### 空间只留一行

`dp[i][j]` 只依赖上一行（`dp[i-1]`）和本行左边一格（`dp[i][j-1]`），所以整张表不用留，两个一维数组滚动即可：

```
prev = 上一行
cur  = 这一行（逐格填，左边格子已经算好）
```

空间从 `O(n·m)` 降到 `O(m)`。完整代码用的就是这个版本。

## 完整代码实现

```python
CONFUSABLE = {frozenset(pair) for pair in (('o', '0'), ('i', '1'), ('s', '5'))}


def _sub_cost(x: str, y: str) -> int:
    """替换代价；全部 ×2 存成整数：0 / 1 / 2 分别代表 0 / 0.5 / 1。"""
    if x == y:
        return 0
    return 1 if frozenset((x, y)) in CONFUSABLE else 2


def _distance_x2(a: str, b: str) -> int:
    """加权编辑距离 ×2（a、b 已转小写）。"""
    n, m = len(a), len(b)
    prev = [2 * j for j in range(m + 1)]          # a 为空：插入 j 个字符
    for i in range(1, n + 1):
        cur = [2 * i] + [0] * m                   # b 为空：删除 i 个字符
        for j in range(1, m + 1):
            cur[j] = min(
                prev[j] + 2,                                  # 删 a[i-1]
                cur[j - 1] + 2,                               # 插 b[j-1]
                prev[j - 1] + _sub_cost(a[i - 1], b[j - 1]),  # 替换 / 相同
            )
        prev = cur
    return prev[m]


def find_most_likely(query: str, library: list[str], threshold: float):
    """返回 (最小距离, 并列的型号列表)；没有匹配返回 (None, [])。"""
    q = query.lower()
    limit = int(threshold * 2)                    # 阈值也换成「半格」为单位
    best, hits = None, []

    for model in library:
        m = model.lower()
        if abs(len(q) - len(m)) * 2 > limit:      # 长度差已经超阈值，跳过
            continue
        d = _distance_x2(q, m)
        if d > limit:                             # 「超过」才丢；等于阈值仍匹配
            continue
        if best is None or d < best:
            best, hits = d, [model]
        elif d == best:                           # 并列：全要
            hits.append(model)

    return (None, []) if best is None else (best / 2, hits)
```

## 示例推演

### 把示例 1 的四笔账逐位对上

询盘是 `STM32F1O3C8T6`，四个候选从左到右对齐：

| 库中型号 | 与询盘的差异 | 距离 |
|---------|-------------|------|
| `STM32F103C8T6` | 第 8 位 `O` / `0`，易混替换 | 0.5 |
| `STM32F103CBT6` | 第 8 位 `O` / `0`（0.5）+ 第 11 位 `8` / `B`（1） | 1.5 |
| `STM32F101C8T6` | 第 8 位 `O` / `0`（0.5）+ 第 9 位 `3` / `1`（1） | 1.5 |
| `STM32F103RCT6` | 第 8 位 `O` / `0`（0.5）+ 第 10 位 `C` / `R`（1）+ 第 11 位 `8` / `C`（1） | 2.5，超阈值 |

最小距离是 0.5，只有 `STM32F103C8T6` 一个，按库中顺序返回。

### DP 表怎么填出一个 0.5

拿一对短串 `1O3` 和 `103` 看整张表（单位是乘 2 之后的整数）：

| `dp` | `""` | `1` | `0` | `3` |
|------|------|-----|-----|-----|
| `""` | 0 | 2 | 4 | 6 |
| `1` | 2 | 0 | 2 | 4 |
| `o` | 4 | 2 | **1** | 3 |
| `3` | 6 | 4 | 3 | 1 |

看 `o` 行、`0` 列那一格：替换 `o`→`0` 是易混对，代价 1。它比「先删 `o` 再插 `0`」（2 + 2 = 4）便宜，也比左边和上边的格子小，于是右下角最终是 1，除以 2 得到 0.5。

如果混淆表里没有 `o`/`0`，这一格会是 2，最终距离变成 1 —— 前面「`STM32F1O3C8T6` 和 `STM32F103C8T5` 都是 1」那个并列就又出现了，算法分不出哪个更像手误。

## 复杂度分析

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 二维 DP 表 | O(K·n·m) | O(n·m) | 每对型号开一张 (n+1)×(m+1) 的表，直观 |
| 滚动数组（最优） | O(K·n·m) | O(m) | 只保留上一行，空间降到型号长度 |

其中 K 为型号库大小，n 为询盘长度，m 为型号长度。

## 易错点总结

### 1. 归一化之后还把易混对写成大写

`query.lower()` 之后，字符里只剩 `o` / `i` / `s`。混淆表要是写成 `{'O', '0'}`，这个集合永远匹配不上，所有易混替换都按普通替换算 —— 代码照样跑，示例 1 会给出 1.0 而不是 0.5。混淆表必须和归一化之后的字符同一种大小写。

### 2. 阈值没有跟着乘 2

距离全部乘 2 之后，易混替换是 1、普通替换是 2，阈值 2 对应 4。如果只把 DP 乘 2、阈值仍按 2 比较，实际阈值就缩小了一半。拿询盘 `STM32F1O3C8T6`、库里只有 `STM32F103CBT6` 试：它和询盘的距离是 1.5（乘 2 后 3），按正确阈值 4 应该返回，按错误的 2 比较会被判成「超过阈值」，最后返回空。

### 3. 并列只保留了第一个

`if d < best` 只处理了「找到了更近的」，忘了 `elif d == best` 就把并列的其余型号漏掉。示例 2 的两个候选距离都是 1.0，正确结果是两个都返回；只写 `<` 会只剩第一个。

## 扩展思考

- **带状 DP**：所有代价非负，一条路径从 `(0, 0)` 走到 `(i, j)`，`|i - j|` 最多等于已经花掉的插入/删除次数，而每次插删都恰好花 1 的代价。所以距离不超过 T 的路径只可能落在 `|i - j| ≤ T` 的带内，每行只算带内的格子，单对字符串从 `O(n·m)` 降到 `O(n·T)`。型号只有十几位，这个优化在这里没有收益，主代码没写。
- **大库先分桶**：库上万条时，可以按型号长度分桶，只与长度差不超过阈值的桶比，省掉大量前缀检查。
- **代价可配置**：把 `CONFUSABLE` 抽成配置，不同品类可以加自己的易混对（`Z`/`2`、`B`/`8`），代价也能按业务统计的错字频率调整。
- **告诉业务改哪一位**：DP 只给出距离。如果客服需要看到「第 8 位 `O` 应为 `0`」，要在转移时记下选择，再从 `(n, m)` 倒推出一条最短编辑路径。
- **全角字符**：客户从中文输入法里可能打出全角 `Ｏ`、`０`。在归一化阶段加一步 NFKC 折叠，比把它们逐个塞进易混表干净。
