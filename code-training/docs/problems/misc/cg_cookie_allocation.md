# 饼干分配（一个孩子可拿多块）

> 成谷科技笔试编程题 · ACM 模式（stdin/stdout）

## 题目描述

有 $n$ 个孩子和 $m$ 块饼干。第 $i$ 个孩子的胃口是 $g_i$，第 $j$ 块饼干的尺寸是 $s_j$。

每块饼干最多分给一个孩子，一个孩子可以拿多块饼干。一个孩子拿到的饼干总尺寸**大于等于**它的胃口时，这个孩子就算被满足。求最多能满足多少个孩子。

## 输入格式

- 第一行：两个整数 $n$、$m$；
- 第二行：$n$ 个整数，表示每个孩子的胃口；
- 第三行：$m$ 个整数，表示每块饼干的尺寸。

## 输出格式

- 一行：一个整数，最多能满足的孩子数量。

## 数据范围与解法

下面的精确解按 $m\le16$ 设计，使用 $O(3^m)$ 的状压 DP。

> 整块分配、一个孩子可以拿多块时，一般情形是 NP-hard：所有孩子的胃口相同时，问题就退化成 bin covering。若原题的 $m$ 远大于 16，题面通常还有额外限制（例如允许把饼干切开），见「扩展思考」。

## 示例

### 示例 1

**输入：**
```
1 1
3
3
```

**输出：**
```
1
```

**说明：**
一块尺寸为 3 的饼干正好等于胃口 3，满足条件，答案 1。

### 示例 2

**输入：**
```
3 4
1 4 5
1 2 3 4
```

**输出：**
```
3
```

**说明：**
把 `1` 给胃口 1 的孩子，把 `4` 给胃口 4 的孩子，把 `2+3=5` 给胃口 5 的孩子，三个都能满足。

### 示例 3

**输入：**
```
1 2
5
2 2
```

**输出：**
```
0
```

**说明：**
两块饼干总和 $4$，小于胃口 5，一个孩子也满足不了。

### 示例 4

**输入：**
```
3 2
1 2 3
1 1
```

**输出：**
```
1
```

**说明：**
一块尺寸为 1 的饼干就能满足胃口为 1 的孩子，但剩下两个孩子需要 2 和 3，剩下的一块 1 不够，答案 1。

## 解题思路

### 这题要走哪条路

先把「满足哪些孩子」这件事定下来：最优解一定满足**胃口最小的前 $k$ 个孩子**。剩下的事是判断这些饼干能不能凑出 $k$ 组，每组总和大于等于对应胃口。饼干是整块的，不能切开，这个判定一般情形是 NP-hard；小规模下用状压 DP 枚举每一组用了哪些饼干。

### 第一步：最优解是排序后的前缀

假设某个方案满足了胃口较大的孩子 $j$，却没有满足胃口较小的孩子 $i$（$g_i\le g_j$）。把分给 $j$ 的那组饼干改分给 $i$，因为总和本来就大于等于 $g_j$，大于等于 $g_i$ 更没问题，满足人数不变。反复做这种交换，就能得到一个「只满足前 $k$ 小胃口」的最优解。

所以先把胃口升序排序，答案一定是某个前缀长度 $k$。

### 第二步：为什么不能直接贪心

一个很自然的想法是：胃口从小到大处理，每次拿最小的饼干，累加到大于等于当前胃口为止。这个贪心**不保证最优**：

胃口 `[1,4,5]`，饼干 `[1,2,3,4]`。贪心先用 1 满足胃口 1，再用 `2+3=5` 满足胃口 4（5 已经大于 4），最后只剩 4，不够胃口 5，答案 2。正确做法是 `1`、`4`、`2+3=5` 分别给三个孩子，答案 3。

问题在于「拿哪几块饼干凑一组」会影响后面：贪心为了凑够 4 多拿了一块 3，正好把胃口 5 需要的组合拆掉了。小规模下只能把子集选择枚举出来。

### 第三步：状压 DP 的状态与转移

用二进制掩码表示饼干的集合：

- `sum_mask[mask]`：掩码 `mask` 里所有饼干的尺寸和。
- `f[mask]`：只用 `mask` 里的饼干（可以剩一些不用），最多能满足前几个孩子。

转移时枚举 `mask` 的一个非空子集 `sub`，把它作为「下一个孩子」的一组饼干：

$$\text{rest}=\text{mask}\setminus\text{sub},\qquad k=f[\text{rest}]$$

如果 $k<n$ 且 $\text{sum\_mask}[\text{sub}]\ge g_k$，就把 `sub` 分给第 $k$ 个孩子（下标从 0 开始）：

$$f[\text{mask}]=\max\left(f[\text{mask}],\ k+1\right)$$

`rest` 是 `mask` 的真子集，所以 `f[rest]` 在遍历到 `mask` 时已经算好了。最终答案是 `f[(1 << m) - 1]`。

为什么这样能得到最优解：任取一个最优分组，把最后一个被满足孩子的饼干组记作 `sub`，其余组记作 `rest`。`rest` 至少能满足前 $k-1$ 个孩子，而 `sub` 的总和大于等于第 $k-1$ 个胃口；胃口是升序的，所以 `sub` 也一定大于等于第 `f[rest]` 个胃口。转移因此能构造出不少于原方案的分组。

### 第四步：边界与失败方式

- 胃口和饼干都为空时答案是 0：`n == 0 or m == 0` 直接返回。
- 等于也算满足：判定写 `sum_mask[sub] >= g[k]`，不能写成 `>`。
- 枚举子集用 `sub = (sub - 1) & mask`。漏掉 `& mask` 会枚举到不属于当前掩码的位，`sum_mask` 就会读到错误的值。
- `f` 数组的答案在 `f[total - 1]`，不是 `f[0]`。

### 推演：拿示例 2 走一遍

胃口 `[1,4,5]`，饼干 `[1,2,3,4]`，编号 0~3。

| 掩码 | 包含的饼干 | 总和 | `f` |
|---|---|---|---|
| `0b1001` | 1、4 | 5 | 2 |
| `0b0110` | 2、3 | 5 | 1 |
| `0b1111` | 全部 | 10 | 3 |

处理 `0b1111` 时，枚举到 `sub = 0b0110`（饼干 2、3，和 5）：`rest = 0b1001`，`f[rest] = 2`，第 2 个孩子胃口是 5，$5\ge5$，得到 $2+1=3$。这就是三组 `(1)`、`(4)`、`(2,3)`，与示例一致。

## 完整代码实现

```python
import sys


def max_satisfied(g, s) -> int:
    """返回最多能满足的孩子数量。"""
    g = sorted(g)
    s = sorted(s)
    n, m = len(g), len(s)
    if n == 0 or m == 0:
        return 0

    total = 1 << m
    # sum_mask[mask] = mask 里所有饼干的尺寸和
    sum_mask = [0] * total
    for mask in range(1, total):
        low = mask & -mask
        sum_mask[mask] = sum_mask[mask ^ low] + s[low.bit_length() - 1]

    # f[mask] = 用 mask 里的饼干最多能满足前几个孩子
    f = [0] * total
    for mask in range(1, total):
        best = 0
        sub = mask
        while sub:
            rest = mask ^ sub
            k = f[rest]
            # 把 sub 这一组饼干分给第 k 个孩子（胃口为 g[k]）
            if k < n and sum_mask[sub] >= g[k]:
                cand = k + 1
                if cand > best:
                    best = cand
                    if best == n:      # 已经满足所有孩子，不可能更好
                        break
            sub = (sub - 1) & mask
        f[mask] = best
    return f[total - 1]


def solve() -> None:
    data = list(map(int, sys.stdin.read().split()))
    if not data:
        return
    n, m = data[0], data[1]
    g = data[2:2 + n]
    s = data[2 + n:2 + n + m]
    print(max_satisfied(g, s))


if __name__ == "__main__":
    solve()
```

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |

| 状压 DP + 子集枚举（最优） | O(3^m) | O(2^m) | 每个掩码枚举它的所有子集；`sum_mask` 与 `f` 各开 2^m |

其中 $m$ 为饼干数量。

## 易错点总结

### 1. 把「大于等于」写成「大于」

题目要求总尺寸**大于等于**胃口，等于也算满足。`g=[3]`、`s=[3]` 时答案是 1；写成 `>` 会输出 0。

### 2. 直接套 LeetCode 455 的双指针

455 的限制是「每个孩子最多一块饼干」，本题一个孩子可以拿多块。`g=[5]`、`s=[3,3]` 时，455 的双指针会输出 0，而本题可以两块一起给，$3+3=6\ge5$，答案是 1。

### 3. 用「最小胃口 + 最小饼干逐个累加」的贪心

这个贪心在示例 2 上就会错：先用 1 满足胃口 1，再用 `2+3=5` 满足胃口 4，只剩 4 不够胃口 5，得到 2；正确分组是 `(1)`、`(4)`、`(2,3)`，答案是 3。饼干是整块的，凑组的选择会影响后面，必须枚举子集。

## 扩展思考

如果允许把饼干**掰开**分给多个孩子，问题就退化成总量比较：把胃口升序排序，设饼干总尺寸为 $S$，答案就是最大的 $k$ 使

$$\sum_{i=0}^{k-1}g_i \le S$$

因为可以把所有饼干当成一个总量池，按胃口从小到大依次填满；等于也可以，所以是小于等于。这时时间复杂度只有排序的 $O((n+m)\log(n+m))$。整块分配的一般情形是 NP-hard，所以本题的小规模限制（或「可切分」的额外条件）是绕不开的。
